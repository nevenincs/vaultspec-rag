# Start vaultspec-rag

vaultspec-rag is a semantic retrieval engine for vault Markdown and architecture decisions, source code, and admitted independent documents. It turns sources into chunks with provenance, GPU-generated dense and optional sparse vectors, and searchable Qdrant payloads. Search combines vector candidates with content ranking and source-specific shaping. A resident local service shares models and project runtimes and manages durable indexing jobs; Python, CLI, stdio MCP and a browser monitor expose different parts of that system.

Read this orientation first, then only references relevant to the task. Never preload the collection. Each capability reference contains module summaries and selective detail parts; follow only owners needed for the change. References distinguish inspected implementation, documentation claims, static test expectations and uncertainty. They hold the detailed library; this entrypoint explains how the parts fit together.

Use Vaultspec RAG for finer discovery of current code and governing decisions, then inspect current source before planning or editing. If RAG is unavailable or inconclusive, use scoped local search within the identified package or family. This is a static orientation snapshot. Current source, accepted decisions and project instructions govern work.

## Request surfaces and runtime ownership

The lazy facade in [the package entrypoint](../../../src/vaultspec_rag/__init__.py) resolves public indexing, search, model and store exports on first use. The `cli/` package assembles commands and shared rendering; `server/` owns the loopback HTTP daemon and route adapters. `serviceclient/` supplies discovery, compatibility and bounded transport; `mcp/` is the stdio assistant adapter. Service-first dispatch crosses the adapter boundary into the service-owned capability. MCP handlers explicitly require a reachable compatible service and offload synchronous transport calls; their search, reindex and resource operations delegate to that service. The server entrypoint selects separate HTTP and stdio branches and imports MCP only for stdio. See [Public API and CLI](references/public-api-cli.md), [Service lifecycle](references/service-lifecycle.md) and [MCP integration](references/mcp-integration.md).

Keep this dispatch distinct from embedded execution. Indexers and `VaultStore` are directly constructible Python components, and support profiles distinguish managed-service and embedded-local use. That does not establish automatic local fallback for every CLI or Python call. The monitor's persisted-inventory fallback through the owner CLI is a specific contract; MCP's compatible-service requirement is another. Follow the relevant adapter before changing fallback behavior.

The daemon binds on loopback, checks Host and supplied Origin, and uses request-runtime credentials for protected operations. Discovery carries process/version/schema and launch identity plus service and optional Qdrant/monitor observations. Startup publishes RUNNING as a required ownership claim before requests; warming and heartbeat publication have separate best-effort paths. Anonymous `/health` omits the service token, authenticated health includes it, and presented credentials are validated. Reachability, identity compatibility and capability readiness answer different questions.

[The registry](../../../src/vaultspec_rag/service.py) defines `ServiceRegistry`, with a process-level singleton in `registry.py`. It owns shared embedding/reranker state and per-root slots containing store, graph and runtime collaborators. Root admission counts both resident slots and construction reservations. Leases distinguish warm reads, transient cold read-only access, exclusive maintenance and compute work. A cold read-only lease can open and close a temporary store without making the root a warm compute resident. Runtime construction wires `VaultSearcher`, `VaultIndexer`, `CodebaseIndexer` and `DocumentIndexer` to the slot store, shared GPU lock, graph cache and publication/readiness callbacks.

Compute leases acquire a `ServiceQuiesceController` ticket before obtaining project/runtime resources. The controller closes admission during pause, tracks epoch-bound in-flight tickets, and requires drain before GPU-release acknowledgement can establish a quiesced state safe for borrowing. Warming keeps admission closed until completion advances the epoch. Pause intent, drained workers and released GPU ownership are separate facts. Shutdown similarly stops intake, settles work, closes stores and stops owned children before releasing machine ownership; a transport shim cannot supply those host-runtime guarantees.

GPU coordination is split between `_gpu_owner.py`, `_gpu_admission.py`, `_gpu.py` and `embeddings.py`. Machine-wide ownership permits one model stack or an identity-bound loan; a separate load-window claim serializes memory admission and loading. Accelerator resolution checks ownership before importing torch, prefers CUDA then MPS, and refuses CPU inference. Admission uses available memory with credit for this process's allocation and handles unreadable readings separately. `EmbeddingModel` loads checked local snapshots, maintains independent dense/sparse bucket budgets and replans recognized OOMs. CPU chunk workers do not own models. See [GPU and model runtime](references/gpu-model-runtime.md).

## Admission, extraction and chunk production

Indexing first resolves mutable configuration into an immutable `ResolvedIndexPolicy` in `indexer/_resolved_policy.py`. The snapshot binds routes, profile, ignores, decoding, chunking and approved preprocessing to canonical fingerprints. Persistent membership, operation-only exclusions and content semantics have separate identities, including code/document-specific epochs. Workers consume that policy rather than rereading options halfway through a run. See [Content admission](references/content-admission-policy.md).

Code and independent-document ownership use a closed content-kind vocabulary. Classification handles ignores, explicit routes/transforms and conflicts; an explicit-only profile rejects unmatched paths, while the conventional profile admits its conventional code suffix set. Parser selection is separate: a language-map suffix need not be conventionally admitted. `CodeContentDiscovery` produces full-tree or exact changed-path preflight authority, canonicalizes in-root paths, applies raw-code size/binary probes unless a transform applies, and reports structured counts with bounded examples. Documents do not become admitted code merely because discovery encountered them.

Code/document worker reads bind work to regular admitted files. `indexer/_source_file.py` rejects links/noncanonical paths and compares the opened descriptor with observed identity; platform-specific opening checks prevent source-name redirection. Workers hash bounded blocks and distinguish vanished, unavailable, skipped and failed outcomes. Those differences feed file-state and retry behavior: no usable chunks is not interchangeable with verified deletion.

`CodebaseIndexer` in `_codebase_indexer.py` coordinates discovery, checkpoints, support accounting and publication. `CodeChunkProducer` in `_chunk_producer.py` owns CPU submission; `_chunk_worker.py` hashes/decodes and constructs chunks; `CodeConsumerPipeline` in `_consumer_pipeline.py` owns encode/write consumption. Code uses AST parsing where a grammar exists and falls back to `TextSplitter` on parsing failure. `ASTChunker` preserves structural text, line bounds and function/class context, recursively splits oversized nodes and merges small adjacent output. Text chunks locate exact emitted substrings for spans. Paths, content hashes and file-local ordinals participate in identity. See [Code indexing](references/code-indexing.md).

Approved document processing has its own pipeline. Preprocessing supports command or entry-point hooks and bounded batches; outputs and locators are validated before becoming indexed units. Worker cache identity includes source hash, rule/invocation context, mode and output bounds, and cached output is revalidated. Emitted units retain extractor identity/version, source path, title, section, anchor, locator and metadata. `DocumentIndexer` in `_document_indexer.py` streams fragments into document-native chunks; `_document_identity.py` derives fragment-aware IDs from canonical source identity, content fingerprint and locator or unit ordinal. Approval, environment hygiene and process limits have separate owners: `_hook_sandbox.py` curates a child environment but is not an OS sandbox. See [Document processing](references/document-processing.md) before extending extractors or cache behavior.

Vault Markdown has semantic preparation separate from code and extracted documents. `VaultIndexer` in `_vault_indexer.py` calls `_vault_prep.py` for document type, metadata, title/status/feature extraction and Markdown chunks. Chunks carry line spans, sections and passages; the first also retains the full body. This supports ADR/status/graph handling rather than treating vault hits as ordinary text records. Parsing/traversal delegated to `vaultspec_core` remain dependency boundaries in the evidence. See [Vault indexing](references/vault-indexing.md).

## Bounded encoding and incremental work

The code producer runs serially or through spawn workers with a bounded future window and batch manifests. Its consumer queue bounds both chunk count and retained byte weight, rejecting an individually oversized segment. Producers check cooperative control while blocked and detect consumer failure. The indexer owns preprocessing/support accounting and supplies callbacks. CPU parsing can advance without granting workers model, store or publication ownership.

`indexer/_slicing.py` estimates text/payload/vector memory, segments files with stable ordinals and final markers, and packs ordered weighted slices. `_streaming.py` encodes dense/sparse values, converts them for storage, brackets mutations and clears vector-bearing fields after settlement. Its bounded `_SliceWriter` preserves write order where queued writes overlap inference/storage, has bounded close/abandon paths and retains the first failure. Vault streaming sorts chunks by embedding-text length and feeds slices rather than encoding the corpus at once. Embedding forwards hold the GPU lock; relevant conversions occur outside that section.

`CodeSupportBudget`, document accounting and `_resource_ceilings.py` connect source/extracted bytes, generated chunks, weighted retention, RSS/CUDA observations and admitted profile limits. Profile checks also cover backend, RAM, store-volume free space and separate workspace write headroom. Vault's inspected memory telemetry is observational, without the configured ceilings used for code/document admission. `RunPolicy` measures no-progress liveness using explicitly typed durable progress, supports protected mutations, and exposes bounded waits to storage writes. Activity counters alone do not reset its durable-progress clock.

Code full indexing prepares a build collection, streams admitted paths, verifies deferred writes, reconciles identities and publishes. Unscoped incremental work discovers membership and compares hashes with prior evidence; scoped work classifies only supplied paths and reads affected-path evidence. A membership/content policy epoch mismatch requires full reindex. Code drift repair removes exact superseded IDs before reopening evidence, retries within a per-path budget and exposes deferred paths when exhausted.

Documents support full, discovered-incremental and exact-scope runs. Full runs retain previous points on per-file processing failure and publish only when failures do not remain. Incremental runs recover pending publication, compare discovered/scoped sources with prior evidence, replace changed points and remove obsolete/deleted identities before reconciliation and publication. Extractor refusal therefore cannot silently replace previously searchable content with authoritative absence.

Vault fingerprints separate raw bytes, normalized body and indexed metadata. Metadata-only work can overwrite payload while retaining vectors if prepared/stored ordinals match exactly; uncertain shape falls back to body re-embedding. Full work removes shrunken chunk tails and purges stale documents after streaming and the ingest barrier; clean rebuild has a bounded geometry-recreation path. Scoped work deletes only candidates established by prior proof. The stat-evidence cache reuses hashes for matching size/mtime outside its racy-write window, but content identity remains authority. Full-membership pruning and scoped updates differ.

Donor reuse optimizes encoding across compatible evidence. Discovery/inspection are capped; eligibility checks source kind, schemas, model identity and content epoch; the encode seam reconstructs exact embedding evidence before adopting vectors. Missing sparse data, read failure or mismatch remains an encode miss. Only vectors are adopted; local payload construction and publication obligations still apply. Reuse does not substitute for source admission or confirmed local writes.

## Durable publication and searchable authority

Treat an indexing result, persisted vectors and a published search generation as three outcomes. `IndexResult` reports work counts and telemetry. Qdrant contains applied bytes. The run ledger/publication machinery determine which compatible generation is authoritative for serving. `job_dispatch.py` checks actual successful publication before converting an indexer return into durable job success; certified publication can settle an unwind race. [Publication integrity](references/publication-integrity.md) is central for resume, freshness, audit and repair.

`RunLedger` in `indexer/_run_ledger_runtime.py` persists generation signatures, commit units, file outcomes, proof/evidence, receipts, mutations and tombstones in SQLite. Construction verifies an exact supported schema; explicit integrity checking is separate. A compatible active generation may resume, changed signature invalidates it, and repeated failures can retire it. Unsupported durable format requires rebuild/set-aside handling rather than reinterpretation of old evidence.

The mutation seam is explicit: prepare exact receipt units before external storage action, apply the operation, persist applied state, obtain storage confirmation, then record confirmed evidence and acknowledgement. `_run_ledger_commits.py` guards receipt transitions and replay/conflict checks. `_run_ledger_files.py` marks a path indexed only with complete matching confirmed upserts; deletion requires its deletion-unit evidence. A write returning from one layer is insufficient to skip the rest. Server-mode deferred ingestion adds an ingest barrier and exact point-count check before terminal actions.

Publication compatibility includes root/source/backend/collection, storage/vector schemas, policy and content identities. `ProofReadToken` fences backend reads with ledger revision and reservation sequence and rejects open receipts; a second snapshot detects authority changes during reads. Finalization advances through guarded phases, checks complete segment sequences and convergent file outcomes, and requires durable publication before successful finish. Code generation lifecycle publishes breadth before moving the served pointer and certifies after reconciliation, separating build work from the served generation.

Interrupted work can leave prepared/applied mutations, retained points or pending publication. Recovery validates storage against proof, settles complete confirmed receipts where possible, and otherwise removes exact affected IDs and replays affected source work within the recovery boundary. Resume skips confirmed units only when compatibility/evidence support it. Drift reopening, rollback direction, tombstones and failed extraction carry different durable obligations; a single last-run-success flag cannot express them.

Cleanup is equally exact. Ledger compaction accepts a successful newest generation and preserves generations referenced by publication or surviving file evidence. Cross-domain route changes journal origin deletion after destination confirmation and retain destination-generation/exact origin-ID obligations through replay. Old code build collections become reclaim candidates only under verified pointer/proof evidence, active-reader protection and grace rules. Search readiness may therefore be unavailable, stale or non-authoritative even when a collection exists.

## Retrieval, result shaping and availability

`VaultSearcher` in [the search package](../../../src/vaultspec_rag/search/_searcher.py) owns encoding/cache coordination and source pipelines. `_parsing.py` removes inline filter tokens into canonical keys; `_validation.py` validates values and rejects filters incompatible with the selected source, including document filters when combined search excludes documents. Code noise selection merges persistent/per-call hide, only and demote controls. Domains distinguish production, tests, docs, locale, generated, vendored and worktree paths. Selection/preference affect candidates separately from index admission. See [Search retrieval](references/search-retrieval.md).

Cleaned query text is encoded into dense and optional sparse representations, cached by surface/text; dense-only cache entries are recomputed when sparse data is required. Store search requests retrieve vector candidates for the corresponding source collection. Retrieval and content ranking are separate: results retain full candidate `rerank_text`, while snippets/passages are shaped for display. CrossEncoder prediction runs under GPU serialization, bounds content length and reduces batch size on recognized OOM. Display snippets should not replace available content evidence at the ranking seam.

Vault search filters metadata, removes index-type rows, maps/reranks chunks, groups by document, applies bounded graph and intent/type/status adjustments, and selects passages. `GraphCache` refreshes per-root graphs by TTL and uses a shorter retry interval after failure. Code search pushes domain restrictions into storage, applies path-glob and legacy-payload fallback filtering, widens retrieval within a cap to fill a page, then reranks, demotes, applies preference and optional locale deduplication. Document search maps independent provenance/locators and ranks its candidates. Combined orchestration reuses the parsed/encoded query, gathers selected domains and selects a deterministic global page.

Optional hosted TypeSafe query assessment and relevance scoring live under `search/_typesafe_*`. Query judgments are advisory; candidate questions use full rerank content and bounded query clauses. Only sufficiently confident rejection of every clause drops a candidate; survivor scores use useful probabilities. Transport bounds deadlines/bytes/concurrency, caches/coalesces requests and exposes circuit cooldown with redacted reasons. Unavailable query assessment can yield no session, while candidate-ranking failure has its own fallback/error path. This remote layer does not own storage/publication; inspect the reference before changing availability behavior.

Service/client shaping connects retrieval to publication/readiness. Combined outcomes preserve per-domain success/failure and partial results, with selected-source readiness. A successful neighboring source does not establish absence in a failed one. An empty page is authoritative absence only when serving evidence supports it. Freshness policy/wait observations, generation/revision, reason, retryability and remediation distinguish usable current authority, accepted stale evidence and inability to establish absence. Transport success alone does not settle these facts. Feedback IDs exist on option surfaces, but the observed combined-option partition does not copy them into domain options; end-to-end combined feedback propagation remains uncertain.

## Jobs and watcher convergence

The `job_manager/` family separates durable job/attempt identity, desired control state, execution binding and persistence. Control validates target/revision/state and persists intent before signalling a worker. Completion/control acknowledgement are fenced by exact attempt and task identity, with released-worker/resource evidence required before acknowledging unwind. Retry creates a linked identity and can supersede retryable ancestors after success; deleting retained terminal history is separate. See [Durable jobs](references/durable-index-jobs.md).

Execution binds runners, persists start before opening the execution gate, and runs synchronous indexing in worker threads behind the appropriate limiter. Resource flags track leases, capacity, GPU wait and pipeline ownership. `job_control.py` delivers cooperative pause, cancel, shutdown and quiesce at safe checkpoints/protected-span edges; intent is not immediate proof of termination. Quiesce preparation uses exact attempt/binding/generation claims against duplicate resumed dispatch. Restore preserves invalid/newer snapshots separately and normalizes interrupted work; shutdown closes dispatch, joins within bounds, flushes state and reports surviving owners.

Watching adds durable convergence intent above jobs. `watcher_intake.py` classifies native events through a policy snapshot, includes prior ownership for deletions, and persists source-qualified observations before making them executable. `WatcherRetryState` records exact pending/captured paths and events, convergence generation, attempt token/job/owner, failures and circuit/refusal. Scope-capacity overflow records full-reindex-required refusal rather than truncating paths and claiming exactness. See [Watcher convergence](references/watcher-convergence.md).

`WatcherController` models coalescing/freshness deadlines, service/capacity pressure, retry and circuit delays. Admission chooses eligible READY work by earliest deadline and rotates exact ties. `watcher_execution.py` reserves/captures scope, validates preflight, creates or joins a managed incremental publication job, runs under a registry compute lease and settles durable state. Success clears the captured attempt while retaining newer pending observations; interruption/failure restores scope and applies retry policy. An event is an observation, admission creates a bounded work request, and certified publication/settlement establishes convergence.

Restart recovery checks durable fences against manager history, reattaches eligible active work or settles missing/mismatched/terminal attempts. Deadline-expired durability can hand off a bounded recovery marker; lost exact scope requires unscoped/full-reindex recovery. A qualifying certified explicit rebuild can reconcile existing refusal state; any successful job cannot. Settlement tasks and generation-owned drains have lifetime boundaries. Project convergence from these authorities and refusals, not solely from an empty in-memory queue.

## Storage, maintenance and observation

`VaultStore` in [store runtime](../../../src/vaultspec_rag/store_runtime.py) composes collection, ingest, donor, catalog and search mixins. Local mode uses root-local Qdrant storage and exclusive/per-collection locks; server mode uses root-prefixed collections on a shared endpoint and different point-lock behavior. `store_schema.py` centralizes geometry, payload/filter/index vocabulary and provenance/conformance. Reads reconcile existing schema/index evidence without creating absent collections. Fatal geometry/sparse-model mismatch differs from same-geometry dense-model mismatch retained as nonconforming. See [Vector store](references/vector-store.md).

Managed Qdrant supply/supervision are independent from store access. Pinned acquisition/trust, authenticated children, attach/refuse/orphan recovery, quarantine and storage-version gates belong to [Managed Qdrant](references/managed-qdrant.md). Daemon startup supervises a child in server mode when an explicit URL is absent; external endpoints and owned children have different lifetime authority. Model/cache supply, role/extras intent and Torch repair belong to [Installation provisioning](references/installation-provisioning.md), not inference dispatch.

[Storage maintenance](references/storage-maintenance.md) covers attribution/manifests, live/disk survey, protected namespaces, archive/restore/migration and reclaim. Generation surveys report candidates; removal is separate. Unverifiable pointers, active readers and invalid/young grace stamps hold reclaim. Missing/malformed stamp data restarts grace conservatively. Shared anchors, atomic/private writes, held traversal and process-incarnation probes support callers but confer no namespace mutation authority; see [Platform filesystem](references/platform-filesystem.md).

Operator readiness, structured logs, job/resource projections, process observations and metrics provide different evidence views. Pressure classification receives sampled signals and is described as presentation evidence, not admission policy. CLI human/JSON output and terminal watch consume service/job/log lanes. Doctor/status may remove confirmed-dead discovery records, so blanket read-only descriptions are inaccurate. See [Observability readiness](references/observability-readiness.md).

Monitor source is `src/monitor/`. `App.tsx` composes health/work/inventory/request/runtime/log views; `model.ts` validates payloads and supplies authenticated requests; `use-polling.ts` avoids overlap, aborts on hidden/cleanup and retains prior data with stale/error evidence. `server/local-service.ts` is a capability bridge with loopback/origin/auth checks, bounded forwarding and route allowlists. It forwards service operations, runs lifecycle controls through the owner CLI and can read persisted inventory when live forwarding fails. Browser observations are not durable job/index state. See [Monitor UI](references/monitor-ui.md).

[Configuration](references/configuration.md) owns environment/settings contracts. [Developer toolchain](references/developer-toolchain.md) covers command registry, init and static guards; [CI release delivery](references/ci-release-delivery.md) covers workflows, exact-wheel/native artifacts, monitor admission, smoke harnesses and channels. Frozen corpora, labels, spans, metrics and performance captures belong to [Retrieval evaluation](references/retrieval-evaluation.md); controlled fixtures, test tiers, accelerator borrowing and architecture guards to [Test infrastructure](references/test-infrastructure.md). Historical measurements and assertion source describe evidence or expectations, not current passing checks.

## Route a feature through its owners

For a search option or result field, start with search parsing/validation/options/models and the owning pipeline, then follow server serialization, serviceclient/CLI and MCP contracts exposing it. Read search retrieval and public API/CLI first; add vector store for filters/payloads, MCP or monitor when those surfaces participate. A display field and stored field have different persistence implications.

For an extractor/content kind, start with content admission and document processing; add code/vault indexing if ownership moves. Fingerprints, approval/cache identity, locator/point identity, resource bounds and destination-confirmed migration are connected obligations. Add publication integrity/vector store for durable schema or authority changes.

For resume/publication faults, pair publication integrity with the source indexer, vector store for confirmation and durable jobs for recovery. Distinguish drift, applied-but-unconfirmed mutations, proof compatibility, finalization and served-pointer movement before choosing repair. For watcher convergence, pair watcher convergence, durable jobs and publication integrity; add content admission for routing/policy refresh.

For service/job controls, combine service lifecycle, durable jobs and GPU runtime to trace intent through admission closure, unwind and release. For a monitor feature, pair monitor UI with the backend capability and observability readiness: route shape, bridge allowlist, decoder and stale-state handling must agree with the authority shown. Use the index to select further families, not to preload every reference.
