## Capability summary

- [src/vaultspec_rag/tests/test_document_index_symlinks.py](../../../../src/vaultspec_rag/tests/test_document_index_symlinks.py) exercises the document-indexing path against unsafe aliases and source swaps: discovery/preflight membership, admission scan reasons, revalidation of accepted or forged preflight state, worker reads and hashing, preprocess extractor launch, incremental digest selection and point removal, and ordinary-file behavior including a symlinked project root. Fixtures use temporary files, an unloaded embedding model with a test forward stub, and `VaultStore` call sites. These are intended guards, not verified implementation claims.
- [src/vaultspec_rag/tests/test_document_result_shaping.py](../../../../src/vaultspec_rag/tests/test_document_result_shaping.py) covers document hit mapping (identity, locator, metadata and rerank text), rejection of malformed metadata, stable combined-domain ordering, stored-offset passage extraction and validation, plus rank-ordered passage-pair budgeting. [src/vaultspec_rag/tests/test_document_search_validation.py](../../../../src/vaultspec_rag/tests/test_document_search_validation.py) covers filter compatibility for document, combined, code, and the legacy `docs` alias. [src/vaultspec_rag/tests/test_document_store_search.py](../../../../src/vaultspec_rag/tests/test_document_store_search.py) checks which named document filters become store predicates and that unknown keys do not.
- [src/vaultspec_rag/tests/test_document_unit_bounding.py](../../../../src/vaultspec_rag/tests/test_document_unit_bounding.py) covers splitting oversized preprocessor units within the configured document bound, gapless text coverage, inherited unit provenance, unique and repeatable point IDs, and omission of whitespace-only units. [src/vaultspec_rag/tests/test_domain.py](../../../../src/vaultspec_rag/tests/test_domain.py) pins path-domain examples, precedence, label sets, and Windows-separator normalization.
- [src/vaultspec_rag/tests/test_donor_admission.py](../../../../src/vaultspec_rag/tests/test_donor_admission.py) exercises candidate filtering/ranking and a bounded donor inspection window using mocked manifest, publication-pointer, proof, and transport seams. Expectations include stopping after three selected donors, six maximum candidate inspections, avoiding pointer reads when reuse is disabled or the manifest is unavailable, and treating failed vector adoption as an encode miss. [src/vaultspec_rag/tests/test_donor_embedding_identity.py](../../../../src/vaultspec_rag/tests/test_donor_embedding_identity.py) covers fail-closed donor reuse for changed, absent, or malformed CODE embedding inputs, plus identical-input reuse and existing VAULT/document identity contracts.
- [src/vaultspec_rag/tests/test_embeddings_dependencies.py](../../../../src/vaultspec_rag/tests/test_embeddings_dependencies.py) expects missing Torch or Sentence Transformers to produce actionable provisioning guidance. [src/vaultspec_rag/tests/test_encode_bucket_planner.py](../../../../src/vaultspec_rag/tests/test_encode_bucket_planner.py) covers contiguous token-budget planning, count caps and oversized singleton items; token-denominated OOM ceilings and recovery; dense and sparse bucketed encoding, bucket-local retry, output order, progress reporting, GPU-lock scope, independent ceilings, and calibration against a tokenizer. The calibration test is written to acquire a model snapshot before CPU tokenizer use; this report does not run it. [src/vaultspec_rag/tests/test_encode_hygiene_unit.py](../../../../src/vaultspec_rag/tests/test_encode_hygiene_unit.py) checks dense/COO/CSR sparse conversion parity and all-zero rows, and query embedding cache round-trip, LRU eviction, surface separation, and concurrent access.
- [src/vaultspec_rag/tests/test_env_boolean_dialects.py](../../../../src/vaultspec_rag/tests/test_env_boolean_dialects.py) compares four environment readers on shared boolean spellings, then pins each reader's empty or unrecognized-value policy and a fresh-import dependency boundary for the memory probe. [src/vaultspec_rag/tests/test_env_credentials.py](../../../../src/vaultspec_rag/tests/test_env_credentials.py) covers workspace-file credential resolution gates, environment precedence, child-environment assignments and root-variable removal, and import/runtime checks intended to keep workspace-file resolution out of the resident daemon path.

## Interfaces and data flow

The test setup writes fixture files and ignore/preprocess configuration, then inspects accepted paths, chunk content, outcomes, or document-store rows. Recording doubles expose call order, batch sizes and simulated OOMs; expected results preserve input order and are paired with progress events. The calibration test obtains configured model/divisor values and tokenizes a fixed corpus. See [src/vaultspec_rag/tests/test_encode_bucket_planner.py:30-235,237-375,377-832,834-956](../../../../src/vaultspec_rag/tests/test_encode_bucket_planner.py#L30); sparse conversion/cache call sites are in [src/vaultspec_rag/tests/test_encode_hygiene_unit.py:20-151](../../../../src/vaultspec_rag/tests/test_encode_hygiene_unit.py#L20).

They set and restore environment mappings and use temporary workspace declarations and `.env` files. Fresh-interpreter probes assert import exclusions.
