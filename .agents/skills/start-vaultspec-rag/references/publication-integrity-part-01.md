## Capability summary

- [src/vaultspec_rag/\_index_breadth.py](../../../../src/vaultspec_rag/_index_breadth.py) provides the code-index breadth snapshot, shortfall value and canonical warning wording/projection shared by search surfaces. Its docstrings identify CLI and service rendering as consumers.
- [src/vaultspec_rag/\_index_integrity.py](../../../../src/vaultspec_rag/_index_integrity.py) reconciles a publication's claimed breadth with a live count, and supplies an exhaustive, proof-fenced audit of one or all concrete source collections. Serve-time results distinguish consistent, shrunken, and unverifiable. Audits distinguish consistent, drift, conflict, and rebuild-required.
- [src/vaultspec_rag/\_integrity_remediation.py](../../../../src/vaultspec_rag/_integrity_remediation.py) remembers recent shrunken observations per root and source, reports them for status, and optionally requests an incremental repair asynchronously. It does not act on unverifiable observations; the indexer's admission/evidence policy remains downstream.
- [src/vaultspec_rag/\_job_admission.py](../../../../src/vaultspec_rag/_job_admission.py) creates index jobs and performs code/document content preflight and support-profile admission before returning preflight results.
- [src/vaultspec_rag/\_job_errors.py](../../../../src/vaultspec_rag/_job_errors.py) owns stable job failure kinds, ordered legacy text classification, remediation text, and shared stall/degradation/rate-collapse thresholds.
- [src/vaultspec_rag/\_job_evidence.py](../../../../src/vaultspec_rag/_job_evidence.py) gathers cached GPU, device-load, CPU, backend, forward-pass, encode, and rate evidence; it also assembles machine-pressure evidence and passes signals to the pressure evaluator.
- [src/vaultspec_rag/\_job_progress.py](../../../../src/vaultspec_rag/_job_progress.py) samples per-step progress rates and run baselines, records acknowledged chunk work and forward/encode telemetry, and independently throttles log and durable progress writes.
- [src/vaultspec_rag/\_job_registry_state.py](../../../../src/vaultspec_rag/_job_registry_state.py) owns the in-memory bounded job-record ring, shared lock/logger, and best-effort atomic snapshot of running jobs for restart recovery.
- [src/vaultspec_rag/\_job_values.py](../../../../src/vaultspec_rag/_job_values.py) provides shared narrowing for untyped job-record values: counts, measurements, mappings, booleans, and text.

## Interfaces and data flow

Search breadth flow: `acquire_code_breadth_snapshot` reads a code publication and captures its retained-point claim; `CodeBreadthSnapshot.finish(live_count)` validates the publication fence and returns a shortfall only when the live count is below the claim. The `_if_proven` wrapper maps unreadable publication to no breadth proof. `shortfall_warnings` turns carried `shortfall` and `result_collapse` blocks into shared warning values (implementation in [src/vaultspec_rag/\_index_breadth.py:31-194](../../../../src/vaultspec_rag/_index_breadth.py#L31)).

Serve-time integrity flow: `acquire_index_integrity_snapshot` rejects combined source, obtains a publication snapshot, and records retained points, generation, and indexed identities. The snapshot's `finish` validates the token after caller-supplied backend work and classifies its live count. An absent/unreadable proof can instead be represented as unverifiable. A demonstrated shrink logs a rate-limited error; result projection emits an `index_integrity` block. The count is supplied by the serving path, not repeated here ([src/vaultspec_rag/\_index_integrity.py:187-400](../../../../src/vaultspec_rag/_index_integrity.py#L187)).

Exact audit flow: `audit_index_integrity(root, source, authority, store_factory)` requires audit-verification authority, resolves the root, reads the canonical proof, checks storage projection compatibility, pages through backend content in bounded pages, classifies payload identities against ledger evidence, then validates the publication read token. `audit_index_sources` audits the requested source or fans combined into vault, code, and document domains, mapping proof conflicts, rebuild needs, and drift to domain results and rebuild commands ([src/vaultspec_rag/\_index_integrity.py:440-946](../../../../src/vaultspec_rag/_index_integrity.py#L440)).

Repair flow: `note_integrity_verdict` records only shrunken verdicts, clears a source observation on consistent, and returns any already-known repair job ID. When configured, it launches a daemon thread to call the source-specific job starter with publication authority and an integrity initiator. `shrunken_observations` expires stale observations and returns per-source repair ID and enabled/disabled state ([src/vaultspec_rag/\_integrity_remediation.py:40-260](../../../../src/vaultspec_rag/_integrity_remediation.py#L40)).

Job admission flow: `admit_index_job` resolves the root, constructs a source/mode/authority `JobSpec` and initiator, calls the job manager, and records start plus queued progress only for a newly created job. Code and document paths expose full and scoped preflight and profile validation functions. Code profile admission augments discovery measurements with queue/RSS and host/backend/volume measurements; document admission counts scoped files and bytes with run-control checkpoints ([src/vaultspec_rag/\_job_admission.py:24-256](../../../../src/vaultspec_rag/_job_admission.py#L24)).

Job observability flow: progress reporters update shared records under `_job_registry_state._lock`; sampled rates and telemetry are read by job ID. [src/vaultspec_rag/\_job_evidence.py](../../../../src/vaultspec_rag/_job_evidence.py) narrows conditional encode/rate blocks, samples process and machine signals, and probes a backend on a daemon thread with a two-second wait bound and short cache. `degradation_evidence` emits stable forward/CPU/GPU/backend evidence plus reported encode/rate blocks; `machine_pressure` folds available signals into a tier using the pressure evaluator ([src/vaultspec_rag/\_job_evidence.py:18-511](../../../../src/vaultspec_rag/_job_evidence.py#L18)). Progress snapshots are persisted through the registry-state helper; that helper writes running-job projections atomically and treats OS write errors as best effort ([src/vaultspec_rag/\_job_progress.py:13-583](../../../../src/vaultspec_rag/_job_progress.py#L13); [src/vaultspec_rag/\_job_registry_state.py:24-94](../../../../src/vaultspec_rag/_job_registry_state.py#L24)).

## Boundaries and dependencies

- Direct local relationships visible in the slice: breadth uses operator-command formatting and source types, with publication-state imports deferred in acquisition functions ([src/vaultspec_rag/\_index_breadth.py:8-15,154-194](../../../../src/vaultspec_rag/_index_breadth.py#L8)). - Progress and registry-state share one lock, ring, and logger. Progress also uses common measurement narrowing and event logging. The snapshot path derives from managed status configuration and the job manager's record bound ([src/vaultspec_rag/\_job_progress.py:15-19](../../../../src/vaultspec_rag/_job_progress.py#L15); [src/vaultspec_rag/\_job_registry_state.py:14-44](../../../../src/vaultspec_rag/_job_registry_state.py#L14)).
