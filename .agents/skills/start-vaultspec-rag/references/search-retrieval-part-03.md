## Capability summary

**Implementation.** [src/vaultspec_rag/synthetic.py](../../../../src/vaultspec_rag/synthetic.py) builds a deterministic `.vault/` fixture: sorted indexable document types, seeded density edges plus fixed pipeline-role links, unique needles, ADR status variants, Markdown frontmatter/body, and a `CorpusManifest` of docs, needles, edges, and statuses ([src/vaultspec_rag/synthetic.py:17-53,91-137,139-209,212-293,296-359](../../../../src/vaultspec_rag/synthetic.py#L17)).

[src/vaultspec_rag/watcher_policy.py](../../../../src/vaultspec_rag/watcher_policy.py) classifies vault Markdown separately from code and document paths. Code/document classification excludes vault paths, requires a path under root, admits configured control filenames directly, and otherwise uses a resolved index policy; refresh retains the previous policy after `OSError`/`ValueError` ([src/vaultspec_rag/watcher_policy.py:19-77,80-105](../../../../src/vaultspec_rag/watcher_policy.py#L19)).

[src/vaultspec_rag/watcher_controller.py](../../../../src/vaultspec_rag/watcher_controller.py) defines immutable controller inputs/snapshots/transitions and a per-root/source adaptive convergence state machine. It covers observed scopes, collection/coalescing and freshness deadlines, retry/circuit delays, service and capacity pressure, admission/start, successful completion/cooling, cancellation/supersession release, and typed refusal ([src/vaultspec_rag/watcher_controller.py:32-74,77-269,299-410,412-519,520-657,658-765](../../../../src/vaultspec_rag/watcher_controller.py#L32)).

[src/vaultspec_rag/watcher_admission.py](../../../../src/vaultspec_rag/watcher_admission.py) picks one eligible `READY` controller with the earliest deadline. It sorts exact ties by `(canonical_root, source)` and rotates after the previous selection; the result records the selected identity, deadline, reason, and tied candidates ([src/vaultspec_rag/watcher_admission.py:14-59,62-90](../../../../src/vaultspec_rag/watcher_admission.py#L14)).

[src/vaultspec_rag/watcher_durability.py](../../../../src/vaultspec_rag/watcher_durability.py) wraps state operations in bounded worker capacity and retries transient capacity/I/O failures with backoff. It defers cancellation during durable operations, runs a separately bounded recovery-marker handoff when the durability deadline expires, and exposes helpers to initialize retry policies, persist observations, atomically admit captured scope, settle success/interruption/failure, and deliver cancellation after settlement ([src/vaultspec_rag/watcher_durability.py:39-42,72-104,107-145,148-243,245-333,336-466](../../../../src/vaultspec_rag/watcher_durability.py#L39)).

[src/vaultspec_rag/watcher_execution.py](../../../../src/vaultspec_rag/watcher_execution.py) translates persisted retry timestamps to process-monotonic time, captures and validates exact scoped admissions, creates/joins manager jobs, binds and dispatches watcher-owned attempts, tracks attempt-generation aliases, settles durable retry state on all terminal paths, and wakes the scheduler. The worker resolves scoped/unscoped paths and preflights, runs the selected incremental indexer under a registry compute lease, handles quiesce races, and publishes retry/checkpoint resilience ([src/vaultspec_rag/watcher_execution.py:85-187,190-217,220-400,424-565,567-630,631-843,846-905,907-1117](../../../../src/vaultspec_rag/watcher_execution.py#L85)).

[src/vaultspec_rag/watcher_intake.py](../../../../src/vaultspec_rag/watcher_intake.py) owns native `awatch` intake. It filters accepted add/modify/delete events through a policy snapshot; routes vault, code, and document paths (including stored ownership for deleted files); merges observations by relative path; durably persists per-source observations before exposing them to execution; initializes retry-backed convergence slots/controllers; registers reevaluation/admission callbacks; and unregisters controllers on shutdown ([src/vaultspec_rag/watcher_intake.py:74-221,224-353,356-427,430-552,555-655](../../../../src/vaultspec_rag/watcher_intake.py#L74)).

## Interfaces and data flow

- Public fixture entry point: `build_synthetic_vault(root, n_docs=24, graph_density=0.3, seed=42) -> CorpusManifest`; generated files are written under the configured vault directory, with workspace directory created as well ([src/vaultspec_rag/synthetic.py:296-359](../../../../src/vaultspec_rag/synthetic.py#L296)).
- Watch entry point: `watch_and_reindex(WatcherConfiguration)`. Initialization opens vault/code retry state and document retry state when enabled, creates one convergence slot and controller per source, reconciles restarted slots with the job manager, and registers scheduler callbacks ([src/vaultspec_rag/watcher_intake.py:442-552](../../../../src/vaultspec_rag/watcher_intake.py#L442)). The loop watches the root, refreshes policy when a configured control filename changes, classifies accepted events, persists each source's observations, updates dirty slots/controller scope, then wakes the scheduler ([src/vaultspec_rag/watcher_intake.py:555-655](../../../../src/vaultspec_rag/watcher_intake.py#L555)).
- Controller inputs/outputs: immutable `ControllerScope`, `ControllerMeasurement`, and `ControllerSnapshot` values carry generation-fenced pending/captured paths, event kinds, timing, pressure measurements, retry/circuit state, and transition evidence. `WatcherController` returns updated snapshots for observe/evaluate/admit/advance/complete/release/refuse operations ([src/vaultspec_rag/watcher_controller.py:113-269,299-410,520-657](../../../../src/vaultspec_rag/watcher_controller.py#L113)).
- Scheduling interface: controller registration receives async `reevaluate` and `admit` callbacks. Reevaluation refreshes retry truth, captures service measurements, and evaluates the controller; admission advances the fair-turn transition and calls `submit_watcher_job` ([src/vaultspec_rag/watcher_intake.py:290-353](../../../../src/vaultspec_rag/watcher_intake.py#L290)). The exact scheduler policy beyond the callback and arbiter contracts is uninspected.
- Job interface: `submit_watcher_job` asks the manager to create an incremental publication-authority index job, validates scoped code/document preflights, binds execution callbacks, and dispatches the job. The runner selects vault/code/document incremental indexing and returns a `JobExecutionResult` ([src/vaultspec_rag/watcher_execution.py:259-400,424-565,907-1049](../../../../src/vaultspec_rag/watcher_execution.py#L259)).
- State/storage: `WatcherRetryPolicy` is the delegated durable authority for pending/captured observations, attempts, retry state, and recovery markers; the assigned durability code calls its methods but does not define its schema or on-disk location ([src/vaultspec_rag/watcher_durability.py:336-466](../../../../src/vaultspec_rag/watcher_durability.py#L336)). The job manager stores and dispatches job state; the project registry supplies a compute lease; vault indexing invalidates the primary and optional secondary graph caches ([src/vaultspec_rag/watcher_execution.py:424-520,907-949,982-1034](../../../../src/vaultspec_rag/watcher_execution.py#L424)).
- External/runtime integration: `watchfiles.awatch` supplies change tuples; AnyIO worker-thread calls isolate synchronous state and indexing work; logging emits watcher lifecycle/settlement events ([src/vaultspec_rag/watcher_intake.py:17-21,594-623](../../../../src/vaultspec_rag/watcher_intake.py#L17); [src/vaultspec_rag/watcher_durability.py:20-21,72-91](../../../../src/vaultspec_rag/watcher_durability.py#L20); [src/vaultspec_rag/watcher_execution.py:19,38](../../../../src/vaultspec_rag/watcher_execution.py#L19)).
