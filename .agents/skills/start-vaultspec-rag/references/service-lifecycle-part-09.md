## Capability summary

- `serviceclient/__init__.py` defines the package's intended import-light shared client role in its module documentation and explicitly exports nothing; callers are told to import names from their defining submodules ([src/vaultspec_rag/serviceclient/__init__.py:1-12](../../../../src/vaultspec_rag/serviceclient/__init__.py#L1), in-source documentation claim).
- [src/vaultspec_rag/serviceclient/\_compat.py](../../../../src/vaultspec_rag/serviceclient/_compat.py) centralizes client/service release compatibility. It defines `package_version` as the wire field, exact-match/mismatch/unreported states and error codes, resolves this install's version from `vaultspec_rag.__version__`, classifies a payload, and supplies common reason/remediation/JSON output. `DataPlaneService` combines an optional ready port with the version verdict; `resolve_data_plane_service()` obtains both from one discovery resolution ([src/vaultspec_rag/serviceclient/\_compat.py:35-69,72-85,88-210,213-259](../../../../src/vaultspec_rag/serviceclient/_compat.py#L35)). Its docstring says data-plane operations use this seam and lifecycle/observability commands remain ungated ([src/vaultspec_rag/serviceclient/\_compat.py:237-251](../../../../src/vaultspec_rag/serviceclient/_compat.py#L237), in-source documentation claim; actual external callsites not inspected).
- [src/vaultspec_rag/serviceclient/\_discovery.py](../../../../src/vaultspec_rag/serviceclient/_discovery.py) owns service discovery and the `service.json` status publication helpers. It defines schema/phase/state/reason/source vocabularies and heartbeat thresholds; chooses the managed status path; serializes merges, replacements, and conditional deletion with a sibling OS lock and atomic private JSON writes; reads and validates status; and resolves the machine singleton into ready/absent/degraded evidence. A held lock is authoritative: the machine pointer is checked against holder identity, schema, port, and heartbeat freshness; status-file fallback is used only when no holder exists. `_default_service_port()` returns a port only for a ready resolution ([src/vaultspec_rag/serviceclient/\_discovery.py:30-99,132-160,188-379,382-443,446-710](../../../../src/vaultspec_rag/serviceclient/_discovery.py#L30)).
- [src/vaultspec_rag/serviceclient/\_search_transport.py](../../../../src/vaultspec_rag/serviceclient/_search_transport.py) owns the `/search` client entry point. It normalizes positional/named arguments into `SearchCallRequest`, narrows runtime types, parses and validates source/filter combinations, builds a source-specific payload, applies a bounded search timeout, calls the shared HTTP transport, and distinguishes a valid envelope, refusal/unavailability, malformed response, and other transport errors ([src/vaultspec_rag/serviceclient/\_search_transport.py:36-65,78-138,141-160,163-322,325-425](../../../../src/vaultspec_rag/serviceclient/_search_transport.py#L36)). The shared four-key document-filter projection is also provided here ([src/vaultspec_rag/serviceclient/\_search_transport.py:46-65](../../../../src/vaultspec_rag/serviceclient/_search_transport.py#L46)).
- [src/vaultspec_rag/serviceclient/\_status.py](../../../../src/vaultspec_rag/serviceclient/_status.py) composes canonical operator status from a `MachineResolution`, caller-probed liveness facts, and optional health data. It maps liveness to lifecycle, serializes a common status body, and provides bounded discovery reconciliation. Reconciliation only polls and reports; it does not publish, delete, restart, or terminate ([src/vaultspec_rag/serviceclient/\_status.py:48-118,121-242,245-465](../../../../src/vaultspec_rag/serviceclient/_status.py#L48)). The module documentation names `server status` and `server doctor` as adapters, but their concrete callsites were outside this read ([src/vaultspec_rag/serviceclient/\_status.py:1-8](../../../../src/vaultspec_rag/serviceclient/_status.py#L1), in-source documentation claim).
- [src/vaultspec_rag/serviceclient/\_transport.py](../../../../src/vaultspec_rag/serviceclient/_transport.py) is the shared loopback HTTP client. It provides typed request shapes, configurable finite timeouts, a response byte ceiling, refusal/timeout recognition, optional discovery-token authentication and one 401 refresh/retry, and a never-raising health probe with separate outcomes for no connection, HTTP error, timeout, and a health body ([src/vaultspec_rag/serviceclient/\_transport.py:1-29,75-98,101-135,136-267,270-327,330-503,506-760](../../../../src/vaultspec_rag/serviceclient/_transport.py#L1)). It implements reindex, non-seeding index audit, clean, job get/state/retry/delete, admin-route mapping, code-file, and vault-document calls, with refusal/timeout/other-error envelopes ([src/vaultspec_rag/serviceclient/\_transport.py:763-1249](../../../../src/vaultspec_rag/serviceclient/_transport.py#L763)). Admin query helpers allowlist filter keys for logs, jobs, search activity, storage survey, and watcher routes ([src/vaultspec_rag/serviceclient/\_transport.py:999-1123](../../../../src/vaultspec_rag/serviceclient/_transport.py#L999)).
- [src/vaultspec_rag/serviceclient/\_typed_state.py](../../../../src/vaultspec_rag/serviceclient/_typed_state.py) parses a mapping into one of the shared health/service-state Pydantic models and returns `None` for non-mappings or validation errors ([src/vaultspec_rag/serviceclient/\_typed_state.py:1-32](../../../../src/vaultspec_rag/serviceclient/_typed_state.py#L1)).

## Interfaces and data flow

- Compatibility/data plane: `resolve_data_plane_service()` calls `resolve_machine_service()`, uses its port only when ready, and classifies the same resolution payload; this avoids a separate version probe ([src/vaultspec_rag/serviceclient/\_compat.py:237-259](../../../../src/vaultspec_rag/serviceclient/_compat.py#L237)). `classify_service_version()` uses exact string equality after trimming a nonblank string; missing, blank, or non-string fields become `unreported` ([src/vaultspec_rag/serviceclient/\_compat.py:167-210](../../../../src/vaultspec_rag/serviceclient/_compat.py#L167)). Verdicts carry state, client/service versions, compatibility, error code, reason, remediation, and a JSON dictionary ([src/vaultspec_rag/serviceclient/\_compat.py:88-164](../../../../src/vaultspec_rag/serviceclient/_compat.py#L88)).
- Discovery/storage: discovery reads `VAULTSPEC_RAG_STATUS_DIR` indirectly through `managed_status_dir()` and `SERVICE_STATUS_FILENAME` ([src/vaultspec_rag/serviceclient/\_discovery.py:145-159](../../../../src/vaultspec_rag/serviceclient/_discovery.py#L145)). `service.json` is JSON; a sibling `service.json.lock` serializes status operations. Merge can create the parent directory and preserve a same-port authoritative daemon identity; replacement writes a complete daemon-owned snapshot; conditional deletion can require expected PID/port. Writes use `write_json_atomically(..., JsonWriteOptions(private=True))` ([src/vaultspec_rag/serviceclient/\_discovery.py:188-379](../../../../src/vaultspec_rag/serviceclient/_discovery.py#L188)). Resolution first probes the machine lock, then reads its pointer if held; only an unheld singleton permits status-file fallback ([src/vaultspec_rag/serviceclient/\_discovery.py:496-547,562-693](../../../../src/vaultspec_rag/serviceclient/_discovery.py#L496)).
- Search: arguments are type-checked and converted into `SearchCallRequest`; invalid source/filter inputs return structured refusals before network I/O. Valid input is mapped to `/search`, with source-dependent filters and optional feedback/freshness fields, then passed to `_do_http_call`; connection refusal returns `None`, malformed JSON/shape returns `invalid_service_response`, and other exceptions return `http_call_failed` ([src/vaultspec_rag/serviceclient/\_search_transport.py:78-138,277-379,382-425](../../../../src/vaultspec_rag/serviceclient/_search_transport.py#L78)).
- HTTP/admin: general calls use `http://127.0.0.1:{port}{path}`, derive a bearer token from a ready matching discovery record unless an initial token is supplied, and use the shared redirect-refusing opener. Requests and decoded response bodies are bounded; response reading allows at most one byte beyond the 8 MiB ceiling to detect oversize ([src/vaultspec_rag/serviceclient/\_transport.py:297-305,376-384,506-525,557-594,653-760](../../../../src/vaultspec_rag/serviceclient/_transport.py#L297)). Health probing may be unauthenticated when no matching token exists and never raises ([src/vaultspec_rag/serviceclient/\_transport.py:386-478](../../../../src/vaultspec_rag/serviceclient/_transport.py#L386)). The general transport's callers convert failures to `None` or structured `ok: false` mappings according to each wrapper ([src/vaultspec_rag/serviceclient/\_transport.py:763-807,810-855,857-885,891-997,1125-1249](../../../../src/vaultspec_rag/serviceclient/_transport.py#L763)).
- Operator status/reconcile: adapters supply `LivenessSignals` and callbacks for discovery, liveness, health, sleeping, and clock; `compose_discovery_status()` emits lifecycle plus evidence. Reconciliation requires matching machine-pointer source, positive equal holder/pointer PIDs, a nonempty service token, fresh heartbeat, matching liveness signals, and matching health PID/token before reporting convergence ([src/vaultspec_rag/serviceclient/\_status.py:48-75,209-242,290-301,313-393,396-465](../../../../src/vaultspec_rag/serviceclient/_status.py#L48)).
- Typed reports: `parse_report(model, payload)` accepts a mapping, validates a copied mapping with the supplied `HealthReport` or `ServiceStateReport` type, and returns `None` on Pydantic validation failure ([src/vaultspec_rag/serviceclient/\_typed_state.py:13-32](../../../../src/vaultspec_rag/serviceclient/_typed_state.py#L13)).
