## Interfaces and data flow

- Admin helpers accept keyword filters/roots and return decoded dictionary-shaped results from the daemon's admin transport. CLI contract helpers start loopback HTTP servers, accept HTTP JSON or query inputs, record requests, and serve fixed or option-shaped JSON responses; callers use the returned server/thread/request collection to assert and then shut down the server. The shared `_serving` context owns server/thread shutdown (120-128).
- Process helpers communicate through marker files, stderr files, or child stdout. Indexer helpers accept a production indexer and paths, then return materialized file results or chunks; queue observers read private counters while holding the queue condition. Job helpers use manager/job APIs or the persisted activity/job mechanisms and return job identifiers or edited record mappings.
- `_env_surface.source_surface()` scans configured source roots at runtime when called and produces a `Surface` of names, reads, carriers, dynamic sites, enum members, attributes, and strings. `template_assignments()` separately parses the example environment file. This slice does not show the guard tests that compare these outputs.
- The CLI helper export list is at [src/vaultspec_rag/tests/\_cli_helpers.py:1024-1077](../../../../src/vaultspec_rag/tests/_cli_helpers.py#L1024). Direct helper relationships visible here include `_cli_helpers` using `_config_fixtures` and `_http_stubs`, and `_job_manager_transition_helpers` using `_job_roots`. The importing pytest modules are not in the allowed slice, so exact test callers remain unknown.
