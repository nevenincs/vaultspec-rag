## Capability summary

- [src/vaultspec_rag/\_store_locks.py](../../../../src/vaultspec_rag/_store_locks.py) provides deterministic collection-lock acquisition, a deadline-bounded variant for teardown, the storage-lock exception with same-process diagnostics, and a non-blocking OS file-lock wrapper with a process-local path-holder count. The OS lock remains the exclusivity authority; the table is diagnostic (lines 22-29, 51-97, 99-129, 132-211).
- [src/vaultspec_rag/\_store_models.py](../../../../src/vaultspec_rag/_store_models.py) defines immutable document locator, metadata, and payload types; mutable vault, vault-chunk, code-chunk, and document-chunk records; metadata digest and Qdrant payload builders; root collection naming; and the served-code-generation pointer lifecycle (lines 50-172, 174-216, 219-394, 402-538, 541-770).
- [src/vaultspec_rag/\_store_search.py](../../../../src/vaultspec_rag/_store_search.py) supplies a request record and a VaultStore search mixin for vault, code, and document collections. It builds dense/sparse prefetches and filters, executes reciprocal-rank fusion with dense-only fallback, resolves feedback anchors, drops removed anchors, and maps Qdrant points to result dictionaries (lines 42-194, 196-238, 240-423, 424-608).
- [src/vaultspec_rag/\_store_writes.py](../../../../src/vaultspec_rag/_store_writes.py) classifies disk-full failures, runs replay-safe store operations with bounded retries/backoff and optional caller-owned progress budgets, and probes/checks disk headroom for store and project-data volumes (lines 57-73, 76-92, 106-129, 132-243, 246-405, 408-619).
- [src/vaultspec_rag/\_sync_vocabulary.py](../../../../src/vaultspec_rag/_sync_vocabulary.py) owns the StrEnum provisioning outcome vocabulary: created, updated, unchanged, skipped, failed, and dry_run (lines 23-46).
- [src/vaultspec_rag/\_timestamps.py](../../../../src/vaultspec_rag/_timestamps.py) parses ISO timestamps into aware datetimes, treating offset-free values as UTC, and calculates a field's age in seconds or returns None (lines 31-72).
- [src/vaultspec_rag/\_typed_fields.py](../../../../src/vaultspec_rag/_typed_fields.py) shares typed predicates for required/optional strings and integers, required booleans and finite floats, and required JSON mappings while letting callers select the error factory (lines 17-110).
- [src/vaultspec_rag/\_units.py](../../../../src/vaultspec_rag/_units.py) centralizes binary byte/MiB conversion and human-readable IEC byte formatting (lines 17-79).
- [src/vaultspec_rag/\_verified_import.py](../../../../src/vaultspec_rag/_verified_import.py) hashes supplied source bytes before importing them through a loader backed by that same buffer; digest-keyed module reuse and cleanup after failed execution are implemented (lines 30-116).

## Interfaces and data flow

- Lock helpers accept a mapping from collection names to the ReentrantLock protocol. The normal context manager takes locks in sorted-name order. The bounded context manager spends one deadline across attempts, skips locks it cannot acquire before expiry, yields whether all locks were acquired, and releases acquired locks in reverse order ([src/vaultspec_rag/\_store_locks.py:33-97](../../../../src/vaultspec_rag/_store_locks.py#L33)). FileLock opens a path, delegates exclusivity to \_fd_lock, records the normalized path after successful acquisition, and unregisters on release (132-211).
- DocumentPayload separates document-native fields from vector-store syntax. DocumentMetadata stores canonical JSON and materializes a fresh mapping. VaultDocument and VaultChunk carry vault document/chunk metadata and vectors; CodeChunk carries source location, syntax-node, and optional preprocessor locator fields; DocumentChunk carries document payload plus dense/sparse vectors ([src/vaultspec_rag/\_store_models.py:72-172, 219-372](../../../../src/vaultspec_rag/_store_models.py#L72)). Payload builders flatten those records into vault_docs/codebase_docs payload shapes; code payloads include a path-derived domain (470-538). The vault metadata digest covers the indexed metadata subset including body_line, preserves list order, trims scalar/list-element whitespace, and uses a 16-byte BLAKE2b digest (396-467).
- HybridSearchRequest contains a dense vector, query text, optional filters, limit, sparse result, feedback IDs, and domain constraints. The mixin exposes hybrid_search, hybrid_search_codebase, and hybrid_search_document; each builds a query/filter and delegates execution to \_execute_hybrid_query ([src/vaultspec_rag/\_store_search.py:42-63, 98-194](../../../../src/vaultspec_rag/_store_search.py#L42)). Prefetch uses four times the requested limit per dense or sparse leg; multiple legs run with RRF k=60, while failure falls back to dense query (268-368). Results expose payload fields, normalized id, and \_relevance_score (424-451). In this module query_text is declared but not read by the shown methods.
- Vault feedback strings resolve to the chunk-head point when present, with a legacy bare document point fallback; a missing/unavailable collection falls back to the head ID without ensuring a collection just to resolve feedback ([src/vaultspec_rag/\_store_search.py:196-238](../../../../src/vaultspec_rag/_store_search.py#L196)). Recommendation query anchors are retrieved under the point lock and removed if their points no longer exist (370-422).
- Code collections are derived locally or under a root-specific prefix. The served pointer is stored under configured data_dir as code_served_collection.json. Reads distinguish missing from unverifiable pointers; the read resolver falls back to the derived collection. Publishing accepts only a root-owned collection and writes JSON atomically. Generation publication records breadth before moving the pointer; reclaimability excludes served names and non-generation base names ([src/vaultspec_rag/\_store_models.py:541-770](../../../../src/vaultspec_rag/_store_models.py#L541)).
- StoreWritePolicy supplies remaining_seconds and wait callbacks. Retry attempts use configured timeouts, capped exponential delays, optional elapsed and durable-progress budgets, and immediately propagate classified unrecoverable disk-full errors. VolumeReading records role, intended and measured paths, free bytes, and device identity. Remote stores are reported as unmeasured; local probes walk to an existing ancestor. Headroom admission uses a 1 GiB floor plus 16 KiB per proposed point and formats refusals with binary units ([src/vaultspec_rag/\_store_writes.py:80-92, 106-243, 287-405, 423-581, 584-619](../../../../src/vaultspec_rag/_store_writes.py#L80)).
- Utility interfaces: ProvisionAction is a string enum; parse_iso_timestamp accepts object input and an optional field label, while age_seconds accepts a mapping plus field; typed-field predicates accept an error factory; unit helpers convert floats to/from MiB and render byte counts; import_verified_source accepts source bytes, expected SHA-256, and a display filename ([src/vaultspec_rag/\_sync_vocabulary.py:26-46](../../../../src/vaultspec_rag/_sync_vocabulary.py#L26); [src/vaultspec_rag/\_timestamps.py:36-72](../../../../src/vaultspec_rag/_timestamps.py#L36); [src/vaultspec_rag/\_typed_fields.py:32-110](../../../../src/vaultspec_rag/_typed_fields.py#L32); [src/vaultspec_rag/\_units.py:29-79](../../../../src/vaultspec_rag/_units.py#L29); [src/vaultspec_rag/\_verified_import.py:71-116](../../../../src/vaultspec_rag/_verified_import.py#L71)).
