## Capability summary

The slice contains three groups: (1) static AST/text guards that keep shared rules and representations owned by one production module; (2) behavior-focused tests for process lookup, process termination, and production sites that invoke external tools; and (3) a unit contract suite for progress reporters. Each file marks tests as pytest unit tests. This does not establish that they pass.

- [src/vaultspec_rag/tests/test_process_probe_service_contracts.py](../../../../src/vaultspec_rag/tests/test_process_probe_service_contracts.py) checks shared ownership and behavior across route authentication, duplicate statement fragments, TOML byte-shape writes, unsupported feedback refusals, vector width and output cap validation, MCP failure reporting, and path/content-route validation. AST scans inspect production files through the uninspected \_process_probe_guard_helpers helper. Targeted assertions import the named production APIs and exercise temporary TOML files, source enums, validators, and report records.
- [src/vaultspec_rag/tests/test_process_probe_source_structure.py](../../../../src/vaultspec_rag/tests/test_process_probe_source_structure.py) defines AST normalizers/scanners and guards the shared address-line template, config defaults, duplicate function bodies, atomic replacement, registry lock/load boundaries, vector-name constants, and search timing keys. Some guards scan source structure; others invoke the production APIs named in their imports.
- [src/vaultspec_rag/tests/test_process_probe_vocabulary_guards.py](../../../../src/vaultspec_rag/tests/test_process_probe_vocabulary_guards.py) guards shared ownership of release asset names, CLI option declarations, root collection prefixes, lifecycle labels and exit-code names, managed-log filters, private facade re-exports/private functions, and store schema index sets. It combines source scans with targeted API assertions.
- [src/vaultspec_rag/tests/test_process_termination.py](../../../../src/vaultspec_rag/tests/test_process_termination.py) isolates PID-probe and termination behavior with monkeypatched probe/process dependencies. Expectations cover child exit acknowledgement and reaping, zombie detection, avoiding probes of reused PIDs, wait time, and preserving the deadline passed to owned-child cleanup.
- [src/vaultspec_rag/tests/test_program_lookup.py](../../../../src/vaultspec_rag/tests/test_program_lookup.py) exercises find_program with ordered Where search locations and planted programs. It expects relative/empty PATH entries and the current directory not to supply a result, absolute entries to return absolute paths, search order to be honored, and invalid names/no-place calls to be rejected.
- [src/vaultspec_rag/tests/test_program_lookup_sites.py](../../../../src/vaultspec_rag/tests/test_program_lookup_sites.py) plants same-named programs in a simulated working directory and drives production callers for hardware status, Torch repair/install sync, monitor startup, and Windows task/image/junction operations. Assertions require that the planted working-directory program is not run; Windows-only cases exercise tasklist, taskkill, and PowerShell.
- [src/vaultspec_rag/tests/test_progress_unit.py](../../../../src/vaultspec_rag/tests/test_progress_unit.py) specifies the ProgressReporter protocol through NullProgressReporter and RichProgressReporter, using in-memory Rich consoles. It covers phase start/advance/end, confirmed chunks, logs, unknown/zero totals, sequential phases, terminal fallback, context-manager use, and concurrent counter updates. A local CountingProgressReporter records all protocol events.

## Interfaces and data flow

These are interfaces as exercised or named by the tests, not descriptions verified against implementation source.

- Process termination: reap_if_child(pid) is expected to acknowledge a child exit; pid_alive(pid) and pid_is_zombie(pid) supply probes to wait_for_exit(pid, timeout=...), whose result is treated as boolean. cli.\_process.\_terminate_pid(pid, timeout, graceful_drain) is expected to return an object with alive and signal_denied fields and to pass a deadline to \_reap_owned_qdrant. Inputs/outcomes: [src/vaultspec_rag/tests/test_process_termination.py:33-130](../../../../src/vaultspec_rag/tests/test_process_termination.py#L33). Most probes are substituted, so this does not establish actual OS behavior.
- Program resolution: find_program(name, \*Where) is called with a bare name and one or more ordered search locations. Expected result is a path string or None; tests expect ValueError for a path-containing name and for no locations. Planted executables and environment setup form inputs; marker files/process return codes show whether a plant ran. See [src/vaultspec_rag/tests/test_program_lookup.py:35-154](../../../../src/vaultspec_rag/tests/test_program_lookup.py#L35) and site-level callers in [src/vaultspec_rag/tests/test_program_lookup_sites.py:59-255](../../../../src/vaultspec_rag/tests/test_program_lookup_sites.py#L59).
- Shared ownership/validation: tests name write_doc_preserving_shape, unsupported_feedback_envelope, effective_sparse_dim, validate_max_emitted_bytes, record_mcp_failure, and validate_rel_path, among other owners. Assertions cover TOML bytes before/after patch removal, source refusal decisions, validation exceptions, and report channel contents. Ownership scanners inspect production AST/text, but scan population/path resolution depends on uninspected \_process_probe_guard_helpers. See [src/vaultspec_rag/tests/test_process_probe_service_contracts.py:21-684](../../../../src/vaultspec_rag/tests/test_process_probe_service_contracts.py#L21).
- Structural ownership: scans require one address template and config-owned defaults. Targeted contracts expect an address string, an HF cache location following HF_HOME, an atomic replacement helper distinct from a durable variant, no registry lock-held path reaching a model load, vector schema names sharing identity, and unique suffixed phase keys. See [src/vaultspec_rag/tests/test_process_probe_source_structure.py:184-917](../../../../src/vaultspec_rag/tests/test_process_probe_source_structure.py#L184); implementation sources were not inspected.
- Vocabulary: tests derive supported release/platform relationships, option declarations, lifecycle labels, and schema index sets from production symbols. Managed log filters are expected to trim and omit whitespace-only values while retaining "0". Private facade/source scans compare production AST/text against names referenced in production/test source blobs. See [src/vaultspec_rag/tests/test_process_probe_vocabulary_guards.py:48-675](../../../../src/vaultspec_rag/tests/test_process_probe_vocabulary_guards.py#L48).
- Progress reporting: tested calls are phase_start(name, total), advance(n=1), confirmed_chunks(n), phase_end(), log(message), and forward start/finish callbacks with ordinal and items keywords. RichProgressReporter is expected to render plain lines for noninteractive/dumb terminals and maintain a thread-safe phase count. See [src/vaultspec_rag/tests/test_progress_unit.py:20-218](../../../../src/vaultspec_rag/tests/test_progress_unit.py#L20).

State/storage/integrations visible from test code are temporary paths and TOML files, monkeypatched environment/process probes, planted executable files, in-memory console buffers, and test-created report objects. Tests name integrations with Qdrant identity/process cleanup, MCP report channels, vector schema, Hugging Face configuration, Rich, and Windows OS tools; actual production integration behavior is uninspected.

## Boundaries and dependencies

- The three test_process_probe\_\* modules are cross-package guard suites: they parse or text-scan production modules and also import selected production owners. Their test code says some invariants are scoped to AST shape, literal occurrence, or specific stores/call positions. The helper implementation is not in this slice.
- [src/vaultspec_rag/tests/test_process_termination.py](../../../../src/vaultspec_rag/tests/test_process_termination.py) and [src/vaultspec_rag/tests/test_program_lookup.py](../../../../src/vaultspec_rag/tests/test_program_lookup.py) sit at production API boundaries, replacing or planting OS-facing behavior to make checks deterministic. [src/vaultspec_rag/tests/test_program_lookup_sites.py](../../../../src/vaultspec_rag/tests/test_program_lookup_sites.py) extends the same strategy to actual consumer entry points.
- [src/vaultspec_rag/tests/test_progress_unit.py](../../../../src/vaultspec_rag/tests/test_progress_unit.py) is a focused unit suite; the assigned range uses Rich and thread-pool execution.
- Uninspected dependencies named by the assigned source include tests/\_process_probe_guard_helpers.py, tests/\_planted_programs.py, tests/\_ports.py, tests/conftest.py, tests/\_config_fixtures.py, and production modules imported throughout these suites, including \_process_probe.py, cli/\_process.py, \_program_lookup.py, progress.py, and modules cited above. No behavior behind these imports is asserted here beyond visible test expectations.
