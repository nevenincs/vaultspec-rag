## Capability summary

- [src/vaultspec_rag/tests/integration/test_index_support_admission.py](../../../../src/vaultspec_rag/tests/integration/test_index_support_admission.py) covers code-source preflight measurements, segment and runtime support-budget limits, HTTP admission refusal before job creation, operator-facing error-kind formatting through the route/CLI path, and measurement when a scanned file vanishes before stat. It exercises `CodebaseIndexer` and a real ASGI route in test fixtures (31-95, 98-138, 141-200, 202-288).
- [src/vaultspec_rag/tests/integration/test_indexer_integration.py](../../../../src/vaultspec_rag/tests/integration/test_indexer_integration.py) covers document and code full/incremental indexing, preparation and edge cases; measured N/two-N resource bounds; typed memory-ceiling failures and cleanup; blocked-writer deadlines and cancellation; and a resumed code run during concurrent corpus edits. A final subprocess-GPU class expects refusal when configured CUDA headroom is zero (120-161, 163-305, 308-535, 538-761, 763-990, 992-1112, 1114-1174).
- [src/vaultspec_rag/tests/integration/test_indexer_progress_integration.py](../../../../src/vaultspec_rag/tests/integration/test_indexer_progress_integration.py) records reporter events and expects balanced, ordered phases and counters for vault and code indexing (28-99, 102-224).
- [src/vaultspec_rag/tests/integration/test_ingest_barrier.py](../../../../src/vaultspec_rag/tests/integration/test_ingest_barrier.py) specifies the `VaultStore` barrier contract for real server mode versus embedded mode, injects acknowledged-but-missing points, and expects a rebuild to fail before publication when points are missing and to publish when they apply (48-188, 190-388).
- [src/vaultspec_rag/tests/integration/test_install_basics.py](../../../../src/vaultspec_rag/tests/integration/test_install_basics.py) covers fresh install, corrupt provider intent, merging provider manifests, rollback on persistence failure, directory and bundled-file seeding, MCP host synchronization, and idempotent/upgrade/force seeding (28-225).
- [src/vaultspec_rag/tests/integration/test_install_preview.py](../../../../src/vaultspec_rag/tests/integration/test_install_preview.py) covers dry-run filesystem immutability and reported add/update/prune actions, preview parity with actual install, context restoration, and preservation of unrelated symlinks and Windows junctions (40-329).
- [src/vaultspec_rag/tests/integration/test_install_preview_modes.py](../../../../src/vaultspec_rag/tests/integration/test_install_preview_modes.py) covers install/uninstall mode transitions, preview parity, partial provider state, hard MCP-skip boundaries, durable package placement, and placement conflicts that should prevent commits (30-500).

## Interfaces and data flow

- Indexing tests call `CodebaseIndexer`/`DocumentIndexer`/`VaultIndexer` methods including `preflight_content`, `preflight_changed_paths`, `full_index`, and `incremental_index`; inputs are temporary source trees, an embedding fixture, reporter/control objects, config, and a `VaultStore`. Expected outputs include result counts, drift accounting, support measurements, memory snapshots, and typed errors (support-admission 31-95; indexer 128-160, 181-305, 324-535, 543-761, 1071-1112).
- The admission test posts JSON to `/reindex` with bearer authorization and asserts a structured 422 response and an empty job list for profile refusal (support-admission 179-214). Another assertion follows the response message through route failure conversion and CLI rendering (218-257).
- Progress tests implement reporter methods (`phase_start`, `advance`, `phase_end`, `log`, and forward callbacks) and check emitted phase names/order and counters (progress 28-99, 114-156, 180-222).
- Ingest tests configure `QDRANT_URL`, construct a server-backed or embedded `VaultStore`, upsert points, call `apply_ingest_barrier(table, expected_points=...)`, and count stored points. Rebuild tests call `VaultIndexer.full_index` and check publication through `acquire_publication_snapshot` (ingest 48-78, 104-187, 278-388).
- Install tests call `install_run`, `uninstall_run`, a shared `_install` helper, or the CLI. They inspect report fields such as `seeded`, `sync_providers`, `mcp_sync_failed`, and `mcp_errors`, plus workspace files, provider manifests, MCP configs, ownership state, and lock files (basics 56-104, 106-197; preview 40-224; preview-modes 43-110, 237-301, 435-500).
- State is primarily temporary filesystem content and temporary/local or server-backed store state. Model loading, store internals, job dispatch, publication, install helper behavior, and core-library behavior remain uninspected dependencies.

## Boundaries and dependencies

- These are integration-test modules, not implementation modules. They import package APIs under `vaultspec_rag`, `vaultspec_core`, pytest fixtures/helpers, `httpx`, and `qdrant_client`; imports were not followed. The tests' docstrings describe intended contracts and reported defects, but do not independently establish implementation behavior.
- GPU/resource cases are marked integration/performance/CUDA or subprocess-GPU and use a fixture described as a real model; the ingest suite provisions a pinned Qdrant binary through test helpers. This static read does not establish whether those prerequisites are available or whether the tests pass.
- Install behavior is bounded by tests of command reports and filesystem effects; core manifest, workspace-mode, MCP provider synchronization, path/symlink handling, and helper implementations were not inspected.
