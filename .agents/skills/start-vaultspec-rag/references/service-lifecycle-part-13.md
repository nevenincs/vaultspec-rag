**Test expectations by module:**

The GPU cases carry the `cuda` marker. (Lines 1-682.)
- [src/vaultspec_rag/tests/test_search_timeout.py](../../../../src/vaultspec_rag/tests/test_search_timeout.py) checks default and explicit search/admin timeout resolution for absent, invalid, non-positive, and non-finite values. It also sends a real reindex HTTP request to a delayed local server and expects the configured short deadline to produce an `http_call_failed` result. (Lines 1-173.)
- [src/vaultspec_rag/tests/test_served_pointer_validation.py](../../../../src/vaultspec_rag/tests/test_served_pointer_validation.py) covers accepted and rejected served-code-pointer shapes, root/backend ownership, donor resolution, publication preflight, and guarding read/write/delete/clean/reclamation operations when the pointer is invalid. It includes local-storage and shared-Qdrant cases, valid clean workflows, backend migration in both directions, and migration outcomes where copying or pointer publication does not succeed. (Lines 1-501.)
- [src/vaultspec_rag/tests/test_server.py](../../../../src/vaultspec_rag/tests/test_server.py) groups expectations around route-runtime construction and error envelopes; the `python -m vaultspec_rag.server` entry point; opt-in read-only MCP listings; canonical source names; MCP tool/prompt registration and input schemas; result/capability model serialization; path traversal, vault-root, and sensitive-path checks; root selection and top-k clamping; stdio lifecycle wiring; registry and health behavior; health response reduction; watcher shutdown; native REST routes without `/mcp`; and lifecycle/discovery heartbeat and cleanup helpers. The expected default MCP tool set is listed at lines 391-408, and read-only behavior is exercised at lines 218-361. (Lines 1-1376.)
- [src/vaultspec_rag/tests/test_server_doctor.py](../../../../src/vaultspec_rag/tests/test_server_doctor.py) covers the `server doctor` CLI’s expected dependency, live-service, and provisioning/mode axes, in JSON and human output. Cases exercise absent discovery state, install mode and version floors, upgrade advice, mode mismatch, root target and `VAULTSPEC_RAG_ROOT`, a subprocess check that CLI/doctor use does not import Torch, and the expected “starting” label for a live starting service. (Lines 1-420.)
- [src/vaultspec_rag/tests/test_server_document_models.py](../../../../src/vaultspec_rag/tests/test_server_document_models.py) expects a document-native search result to serialize with source, locator, section, document/unit metadata, and without `rerank_text`. (Lines 1-34.)
- [src/vaultspec_rag/tests/test_server_entry_environment_refusal.py](../../../../src/vaultspec_rag/tests/test_server_entry_environment_refusal.py) launches the stdio and daemon entry forms in fresh subprocesses and expects invalid preprocessing/log-level settings to exit 1 with one named stderr error and empty stdout. (Lines 1-77.)
- [src/vaultspec_rag/tests/test_server_launch_shapes.py](../../../../src/vaultspec_rag/tests/test_server_launch_shapes.py) expects process-command readers to recognize both the current safe-path and previous launch shapes, including stdio launches without a port; reject foreign command lines; discover/confirm both service shapes; and stop either shape. The tests use a sleeping witness process under the service module name. (Lines 1-232.)

## Interfaces and data flow

- Search tests supply query strings and typed filter options, then assert parsed text/filter mappings, validation errors, matching result paths, and shaped snippets/line metadata. A test also directly calls the searcher’s passage-selection and score-prediction methods with constructed result objects. These are test inputs/outputs, not independently confirmed public API guarantees. ([src/vaultspec_rag/tests/test_search_unit.py:79-171, 348-470, 472-553, 555-682](../../../../src/vaultspec_rag/tests/test_search_unit.py#L79).)
- Timeout tests manipulate `VAULTSPEC_RAG_SEARCH_TIMEOUT`, `VAULTSPEC_RAG_ADMIN_TIMEOUT`, and `VAULTSPEC_RAG_REINDEX_TIMEOUT`; the reindex case crosses an actual loopback HTTP boundary. ([src/vaultspec_rag/tests/test_search_timeout.py:31-49, 82-173](../../../../src/vaultspec_rag/tests/test_search_timeout.py#L31).)
- Pointer tests create or poison a JSON pointer under a temporary root, select local/shared storage through `QDRANT_URL`, then assert resolution, operation refusal, collection counts, cleanup results, or migration outcome. Some cases use temporary/in-memory Qdrant clients; one fixture obtains a provisioned Qdrant binary. ([src/vaultspec_rag/tests/test_served_pointer_validation.py:38-42, 139-264, 267-501](../../../../src/vaultspec_rag/tests/test_served_pointer_validation.py#L38).)
- Server tests drive MCP listing/prompt APIs, Starlette `TestClient`, direct route handlers, `CliRunner`, and Python subprocesses. Inputs include route runtime token/port, tool parameters, project roots, environment variables, filesystem paths, process state, and service status files; expected outputs include JSON envelopes, route/tool listings, exit codes, health fields, and cleanup state. ([src/vaultspec_rag/tests/test_server.py:64-147, 154-174, 218-489, 898-1079, 1103-1376](../../../../src/vaultspec_rag/tests/test_server.py#L64).)
- Doctor tests invoke the Typer CLI and inspect JSON/human output; the status directory is isolated and workspace mode is supplied by temporary manifests/declarations, CWD, `--target`, or `VAULTSPEC_RAG_ROOT`. ([src/vaultspec_rag/tests/test_server_doctor.py:44-65, 68-420](../../../../src/vaultspec_rag/tests/test_server_doctor.py#L44).)
- Launch-shape tests build process argv from current/previous command factories and inspect live witness PIDs, status files, and stop/discovery results. ([src/vaultspec_rag/tests/test_server_launch_shapes.py:63-113, 115-232](../../../../src/vaultspec_rag/tests/test_server_launch_shapes.py#L63).)
