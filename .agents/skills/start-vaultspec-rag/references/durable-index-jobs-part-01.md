## Capability summary

- [src/vaultspec_rag/job_models.py](../../../../src/vaultspec_rag/job_models.py) defines immutable, slotted service-job value objects and enums: operation/source/mode, observed and desired states, retry/resume lineage, timestamps, progress, runtime/resource snapshots, resilience, capabilities, and structured command outcomes (lines 40-180, 349-403, 404-747). Construction validates scalar types/ranges and JSON-compatible telemetry values (lines 182-347, 412-667). Snapshots and outcomes serialize to JSON-ready dictionaries (lines 669-820). Helpers classify encode-bearing jobs, validate specs, normalize active-work identity, and derive supported actions (lines 823-886).
- [src/vaultspec_rag/job_persistence.py](../../../../src/vaultspec_rag/job_persistence.py) owns the canonical manager-state JSON codec and filesystem persistence: schema/version-2 envelope, strict parsing and lifecycle/generation validation, atomic durable save with a `published` failure distinction, and best-effort cleanup of old writer temporaries (lines 60-162, 165-249, 251-402). It reconstructs snapshots and nested value objects from persisted dictionaries (lines 403-711).
- [src/vaultspec_rag/jobs.py](../../../../src/vaultspec_rag/jobs.py) provides the activity-record compatibility surface and bridges it to the canonical job manager. It restores prior-process activity as `interrupted`, tracks and projects legacy records, publishes progress/resource observations, exposes indexing status/degradation, binds/activates/restores manager jobs, and provides synchronous vault/code/document reindex starters (lines 109-115, 117-169, 172-264, 267-368, 371-493, 495-633, 636-794, 813-907, 910-1200). Its public exports are enumerated at lines 86-106. The legacy activity ring/snapshot comes from `_job_registry_state`; canonical manager ownership comes from the service registry (lines 45-51, 152-155).

## Interfaces and data flow

- The canonical data contract is `JobSnapshot`: it groups a `JobSpec`, lifecycle/desired state, derived capabilities, attempt lineage, timestamps, progress, attribution, process/resource data, optional resilience, telemetry (`reuse`, `drift`), and GPU-lock wait time; `to_dict()` emits the served/persisted shape ([src/vaultspec_rag/job_models.py:614-727](../../../../src/vaultspec_rag/job_models.py#L614)). `JobOutcome.to_dict()` wraps command/status/code/message and an optional snapshot ([src/vaultspec_rag/job_models.py:729-747](../../../../src/vaultspec_rag/job_models.py#L729)).
- `load_persisted_state(path)` reclaims qualifying stale sibling temporaries, reads UTF-8 JSON, and validates one complete generation. `save_persisted_state(path, state)` serializes the complete generation and calls the imported atomic writer with sorted keys and durability enabled; it translates failures to `PersistenceWriteError(published=...)` ([src/vaultspec_rag/job_persistence.py:118-162](../../../../src/vaultspec_rag/job_persistence.py#L118)). Current schema is `vaultspec.rag.jobs`, version 2; other schema or older versions are refused, while a newer version has a distinct error carrying version bounds (60-63, 268-289). Parsing rejects duplicate IDs, invalid specs/lifecycles/lineage, and duplicate active work identities (251-316, 319-402).
- [src/vaultspec_rag/jobs.py](../../../../src/vaultspec_rag/jobs.py) exports activity APIs (`record_start`, `record_finish`, `snapshot`, `find_job`, `delete_job`, `restore_interrupted`, `resource_snapshot`, `index_job_status`) and the manager/activation/start APIs (86-106). Activity records are appended under `_lock`, mirrored to a persisted active snapshot, and logged at start/finish; finish is idempotent and records classification, preprocessing, reuse/drift telemetry, and finished resource observations (287-368, 371-493). Returned activity snapshots detach nested mutable fields and omit internal progress-throttle/sampling keys (495-553).
- Internal activation flow: `activate_index_job` accepts only newly created/retry-created successful outcomes, requires source-specific preflight for code/document jobs, prepares a matching activity record and binding off-loop, then dispatches unless paused; dispatch refusal is returned or durably failed according to its code ([src/vaultspec_rag/jobs.py:1014-1136](../../../../src/vaultspec_rag/jobs.py#L1014)). Synchronous starters use admission, return an existing ID on deduplication, then bind and dispatch newly created jobs (1171-1260). Startup restoration binds active manager jobs and dispatches only queued jobs whose desired state is running (1139-1168).
- Read projection: `index_job_status(root)` selects the newest canonical indexing snapshot per corpus source at the resolved root, projects lifecycle/progress/resilience and stall state, then adds shrunken-index observations ([src/vaultspec_rag/jobs.py:665-794](../../../../src/vaultspec_rag/jobs.py#L665)). Stall checks use shared confirmed-work timing and the configured threshold; degradation reasons are `stalled`, `failed`, or `interrupted`, plus shrunken observations (636-662, 777-793, 758-774).
- The slice shows internal call paths above. Callers outside these three files were not inspected, so external invocation routes cannot be established from this evidence.
