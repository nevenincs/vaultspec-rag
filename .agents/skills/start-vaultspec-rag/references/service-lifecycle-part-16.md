## Capability summary

- [src/vaultspec_rag/tests/test_service_registry_recovery.py](../../../../src/vaultspec_rag/tests/test_service_registry_recovery.py) exercises expected registry-owned recovery of a quiesced durable job: resume should persist a same-ID retry attempt before reopening admission or starting a bound runner; persistence failure should leave the registry warming and retain the paused job; repaired simultaneous resume callers should share one transition and one attempt. It builds real thread/event-loop coordination and reads persisted job snapshots (helpers and cases at lines 45-307, 310-390, 397-499).
- [src/vaultspec_rag/tests/test_service_search_diagnostics.py](../../../../src/vaultspec_rag/tests/test_service_search_diagnostics.py) pins search-state and empty-result diagnostic shapes, including selected-source counts, path-filter explanations, published-empty precedence, known versus unknown breadth shortfall, consistent projections for in-process and daemon paths, and verbatim integrity verdict data (lines 45-359). It also expects summaries to disclose shortfall and result collapse, MCP output models to retain extra diagnostic fields, and path-filter notes and wait causes to survive route classification/attachment (362-599, 733-765). Timing expectations distinguish named service waits from bounded wait observations; GPU lock timing is tested with fake locks, and separate searcher locks are expected to allow overlapping sections without GPU hardware (601-730).
- [src/vaultspec_rag/tests/test_service_stop_port.py](../../../../src/vaultspec_rag/tests/test_service_stop_port.py) covers CLI port resolution and stop outcomes for free ports, default and explicit port selection, startup/warming and serving identities, discovery pointers, launch tokens, health PID binding, process birth/argv checks, and machine-lock-holder fallback. Assertions expect unconfirmed or mismatched identities to be preserved and refused, and matching dead records to be cleaned (85-689). It also pins strict launch-argument parsing and contains real subprocess witness helpers. Orphan-reap scenarios expect a singleton identified by discovery pointer, worker pointer, or machine-lock lease to survive, the matching-port orphan to be terminated, and a different-port daemon to survive; the envelope must attribute reported reaped PIDs to the orphan pair (735-1107).
- [src/vaultspec_rag/tests/test_service_stop_cleanup.py](../../../../src/vaultspec_rag/tests/test_service_stop_cleanup.py) covers a stop that finishes after successor discovery publication, conditional deletion by PID/port identity, retention of malformed or unreadable identity records, and comparison under the shared write lock so a concurrent replacement survives (39-207). It reuses `isolated_stop_status`, `_starting_process`, and `_port_stop` from [src/vaultspec_rag/tests/test_service_stop_port.py](../../../../src/vaultspec_rag/tests/test_service_stop_port.py) (20-26).
- [src/vaultspec_rag/tests/test_service_store_admission.py](../../../../src/vaultspec_rag/tests/test_service_store_admission.py) checks expected same-root serialization among cold store leases, project-slot creation, and maintenance leases, while different roots can proceed concurrently (123-280, 490-559). It checks capacity accounting during construction, LRU replacement, same-root joining, constructor failure cleanup, and teardown (282-488, 561-719). It also pins refusal messages to verified holder knowledge and verifies that a refused store open does not leave a stale registration (721-756).

## Interfaces and data flow

- Recovery tests construct `ServiceRegistry` and `JobManager`, create an index/rebuild job, defer it for quiesce, bind a runner, call `resume_resources`, and compare both `load_persisted_state` snapshots and manager/registry snapshots. Thread events and an adopted real asyncio loop expose ordering; expected outputs include `QuiesceTransition` codes/snapshots, attempt number, desired state, and runner observations (45-72, 118-165, 223-265, 310-390).
- Search diagnostic tests pass dictionaries and typed input/finding records through search-state builders, route classification/attachment, summary formatting, and MCP `SearchResults.model_validate(...).model_dump()`. Assertions pin keys/values such as `shortfall`, `index_integrity`, `empty.reason`, remediation, wait causes, and timing names (45-69, 149-359, 362-599, 601-765). These are test-observed interfaces, not independently verified production contracts.
- Stop tests invoke the Typer CLI via `CliRunner` or subprocesses, provide ports, status JSON, launch arguments/tokens, and health responses, then inspect exit code/envelope, discovery contents, process liveness, and machine-lock probe results (101-224, 227-689, 850-895). The orphan cases create short-lived real process witnesses and inspect the stop envelope and PID survival/death (735-1107).
- Store tests pass resolved temporary roots to registry `peek_project`, `lease_store`, `lease_maintenance_store`, `lease`, and `try_evict`; thread barriers/events inspect private admission/guard state and store clients. Direct `VaultStore` double-open attempts assert `VaultStoreLockedError` fields and message content (49-115, 123-204, 282-488, 490-756).
- These tests reveal their call sites and expected data flow only. No implementation path was read, so actual runtime semantics and external API exposure remain unconfirmed.
