## Capability summary

The package exposes a loopback HTTP service for native REST routes and a separate stdio MCP forwarder. HTTP mode owns the resident model and service lifecycle; stdio mode loads MCP tooling and forwards through service-client integrations according to the entry-point documentation. The package namespace re-exports response models, lifecycle helpers, watcher helpers, state values, metrics functions, request-runtime functions, `main`, and `create_http_app` as a compatibility surface ([src/vaultspec_rag/server/__init__.py:15-34, 39-94, 96-140](../../../../src/vaultspec_rag/server/__init__.py#L15)).

- [src/vaultspec_rag/server/__init__.py](../../../../src/vaultspec_rag/server/__init__.py): defines package import order and explicit public exports; its `__main__` guard delegates to `main` ([src/vaultspec_rag/server/__init__.py:21-34, 39-60, 96-145](../../../../src/vaultspec_rag/server/__init__.py#L21)).
- [src/vaultspec_rag/server/__main__.py](../../../../src/vaultspec_rag/server/__main__.py): enables `python -m vaultspec_rag.server` by delegating to `_main.main` ([src/vaultspec_rag/server/__main__.py:1-17](../../../../src/vaultspec_rag/server/__main__.py#L1)).
- [src/vaultspec_rag/server/\_auth.py](../../../../src/vaultspec_rag/server/_auth.py): extracts a bearer or query token and compares it in constant time to the token in the request runtime; returns a JSON 401 on failure ([src/vaultspec_rag/server/\_auth.py:24-71](../../../../src/vaultspec_rag/server/_auth.py#L24)).
- [src/vaultspec_rag/server/\_http_boundary.py](../../../../src/vaultspec_rag/server/_http_boundary.py): ASGI middleware rejects requests with a missing, duplicated, or non-loopback Host and rejects a supplied Origin unless it matches the request scheme and authority; refusals are JSON 403 responses ([src/vaultspec_rag/server/\_http_boundary.py:16-87](../../../../src/vaultspec_rag/server/_http_boundary.py#L16)).
- [src/vaultspec_rag/server/\_lifecycle.py](../../../../src/vaultspec_rag/server/_lifecycle.py): resolves daemon log/status locations; builds and serializes owner discovery snapshots; coordinates best-effort or required publication, heartbeats, Qdrant liveness/restart checks, storage surveys and maintenance, shutdown logging, and atexit cleanup ([src/vaultspec_rag/server/\_lifecycle.py:73-207, 223-423, 437-508, 510-918](../../../../src/vaultspec_rag/server/_lifecycle.py#L73)).
- [src/vaultspec_rag/server/\_lifespan.py](../../../../src/vaultspec_rag/server/_lifespan.py): claims the machine singleton; starts the monitor, optional supervised Qdrant, storage-manifest reconciliation, models, job recovery/manager, and periodic tasks; drains and tears down owned resources; computes the health verdict, degradation reasons, job rollup, and `/health` payload ([src/vaultspec_rag/server/\_lifespan.py:63-218, 278-600, 628-950, 952-1459](../../../../src/vaultspec_rag/server/_lifespan.py#L63)).
- [src/vaultspec_rag/server/\_main.py](../../../../src/vaultspec_rag/server/_main.py): chooses HTTP daemon or stdio mode; constructs the Starlette app and its middleware/routes; installs daemon logging and runtime identity; configures the stdio watchdog and optional read-only MCP tool surface ([src/vaultspec_rag/server/\_main.py:44-89, 111-155, 190-345](../../../../src/vaultspec_rag/server/_main.py#L44)).
- [src/vaultspec_rag/server/\_models.py](../../../../src/vaultspec_rag/server/_models.py): defines transport-safe document locators and the Pydantic `SearchResultItem` serialization shape, including optional document metadata and internal excluded `rerank_text` ([src/vaultspec_rag/server/\_models.py:17-106](../../../../src/vaultspec_rag/server/_models.py#L17)).

## Interfaces and data flow

`main(port=None)` parses `--port`, `--parent-pid`, `--launch-token`, and `--read-only`; a port selects HTTP and no port selects stdio ([src/vaultspec_rag/server/\_main.py:111-155, 309-345](../../../../src/vaultspec_rag/server/_main.py#L111)). HTTP startup refuses unusable environment configuration, configures managed logging, creates a per-process token and a `ServerRouteRuntime`, then mounts `/health` plus the imported `ROUTES` table behind `LoopbackHTTPBoundary` and runs Uvicorn on `127.0.0.1` ([src/vaultspec_rag/server/\_main.py:70-89, 190-254](../../../../src/vaultspec_rag/server/_main.py#L70)). The actual `ROUTES` contents are outside this slice. Stdio startup imports MCP only on that branch, optionally removes mutating tools, installs a lifetime watchdog, and runs the stdio transport; its `finally` stops watchers and closes the registry ([src/vaultspec_rag/server/\_main.py:272-307](../../../../src/vaultspec_rag/server/_main.py#L272)).

On HTTP lifespan entry, the app runtime provides the registry and request identity. Startup stamps process start times, acquires the machine lock, creates a discovery publisher, starts the optional monitor, then starts components and the canonical job manager. It publishes RUNNING as a required claim before yielding to requests ([src/vaultspec_rag/server/\_lifespan.py:294-357](../../../../src/vaultspec_rag/server/_lifespan.py#L294)). Server mode starts a supervised Qdrant child only when an explicit Qdrant URL is absent; it then publishes/validates child identity and exports the child URL. Startup reconciles the storage manifest best-effort, loads dense/sparse models and optionally a reranker, restores interrupted and managed jobs, then starts heartbeat, borrower-lease recovery, and server-mode maintenance/survey tasks ([src/vaultspec_rag/server/\_lifespan.py:415-600, 628-668](../../../../src/vaultspec_rag/server/_lifespan.py#L415)).

The discovery snapshot includes service schema/version, process and parent PIDs, port, phase/progress, timestamps, token, interpreter/package identity, optional launch token, Qdrant identity, and monitor fields. The publisher writes the service-status view and machine-discovery pointer separately; WARMING/heartbeats are best effort, while a required RUNNING status write may abort startup ([src/vaultspec_rag/server/\_lifecycle.py:146-207, 242-274, 375-423](../../../../src/vaultspec_rag/server/_lifecycle.py#L146)). Heartbeats also perform bounded Qdrant liveness/restart checks. Storage maintenance opens a bounded-time Qdrant client, runs a configured survey/reclamation/reconciliation cycle, publishes a survey snapshot and metrics, and records a maintenance job outcome ([src/vaultspec_rag/server/\_lifecycle.py:674-804](../../../../src/vaultspec_rag/server/_lifecycle.py#L674)).

`health_handler` conditionally validates credentials: if an Authorization header or `token` query parameter is supplied, it requires a valid runtime token; with no presented credential it proceeds anonymously. It assembles registry, Qdrant, quiesce, job, feature, package/schema, device, and support-profile data into a `HealthReport`; `service_token` is included only for an authenticated response ([src/vaultspec_rag/server/\_lifespan.py:1361-1459](../../../../src/vaultspec_rag/server/_lifespan.py#L1361)). The underlying health logic marks models, Qdrant availability, nonconforming/quarantined collections, migrated storage, stalled/undispatched/degraded jobs, and unsuperseded current-generation job failures as degradation conditions ([src/vaultspec_rag/server/\_lifespan.py:965-1052, 1176-1200, 1259-1358](../../../../src/vaultspec_rag/server/_lifespan.py#L965)).

Shutdown quiesces discovery publication, stops monitor and watcher/manager intake, cancels periodic tasks, removes discovery views, drains managed work, closes registry stores, stops Qdrant, and releases the machine lease after successful convergence. Standalone daemon shutdown uses bounded exit/log flushing and `os._exit`; embedded lifespan use leaves the process-exit gate false ([src/vaultspec_rag/server/\_lifespan.py:230-276, 799-950](../../../../src/vaultspec_rag/server/_lifespan.py#L230)).

`SearchResultItem.serialize` validates an object from attributes and dumps JSON. Its fields cover vault, codebase, and document results, source spans and AST metadata, anchors/locators/sections, document and unit metadata, and optional extractor information ([src/vaultspec_rag/server/\_models.py:27-106](../../../../src/vaultspec_rag/server/_models.py#L27)).

## Boundaries and dependencies

The HTTP app surface depends on Starlette, the imported `._routes.ROUTES` table, the app/request runtime in `._runtime`, and imported `._state`, `._watcher`, and `._utils` package components. Those files were not inspected; their route definitions, runtime construction, and storage semantics are unknown ([src/vaultspec_rag/server/\_main.py:30-33, 70-89](../../../../src/vaultspec_rag/server/_main.py#L30); [src/vaultspec_rag/server/__init__.py:60-94](../../../../src/vaultspec_rag/server/__init__.py#L60)). Authentication is applied within the inspected health handler only when credentials are presented; which other routes require it depends on the uninspected route handlers ([src/vaultspec_rag/server/\_lifespan.py:1384-1392](../../../../src/vaultspec_rag/server/_lifespan.py#L1384); [src/vaultspec_rag/server/\_auth.py:42-71](../../../../src/vaultspec_rag/server/_auth.py#L42)).

Lifecycle orchestration calls machine-lock, discovery/status, settings, Qdrant supervisor/client, storage manifest/reclamation/survey, service registry, watcher, job registry/manager, operator-state, and monitor APIs. This report records those call sites, not behavior behind those dependencies ([src/vaultspec_rag/server/\_lifecycle.py:47-59, 102-143, 322-423, 674-804](../../../../src/vaultspec_rag/server/_lifecycle.py#L47); [src/vaultspec_rag/server/\_lifespan.py:23-39, 415-600, 628-668, 799-950](../../../../src/vaultspec_rag/server/_lifespan.py#L23)). The explicit `__all__` list is a compatibility/public namespace contract in this slice; whether external callers rely on each name was not independently inspected ([src/vaultspec_rag/server/__init__.py:96-140](../../../../src/vaultspec_rag/server/__init__.py#L96)).
