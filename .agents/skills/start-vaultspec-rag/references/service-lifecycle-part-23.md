## Capability summary

This slice describes test coverage for CLI job presentation, daemon lifecycle and discovery, indexing checkpoints and ledger safety, local storage cleanup, HTTP boundaries, and managed logging. Every capability below is a test expectation; implementation behavior is unverified.

- Job presentation:

  - [src/vaultspec_rag/tests/test_jobs_retry_lineage_display.py](../../../../src/vaultspec_rag/tests/test_jobs_retry_lineage_display.py) builds job payloads and checks feed/detail rendering for retry parent-child links, orphaned child links, newest retry state, no annotations on unrelated jobs, and superseded-parent resolution without stale error text. It also checks the finished/failed aggregate label. The exercised entry points are `_render_jobs_feed` and `render_job_detail`. (1-21, 24-55, 57-218)
  - [src/vaultspec_rag/tests/test_jobs_tui_status.py](../../../../src/vaultspec_rag/tests/test_jobs_tui_status.py) supplies a loopback HTTP service and checks status fetching, header rendering, and mounted Textual widget output. Expectations cover health, store footprint, admission seats, project capacity and in-flight leases, Qdrant state, watcher count, uptime, degradation count, absent/unreachable/error states, hostile or partial payloads, omitted unbuilt metric pools, width-based field shedding, resize without refetch, pending output, and a tone for every health verdict. (1-35, 37-160, 163-308, 310-578)

- Indexing and durable work:

  - [src/vaultspec_rag/tests/test_large_index_resilience_harness.py](../../../../src/vaultspec_rag/tests/test_large_index_resilience_harness.py) checks deterministic corpus preparation, repeat preparation, rejection of marker dimension drift, prepare-only JSON output, and evidence retention including concurrent writers. It imports the benchmark helper’s `CorpusSpec`, `prepare_corpus`, `retain_benchmark_evidence`, and `main`; no live benchmark execution is asserted here. (1-21, 24-141)
  - [src/vaultspec_rag/tests/test_ledger_set_aside.py](../../../../src/vaultspec_rag/tests/test_ledger_set_aside.py) checks that unsupported SQLite run ledgers and companion WAL/SHM files are preserved when moved aside, while current or absent ledgers are unchanged. For code, document, and vault indexers, rebuild authority is expected to set an old ledger aside before touching the supplied stand-in store/model; publication authority is expected to leave it untouched. (1-34, 37-93, 95-183)
  - [src/vaultspec_rag/tests/test_live_checkpoint_resilience.py](../../../../src/vaultspec_rag/tests/test_live_checkpoint_resilience.py) uses CPU-sized store/index fixtures and a real job manager to assert live attempt resilience publication at durable checkpoint boundaries. Coverage includes checkpoint registration for code/document/vault sources, confirmed unit commits, throttled/coalesced persistence and exit flush, no credit for failed store or SQLite writes, stale-task rejection, reconciliation and finalization publication, observer lock/failure handling, control requests around certified publication, protection against claiming a previous checkpoint, and propagation of an application failure after publication. (1-69, 72-195, 198-395, 397-647)

- Daemon lifespan, storage, and machine discovery:

  - [src/vaultspec_rag/tests/test_lifespan_device_load.py](../../../../src/vaultspec_rag/tests/test_lifespan_device_load.py) checks that the health response includes the `device_load` key. It explicitly points to a separate GPU-admission test for projection/absent-value behavior, which is outside this slice. (1-45)
  - [src/vaultspec_rag/tests/test_lifespan_machine_lock.py](../../../../src/vaultspec_rag/tests/test_lifespan_machine_lock.py) creates a real loopback foreign Qdrant-like listener and isolated storage/lock paths; it checks that a pre-yield startup refusal releases the machine lock for a subsequent acquire, including repeated failure paths. (1-37, 40-88, 91-175)
  - [src/vaultspec_rag/tests/test_lifespan_storage_tasks.py](../../../../src/vaultspec_rag/tests/test_lifespan_storage_tasks.py) checks maintenance/warm-up task scheduling against server/local-only configuration and independently enabled prune/reconcile stages, component startup task inclusion, and a disabled maintenance tick followed by an enabled tick. The malformed test endpoint is intended to stop at construction without external network work. (1-28, 31-89, 91-184)
  - [src/vaultspec_rag/tests/test_machine_discovery.py](../../../../src/vaultspec_rag/tests/test_machine_discovery.py) checks the machine-global pointer path beside the lock, absent and malformed reads, publisher round trips, phase details and optional counts across heartbeats, cleanup, bounded quiesce during a wedged guard, fail-loud authoritative RUNNING publication under status-lock contention, best-effort WARMING publication, and bounded startup manifest reconciliation against a stalled socket. (1-34, 37-160, 163-218, 220-338)

- Storage and logging:

  - [src/vaultspec_rag/tests/test_local_store_sqlite_lifetime.py](../../../../src/vaultspec_rag/tests/test_local_store_sqlite_lifetime.py) launches a fresh interpreter with warnings treated as errors and checks that creating local collections leaves no SQLite resource warning at process exit. (1-54)
  - [src/vaultspec_rag/tests/test_log_level_resolution.py](../../../../src/vaultspec_rag/tests/test_log_level_resolution.py) checks default, recognized and case-insensitive levels, rejection of unusable values with a configuration error naming the setting/value, and blank-as-unset handling. (1-29, 32-96)
  - [src/vaultspec_rag/tests/test_logging_config.py](../../../../src/vaultspec_rag/tests/test_logging_config.py) checks managed log discovery and per-source limits; input validation; multibyte records; record/source byte caps and truncation metadata; event formatting; daemon capture of Python and raw stdio; bounded rotating retention; polled-access filtering; and fatal-signal trace output. (1-28, 31-278, 280-363, 365-439, 442-510, 513-568)
  - [src/vaultspec_rag/tests/test_logging_enrollment.py](../../../../src/vaultspec_rag/tests/test_logging_enrollment.py) statically scans production Python files and asserts that model encode/predict calls disable progress bars, logging configuration is installed only by the designated owner, and modules do not create self-owned log-file handlers. This is a structural guard, not a report of the scan result. (1-19, 21-107, 109-160)

- HTTP and credential boundary:

  - [src/vaultspec_rag/tests/test_loopback_http_security.py](../../../../src/vaultspec_rag/tests/test_loopback_http_security.py) checks public versus authenticated health responses, protected routes, invalid credentials, Host and Origin validation (including duplicate authorities), continued same-origin loopback use, wire-client matching against discovery identity/port, and private atomic publication of service and machine discovery files. (1-24, 26-68, 70-186, 188-245, 247-281)
