## Capability summary

- [src/vaultspec_rag/indexer/\_document_indexer.py](../../../../src/vaultspec_rag/indexer/_document_indexer.py): owns document-domain read-only preflight and full, discovered-incremental, and caller-scoped indexing. It resolves policy and canonical in-root sources, bounds aggregate chunk/byte/RSS/CUDA usage, extracts and chunks documents, encodes and upserts slices through a writer, checkpoints confirmed mutations, reconciles stale/deleted points, and publishes/recovers document generations. DocumentIndexer.for_preflight constructs a model/store-free instance for policy/preflight methods; its docstring says such an instance must not enter a run. The module exposes DocumentIndexPreflight, DocumentScopedPreflight, and DocumentIndexer in __all__ (76-97, 278-354, 1101-1171, 1289-1493).
- [src/vaultspec_rag/indexer/\_donor_candidates.py](../../../../src/vaultspec_rag/indexer/_donor_candidates.py): discovers and ranks manifest-described donor namespaces, lazily resolves served code collections, and returns structured eligibility reasons after checking kind, storage/vector schema, embedding-model identity, and effective content epoch. Candidate discovery is capped at three; pointer/proof inspections are bounded at six (91-100, 297-411, 414-501).
- [src/vaultspec_rag/indexer/\_drift_owner.py](../../../../src/vaultspec_rag/indexer/_drift_owner.py): owns repair of code paths whose bytes change during a generation. It removes superseded point IDs before reopening ledger evidence, handles pre-dispatch drift and record-time collisions, retries per path up to a configurable positive budget (default three), and reports superseded/colliding/deferred paths (42-47, 91-143, 145-177, 212-360).
- [src/vaultspec_rag/indexer/\_file_state.py](../../../../src/vaultspec_rag/indexer/_file_state.py): defines canonical relative-path validation and the immutable per-file outcome vocabulary (indexed, policy-rejected, extraction retryable/terminal, decode failed, chunk failed). It validates state-specific evidence and determines convergence/retryability; configuration-stable rejections converge directly, while evidence-stable rejections need a content hash (27-55, 58-75, 140-257).
- [src/vaultspec_rag/indexer/\_generation_lifecycle.py](../../../../src/vaultspec_rag/indexer/_generation_lifecycle.py): owns code-generation checkpoint opening, drift-owner lifetime, lost-evidence detection, build-collection naming, and publication/finalization. It publishes breadth before switching the served pointer, and can retire a completed generation whose build collection disappeared (81-149, 151-228, 291-316, 318-473).
- [src/vaultspec_rag/indexer/\_hook_sandbox.py](../../../../src/vaultspec_rag/indexer/_hook_sandbox.py): provides a case-insensitive environment allow-list and a direct subprocess launcher with captured stdout/stderr, caller-supplied cwd, and curated environment. It implements environment hygiene, not an OS sandbox; caller-side timeout/draining is stated in its docstring but not implemented here (1-17, 34-95).

## Interfaces and data flow

- Document indexing accepts a root, embedding model, store, and optional GPU lock, excludes, root content policy, and publication-readiness callback. Preflight returns a resolved-policy snapshot plus either discovered paths or the exact normalized changed-path set. Run methods return IndexResult; document run/checkpoint and telemetry state are exposed through last_checkpoint, memory_budget_snapshot, and reuse result data (79-97, 278-354, 375-393, 448-536, 1101-1171, 1289-1431).
- Full document runs discover admitted document files, read previous publication evidence when available, retain old points on per-file failure, delete obsolete points, reconcile storage, and publish only when the run has no failures. Incremental runs recover pending publication, compare either the scoped paths or cached/stat-gated discovery against publication evidence, upsert changed files, remove stale/deleted points, then reconcile and publish (881-961, 963-1100, 1173-1287, 1289-1493).
- A document file is extracted/hashed and streamed into weighted slices. Each slice is reserved against profile ceilings, encoded/upserted, and marked confirmed only after storage returns; empty output and skipped extraction become checkpointed file failures. The run records support-profile limits, source/chunk sizing, backend identity, model identity, and sparse/dense configuration in its generation checkpoint (588-710, 712-771, 773-821).
- Document durable state includes a root-specific document_index.statgate.sqlite3 and checkpoint/ledger-backed publication evidence under the resolved workspace data root. Vector point reads/writes/deletes go through VaultStore; publication proof/snapshots and generation routing are accessed through locally imported helpers (299-317, 797-821, 1202-1276, 1315-1405).
- Donor inputs are a target root, collection kind, backend, optional manifest, and cap. The result is a ranked iterator of candidates; eligibility takes expected content epoch and optional expected vector schema, donor-schema probe, and model identity. Missing/unreadable proof or unavailable schema fails closed (56-72, 393-411, 414-501).
- Code drift ownership takes an open code checkpoint and store, plus optional build collection and retry budget. Its methods query checkpoint digest/unit evidence, delete exact code IDs from the selected collection, and reopen/retire ledger evidence in that order. Generation lifecycle supplies this owner when it opens a checkpoint; its publisher counts/reconciles the generation's build target and publishes the served pointer (58-89, 145-210, 212-334; 151-210, 318-423).
- FileState is an immutable value constructed from a canonical project-relative POSIX path, enum state/kind, and optional digest/reason/error/detail. It rejects malformed combinations at construction; converged and retryable are derived properties (140-257, 259-309).
- Hook launching takes argv, cwd, and an explicitly supplied environment; the helper forwards only present allow-listed names and starts the child with stdout/stderr pipes. Approval of a root's hook policy, pipe draining, and timeout enforcement are not implemented in this file (40-95).
