  - [src/vaultspec_rag/tests/test_watcher_rebuild_settlement.py](../../../../src/vaultspec_rag/tests/test_watcher_rebuild_settlement.py) checks preservation of unknown-marker intent, restoration of captured scope, non-stealing of a live attempt fence, unknown-scope cutoffs, settlement of dead legacy fencing, and protection against historical timestamps replacing newer observations (111-342).
  - [src/vaultspec_rag/tests/test_watcher_recovery.py](../../../../src/vaultspec_rag/tests/test_watcher_recovery.py) uses a fake job history to specify restart handling for successful, unsuccessful, live, and unsafe/foreign-root jobs.   - [src/vaultspec_rag/tests/test_watcher_root_identity.py](../../../../src/vaultspec_rag/tests/test_watcher_root_identity.py) specifies canonical root normalization, HTTP query selection through root aliases, alias-based unregister and callback joining, deadline behavior, and bad-request handling for invalid roots (65-217).
  - [src/vaultspec_rag/tests/test_watcher_route_projection.py](../../../../src/vaultspec_rag/tests/test_watcher_route_projection.py) specifies filtering and limiting of `/watcher` controller envelopes and attachment of the same envelope to job detail/list responses by job ID (83-138).
  - [src/vaultspec_rag/tests/test_watcher_scheduler.py](../../../../src/vaultspec_rag/tests/test_watcher_scheduler.py) specifies deadline/reevaluation timeout choice, event wakeups, deterministic bounded recovery jitter, callback failure tolerance, scheduler revival, joining in-flight dispatch, and logging only state/reason transitions (63-294).
  - [src/vaultspec_rag/tests/test_watcher_start_contract.py](../../../../src/vaultspec_rag/tests/test_watcher_start_contract.py) specifies validation before lifecycle dispatch, authentication before body validation, canonical alias dispatch, active-stop cleanup, queued-behind-drain outcomes, and disabled-watch responses (145-422).

They suggest those concerns meet through a shared per-root/source retry/controller state and server lifecycle, but the production call chain and implementation are unverified here.

## Interfaces and data flow

- Retry tests construct `WatcherRetryPolicy` with a state path and options, feed `WatcherPathObservation` values through `mark_scope_pending`, request admission, settle attempts with `record_success`, `record_failure`, or `record_interrupted`, and reload via `refresh` or a new policy instance. Assertions inspect returned retry state, admission decisions, and serialized state. The tests exercise `write_recovery_marker` and `read_state` paths as well ([src/vaultspec_rag/tests/test_watcher_retry.py:43-99, 101-318, 600-1049](../../../../src/vaultspec_rag/tests/test_watcher_retry.py#L43)).
- Rebuild tests construct `JobSnapshot` values and a real test `RunLedger`/publication record through `_published_rebuild`, then call `reconcile_completed_rebuild` or `reconcile_restarted_slot`. The helper associates source, root, rebuild mode, authority, generation, terminal result, and timestamps with the simulated publication ([src/vaultspec_rag/tests/test_watcher_rebuild_reconciliation.py:70-161, 164-746](../../../../src/vaultspec_rag/tests/test_watcher_rebuild_reconciliation.py#L70); [src/vaultspec_rag/tests/test_watcher_rebuild_settlement.py:111-342](../../../../src/vaultspec_rag/tests/test_watcher_rebuild_settlement.py#L111)).
- Restart tests pass job-history lookup behavior to `reconcile_restarted_slot` with a `WatcherConvergenceSlot`; expected outputs are attached job/captured paths or restored/refused retry state ([src/vaultspec_rag/tests/test_watcher_recovery.py:34-113, 115-265](../../../../src/vaultspec_rag/tests/test_watcher_recovery.py#L34)).
- Scheduler/controller tests register controller snapshots with reevaluation and admission callbacks. They assert controller state, callback timing, and registration cleanup ([src/vaultspec_rag/tests/test_watcher_scheduler.py:34-61, 63-294](../../../../src/vaultspec_rag/tests/test_watcher_scheduler.py#L34); [src/vaultspec_rag/tests/test_watcher_root_identity.py:31-64, 78-197](../../../../src/vaultspec_rag/tests/test_watcher_root_identity.py#L31)).
- HTTP tests issue authenticated requests to `/watcher`, `/watcher/start`, `/watcher/stop`, `/watcher/reconfigure`, and job routes. Inputs include root/source/state/limit query parameters and JSON request bodies; assertions inspect status codes and response fields ([src/vaultspec_rag/tests/test_watcher_root_identity.py:78-217](../../../../src/vaultspec_rag/tests/test_watcher_root_identity.py#L78); [src/vaultspec_rag/tests/test_watcher_route_projection.py:83-138](../../../../src/vaultspec_rag/tests/test_watcher_route_projection.py#L83); [src/vaultspec_rag/tests/test_watcher_start_contract.py:145-422](../../../../src/vaultspec_rag/tests/test_watcher_start_contract.py#L145)).
- Storage/integrations visible in test setup include retry JSON and recovery marker paths, workspace-volume paths, run-ledger/publication helpers, child processes for owner/cancellation scenarios, async tasks/locks, the job manager/history seam, service registry, and ASGI HTTP clients. Their implementation semantics are outside this slice.
