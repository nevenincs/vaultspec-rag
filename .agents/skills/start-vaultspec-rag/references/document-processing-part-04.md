## Capability summary

All fourteen modules are integration-test sources. No production implementation or user-facing documentation was inspected, so implementation behavior and documentation claims are not independently established.

- [src/vaultspec_rag/tests/integration/test_document_mcp.py](../../../../src/vaultspec_rag/tests/integration/test_document_mcp.py) exercises the live HTTP and stdio MCP surfaces: it sets up vault and document indexing, checks partial combined reindex behavior, document and combined retrieval, stable public result fields, feedback rejection, MCP tool discovery, status/clean calls, and reindex calls. (1–363)
- [src/vaultspec_rag/tests/integration/test_document_resource_bounds.py](../../../../src/vaultspec_rag/tests/integration/test_document_resource_bounds.py) builds an approved document extractor route and invokes an indexing attempt with a queue limit just over budget. It expects admission refusal before model/project initialization, extractor launch, or data-directory creation. (1–117)
- [src/vaultspec_rag/tests/integration/test_document_search.py](../../../../src/vaultspec_rag/tests/integration/test_document_search.py) indexes three text documents into real storage, then checks document retrieval, source-path filtering, rerank text, and repeatable combined-search selection. (1–82)
- [src/vaultspec_rag/tests/integration/test_document_store.py](../../../../src/vaultspec_rag/tests/integration/test_document_store.py) provisions local or server Qdrant and checks document chunk upsert/scroll/delete, independent collection lifecycle and schema, normalized point identity, document counts in surveys, and a snapshot manifest. (1–280)
- [src/vaultspec_rag/tests/integration/test_document_watcher.py](../../../../src/vaultspec_rag/tests/integration/test_document_watcher.py) seeds run-ledger ownership evidence and classifies watcher events. It expects a deleted path to retain its previous code owner across an incomplete clean and a policy-control edit to schedule code and document slots independently. (1–250)
- [src/vaultspec_rag/tests/integration/test_ecosystem_integration.py](../../../../src/vaultspec_rag/tests/integration/test_ecosystem_integration.py) seeds RAG builtins into temporary vaultspec-core workspaces and runs the installed core CLI in subprocesses. It expects provider rule/MCP propagation, vault preservation over uninstall/reinstall, vault command coexistence, and idempotent sync. (1–443)
- [src/vaultspec_rag/tests/integration/test_embeddings.py](../../../../src/vaultspec_rag/tests/integration/test_embeddings.py) covers the real embedding fixture: dense shapes and related-query similarity, batching, sparse adapter parity against its upstream model, and CPU-retained sparse outputs with bounded CUDA allocation across slices. (1–191)
- [src/vaultspec_rag/tests/integration/test_generation_reclaim.py](../../../../src/vaultspec_rag/tests/integration/test_generation_reclaim.py) creates real local Qdrant collections and ledger/pointer evidence. It expects reclamation to spare served or held generations, handle unreadable pointers conservatively, honor dry-run, and be invoked by the maintenance cycle. (1–307)
- [src/vaultspec_rag/tests/integration/test_gpu_pipeline_integration.py](../../../../src/vaultspec_rag/tests/integration/test_gpu_pipeline_integration.py) compares serial and parallel code indexing results/IDs, then induces a real vector-dimension write error and expects it to surface to the caller. (1–153)
- [src/vaultspec_rag/tests/integration/test_helpers_qdrant_mirror.py](../../../../src/vaultspec_rag/tests/integration/test_helpers_qdrant_mirror.py) checks that a provisioned Qdrant binary resolved inside an isolated service environment remains under that environment and matches its recorded SHA-256. (1–50)
- [src/vaultspec_rag/tests/integration/test_index_job_control_managed.py](../../../../src/vaultspec_rag/tests/integration/test_index_job_control_managed.py) covers cooperative pause/cancel during code streaming and scoped replacement, managed vault/code pause and resume, cancellation write quiescence, and cancel at the managed write gate. It asserts release/reconciliation properties through imported helpers. (1–466)
- [src/vaultspec_rag/tests/integration/test_index_job_control_publication.py](../../../../src/vaultspec_rag/tests/integration/test_index_job_control_publication.py) checks stale collection handling after out-of-band deletion, served-index survival during interrupted clean rebuild, and interrupted incremental recovery for vault, code, and document sources after drift, revert, or delete. (1–445)
- [src/vaultspec_rag/tests/integration/test_index_job_control_stream.py](../../../../src/vaultspec_rag/tests/integration/test_index_job_control_stream.py) covers pause/cancel between vault stream slices, confirmed-unit reuse on rebuild resume for all three sources, and vault partial-source grow/shrink/delete reconciliation. (1–323)
- [src/vaultspec_rag/tests/integration/test_index_reuse_daemon_path.py](../../../../src/vaultspec_rag/tests/integration/test_index_reuse_daemon_path.py) drives managed code rebuild jobs through a service registry backed by supervised Qdrant. It expects donor reuse telemetry on the served job record and a null reuse field when the environment flag is off. (1–232)

## Interfaces and data flow

- Test entry points are pytest functions/classes in the fourteen files above. Their caller inputs are pytest fixtures, temporary roots/files, environment overrides, and—in parametrized control tests—source kind, control request, or source change.
- The exercised paths span direct indexer/store APIs, internal job dispatch and manager APIs, HTTP transport helpers, an MCP stdio client session, watcher classification, storage maintenance, and subprocess invocation of `vaultspec_core`. The tests inspect results, Qdrant records/collections, ledger/publication evidence, service job snapshots, files, or subprocess output depending on the path.
- Test-local document extractor fixtures write a TOML route, approve it through a helper, and point it at a generated script. The MCP test then indexes a document and uses HTTP and MCP search/status/reindex calls. The resource-bound test instead expects dispatch to stop before its extractor sentinel is written.
- The store tests use real local Qdrant or a supervised Qdrant server; GPU/model tests request model-bearing fixtures. The ecosystem tests use temporary workspaces and subprocesses. These are stated test setups, not a report of execution.
- Public-shape expectations include MCP tool names and schemas, HTTP result fields, index status, and the `/jobs` snapshot record. Internal expectations include ledgers, publication proofs, Qdrant payloads, and manager resource counters.

## Boundaries and dependencies

- The inspected files are tests, so they establish requested contracts and test setup, not production ownership or runtime guarantees. Imports such as `DocumentIndexer`, `VaultSearcher`, `VaultStore`, `RunLedger`, `JobManager`, `ServiceRegistry`, and `reclaim_superseded_generations` were not followed.
- Test support and fixtures were not inspected: among them `integration/_helpers.py`, `_index_job_control_support.py`, publication/store/watcher/config fixtures, and the shared [conftest.py](../../../../conftest.py). Their fixture lifecycle and helper semantics remain outside this slice.
- The ecosystem module names `vaultspec-core` as a companion package and executes its CLI, but core code was not inspected. The Qdrant mirror module description mentions an absent-binary fallback; the assigned test itself requires `required_host_provisioned_qdrant_source`, so this slice only covers the present-binary path.
- Some tests explicitly depend on GPU model fixtures, CUDA, or real Qdrant. Source inspection alone cannot establish that these resources are available or that the tests pass.
