## Capability summary

- [src/vaultspec_rag/indexer/\_run_ledger_models.py](../../../../src/vaultspec_rag/indexer/_run_ledger_models.py) defines the shared SQLite access and transaction helpers, WAL/concurrency retry policy, ledger schema contract (base generation/commit/file-state tables plus publication proof, receipt, and tombstone tables), row shapes, enums, errors, and immutable run/publication records. It validates deterministic commit units, receipt state/timestamps, delta ordering and ownership, and that sealed storage mutations exactly cover proof changes.
- [src/vaultspec_rag/indexer/\_run_ledger_publication_identity.py](../../../../src/vaultspec_rag/indexer/_run_ledger_publication_identity.py) projects a `RunSignature` or generation onto the canonical `ProofCompatibilityKey`, exposes the stable four-field lookup tuple, and decodes compatibility keys from SQLite rows.
- [src/vaultspec_rag/indexer/\_run_ledger_publication_proofs.py](../../../../src/vaultspec_rag/indexer/_run_ledger_publication_proofs.py) reads current proofs, checks no-op and already-committed publication states, invalidates proof/receipt state before a backing source is cleared, establishes verified proof only under rebuild authority, and checks that proof state permits generation finalization.
- [src/vaultspec_rag/indexer/\_run_ledger_publication_reads.py](../../../../src/vaultspec_rag/indexer/_run_ledger_publication_reads.py) supplies bounded/keyset-paginated proof-evidence and point-membership reads; locates active or recoverable receipts; selects a current proof with a read token; fences ordinary readers during open receipts while allowing the owning recovery writer; and validates the token after backend reads.
- [src/vaultspec_rag/indexer/\_run_ledger_publication_receipts.py](../../../../src/vaultspec_rag/indexer/_run_ledger_publication_receipts.py) reserves monotonic receipt sequences, validates rebuild recovery projection and receipt ownership, checks old/new evidence and point ownership, commits sealed and confirmed receipt deltas with revision/sequence compare-and-swap, replaces changed evidence, and prunes bounded closed history.

## Interfaces and data flow

- Durable store: `index_run_ledger_path(data_root)` returns the per-root `index_runs.sqlite3` path. Connection helpers use a 10-second SQLite busy timeout, set row factories and foreign keys, request WAL for durable files, optionally run read-only format preflight/before-journal hooks, and close handles/transactions through context managers. Whole-transaction writes retry lock contention four times with bounded backoff. ([src/vaultspec_rag/indexer/\_run_ledger_models.py](../../../../src/vaultspec_rag/indexer/_run_ledger_models.py) lines 110-183, 223-349, 533-599, 716-718.)
- Schema contract: schema version is 9; `REQUIRED_SCHEMA` combines base ledger and publication tables, while named required indexes and partial-index predicates are specified alongside it. `PUBLICATION_PROOF_SCHEMA` is derived from the publication row TypedDicts. ([src/vaultspec_rag/indexer/\_run_ledger_models.py](../../../../src/vaultspec_rag/indexer/_run_ledger_models.py) lines 533-713.)
- Identity flow: `compatibility_for_signature` maps source/root/backend/collection, storage and payload schema, model/dimension/embedding, preprocessing, membership/content epoch, and policy fingerprint into the proof key. Row parsing narrows SQLite columns through corruption-checking helpers. ([src/vaultspec_rag/indexer/\_run_ledger_publication_identity.py](../../../../src/vaultspec_rag/indexer/_run_ledger_publication_identity.py) lines 19-69; [src/vaultspec_rag/indexer/\_run_ledger_models.py](../../../../src/vaultspec_rag/indexer/_run_ledger_models.py) lines 352-375, 866-936.)
- Main records include `RunSignature` (canonical JSON and fingerprints), `CommitUnit` (deterministic idempotency identity), `RunGeneration`, `PublicationProof`, `PublicationReceipt`, receipt-bound `PublicationMutationUnit`, and `EffectivePublicationRead`; TypedDicts describe persisted generation/evidence/point/receipt/mutation/delta/tombstone rows. ([src/vaultspec_rag/indexer/\_run_ledger_models.py](../../../../src/vaultspec_rag/indexer/_run_ledger_models.py) lines 378-531, 866-1009, 1018-1326.)
- Proof establishment takes generation ID, `RunAuthority`, and unique path/point evidence. It only accepts rebuild authority and a full operation in an allowed early finalization phase, rejects open receipts, and transactionally replaces proof/evidence/point rows as a verified proof. Finalization checks require a compatible current proof, no open receipt, and for delta-derived proofs a matching committed receipt. ([src/vaultspec_rag/indexer/\_run_ledger_publication_proofs.py](../../../../src/vaultspec_rag/indexer/_run_ledger_publication_proofs.py) lines 208-374, 376-465.)
- Read APIs include `publication_evidence_for_paths` (max 256 paths), `publication_evidence_page` (keyset pagination, max 256), `publication_point_ids_for_candidates` (max 256), `active_publication_receipt`, `recoverable_publication_receipt`, `acquire_current_publication_snapshot`, and `validate_publication_read_token`. Reads generally start one SQLite snapshot and roll it back after use. A read token binds compatibility key, proof revision, reservation sequence, and open-receipt status. ([src/vaultspec_rag/indexer/\_run_ledger_publication_reads.py](../../../../src/vaultspec_rag/indexer/_run_ledger_publication_reads.py) lines 83-128, 139-234, 236-325, 327-476.)
- Receipt APIs include `publication_receipt_for_generation`, `rebuild_recovery_receipt`, `reserve_publication_receipt`, and `commit_publication_receipt`. Reservation advances the current proof reservation sequence and creates an open receipt in one retryable transaction. Commit requires a sealed, confirmed receipt, validates proof/evidence/generation authority, applies deltas, replaces normalized evidence, advances revision by compare-and-swap, and closes the receipt atomically. Explicit rebuild recovery requires a full rebuild signature matching the stable projection. ([src/vaultspec_rag/indexer/\_run_ledger_publication_receipts.py](../../../../src/vaultspec_rag/indexer/_run_ledger_publication_receipts.py) lines 105-170, 287-463, 465-572, 574-747.)
