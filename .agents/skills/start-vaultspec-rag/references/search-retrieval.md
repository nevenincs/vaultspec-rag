## Limits and reconciliations

Findings describe the inspected snapshot. External dependency internals and operational outcomes were not verified. Test assertions and recorded benchmark results do not establish a current passing run.

- CombinedSearchOptions.from_arguments omits inherited like_ids/unlike_ids; potential combined feedback loss is a code observation, not verified user behavior.
- Default combined CLI search excludes documents unless a type is explicit; the docs alias refers to vault.
- TypeSafe credential/remote outcomes, performance and fallback availability remain unverified; full rerank_text is internal and not public JSON.
- Authority requires compatible complete publication/conformance evidence; partial failures, authoritative emptiness and transport failure remain distinct.
- Documentation ambiguity: docs/service-mode.md:451-463 describes ungated GET /health returning service_token, while docs/service-discovery.md:155-157 says unauthenticated /health omits service_token; conditional authentication behavior is unresolved. Source-backed server/client evidence resolves the response contract: no-credential health is anonymous, presented invalid credentials are rejected, and service_token is included only for authenticated health. Discovery publication is token-bearing separately; conflicting guide wording remains a documentation limitation.
- s1-0033 broad watcher_runtime awatch docstring is not its implementation role. s1-0032 identifies the actual native intake loop; retry/runtime are coordination layers. watcher_intake.py owns native intake/awatch; watcher runtime/retry coordinate it. This is a docstring scope discrepancy, not an uninspected loop.
