## Capability summary

- [src/vaultspec_rag/tests/test_mcp_no_local_fallback.py](../../../../src/vaultspec_rag/tests/test_mcp_no_local_fallback.py) exercises MCP service-down behavior for five tools and one resource, including an actionable “server start” message, and fresh-interpreter checks for absence of Torch, sentence-transformers, Qdrant, Transformers, and ONNX Runtime on failed calls (1-18, 48-110, 113-141). It also constructs a loopback HTTP daemon and compares its calls with the live MCP tool registry, checking ordinary success and stale-token retry paths against the same forbidden-import set (144-424, 518-554). Additional expectations cover serialized success/failure `SearchResults` shapes and rejection of an invalid search preference (427-515). The six service-down calls and twelve registered stub calls are distinct inventories (48-71; 333-368).
- [src/vaultspec_rag/tests/test_mcp_project_root_contract.py](../../../../src/vaultspec_rag/tests/test_mcp_project_root_contract.py) covers MCP root resolution and the advertised optional parameter contract for twelve tools (33-49, 213-245): explicit root over environment root, environment root over working directory, omitted/blank root falling through to an enrolled CWD, unresolved-root remediation, and acceptance by the server route validator (52-189). It also scans MCP modules for the old blank-root forwarding expression (191-210). These are resolver, signature, and source-scan assertions; the file does not call every listed tool through its full transport.
- [src/vaultspec_rag/tests/test_metrics.py](../../../../src/vaultspec_rag/tests/test_metrics.py) checks precision@k, reciprocal rank, and nDCG@k on perfect, partial, empty, truncated, and no-relevant-result examples (7-54).
- [src/vaultspec_rag/tests/test_mixin_declarations.py](../../../../src/vaultspec_rag/tests/test_mixin_declarations.py) statically discovers production classes ending in `Mixin`, requires at least ten matches, and rejects `dataclass` decorators on them (34-58, 61-92).
- [src/vaultspec_rag/tests/test_model_download_child_shadowing.py](../../../../src/vaultspec_rag/tests/test_model_download_child_shadowing.py) checks that `download_snapshot`'s child does not import a planted package or `huggingface_hub` from the current checkout, using an offline absent repository; a control launches the prior `python -m` shape and expects both plants to run (1-10, 20-28, 37-97).
- [src/vaultspec_rag/tests/test_model_fetch.py](../../../../src/vaultspec_rag/tests/test_model_fetch.py) covers configured model inventory probing, offline failure, dry-run preview, progress reporting through provisioning and install, successful fetch/cache reuse, and a range of download failure modes (134-327, 329-600). It checks the progress-floor timing/byte rule, stopping wedged or trickling downloads and descendants, cache cleanup after failures, cache contention and a second fetch observing newly cached content (622-1011, 1023-1079). It covers TLS certificate refusal/trust, `server warmup` exit/report behavior and no-Torch expectation, and install JSON failure then successful rerun (1081-1302). The tests describe both loopback HTTP/TLS transfers and isolated child processes; helper implementations are uninspected.
- [src/vaultspec_rag/tests/test_model_fetch_bounds.py](../../../../src/vaultspec_rag/tests/test_model_fetch_bounds.py) covers a whole-fetch deadline, a shared cache-contention allowance across repositories, starting that wait allowance when the cache is found held, and distinguishing local cache write faults from network failures (48-238).
- [src/vaultspec_rag/tests/test_model_fetch_checked.py](../../../../src/vaultspec_rag/tests/test_model_fetch_checked.py) checks pinned-commit requests and rejection of content that fails committed SHA-256 checks, refetching altered cache files, and refusal of a repository containing only pickle weights (27-152). Its docstring explicitly limits the suite: it does not serve the real gigabyte-scale weights or prove a repaired fetch succeeds against matching content (27-40).
- [src/vaultspec_rag/tests/test_model_hub_endpoint.py](../../../../src/vaultspec_rag/tests/test_model_hub_endpoint.py) checks endpoint export before the hub client is imported through fresh CLI/server processes, config-versus-operator precedence, default and unset behavior, normalization/validation, spawned-service environment inheritance, and that workspace files cannot provide this setting (47-349). It asserts the HTTP daemon's first non-docstring statement is the environment preflight (192-217).

## Interfaces and data flow

- MCP tests call search, retrieval, reindex, clean, and status functions, plus a vault-document resource; expected inputs include query/path and optional `project_root`, and outputs/errors include tool results, serialized search envelopes, or MCP protocol errors ([src/vaultspec_rag/tests/test_mcp_no_local_fallback.py:48-71, 333-368, 427-515](../../../../src/vaultspec_rag/tests/test_mcp_no_local_fallback.py#L48); [src/vaultspec_rag/tests/test_mcp_project_root_contract.py:33-49, 227-245](../../../../src/vaultspec_rag/tests/test_mcp_project_root_contract.py#L33)). The loopback stub writes a discovery/status JSON file and receives real HTTP requests; tests redirect status and Qdrant storage paths into temporary locations ([src/vaultspec_rag/tests/test_mcp_no_local_fallback.py:162-186, 311-371](../../../../src/vaultspec_rag/tests/test_mcp_no_local_fallback.py#L162)).
- Root resolution consumes an explicit string or `None`, `VAULTSPEC_RAG_ROOT`, and process CWD; tests model an enrolled workspace with `.vault` and `.vaultspec`. The route validator is expected to accept the resolved absolute root and reject blank input ([src/vaultspec_rag/tests/test_mcp_project_root_contract.py:52-56, 94-127, 130-170](../../../../src/vaultspec_rag/tests/test_mcp_project_root_contract.py#L52)).
- Model provisioning consumes configured repository IDs, cache contents, dry-run/offline flags, and optional progress sinks. Expected outcomes carry per-repository action/detail, summary code/detail, and child process counts ([src/vaultspec_rag/tests/test_model_fetch.py:105-124, 134-207, 291-327](../../../../src/vaultspec_rag/tests/test_model_fetch.py#L105); test_model_fetch_child_shadowing.py:68-75). Fetch tests use temporary Hugging Face caches, loopback HTTP/TLS endpoints, environment overrides for endpoint/timeouts/deadline, and subprocess results. Tests inspect downloaded file requests, cache completeness, progress strings, process termination, and rerun outcomes ([src/vaultspec_rag/tests/test_model_fetch.py:272-327, 431-460, 753-800, 1084-1127](../../../../src/vaultspec_rag/tests/test_model_fetch.py#L272); [src/vaultspec_rag/tests/test_model_fetch_bounds.py:48-91](../../../../src/vaultspec_rag/tests/test_model_fetch_bounds.py#L48)).
- Pinned verification inputs are a model ID, commit revision, manifest entries and file bytes; expected output is a failed `MODELS_UNVERIFIED` result when downloaded or cached content disagrees ([src/vaultspec_rag/tests/test_model_fetch_checked.py:43-89, 90-120](../../../../src/vaultspec_rag/tests/test_model_fetch_checked.py#L43)). Hub endpoint selection flows from `VAULTSPEC_RAG_HF_ENDPOINT` and/or operator `HF_ENDPOINT` into child environment and the hub client's imported endpoint constant ([src/vaultspec_rag/tests/test_model_hub_endpoint.py:55-82, 104-142, 145-189, 319-335](../../../../src/vaultspec_rag/tests/test_model_hub_endpoint.py#L55)).

## Boundaries and dependencies

- This slice defines tests under `src/vaultspec_rag/tests`; it does not establish that the named production paths pass. MCP behavior is coupled by assertions to `mcp._tools`, `mcp._resources`, the service client, discovery status, and server root validation, but their implementations were not inspected ([src/vaultspec_rag/tests/test_mcp_no_local_fallback.py:48-71, 98-110](../../../../src/vaultspec_rag/tests/test_mcp_no_local_fallback.py#L48); [src/vaultspec_rag/tests/test_mcp_project_root_contract.py:94-115](../../../../src/vaultspec_rag/tests/test_mcp_project_root_contract.py#L94)).
- Model-fetch tests depend on command/provision modules, settings, model cache and pin helpers, cache lock helpers, process utilities, CLI/server entry points, and test-only loopback/cache/child helpers; all are uninspected beyond import names and usage ([src/vaultspec_rag/tests/test_model_fetch.py:35-84](../../../../src/vaultspec_rag/tests/test_model_fetch.py#L35); [src/vaultspec_rag/tests/test_model_fetch_bounds.py:22-36](../../../../src/vaultspec_rag/tests/test_model_fetch_bounds.py#L22); [src/vaultspec_rag/tests/test_model_fetch_checked.py:14-19](../../../../src/vaultspec_rag/tests/test_model_fetch_checked.py#L14)). They expect Hugging Face Hub behavior and OS process/filesystem/network behavior, but this slice cannot validate those dependencies independently.
- Static checks in the mixin and project-root tests read broader production source trees at test runtime (mixin discovery excludes tests; root scan covers `mcp/*.py`); that describes their test scope, not files inspected for this report ([src/vaultspec_rag/tests/test_mixin_declarations.py:48-58](../../../../src/vaultspec_rag/tests/test_mixin_declarations.py#L48); [src/vaultspec_rag/tests/test_mcp_project_root_contract.py:191-210](../../../../src/vaultspec_rag/tests/test_mcp_project_root_contract.py#L191)).
- The endpoint test imports both package settings and `huggingface_hub.constants`; it states that the client reads `HF_ENDPOINT` on import. This causal behavior is a test premise, not independently verified here ([src/vaultspec_rag/tests/test_model_hub_endpoint.py:1-14, 61-82](../../../../src/vaultspec_rag/tests/test_model_hub_endpoint.py#L1)).
