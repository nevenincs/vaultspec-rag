## Capability summary

- [src/vaultspec_rag/tests/test_store_schema_drift.py](../../../../src/vaultspec_rag/tests/test_store_schema_drift.py): marked integration; creates local Qdrant collections through `VaultStore.ensure_table()` and `ensure_code_table()` and compares live named dense/sparse vector configuration with schema constants and the schema descriptor. It also checks the store's configured dimension against the schema's effective dimension. The module docstring says payload-index drift is covered by a CI-gated invariant elsewhere; that other test was not read.
- [src/vaultspec_rag/tests/test_store_schema_parity.py](../../../../src/vaultspec_rag/tests/test_store_schema_parity.py): marked unit; uses `VaultChunk`/`CodeChunk` fixtures to pin serialized payload shape and values. It covers ordinal-dependent `doc_content`, code chunk fields, and path-derived `domain` values for source, tests, and worktree paths.
- [src/vaultspec_rag/tests/test_store_writes.py](../../../../src/vaultspec_rag/tests/test_store_writes.py): marked unit; exercises error classification, retry policy outcomes/budget limits, and disk-space admission/probing. Coverage includes real refused loopback TCP connections, a real `VaultStore._collection_exists` call site in server mode, scoped environment/config restoration, store versus workspace volume selection, unknown remote volume handling, and human-readable refusal descriptions.
- [src/vaultspec_rag/tests/test_streaming_segments.py](../../../../src/vaultspec_rag/tests/test_streaming_segments.py): marked unit; exercises code-chunk segment/slice boundaries, byte estimates, weighted queue capacity/backpressure, producer wait expiry, consumer progress/drain, vector-field release, and dense-vector conversion from NumPy and CPU Torch rows. It supplies the inputs and policies to the imported producer, consumer, slicing, streaming, and type APIs; it does not establish their behavior beyond the assertions written here.
- [src/vaultspec_rag/tests/test_substitution_discipline.py](../../../../src/vaultspec_rag/tests/test_substitution_discipline.py): marked unit; scans Python files under the tests package for textual `monkeypatch.setattr`/`monkeypatch.delattr` occurrences, compares per-file counts against `_ALLOWED`, and requires declared counts to remain present. The table records counts and explanations for many other test modules, but those modules were not inspected and the reasons are assertions in this file, not independently verified facts.
- [src/vaultspec_rag/tests/test_textual_timer_cancel.py](../../../../src/vaultspec_rag/tests/test_textual_timer_cancel.py): marked unit; starts a fresh Python subprocess that repeatedly stops and cancels Textual timers, then checks whether the loop's default executor shuts down within a bounded join. Its source documents a Windows hang scenario and a mutation; neither platform behavior nor the test result was run here.

## Interfaces and data flow

- Test entry points are pytest test functions and fixtures. The schema drift fixture constructs/closes `VaultStore`; parity tests pass typed chunks to payload builders; write tests call store-write helpers with operations, descriptions, and optional `StoreWritePolicy`; streaming tests pass chunks and explicit limits through `CodeFileSegmentRequest` → segments → weighted slices/queue, then observe draining/progress and vector conversion/release.
- Write-path tests temporarily set environment variables and call `reset_config()` around each scenario. They use `tmp_path` for isolated paths, `caplog` for retry records, a closed loopback port for network refusals, `shutil.disk_usage` through a helper for live free-space comparisons, and an actual local Qdrant store in the call-site test. These are test inputs/assertions, not evidence of a successful test run.
- The substitution guard's input is the test tree: `_substitution_counts()` recursively finds `*.py`, reads text as UTF-8 with replacement, counts matching lines per relative path, and compares those counts with `_ALLOWED`. The timer test passes an embedded child program to `subprocess.run`, captures output, and expects `joined`.
