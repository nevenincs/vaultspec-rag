## Interfaces and data flow

- Environment tests supply mappings through `monkeypatch` or `managed_env`, inspect enum/registry/settings results, and in several cases launch fresh Python processes. The CLI subprocess path shown is `python -m vaultspec_rag server status --json`; entry-import tests start a child interpreter to inspect whether dotenv entered `sys.modules` ([src/vaultspec_rag/tests/test_env_log_level.py](../../../../src/vaultspec_rag/tests/test_env_log_level.py) 117-186; [src/vaultspec_rag/tests/test_env_parity.py](../../../../src/vaultspec_rag/tests/test_env_parity.py) 210-230).
- Holder tests create a temporary virtual environment with `uv venv`, launch real children, then inspect `environment_holders` results such as `holders`, `relation`, `complete`, `uninspectable`, `held`, `certain`, and `self_held`. Injected process rows drive branches unavailable from a live process table ([src/vaultspec_rag/tests/test_env_holders.py](../../../../src/vaultspec_rag/tests/test_env_holders.py) 59-90, 112-159, 202-259, 307-343, 353-405).
- Interpreter-probe tests call `probe_interpreter` or parse its child output into facts containing compute capability and, where applicable, backend, device name, memory, and detail. Some classifications use a minimal in-memory torch-shaped module ([src/vaultspec_rag/tests/test_environment_probe.py](../../../../src/vaultspec_rag/tests/test_environment_probe.py) 45-89, 119-148, 151-234).
- Anchor tests coordinate child scripts through anchor, readiness, and stop paths. They inspect `AnchorOutcome`, descriptor, fault, and holder PID returned from `observe_existing_anchor`; a separate test parses the persisted record as JSON ([src/vaultspec_rag/tests/test_existing_anchor_observation.py](../../../../src/vaultspec_rag/tests/test_existing_anchor_observation.py) 41-148, 151-200, 203-349).
- Generation tests pass roots, derived collection names, collections, pointer/proof state, time, stamps, reader presence, and dry-run/policy values to survey and reclamation APIs. They inspect reports/results and a shaped storage-survey payload. Storage integrations include local Qdrant and archive files in the autoprune module, a fake collection transport in conflict/reclaim cases, and a run ledger/publication proof used by the survey helper ([src/vaultspec_rag/tests/test_generation_autoprune_policy.py](../../../../src/vaultspec_rag/tests/test_generation_autoprune_policy.py) 41-97, 132-177; [src/vaultspec_rag/tests/test_generation_survey.py](../../../../src/vaultspec_rag/tests/test_generation_survey.py) 30-66, 282-296, 375-390, 528-545, 585-628).
- The only direct within-slice helper dependency found is [src/vaultspec_rag/tests/test_generation_autoprune_policy.py](../../../../src/vaultspec_rag/tests/test_generation_autoprune_policy.py) importing `_publish_code_proof` from [src/vaultspec_rag/tests/test_generation_survey.py](../../../../src/vaultspec_rag/tests/test_generation_survey.py) (lines 29-32).
