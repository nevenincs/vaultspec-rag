## Capability summary

- [src/vaultspec_rag/tests/test_cli_server.py](../../../../src/vaultspec_rag/tests/test_cli_server.py) exercises the Typer `app` command surface for server lifecycle and operator commands. Expectations cover `server --watch` dispatch, flattened command routing and unsupported aliases, help text, status and Qdrant summaries, update status, grouped and filtered logs, jobs, and project list/unload responses. The same module also covers lifecycle shutdown logging and attribution, termination behavior, platform drain windows, and the start readiness deadline. These are assertions in tests, not evidence that the suite currently passes. (test source: [src/vaultspec_rag/tests/test_cli_server.py:1-1007](../../../../src/vaultspec_rag/tests/test_cli_server.py#L1))

(test source: [src/vaultspec_rag/tests/test_cli_server_start.py:39-341](../../../../src/vaultspec_rag/tests/test_cli_server_start.py#L39))
- [src/vaultspec_rag/tests/test_cli_server_stop.py](../../../../src/vaultspec_rag/tests/test_cli_server_stop.py) owns stop JSON/human outcome contracts and live CLI cases: already stopped, stale recorded PID cleanup, unconfirmed live PID refusal, initiator attribution, unsuccessful termination and remediation wording, and platform-specific commands. It includes one AST-based structural assertion that callers inspect termination results. (test source: [src/vaultspec_rag/tests/test_cli_server_stop.py:46-478](../../../../src/vaultspec_rag/tests/test_cli_server_stop.py#L46))

It builds health/job payloads and live status-contract fixtures, then checks degraded-reason rendering and next actions, index degradation formatting, quiet healthy output, process identity and status-file read/write cases, status/health probe outcomes, port-only output, sparse or missing service fields, JSON status, unreachable-port envelopes, and degradation-registry invariants.
