## Interfaces and data flow

- Install tests pass a temporary workspace path and options such as assume_yes, configure_torch, force, dry_run, confirm, sync_after, provision, mode, and torch_group into install_run; uninstall_run receives a workspace and uninstall options. They inspect report fields including torch configuration/direct-dependency/sync actions, conflicts, warnings, MCP status, and JSON serialization. Test fixtures write and reread [pyproject.toml](../../../../pyproject.toml); SHA-256 comparisons pin no-mutation paths. ([src/vaultspec_rag/tests/test_install_torch_config.py:46-55, 58-152, 331-457, 467-620, 623-878, 880-956, 1037-1292](../../../../src/vaultspec_rag/tests/test_install_torch_config.py#L46))
- The unattended tests resolve \_confirmation_hook using an explicit callback, JSON flag, environment mapping, and in-memory stdin/stdout streams; environment keys come from vaultspec_core.config. ([src/vaultspec_rag/tests/test_install_unattended.py:21-48, 51-88](../../../../src/vaultspec_rag/tests/test_install_unattended.py#L21))
- Integrity tests send a root path, source type, verdict, and supplied monotonic timestamp to \_record_verdict; they read observations, status dictionaries, or a search-state dictionary. The auto-repair setting is scoped through managed_env; the status test scopes a status directory and resets the job manager around its check. ([src/vaultspec_rag/tests/test_integrity_remediation.py:45-49, 61-116, 129-169, 172-257](../../../../src/vaultspec_rag/tests/test_integrity_remediation.py#L45))
- Job-contract helpers construct JobSpec, JobSnapshot, state/resource/runtime/timestamp/progress/telemetry values, then use persistence load/save functions and a real temporary directory. The visible persistence tests create and age files on disk before calling load_persisted_state. ([src/vaultspec_rag/tests/test_job_contracts.py:329-445, 708-930, 927-939, 1021-1110](../../../../src/vaultspec_rag/tests/test_job_contracts.py#L329))
