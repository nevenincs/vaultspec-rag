## Capability summary

- [src/vaultspec_rag/tests/test_config.py](../../../../src/vaultspec_rag/tests/test_config.py) exercises RAG configuration defaults, environment overrides and validation; HF offline/cache-only detection; blank and nonblank path handling; service and managed-log settings; independent dense, sparse and document embedding budgets; storage/index/watch resilience knobs; CUDA ceiling derivation; and `MemoryBudget` enforcement and measurement-failure behavior. These are asserted contracts, not implementation findings. (1–1039)
- [src/vaultspec_rag/tests/test_config_backend.py](../../../../src/vaultspec_rag/tests/test_config_backend.py) exercises effective Qdrant server versus local-only selection; code-noise and locale-dedup settings; reranker enablement; index-reuse switch parsing; malformed and ranged-setting refusals; document chunk sizing/overlap; preprocessing kill-switch parsing; storage auto-prune grace limits; and sparse-enabled model-repository inventory. (1–596)
- [src/vaultspec_rag/tests/test_config_epoch.py](../../../../src/vaultspec_rag/tests/test_config_epoch.py) covers expected epoch hashing and run-signature invalidation, plus `CodebaseIndexer` policy snapshots and reachable/unreachable ignore-file effects on membership scans. Its module description says these paths avoid embedding and store construction; that is a test-source description, not independently verified implementation behavior. (1–196)
- [src/vaultspec_rag/tests/test_config_operator_binary.py](../../../../src/vaultspec_rag/tests/test_config_operator_binary.py) specifies the operator-supplied Qdrant binary path/digest pair contract: unset default, paired resolution, digest normalization/shape, construction-time and subsequent-read refusal, registry metadata, and CLI error/help/version output expectations. It defines a subprocess helper for CLI cases; no subprocess was run in this analysis. (1–332)
- [src/vaultspec_rag/tests/test_config_sources.py](../../../../src/vaultspec_rag/tests/test_config_sources.py) specifies Qdrant download-source defaults and overrides, URL and host-list validation, settings refusal through startup validation, and expectations that source settings are not workspace-dotenv or project-store inputs. It also checks the shared checked-setting URL path for `hf_endpoint`. These are source-test assertions, not verified download implementation. (1–432)
- [src/vaultspec_rag/tests/test_config_watcher.py](../../../../src/vaultspec_rag/tests/test_config_watcher.py) specifies watcher defaults, environment parsing, mapping from legacy debounce/cooldown inputs to adaptive bounds, precedence of explicit adaptive inputs, and cross-setting bound validation. (1–232)
- [src/vaultspec_rag/tests/test_configuration_doc.py](../../../../src/vaultspec_rag/tests/test_configuration_doc.py) checks configuration-reference tables against declared environment variables, defaults, types, the override map, exception-parsing section, and config-only keys. The module docstring claims mutations were run and restored, but this analysis did not run tests or inspect [docs/configuration.md](../../../../docs/configuration.md); treat that statement as a claim in test source. (1–294)
- [src/vaultspec_rag/tests/test_confirmed_chunk_progress.py](../../../../src/vaultspec_rag/tests/test_confirmed_chunk_progress.py) specifies acknowledged-chunk progress and liveness expectations across detail/summary/root-status projections, independently of CODE file-count display; it also covers acknowledgement recency, phase and attempt ownership, terminal jobs, JSON projection, and publication rollback. These are test expectations about the imported reporters and projections. (1–491)

## Interfaces and data flow

- Configuration tests set or clear `EnvVar` process-environment values, call `reset_config()`, then read `get_config()` properties. Some also construct `VaultSpecConfigWrapper` directly or invoke settings/schema helpers; reset-fixture implementation is uninspected. ([src/vaultspec_rag/tests/test_config.py](../../../../src/vaultspec_rag/tests/test_config.py) 182–189, 228–255; [src/vaultspec_rag/tests/test_config_backend.py](../../../../src/vaultspec_rag/tests/test_config_backend.py) 32–49, 73–80; [src/vaultspec_rag/tests/test_config_watcher.py](../../../../src/vaultspec_rag/tests/test_config_watcher.py) 22–24)
- The config tests pass settings into `MemoryBudget`, call `observe()`/`sample()`, and assert snapshot fields or typed `JobError`s. CUDA helper tests feed `CudaCeilingObservation` values to ceiling-resolution functions. Actual measurement and enforcement code is uninspected. ([src/vaultspec_rag/tests/test_config.py](../../../../src/vaultspec_rag/tests/test_config.py) 286–396, 837–1039)
- Epoch tests create temporary roots and call `CodebaseIndexer.resolve_policy_snapshot()`, `_begin_preprocess_run()`, and `_scan_changed_paths()`; separate tests create `RunLedger` signatures and compare generations after signature changes. The scanner, epoch function, and ledger implementation are uninspected. ([src/vaultspec_rag/tests/test_config_epoch.py](../../../../src/vaultspec_rag/tests/test_config_epoch.py) 48–54, 90–123, 125–196)
- Binary/source tests drive settings via the environment; the binary tests also call `collect_environment_problems()` and define a `python -m vaultspec_rag` subprocess for CLI behavior. No download or binary execution path was inspected. ([src/vaultspec_rag/tests/test_config_operator_binary.py](../../../../src/vaultspec_rag/tests/test_config_operator_binary.py) 73–81, 274–332; [src/vaultspec_rag/tests/test_config_sources.py](../../../../src/vaultspec_rag/tests/test_config_sources.py) 73–77, 280–300)
- Progress tests call `record_start`, `JobProgressReporter` phase/forward/acknowledgement methods, then inspect `snapshot`, `_job_with_liveness`, `_job_summary`, and `index_job_status` results. A publication test supplies an acknowledgement callback to `execute_store_mutation`; managed-attempt tests exercise manager pause/resume/finish boundaries. Implementations and persistence formats are uninspected. ([src/vaultspec_rag/tests/test_confirmed_chunk_progress.py](../../../../src/vaultspec_rag/tests/test_confirmed_chunk_progress.py) 50–82, 85–139, 187–268, 281–370, 373–433, 435–491)

## Boundaries and dependencies

- The assigned corpus is under `src/vaultspec_rag/tests`; every described capability is observed as an expectation in test source, not as a production capability verified by reading implementation.
- Visible local relationships include config tests importing `config._settings`, `config._schema`, `config._registry`, and `config._types`; epoch tests importing indexer, run-ledger, and policy-facing APIs; and progress tests importing jobs, job progress, and server job routes. Those imported modules were not read, so their internals and contracts outside these assertions are unknown.
- External/framework dependencies visible in the tests include `pytest`, `vaultspec_core` config/env vocabularies, and Python subprocess/filesystem facilities. Their implementation and runtime availability were not inspected.
- The docs test points at [docs/configuration.md](../../../../docs/configuration.md), but that file was outside the read allowance. It checks for a shipped-file skip condition and describes table reconciliation; the document's current content is unknown. ([src/vaultspec_rag/tests/test_configuration_doc.py](../../../../src/vaultspec_rag/tests/test_configuration_doc.py) 45–68)
