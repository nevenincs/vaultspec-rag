## Capability summary

- [src/vaultspec_rag/cli/\_install.py](../../../../src/vaultspec_rag/cli/_install.py): registers custom `install` and `uninstall` Typer commands. It declares CLI options, maps parsed values to request dataclasses, routes work to command-layer functions, formats errors/reports, emits JSON envelopes, and determines status/exit codes. Install flags cover enrollment/upgrade/dry-run, PyTorch config, optional provisioning, MCP enrollment, local-only mode, and component skips. Uninstall requires `--force` to execute and can request data removal.
- [src/vaultspec_rag/cli/\_jobs_tui.py](../../../../src/vaultspec_rag/cli/_jobs_tui.py): implements the Textual `ServerWatchApp` and `run_server_watch` entry point. The app presents indexing jobs, served-search activity, focused logs, all-source managed logs, and service status; handles refresh scheduling, responsive pane layout, selection, keyboard actions, pending action feedback, row tombstones, and repainting. Job controls, header rendering, log panes, palettes, payload validation, and status fetching are partly delegated to imported helpers/mixins.
- [src/vaultspec_rag/cli/\_jobs_tui_cells.py](../../../../src/vaultspec_rag/cli/_jobs_tui_cells.py): converts job and served-search records into Rich cell/detail text. It provides identity lookup and sanitization, capability interpretation, phase/progress/time formatting, and search identity, outcome, timing, and failure lines. Its module docstring describes these functions as record-to-presentation transforms without app or transport access.
- [src/vaultspec_rag/cli/\_jobs_tui_constants.py](../../../../src/vaultspec_rag/cli/_jobs_tui_constants.py): centralizes table width weights and thresholds, action-to-capability/state maps, key and refusal vocabularies, status summary/pill vocabularies, estimate field name, log/search limits, and Textual worker-group names.

## Interfaces and data flow

- Install parsing enters through `_InstallCommand.invoke` or `_UninstallCommand.invoke`; each casts Click parameters to a typed mapping and creates an options record. `_run_install` resolves the command target against the root-level target, creates an unattended-aware confirmation callback, maps model/Qdrant skips, and calls `commands._install.install_run`. It passes the progress reporter through the call. The returned report is converted to a plain report or `rag.install` JSON envelope, classified into an outcome and exit code, and may trigger a non-JSON active-PyTorch warning. Exceptions are rendered as plain text or a core error envelope and exit 1. `_run_uninstall` similarly resolves the target and calls `commands._uninstall.uninstall_run`; it renders an uninstall report/envelope and exits 1 if MCP sync failed.
- Install outcome classification maps hard failures (MCP action/sync error, blocking tool-torch repair, requested torch config error, or failed provisioning) to `failed`/1; unattended/EOF torch skips to `skipped`/2; dry-run to `unchanged`/0; upgrade to `updated`/0; otherwise `created`/0. Uninstall status maps MCP sync failure to `failed`, dry-run or no removals to `unchanged`, and removals to `removed`.
- `run_server_watch(fetch, port, interval, watch_mode)` constructs and runs the app. The injected `fetch` callable supplies job-list snapshots. Separate Textual worker groups perform job fetches, served-search admin requests, managed-log requests, status polling, and controls/log operations. Generation stamps reject stale job, search, managed-log, and status responses. Job responses update in-memory jobs, totals/summary, GPU/pressure/quiesce signals, estimates, selection, and rendered rows. Served-search responses request a bounded projection and render counts plus activity records. Managed logs request grouped sources and pass the response through managed-log validation. Status polling updates the service identity/status header.
- App-owned state includes the current job/search snapshots, refresh/error timestamps, estimates, pending controls, tombstones, focus/layout state, and service signals. Rendering writes into Textual tables, statics, and log views. Job/search cells are produced by the assigned pure formatting module; sizing and worker groups are sourced from the constants module. The exact network protocol, mutation transport, backend persistence, and lower-level install/uninstall effects are not defined in the inspected files.

## Boundaries and dependencies

- [src/vaultspec_rag/cli/\_install.py](../../../../src/vaultspec_rag/cli/_install.py) depends on `_app` for the Typer app/global target, `_render` for output, progress reporters, core unattended/envelope behavior, and command-layer `install_run`/`uninstall_run`. The CLI shows options and arguments passed across these boundaries, but the command implementations were not inspected.
- [src/vaultspec_rag/cli/\_jobs_tui.py](../../../../src/vaultspec_rag/cli/_jobs_tui.py) composes `JobControlMixin`, `HeaderRenderingMixin`, and `LogPanesMixin`; delegates focused logs to `JobsLogView`, grouped logs to `ManagedLogTankView`, palettes to `_jobs_tui_palette`, record parsing to `_jobs_tui_payload`, state to `_jobs_tui_state`, and status requests/rendering to `_jobs_tui_status`. It calls the HTTP admin transport for search activity and managed logs. These imported modules are uninspected, so their exact contracts are known here only from call sites and names/docstrings in the assigned file.
- [src/vaultspec_rag/cli/\_jobs_tui_cells.py](../../../../src/vaultspec_rag/cli/_jobs_tui_cells.py) calls shared value readers, search outcome constants, duration formatting, job presentation/query helpers, and palette styling; their implementations are uninspected.
- [src/vaultspec_rag/cli/\_jobs_tui_constants.py](../../../../src/vaultspec_rag/cli/_jobs_tui_constants.py) imports canonical job state enums and derives terminal states from them; enum definitions are uninspected.
- Documentation claims are limited to module/class/function docstrings and CLI option/help text in the assigned files. No standalone user documentation was read. No test source was read; therefore this report makes no claims about test expectations or passing tests.
