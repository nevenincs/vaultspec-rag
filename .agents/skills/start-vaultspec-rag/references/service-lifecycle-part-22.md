## Capability summary

This slice is an integration-test inventory, not implementation. It specifies behaviors the suite expects from store, indexing, search, watcher, and adapter surfaces. Test definitions and module docstrings do not establish that the implementation currently has those behaviors or that the tests pass.

- [src/vaultspec_rag/tests/integration/test_store_integration.py](../../../../src/vaultspec_rag/tests/integration/test_store_integration.py) covers VaultStore CRUD, identifiers, context-manager cleanup and same-process locking, dense and dense+sparse hybrid search, empty-store behavior, and deletion. Its served-code-collection cases specify pointer fallback/redirect behavior, generation naming and targeting, breadth-record ordering, failure preservation, and reclamation boundaries.
- [src/vaultspec_rag/tests/integration/test_targeted_reindex_integration.py](../../../../src/vaultspec_rag/tests/integration/test_targeted_reindex_integration.py) covers scoped edits and deletions for vault and code indexers, no-op paths outside the indexed root, the argument-less vault incremental path, and the expected full-rebuild escalation when code admission policy drifts.
- [src/vaultspec_rag/tests/integration/test_teardown_budget.py](../../../../src/vaultspec_rag/tests/integration/test_teardown_budget.py) asserts a platform-specific graceful-exit courtesy duration: zero on Windows, positive project constant on Linux/macOS.
- [src/vaultspec_rag/tests/integration/test_vault_chunking_integration.py](../../../../src/vaultspec_rag/tests/integration/test_vault_chunking_integration.py) specifies chunked vault storage and grouped search for a long document, including tail retrieval, full-body `get_by_id`/listing, deletion of all chunks, and removal of stale tail chunks after shrinking a document.
- [src/vaultspec_rag/tests/integration/test_vault_evidence_gate.py](../../../../src/vaultspec_rag/tests/integration/test_vault_evidence_gate.py) calculates rank, evidence-in-snippet, section-match, and span metrics over frozen-corpus observations; it expects every labeled case to have hits, rates to meet configured floors, and reported spans to match the snippet text and line extent.
- [src/vaultspec_rag/tests/integration/test_vault_payload_fields.py](../../../../src/vaultspec_rag/tests/integration/test_vault_payload_fields.py) expects search results to carry modern ADR status, map a legacy missing marker to empty status, expose related edges, and omit raw status markup from titles.
- [src/vaultspec_rag/tests/integration/test_vault_search_adapter_parity.py](../../../../src/vaultspec_rag/tests/integration/test_vault_search_adapter_parity.py) compares CLI and MCP results for one service-backed vault query, including ordering/content/location and near-equal scores, and checks the public result omits reranker internals.
- [src/vaultspec_rag/tests/integration/test_vault_true_incremental.py](../../../../src/vaultspec_rag/tests/integration/test_vault_true_incremental.py) guards the intended work cost for stamp-only, metadata-only, body, malformed-byte, and unscoped changes. It expects unchanged vectors/content identities for volatile stamps, payload-only tag refresh across every chunk, re-embedding for damaged chunk ranges/body edits, nonfatal handling of undecodable input, and whole-corpus convergence for an unscoped pass.
- [src/vaultspec_rag/tests/integration/test_watcher_config.py](../../../../src/vaultspec_rag/tests/integration/test_watcher_config.py) exercises `_ensure_watcher` with enabled/disabled environment configuration, startup-log propagation of debounce/cooldown settings, and cleanup of a watcher task that exits.
- [src/vaultspec_rag/tests/integration/test_watcher_content_admission.py](../../../../src/vaultspec_rag/tests/integration/test_watcher_content_admission.py) compares real added/modified watchfiles events with full and changed-path code admission under a source profile plus explicit document route.
- [src/vaultspec_rag/tests/integration/test_watcher_control.py](../../../../src/vaultspec_rag/tests/integration/test_watcher_control.py) exercises MCP admin start/stop/state/reconfigure calls, including queued restart reporting and the pull-only result when watching is disabled.

## Interfaces and data flow

The test callers build temporary roots and synthetic vault/source content, then pass them with embedding-model fixtures to `VaultStore`, `VaultIndexer`, `CodebaseIndexer`, or `VaultSearcher`. Assertions inspect `incremental_index` result counters (`added`, `updated`, `removed`, `payload_updated`, `total`), stored IDs, chunk ordinals/payloads/vectors, published content identities, and search result fields. These are tested call shapes and expected observations; the production contracts were not inspected.

Store-facing cases call `count`, `get_by_id`, `list_all_documents`, `hybrid_search(HybridSearchRequest)`, and code-collection methods. Pointer tests write/read a pointer via named helpers and check that collection operations can target a generation. The pointer's actual encoding and persistence rules are uninspected.

Search-facing cases call `VaultSearcher.search_vault`; observed result fields include ID, snippet, section, line bounds, status, related edges, and title. The adapter test seeds a publication, invokes MCP `search_vault` and the CLI JSON `search`, and compares their results. The evidence gate consumes frozen-corpus evidence observations and labels; their fixture/data producers are outside this slice.

Watcher cases drive `server._ensure_watcher`, `watch_and_reindex` configuration, MCP admin operations, `watchfiles.awatch`, and `is_code_change`. Inputs include environment settings, root paths, filesystem events, and a `RootContentPolicy`; outputs checked include task/stop registries, logs, admin response fields, and admitted path sets. The test sources refer to Qdrant and GPU-backed fixtures, but no runtime was launched here.
