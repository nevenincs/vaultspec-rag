## Capability summary

- [src/vaultspec_rag/cli/\_status_render.py](../../../../src/vaultspec_rag/cli/_status_render.py) implements the `server status` CLI command and all local status rendering in this slice. It gathers service identity/liveness signals, derives lifecycle state, probes health and bounded operational summaries, and renders concise text, verbose text, or `service.status` JSON. Its branches handle a local discovery record, an explicit port with or without that record, machine-global discovery when the local record is absent, and the stopped case. It also derives operator follow-up commands and summarizes jobs, storage, degradation, and latest job failure. No test modules were assigned or read.
- [src/vaultspec_rag/cli/\_textual_timer.py](../../../../src/vaultspec_rag/cli/_textual_timer.py) exports `install_cancel_safe_timer_sleep`; it replaces the `textual.timer` module's `sleep` global with an asyncio-based cancellation-safe sleep, subtracting a 0.0005-second overhead from positive delays. The source gives a Windows timer cancellation/shutdown rationale. Its external installer callers are outside the assigned ranges and were not inspected.

## Interfaces and data flow

- `service_status(requested_port=None, json_mode=False, verbose=False)` is registered on `server_root_app` as `server status`. It reads the local service status record, then routes to port-only inspection, machine discovery, or local-record signal evaluation. JSON and verbose modes are independent output choices. Nonzero lifecycle exit codes are raised through `typer.Exit`; JSON uses the `service.status` envelope. See [src/vaultspec_rag/cli/\_status_render.py:1190-1237,1238-1342](../../../../src/vaultspec_rag/cli/_status_render.py#L1190).
- Local-record evaluation extracts PID, port, start time, and token; checks PID liveness and process identity, probes loopback with the fast-connect timeout, reads heartbeat age, checks token identity when possible, and derives lifecycle from the signals. It removes the discovery record only for the confirmed dead-PID lifecycle when the unlink predicate allows it. [src/vaultspec_rag/cli/\_status_render.py:290-347](../../../../src/vaultspec_rag/cli/_status_render.py#L290).
- Without a local record, an explicit port goes through port-only inspection. Without either a record or explicit port, machine-service resolution and liveness compose a discovery verdict; a non-stopped verdict is rendered, while an unheld singleton produces the stopped contract without probing the default port. [src/vaultspec_rag/cli/\_status_render.py:1002-1083,1238-1295](../../../../src/vaultspec_rag/cli/_status_render.py#L1002).
- With an explicit port and a local record, the requested port is probed while PID identity and heartbeat are based on the record. A warming phase counts as starting only when the PID is alive and matches the service. The output records a differing status-file port as operational context. [src/vaultspec_rag/cli/\_status_render.py:1097-1187](../../../../src/vaultspec_rag/cli/_status_render.py#L1097).
- For a listening service, operational summary collection requests jobs with `limit: 5` and a storage survey with `limit: 1`; route exceptions and unavailable results become unavailable summaries. It derives active jobs by excluding queued entries, shapes counts and storage totals, adds degradation/failure information, and selects a next action. [src/vaultspec_rag/cli/\_status_render.py:613-748,750-868](../../../../src/vaultspec_rag/cli/_status_render.py#L613).
- Summary and detail renderers report lifecycle, health, degradation/remediation, busy/queue/processed job information, current jobs, service environment/features, uptime, storage counts/backlog, and next action as available. JSON payloads carry signal fields plus health and operational summaries when available. [src/vaultspec_rag/cli/\_status_render.py:350-387,581-611,871-999,1027-1083](../../../../src/vaultspec_rag/cli/_status_render.py#L350).
- `install_cancel_safe_timer_sleep()` assigns `_cancel_safe_sleep` into `textual.timer.__dict__["sleep"]`; `_cancel_safe_sleep(secs)` waits on `asyncio.sleep` only when `secs - 0.0005` is positive. [src/vaultspec_rag/cli/\_textual_timer.py:27-43](../../../../src/vaultspec_rag/cli/_textual_timer.py#L27).
