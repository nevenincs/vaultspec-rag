## Interfaces and data flow

The tests construct `PreprocessRule`, `PreprocessConfig`, and `PreprocessContext` values directly, or write TOML and call `load_preprocess_rules`; a rule carries a pattern, target, invocation form, extractor version, error policy, timeout, options, and sometimes batch flag (config: 30-32, 41-65; batch: 271-297; worker: 52-80). Config tests expect `match(path)` to select a rule. Approval/policy tests call `root_hook_state`, `resolve_index_policy`, and `resolve_policy_preprocess_context`, expecting an active approved policy to yield context and an unapproved/disabled policy not to do so (hook state: 92-120, 193-220).

For command-form execution, tests invoke `run_preprocessor` with a source, rule, output-byte cap, and project root. Entry-point tests use a `module:callable` reference and the same runner boundary. Batch tests call `run_preprocessor_batch` with a list of files and assert a path-keyed result; worker tests call `chunk_batch_files` or the production chunk path and observe per-file status/chunks. These tests expect hook JSON to validate into `PreprocOutput`, with either text or units, and unit anchors/locators carried into chunks (runner: 103-119, 149-176; entry: 111-142; batch: 309-389; worker: 83-117).

Cache tests supply a cache root and `PreprocessCacheIdentity`, then read/write output. Worker tests expect raw-source content hashes and cache hits to avoid a second extractor invocation; batch tests expect one spawn for a set of misses and no additional spawn for cached items (cache: 35-68; worker: 107-117, 162-175; batch: 475-525, 559-597). Store tests upsert `CodeChunk` objects and scroll payloads from a real local `VaultStore`; they expect source-oriented reconciliation and locator metadata fields to persist (store: 27-68, 71-147).

Process-related test interfaces include `process_lineage`, `kill_process_descendants`, `pid_matches_start_time`, `send_signal`, `wait_for_exit`, runner cleanup helper `_terminate_and_join`, and daemon interpreter/flag constants. The tests create subprocess fixtures and compare process identities and cleanup outcomes (descendant lifetime: 15-24, 31-43, 125-212; lineage: 19-80; daemon: 10-20, 25-90). These are test-visible interfaces only; their implementation and all external integrations remain uninspected.

## Boundaries and dependencies

The tests distinguish document-targeted extraction from code-targeted extraction and assert that the wrong worker rejects a rule; they also expect unmatched files to retain ordinary code chunking (worker: 120-184). Batch tests route matching code rules together and leave unmatched code to the normal path, and exercise serial and process-pool dispatch branches (batch: 601-700). The approval tests assert that a repository config alone grants no approval, that approval is scoped to root and exact config bytes, and that only active policy resolution supplies a worker context (hook state: 99-120, 122-176, 193-220). These remain expected boundaries, not independently verified runtime facts.

Directly named but uninspected production dependencies include:

- `indexer/_preprocess_config.py` (loader, rule/config/context types, hook-state APIs), `indexer/_preprocess_runner.py` (single/batch runners and cleanup), `indexer/_preprocess_entry.py` (entry-point CLI), `indexer/_preprocess_cache.py` (identity and cache operations), and `indexer/_preprocess_schema.py` (output models/validation).
- `indexer/_chunk_worker.py`, `indexer/_preprocess_glue.py`, `indexer/_resolved_policy.py`, `indexer/_preprocess_approval.py`, and `indexer/_content_policy.py` for worker conversion, policy-to-context resolution, approval, and target types.
- `_process_probe.py`, `cli/_process.py`, and `_win32.py` for process identity/lineage and daemon spawning; `store_runtime.py` and `_store_models.py` for payload persistence.
- Test helpers referenced but not inspected: `tests/_chunk_production.py`, `tests/_config_fixtures.py`, `tests/_preprocess_approval.py`, `tests/conftest.py`, `tests/_child_signal.py`, `tests/_indexer_fixtures.py`, and `tests/_import_probe.py`.
- `CodebaseIndexer` is imported from the package root in the batch tests; this slice does not identify its defining module. No caller inventory beyond the test sources can be established.
