## Capability summary

- [src/vaultspec_rag/tests/test_storage_restore_security.py](../../../../src/vaultspec_rag/tests/test_storage_restore_security.py): test expectations for archive restore's read boundary: reject linked archive roots and linked/nonregular members; open member descriptors without following links; and retain the opened file across path/root replacement. Cases branch for Windows and POSIX (24-130).
- [src/vaultspec_rag/tests/test_storage_safety.py](../../../../src/vaultspec_rag/tests/test_storage_safety.py): test expectations for resolved path containment and for temp-rooted orphan reclamation retaining archive, count recheck, liveness, and orphan-attribution gates under a shorter grace window. Assertions cover distinct pending/deferred/failed outcomes and reasons (49-73, 110-123, 126-173, 176-466).
- [src/vaultspec_rag/tests/test_storage_survey.py](../../../../src/vaultspec_rag/tests/test_storage_survey.py): test expectations for namespace grouping/status, root and collection association, aggregate point/footprint values, ordering, Windows extended-path alias handling, unreachable-root prefix generation, and temp-root classification. Its cycle case expects a Qdrant response timeout to hold one namespace while allowing a second namespace to reach an outcome (39-109, 112-192, 194-299).
- [src/vaultspec_rag/tests/test_store.py](../../../../src/vaultspec_rag/tests/test_store.py): broad unit coverage of `VaultStore` contracts: supported Python-version range vs packaging metadata; vault and code filter shapes/values; deterministic IDs; local warning suppression; per-collection locking and concurrent searches; server timeout, remote-mode lock/configuration, quantization setting; collection deletion/recreation; absent-collection count/read/search behavior; index audit reads and physical-ID matching; schema reconciliation for filtered reads/searches; server-mode per-root naming; bounded close; and reapplying indexes for all three collections (30-212, 214-513, 515-658, 660-798, 800-1175, 1177-1277, 1279-1442).
- [src/vaultspec_rag/tests/test_store_codebase.py](../../../../src/vaultspec_rag/tests/test_store_codebase.py): integration expectations for code collection setup, writes to a targeted generation collection without preparing the served collection, code chunk upsert/delete, write-policy timeout before mutation, and code/domain filter construction (25-229).
- [src/vaultspec_rag/tests/test_store_donor_reads.py](../../../../src/vaultspec_rag/tests/test_store_donor_reads.py): local donor-read expectations: exact dense/sparse/payload round trips, missing IDs/collections as misses, local support reporting, empty batches, pagination beyond 256 IDs, sparse-half degradation on malformed entries, and whole-point miss for unusable dense vectors (26-161, 164-241).
- [src/vaultspec_rag/tests/test_store_feedback.py](../../../../src/vaultspec_rag/tests/test_store_feedback.py): removed feedback anchors should not break vault/code dense or hybrid search; surviving feedback IDs remain in the resolved recommendation query (20-115).
- [src/vaultspec_rag/tests/test_store_schema.py](../../../../src/vaultspec_rag/tests/test_store_schema.py): storage-schema descriptor and compatibility expectations: pinned version/collection/index/payload facts, effective dense vector, JSON serialization, older-version compatibility and refusal cases, schema/index invariants, and fresh-import exclusion of Torch (25-311).

## Interfaces and data flow

These test sources call `VaultStore` with temporary roots for embedded storage and, in selected cases, a deliberately unavailable local URL for remote-client configuration checks. Inputs include `VaultChunk`/`CodeChunk`, vectors, filters, IDs, feedback requests, and store policies; asserted outputs include Qdrant filters, rows/counts/IDs, donor point maps, compatibility verdicts, and lifecycle state (for example [src/vaultspec_rag/tests/test_store.py](../../../../src/vaultspec_rag/tests/test_store.py) 110-211, 458-513, 543-629, 896-1175; [src/vaultspec_rag/tests/test_store_codebase.py](../../../../src/vaultspec_rag/tests/test_store_codebase.py) 86-197; [src/vaultspec_rag/tests/test_store_donor_reads.py](../../../../src/vaultspec_rag/tests/test_store_donor_reads.py) 74-161; [src/vaultspec_rag/tests/test_store_feedback.py](../../../../src/vaultspec_rag/tests/test_store_feedback.py) 20-115; [src/vaultspec_rag/tests/test_store_schema.py](../../../../src/vaultspec_rag/tests/test_store_schema.py) 25-264).

The storage safety tests use temporary filesystem roots, synthetic survey/client helpers, and archive fixtures to drive a maintenance-cycle-shaped input/output path. They expect survey classifications and reclaim decisions to lead to per-namespace outcomes, with snapshots/counts/deletes observed on the client stand-in ([src/vaultspec_rag/tests/test_storage_survey.py](../../../../src/vaultspec_rag/tests/test_storage_survey.py) 43-69, 258-299; [src/vaultspec_rag/tests/test_storage_safety.py](../../../../src/vaultspec_rag/tests/test_storage_safety.py) 186-466). The restore security cases construct archive files, links, directories, and FIFOs and call the imported restore readers directly ([src/vaultspec_rag/tests/test_storage_restore_security.py](../../../../src/vaultspec_rag/tests/test_storage_restore_security.py) 24-130). These are test-described flows; production implementation and actual test results were not inspected.

## Boundaries and dependencies

The assigned tests place Qdrant-facing store behavior in `VaultStore`, model payload/vector shapes in `_store_models` / `store_schema`, and search input shape in `HybridSearchRequest`, based on imports and call sites. Storage tests import manifest, survey, safety, reclamation, restore, and test-helper surfaces. These relationships are visible in the tests only; dependency internals and runtime ownership are uninspected. Some tests are marked unit, while [src/vaultspec_rag/tests/test_store_codebase.py](../../../../src/vaultspec_rag/tests/test_store_codebase.py) is marked integration; labels are not evidence that either suite passed (see each file's pytest marker, e.g. [src/vaultspec_rag/tests/test_store.py](../../../../src/vaultspec_rag/tests/test_store.py) 27, [src/vaultspec_rag/tests/test_store_codebase.py](../../../../src/vaultspec_rag/tests/test_store_codebase.py) 22).
