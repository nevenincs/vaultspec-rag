## Capability summary

This slice contains shared test infrastructure, not a suite of test cases. It supplies fixtures and assertions that let tests exercise real application paths against controlled filesystem state, loopback services, synthetic caches, child processes, or planted executables. Its docstrings describe intended uses and some historical failure context; they do not establish that any tests pass or that production behavior is correct.

- [src/vaultspec_rag/tests/\_jobs_tui_harness.py](../../../../src/vaultspec_rag/tests/_jobs_tui_harness.py) builds service-shaped job/search records, a concurrent loopback HTTP service, a real `ServerWatchApp` wired through `_try_http_admin`, and helpers that inspect rendered UI and wait for paints, worker settlement, and layout stability. Its service models mutable jobs, control refusals, delays/gates, health/version, GPU/pressure/quiesce fields, grouped logs, and served-search activity. It also reports lane failures and pending-control markers.
- [src/vaultspec_rag/tests/\_ledger_fixtures.py](../../../../src/vaultspec_rag/tests/_ledger_fixtures.py) offers direct test reads of the latest typed run generation and a publication-proof read token, including revision, reservation sequence, and open-receipt state.
- [src/vaultspec_rag/tests/\_loopback_model_hub.py](../../../../src/vaultspec_rag/tests/_loopback_model_hub.py) serves a small Hub-shaped repository snapshot over loopback HTTP, records requests/downloads/resumes, supports per-repository commits/files/sizes and weight-transfer responders, and builds the child environment for the hub client.
- [src/vaultspec_rag/tests/\_loopback_tls.py](../../../../src/vaultspec_rag/tests/_loopback_tls.py) starts real loopback HTTP/HTTPS responders and silent listeners, tracks GET/HEAD paths, creates trusted and unknown short-lived certificates, scopes trust/proxy environment variables, and provides response modes for truncation, reset, silence, trickle, endless/undelimited bodies, and redirects.
- [src/vaultspec_rag/tests/\_machine_lock_fixtures.py](../../../../src/vaultspec_rag/tests/_machine_lock_fixtures.py) wraps machine-lock lease APIs in a pid/result-oriented acquire helper and releases the current process's held lease after consulting the owning module's registry.
- [src/vaultspec_rag/tests/\_model_cache_seed.py](../../../../src/vaultspec_rag/tests/_model_cache_seed.py) creates Hub-layout cache snapshots, optionally using blob links; points Hub constants at a test cache; configures stand-in model IDs when the environment has not already named models; disables sparse vectors by default; and omits requested repositories.
- [src/vaultspec_rag/tests/\_model_fetch_child.py](../../../../src/vaultspec_rag/tests/_model_fetch_child.py) prepares a fresh interpreter aimed at the loopback Hub and a selected cache, invokes the shipped model fetch through its reporting sink, parses the child's final JSON line, and asserts the fetch process itself made no network connections.
- [src/vaultspec_rag/tests/\_model_setup.py](../../../../src/vaultspec_rag/tests/_model_setup.py) checks whether complete snapshots are already cached, runs real Hugging Face acquisition in a child when needed, bounds the whole operation, terminates/kills the worker and descendants on deadline, and retains bounded diagnostic output. It also exposes configured service model IDs, cache presence, and the private worker entry point.
- [src/vaultspec_rag/tests/\_operator_directory_guard.py](../../../../src/vaultspec_rag/tests/_operator_directory_guard.py) canonicalizes managed paths and installs a process-wide audit hook that refuses filesystem mutations under protected roots and selected `uv` launches targeting environments outside the system temporary directory. It exposes the configured roots and the path canonicalizer.
- [src/vaultspec_rag/tests/\_planted_programs.py](../../../../src/vaultspec_rag/tests/_planted_programs.py) establishes a controlled PATH/current-directory search state and plants marker-writing or native programs so tests can observe executable lookup and execution.
- [src/vaultspec_rag/tests/\_ports.py](../../../../src/vaultspec_rag/tests/_ports.py) supplies a best-effort free loopback port, a held refused port (with a macOS-specific fallback), and a bind probe that handles platform-specific socket reuse behavior.
- [src/vaultspec_rag/tests/\_preprocess_approval.py](../../../../src/vaultspec_rag/tests/_preprocess_approval.py) loads the current strict preprocess policy and writes its digest through the approval store with a fixed timestamp, modeling the CLI approval operation.
- [src/vaultspec_rag/tests/\_private_files.py](../../../../src/vaultspec_rag/tests/_private_files.py) asserts owner-only permissions and ownership on POSIX, or an owner-only DACL matching the current user SID on Windows.

## Interfaces and data flow

`_jobs_tui_harness._app` optionally installs fixture jobs on `_JobService`, then supplies a fetch closure calling `_try_http_admin("get_jobs", {"limit": limit}, service.port)` to `_HarnessWatchApp` (lines 603-625). The threaded handler records HTTP requests, answers `/health`, `/search-activity`, `/logs`, and job-list reads, and mutates held jobs for control requests (253-443). Payload builders snapshot mutable service state under a lock and emit service-shaped envelopes (474-588). UI helpers read the Textual compositor/table and app worker/lane state, polling at a bounded deadline (628-964). The helper imports real `ServerWatchApp`, `QuiesceSnapshot`/`QuiesceState`, and transport functions; their internal behavior is outside this slice.

Model acquisition has two distinct test paths. `_model_cache_seed` writes snapshots into a caller-owned cache and patches `huggingface_hub.constants.HF_HUB_CACHE` for in-process tests (57-155). `_model_fetch_child` instead starts a new interpreter because the Hub endpoint/cache are read at import time; it configures the child environment, captures stdout/stderr, and decodes a JSON outcome (43-202). `_loopback_model_hub` serves Hub metadata, trees, and file transfers through `_loopback_tls.plain_loopback_sources` (130-243). `_loopback_tls.trusted_loopback_sources` mints certificate/key files below the caller-provided directory and temporarily sets `SSL_CERT_FILE` and proxy exclusions through `managed_env` (381-469). `_model_setup.ensure_model_snapshots` checks completeness first and starts its own worker only for missing snapshots (62-123, 286-298, 337-396).

`_ledger_fixtures` takes a `RunLedger` and typed content/key values and returns a typed generation or `ProofReadToken`; database connections and proof-row helpers come from imported ledger modules (32-73). `_machine_lock_fixtures` acquires/releases through imported lease functions and reads `_held_leases` under `_lease_guard` (19-36). `_preprocess_approval` sends the loaded policy digest to `approve_policy` (16-27). `_private_files.assert_private_file` inspects the path's mode/uid or Windows security descriptor (18-52). The directory guard receives roots from an external caller, fixes its guarded and scratch-root sets on first installation, and raises from audit events for refused operations (575-621). Exact callers are not present in the assigned files.

## Boundaries and dependencies

The helpers intentionally retain selected production paths: the TUI and admin transport, Hub client/cache layout, model-fetch command, ledger APIs, machine-lock lease registry, preprocess loader/store, and platform ACL checks. The fake surfaces are local fixtures (loopback service/Hub, synthetic records/cache, planted programs) and do not replace those production paths where the module docstrings say the test is exercising them. This is an implementation observation about the supplied helper code; whether a caller actually uses each path is unknown.

Uninspected imports include [src/vaultspec_rag/cli/\_jobs_tui.py](../../../../src/vaultspec_rag/cli/_jobs_tui.py) (`ServerWatchApp`, `_SPINNER_INTERVAL`), `serviceclient/_transport.py`, `service_quiesce.py`, `_http_stubs.py`, [conftest.py](../../../../conftest.py), [src/vaultspec_rag/tests/\_ports.py](../../../../src/vaultspec_rag/tests/_ports.py) callers, indexer ledger/publication modules, `_machine_lock.py`, config/settings/types, `_model_cache.py`, `_model_pins.py`, `_child_signal.py`, and `_win32.py`. Their contracts and side effects cannot be inferred beyond the names/signatures and comments in this slice. No assigned file contains a test execution result.
