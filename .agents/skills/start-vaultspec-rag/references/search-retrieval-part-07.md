## Capability summary

- **Implementation — [src/vaultspec_rag/server/\_search_availability.py](../../../../src/vaultspec_rag/server/_search_availability.py):** Defines immutable search classification/context records and maps one concrete source's canonical publication facts plus before/after job snapshots into a source readiness fact and HTTP-style response classification. Job matches require a nonterminal known job state, index operation, exact concrete source, normalized project root, and known mode; after-snapshot matches precede before-snapshot matches, duplicate IDs are removed, and exposed evidence is capped. It recognizes a narrowly shaped Qdrant collection-missing 404 and converts it into an unavailable classification. A typed `StorageGeometryError` can replace readiness with a nonretryable rebuild-required refusal. (Evidence: lines 48-134, 136-162, 201-296, 298-419, 479-594.)
- **Implementation — [src/vaultspec_rag/server/\_search_evidence.py](../../../../src/vaultspec_rag/server/_search_evidence.py):** Provides detached bounded JSON capture and materialization for search evidence, with byte budgets (request 64 KiB, response 128 KiB, ledger 4 MiB), depth/item/text limits, and recorded truncation paths. It declares the accepted search-input field set. No caller of `capture_json_evidence` is present in the assigned files, so actual capture sites are unknown. (Lines 12-41, 45-59, 62-147.)
- **Implementation — [src/vaultspec_rag/server/\_search_readiness.py](../../../../src/vaultspec_rag/server/_search_readiness.py):** Owns in-memory publication/controller revisions and bounded async observers for one service lifetime. Keys bind a canonical root to one concrete index source. The registry is event-loop-owned, lock-protected, wakes matching waiters on publication/controller changes, limits observers to 1,024, and can seed a missing publication snapshot from validated durable publication evidence at revision zero. `published_at_least` waits for each unique target revision and optional generation until a monotonic deadline. (Lines 29-42, 92-164, 167-245, 246-420.)
- **Implementation — [src/vaultspec_rag/server/\_search_route_availability.py](../../../../src/vaultspec_rag/server/_search_route_availability.py):** Adapts search measurements to the canonical index-state block and constructs pre-retrieval facts. It finishes integrity evidence, gets readiness snapshots, runs retrieval through the search limiter/thread bridge, classifies collection disappearance and storage-geometry refusal, adds stable empty-result diagnostics, rejects empty results when absence is not authoritative, and applies aggregate readiness/failure facts to combined searches. The module imports `SearchRequest`, `ServiceRegistry`, route snapshot logic, and combined outcomes only as types or local imports; their definitions/call sites are outside this slice. (Lines 53-158, 160-238, 241-357, 360-457, 459-554.)
- **Implementation — [src/vaultspec_rag/server/\_state.py](../../../../src/vaultspec_rag/server/_state.py):** Holds server process globals and helpers: a cached registry alias, watcher maps/lock, lifecycle timestamps and flags, HTTP/launch state, process-local search-activity ledger, immutable storage-survey snapshot publication/access, lock-guarded counters/gauges, and Prometheus rendering. GPU/accelerator memory is queried during render and omitted when unavailable; limiter stats are also rendered. [src/vaultspec_rag/server/\_utils.py](../../../../src/vaultspec_rag/server/_utils.py) consumes its query limit and sensitive path patterns. (Lines 1-25, 36-60, 72-145, 148-197, 200-269, 272-376.)
- **Implementation — [src/vaultspec_rag/server/\_stdio_lifetime.py](../../../../src/vaultspec_rag/server/_stdio_lifetime.py):** Installs a daemon-thread watchdog for the stdio shim. Windows uses an explicit parent and/or a stdin pipe-creator client as precise anchors, otherwise discovers ancestor handles with a grace period; after all anchors disappear it rediscovers and requires repeated unanchored rounds before hard-exiting. POSIX polls the original parent and optional explicit parent. The environment escape hatch disables the watchdog; installation failures are logged and return `None`. Structured stderr events report exit, unanchored, and disarmed states. No installer caller is in this slice. (Lines 1-40, 60-118, 121-143, 146-218, 220-461, 463-584, 586-701.)
- **Implementation — [src/vaultspec_rag/server/\_utils.py](../../../../src/vaultspec_rag/server/_utils.py):** Supplies shared server request helpers: a reusable HTTP 400 missing-root response, typed missing-root error, registry-full and local-store-lock error bodies, `.vault` validation, default-root selection, sensitive-path detection, top-k clamping, query truncation, and project-root resolution. HTTP mode requires an explicit root; stdio mode can use the named root or current directory. (Lines 46-80, 109-149, 152-204, 207-233.)

## Interfaces and data flow

- **Per-source search classification:** `SearchAvailabilityRequestFacts` captures the pre-retrieval job snapshot, root, concrete source, request ID, port, optional readiness snapshot/target, and wait policy. `to_context` adds the after-snapshot and index state, derives integrity verification from a consistent verdict matching the published generation, and packages canonical evidence. `run_search_with_availability` runs the supplied sync retrieval callable using the search limiter. Normal results are later eligible for `classify_search_result`; a typed geometry refusal becomes 409/rebuild-required, while a recognized collection disappearance becomes a 503 classification. Other unexpected Qdrant responses are re-raised. ([src/vaultspec_rag/server/\_search_route_availability.py:70-157, 411-457](../../../../src/vaultspec_rag/server/_search_route_availability.py#L70); [src/vaultspec_rag/server/\_search_availability.py:113-162, 505-594](../../../../src/vaultspec_rag/server/_search_availability.py#L113).)
- **Empty and combined search responses:** `classify_search_result` reads the result's `index_state`, takes a canonical after-job snapshot, classifies it, attaches the requested wait policy, and ensures an empty 200 is returned only when absence authority is authoritative. Authorized empty responses receive `empty` diagnostics; 200 responses receive a readiness block. `apply_combined_search_outcome` serializes per-domain status/readiness and removes results for total failure or empty partial/non-authoritative outcomes. ([src/vaultspec_rag/server/\_search_route_availability.py:289-332, 498-554](../../../../src/vaultspec_rag/server/_search_route_availability.py#L289).)
- **Publication readiness:** `ReadinessRevisionRegistry.start/close` bind and end its owner-loop lifetime. `snapshot(root, source)` reads the registry cache or attempts to restore generation evidence from publication state; `notify_controller` advances desired state without claiming publication, while `publish_next` advances served publication state. Both wake observers for the changed source. `published_at_least` is the async wait interface. `readiness_snapshot(registry, root, source)` is the local adapter; an unstarted or closed service registry yields `None`. ([src/vaultspec_rag/server/\_search_readiness.py:173-245, 246-350](../../../../src/vaultspec_rag/server/_search_readiness.py#L173); [src/vaultspec_rag/server/\_search_route_availability.py:335-353](../../../../src/vaultspec_rag/server/_search_route_availability.py#L335).)
- **Search evidence capture:** `capture_json_evidence(value, maximum_bytes=...)` returns `JsonEvidence(encoded, truncated_paths)`; `materialize()` parses the detached JSON value. Limits are applied while cloning, and a final oversize check falls back to `null` with root truncation. The explicit field set identifies search input fields, but does not itself validate requests in this file. ([src/vaultspec_rag/server/\_search_evidence.py:12-59, 62-147](../../../../src/vaultspec_rag/server/_search_evidence.py#L12).)
- **Service state and metrics:** Module-level mutable state is intentionally split between in-place containers and reassigned values per its module comment. Survey snapshots are handed over as immutable tuples; metric updates are lock-guarded and rendering snapshots the counters/gauges under lock before querying accelerator and limiter metrics. ([src/vaultspec_rag/server/\_state.py:12-24, 74-108, 143-197, 212-269, 312-376](../../../../src/vaultspec_rag/server/_state.py#L12).)
- **Root and request helpers:** `_resolve_root` uses explicit roots when supplied, rejects blank roots, and requires `.vault`; missing roots fall back through `_default_root`, which refuses HTTP mode. Query truncation uses `_MAX_QUERY_LEN`; sensitive-path matching normalizes slashes, rejects dot-prefixed components other than `.` and `..`, and case-folds the basename for configured glob checks. ([src/vaultspec_rag/server/\_utils.py:109-149, 152-184, 187-233](../../../../src/vaultspec_rag/server/_utils.py#L109).)
- **Watchdog lifecycle:** `install_stdio_lifetime_watchdog(parent_pid, grace_seconds, client_pid)` returns a started daemon thread or `None`. On Windows, stdin client PID resolution is main-thread-only and intended before the transport reader starts; the watchdog thread then watches held handles or rediscovers ancestors without querying stdin. On POSIX, it polls every 15 seconds for parent change or explicit-parent death. Its exit event is followed by `os._exit(0)`. ([src/vaultspec_rag/server/\_stdio_lifetime.py:284-341, 492-584, 596-615, 618-701](../../../../src/vaultspec_rag/server/_stdio_lifetime.py#L284).)
