## Capability summary

### Implementation

- [src/vaultspec_rag/server/\_routes_reindex.py](../../../../src/vaultspec_rag/server/_routes_reindex.py) implements handlers for reindex, audit, and clean operations. Reindex validates source/mode authority, expands combined requests into independent vault/code/document domains, validates and creates jobs, returns per-domain outcomes, and reports code preprocess admission details. Audit accepts only audit-verification authority and invokes source auditing through a registry store lease. Clean calls the package clean operation independently for each selected domain and returns per-domain cleared/error information. (lines 18-25, 95-162, 164-216, 218-331, 334-471)
- [src/vaultspec_rag/server/\_routes_runtime.py](../../../../src/vaultspec_rag/server/_routes_runtime.py) implements an authenticated runtime-observation projection: it gathers observations for the request port and adds model, quiesce, and limiter-pool observations before returning JSON. (lines 1, 18-35)
- [src/vaultspec_rag/server/\_routes_search.py](../../../../src/vaultspec_rag/server/_routes_search.py) implements authenticated search request parsing, validation, dispatch, response shaping, availability/freshness handling, timing/logging, and route-owned activity finalization. It dispatches vault, code, document, and combined searches through public API request types; captures integrity and index-state information; serializes hits; and maps canonical failures to HTTP statuses. It supports an opt-in bounded freshness wait, handles backend and quiesce failures, and cancels work when the HTTP request disconnects. (lines 1-7, 481-693, 696-929, 937-1108, 1123-1264, 1267-1328, 1331-1461)
- [src/vaultspec_rag/server/\_routes_storage.py](../../../../src/vaultspec_rag/server/_routes_storage.py) implements a token-gated, server-mode storage survey. It validates status/root/fresh/limit query parameters, serves a daemon-held snapshot when allowed, otherwise performs a read-only survey and publishes the result. The response can filter and bound namespaces and includes totals, point-count verification, generation reports, and root-prefix information. (lines 1-15, 47-163, 166-263, 265-349, 351-419)
- [src/vaultspec_rag/server/\_runtime.py](../../../../src/vaultspec_rag/server/_runtime.py) defines the immutable per-application route runtime (token, registry, port, optional monitor), validates required token/port values, and installs/resolves that runtime through Starlette app state. Request resolution goes through the request app. (lines 1-20, 23-38, 40-74)
- [src/vaultspec_rag/server/\_search_activity.py](../../../../src/vaultspec_rag/server/_search_activity.py) provides the bounded in-process search activity ledger used by the search handler. It records queued, active, and terminal searches; applies active/queue/recent limits and admission waits; supports filtered/sorted snapshots; and bounds captured request/response evidence and query text. Tickets let route code complete or terminalize an admission even when cancellation races with admission. (lines 1-20, 40-44, 78-109, 127-164, 210-250, 251-442, 444-560, 565-614, 616-777)

## Interfaces and data flow

- Route handlers accept Starlette Request and return JSONResponse. Reindex, clean, and audit authenticate first, parse request JSON, use source/root/authority fields, then call job, audit, or clean services. Combined reindex and clean produce independent domain outcomes. ([src/vaultspec_rag/server/\_routes_reindex.py:218-331,334-471](../../../../src/vaultspec_rag/server/_routes_reindex.py#L218))
- Search flow: authenticate; start a ledger ticket; parse a JSON object; record provisional inputs; normalize type, freshness policy, query, top_k, and root; record normalized inputs; optionally wait on publication targets; dispatch using the request-scoped registry; classify/shape the outcome; and always finalize the ticket. The result carries request ID, serialized results, summary/index state, and timing; combined search adds a fan-out outcome. ([src/vaultspec_rag/server/\_routes_search.py:688-693,696-929,937-1108,1123-1264,1361-1461](../../../../src/vaultspec_rag/server/_routes_search.py#L688))
- Activity flow: SearchActivityStart admits a ticket into the bounded ledger; update_request replaces provisional request facts; finish records terminal status, timings, waits, errors, and bounded response evidence. snapshot returns a filtered, sorted projection with counts and pagination fields. ([src/vaultspec_rag/server/\_search_activity.py:210-250,282-442,444-560](../../../../src/vaultspec_rag/server/_search_activity.py#L210))
- Storage flow: query parameters become a bounded \_SurveyPayloadRequest; a cached snapshot is used unless fresh/cold, otherwise a client is opened, surveys are gathered and closed, the result is published, and filtered payload JSON is returned. ([src/vaultspec_rag/server/\_routes_storage.py:52-94,97-163,265-349,351-419](../../../../src/vaultspec_rag/server/_routes_storage.py#L52))
- Request-scoped runtime is installed on the app and resolved from request.app; its registry and port are consumed by search, runtime-observation, and reindex/audit paths. ([src/vaultspec_rag/server/\_runtime.py:23-74](../../../../src/vaultspec_rag/server/_runtime.py#L23); [src/vaultspec_rag/server/\_routes_search.py:1401-1406](../../../../src/vaultspec_rag/server/_routes_search.py#L1401); [src/vaultspec_rag/server/\_routes_runtime.py:18-35](../../../../src/vaultspec_rag/server/_routes_runtime.py#L18); [src/vaultspec_rag/server/\_routes_reindex.py:270-280,384-394](../../../../src/vaultspec_rag/server/_routes_reindex.py#L270))
