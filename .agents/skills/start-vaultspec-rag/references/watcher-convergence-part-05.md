## Capability summary

- [src/vaultspec_rag/tests/test_watcher_transition_logging.py](../../../../src/vaultspec_rag/tests/test_watcher_transition_logging.py): unit-level contract for logging managed watcher-job transitions. It builds a `WatcherConvergenceSlot`, snapshot, and transition context, calls `_log_managed_transition`, then inspects rendered event names and log levels. It expects QUEUED, RUNNING, PAUSING, and CANCELLING to avoid `reindex_failed` and ERROR; FAILED and INTERRUPTED to emit `reindex_failed` at ERROR with a non-null error field; SUPERSEDED to emit one `reindex_superseded` event at INFO; and the failure outcome set to equal exactly the failed terminal states. The module docstring describes the motivating regression as progress states falling through to a failure log.
- [src/vaultspec_rag/tests/test_watcher_unit.py](../../../../src/vaultspec_rag/tests/test_watcher_unit.py): classification expectations for `is_code_change` and `is_vault_change`. Fixtures supply a project root, vault, and resolved conventional source policy. The tests cover root and nested control filenames, vault Markdown, Markdown and unrelated files outside the vault, outside-root rejection, conventional source extensions, case-normalized suffixes, and explicit `target="code"` preprocessing admitting PDF when a resolved policy is supplied. Its module docstring says parser capability and other policy settings do not widen conventional code admission, and explicitly excludes the production watcher’s policy-refresh and failure-retention lifecycle from coverage.
- [src/vaultspec_rag/tests/test_weighted_code_resume.py](../../../../src/vaultspec_rag/tests/test_weighted_code_resume.py): unit-marked resume scenarios using a deterministic encoder boundary with real `VaultStore`, generation lifecycle/checkpoint, ledger, producer/consumer pipeline, weighted queue, and code segments. It creates eight one-chunk segments across two files; persists selected segments, restarts the generation, and sends the complete stream through the weighted consumer. Expectations cover fresh, prefix, cross-file, gapped, end-first, and fully committed cases; no re-encoding of confirmed chunks; retention of unit identity and stored points; file digest convergence after gaps close; and no invented publication. Additional cases expect end markers not to certify files with gaps, malformed raw streams and over-bound committed units to be rejected before resume selection, and changed digest/ordinal/end-marker/chunk identity not to match a committed unit.
- [src/vaultspec_rag/tests/test_workspace_link_boundary.py](../../../../src/vaultspec_rag/tests/test_workspace_link_boundary.py): unit-marked tests using a real temporary filesystem and link fixtures to exercise install, upgrade, dry-run, uninstall, builtin seeding, bootstrap, direct removal steps, and CLI JSON envelopes around linked directories. They compare an outside tree’s bytes and workspace contents around refused operations, and include an ordinary unlinked install/uninstall case. Cases cover `.vault`, `.vaultspec`, nested `rules`/`skills`, and `.vault/data`; the exact platform link kinds come from the uninspected `LINK_KINDS` fixture. The test module documents its intended mutation checks, but those comments do not establish test execution results.

## Interfaces and data flow

- Watcher transition tests pass job state and a `WatcherJobSnapshot` plus `_TransitionLogContext` into `_log_managed_transition`; they capture Python log records and parse the rendered `event=...` fields. The expected output is an event name and severity, with populated error text for failed outcomes.
- Watcher classification tests pass filesystem paths, root/vault paths, and either `None` or a `ResolvedIndexPolicy` snapshot into classification functions and assert booleans. The explicit PDF case writes a preprocessing TOML fixture, resolves policy, then compares the snapshot and no-snapshot results.
- Weighted resume setup resolves policy and run configuration, constructs segments and file results, opens a generation against `VaultStore`, and confirms units by writing chunks before recording confirmation in the checkpoint. A restart finishes the attempt as failed, forgets the open generation, and opens a new checkpoint. A full file-result stream is enqueued; assertions inspect encoder inputs, consumer totals, checkpoint/ledger state, store IDs, indexed path digests, and ingestion-complete state.
- Workspace tests call install/uninstall/seed/bootstrap APIs with `Path` targets and options, or invoke CLI commands through `CliRunner`. The test-observed outputs are reports, exceptions, CLI exit status/JSON, and filesystem trees. Their safety expectation is refusal or warning before outside-tree mutation.

## Boundaries and dependencies

- The four files are all under `src/vaultspec_rag/tests`; each is marked `pytest.mark.unit`. Their imports identify the production boundaries under test, but no imported implementation was inspected. The weighted resume and workspace tests explicitly set up real storage/filesystem pieces while substituting or disabling selected external/model/network work in fixtures.
- Watcher logging depends on job models, watcher runtime/retry types, a snapshot helper, and `ServiceRegistry`. Classification depends on watcher policy and indexer content/preprocess/resolved-policy definitions. Only test expectations about these collaborators are known here.
- Weighted resume depends on chunk production/slicing, consumer pipeline, generation lifecycle/checkpoint and run ledger, config, encoder protocol, progress/run-control helpers, and `VaultStore`. Implementations and persistence details beyond what the test setup directly calls are uninspected.
- Workspace link behavior depends on `_plain_directory`, install/uninstall commands and report models, workspace target resolution, builtin seed/list behavior, CLI dispatch, and `_directory_links` helpers. `LINK_KINDS` membership and link-detection implementation are unknown from this slice.
