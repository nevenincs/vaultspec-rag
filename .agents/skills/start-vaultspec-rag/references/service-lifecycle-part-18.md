## Capability summary

- **Implementation — pytest registration:** [src/vaultspec_rag/tests/integration/\_\_init\_\_.py](../../../../src/vaultspec_rag/tests/integration/__init__.py) enables assertion rewriting and registers `_install_helpers`, `_index_job_control_support`, and `_jobs_registry_support` as pytest plugins (1-17).
- **Implementation — Windows console interrupt helper:** [src/vaultspec_rag/tests/integration/\_console_interrupt.py](../../../../src/vaultspec_rag/tests/integration/_console_interrupt.py) clears inherited Ctrl+C deafness, prepares hidden child startup info, and starts a separate process to send a real console control event to the target process console (64-102). The separate sender and console constraints are module documentation (1-20).
- **Implementation — frozen corpus evidence:** [src/vaultspec_rag/tests/integration/\_frozen_corpus_evidence.py](../../../../src/vaultspec_rag/tests/integration/_frozen_corpus_evidence.py) declares fixed query depths and gold grade, loads query/evidence records, computes per-query ranking reports, materializes the frozen corpus, indexes it with injected model/reranker, records intent searches, persona rankings and evidence spans, and closes the store (46-60, 78-100, 180-237, 240-307, 310-377). Its docstring says this consolidates evidence from one expensive GPU indexing experiment and avoids private model copies (1-18); that rationale is a documentation claim, not a runtime result.
- **Implementation — shared service and index helpers:** [src/vaultspec_rag/tests/integration/\_helpers.py](../../../../src/vaultspec_rag/tests/integration/_helpers.py) provides service reindex-and-publication waiting, managed Qdrant provisioning/serving and binary mirroring, content-policy/indexer builders, minimal project creation, ephemeral port selection, bounded health/process polling, and isolated environment setup/restore (62-254, 257-301, 329-451, 454-542). Its service context snapshots environment values, resets config on entry/exit, and can mirror a host provisioned binary into the isolated status directory (454-542).
- **Implementation — index-control support:** [src/vaultspec_rag/tests/integration/\_index_job_control_support.py](../../../../src/vaultspec_rag/tests/integration/_index_job_control_support.py) supplies real corpus builders and timing/control helpers, predicates for observable production states, pause/resume/cancel routines, resource-release assertions, write-gate cancellation coordination, fixtures for a real registry/manager, stored-code verification, and controlled reporter/control implementations (131-203, 206-383, 386-522, 524-676). The module docstring describes exercising production streaming/indexing with real files, local Qdrant, and the session GPU model (1-7); this is a stated test design, not evidence that a run passed.
- **Implementation — install acceptance support:** [src/vaultspec_rag/tests/integration/\_install_helpers.py](../../../../src/vaultspec_rag/tests/integration/_install_helpers.py) centralizes workspace inventories and byte snapshots, MCP/TOML readers, link/junction signatures, install report extraction, Core MCP seeding, and fresh/installed workspace fixtures. Its `_install` wrapper calls `install_run` with MCP enabled and torch configuration/provisioning disabled by default (58-68, 71-95, 98-159, 162-184). The promised install/uninstall coverage in its docstring is a documentation claim (1-7).
- **Implementation — in-flight registry support:** [src/vaultspec_rag/tests/integration/\_jobs_registry_support.py](../../../../src/vaultspec_rag/tests/integration/_jobs_registry_support.py) resets the registry and stops watchers, waits for a specific service job to reach a terminal phase, and asserts runtime/resource fields for job snapshots (38-52, 54-95, 97-147). Its docstring describes direct registry/ring-buffer/concurrency checks and real GPU reindex-tool coverage (1-13); the assigned file contains support and expectations, not proof those tests passed.
- **Implementation — foreign machine-lock holder:** [src/vaultspec_rag/tests/integration/\_machine_lock_holder.py](../../../../src/vaultspec_rag/tests/integration/_machine_lock_holder.py) launches a launcher process plus a distinct lock-owning interpreter, exposes their PIDs, and coordinates cleanup through test-owned files while requiring the OS lock probe to confirm release (38-83, 86-160, 163-238, 240-334). The module docstring describes the PID-split and cleanup rationale (1-7).
- **Implementation — served drift control:** [src/vaultspec_rag/tests/integration/\_served_drift_control.py](../../../../src/vaultspec_rag/tests/integration/_served_drift_control.py) installs root-scoped monkeypatches in a child process. It forces a failure after a durable source commit, waits for the parent to change that committed file, then permits the original pipeline to retry and signals coordination through files (22-91). Its docstring describes this as barriers for one failed served indexing attempt and retry (1).
- **Implementation — service job-control E2E support:** [src/vaultspec_rag/tests/integration/\_service_job_control_e2e_support.py](../../../../src/vaultspec_rag/tests/integration/_service_job_control_e2e_support.py) provides the shared async fixture for a real model, registry and job manager with watcher/job teardown, plus an assertion that attempts released task, worker, admission, lease, writer-lock and pipeline resources (43-138, 140-158). The division of shared runtime from scenario-specific helpers is documented at 1-11.
- **Implementation — managed job route support:** [src/vaultspec_rag/tests/integration/\_service_jobs_route_helpers.py](../../../../src/vaultspec_rag/tests/integration/_service_jobs_route_helpers.py) builds a Starlette app using the real route factory and a seeded job, creates a paused production manager job, and provides assertions for exact-ID lookup, paused filtering, conflicts, cancellation replay, retry, and deletion (34-109, 112-266).
- **Implementation — managed jobs surface support:** [src/vaultspec_rag/tests/integration/\_service_jobs_support.py](../../../../src/vaultspec_rag/tests/integration/_service_jobs_support.py) includes CLI-output parsers, a local HTTP payload server, a canonical Uvicorn server fixture, job fixtures/waiting, and assertions for MCP job envelopes and CLI initiator attribution (63-207, 209-322, 325-416). The three-layer MCP/CLI/Starlette description is a documentation claim at 1-15; the local HTTP payload helper is implemented at 100-133.

## Interfaces and data flow

- Pytest discovers the three plugins named in [src/vaultspec_rag/tests/integration/\_\_init\_\_.py](../../../../src/vaultspec_rag/tests/integration/__init__.py); their exported fixtures/helpers become shared test support. Other assigned modules expose ordinary helpers/fixtures through names in their `__all__` declarations or direct imports; their consuming test modules are outside this slice ([src/vaultspec_rag/tests/integration/\_\_init\_\_.py](../../../../src/vaultspec_rag/tests/integration/__init__.py): 3-17; [src/vaultspec_rag/tests/integration/\_helpers.py](../../../../src/vaultspec_rag/tests/integration/_helpers.py): 44-59; [src/vaultspec_rag/tests/integration/\_service_jobs_route_helpers.py](../../../../src/vaultspec_rag/tests/integration/_service_jobs_route_helpers.py): 15-23; [src/vaultspec_rag/tests/integration/\_service_jobs_support.py](../../../../src/vaultspec_rag/tests/integration/_service_jobs_support.py): 46-57).
- Frozen-corpus evidence flows from TOML query/case records and predeclared scenario expectations into a materialized vault, an indexed store and a `VaultSearcher`; output is a typed record with corpus/index counts, ranked query results and metrics, testimonials, and evidence hits including independently read span text ([src/vaultspec_rag/tests/integration/\_frozen_corpus_evidence.py](../../../../src/vaultspec_rag/tests/integration/_frozen_corpus_evidence.py): 62-67, 103-168, 180-237, 256-307, 310-377). Model and reranker are inputs; acquisition and their construction are outside this module's documented boundary (310-323).
- Shared service helpers build isolated environment/config state and Qdrant service processes, then restore environment and stop the server; health and process helpers poll bounded deadlines ([src/vaultspec_rag/tests/integration/\_helpers.py](../../../../src/vaultspec_rag/tests/integration/_helpers.py): 120-163, 329-451, 454-542). Inputs include temporary roots, optional environment overrides and optional captured binary/manifest paths.
- Index-control scenarios coordinate against actual manager snapshots and store state. They request controls at observed publication or embedding/write boundaries, then inspect manager state, resource ownership, published IDs, stored payloads and the run-ledger sidecar ([src/vaultspec_rag/tests/integration/\_index_job_control_support.py](../../../../src/vaultspec_rag/tests/integration/_index_job_control_support.py): 152-167, 206-293, 303-383, 386-521, 586-628).
- Machine-lock cleanup uses holder/launcher PIDs and per-test stop files; release is accepted only after `probe_machine_lock()` reports the lock free ([src/vaultspec_rag/tests/integration/\_machine_lock_holder.py](../../../../src/vaultspec_rag/tests/integration/_machine_lock_holder.py): 96-160, 163-199, 202-238, 272-334).
- Route support sends HTTP requests through `TestClient` to the app created from `create_http_app`; it checks status codes and response JSON for route behavior ([src/vaultspec_rag/tests/integration/\_service_jobs_route_helpers.py](../../../../src/vaultspec_rag/tests/integration/_service_jobs_route_helpers.py): 34-75, 112-266). The broader service support reaches jobs through the admin client or CLI and checks job identity and snapshot payloads ([src/vaultspec_rag/tests/integration/\_service_jobs_support.py](../../../../src/vaultspec_rag/tests/integration/_service_jobs_support.py): 288-322, 325-416).
- [src/vaultspec_rag/tests/integration/\_served_drift_control.py](../../../../src/vaultspec_rag/tests/integration/_served_drift_control.py) coordinates child and parent using a control directory (`installed`, `committed.json`, `admitted`, `changed`, `restored`); it scopes behavior to the selected root by checking the generation root identity or indexer root ([src/vaultspec_rag/tests/integration/\_served_drift_control.py](../../../../src/vaultspec_rag/tests/integration/_served_drift_control.py): 22-91).
