## Capability summary

The slice is a unit-test surface for storage survey, reconciliation, namespace reclamation, archive retention, and restore. It exercises imported APIs with temporary files, synthetic surveys, scripted Qdrant-shaped clients, and a real in-memory Qdrant client. The module-level unit marks and docstrings describe test intent; they do not establish runtime behavior.

- [src/vaultspec_rag/tests/test_storage_ops.py](../../../../src/vaultspec_rag/tests/test_storage_ops.py): groups checks for persisted orphan and activity clocks; archive retention and byte-cap eviction; process-local survey snapshot and route cache behavior; ephemeral namespace eligibility; debris reporting/pruning; reclaimed-byte accounting; collection geometry ownership and reconciliation planning; generation point counting; and maintenance-cycle gates, job liveness, and delete/archive outcomes. It also exports fake/scripted clients and helpers for sibling suites (__all__, lines 54-72).
- [src/vaultspec_rag/tests/test_storage_ops_reclaim.py](../../../../src/vaultspec_rag/tests/test_storage_ops_reclaim.py): covers provenance carry during migration, reclaim decisions and tier windows, convergence measurement, reconciliation selection, and maintenance-cycle isolation under snapshot/count/delete/listing failures. It tests partial-drop reporting and manifest narrowing, with companion tests for server refusals and programming errors.
- [src/vaultspec_rag/tests/test_storage_restore.py](../../../../src/vaultspec_rag/tests/test_storage_restore.py): checks archive parsing/refusals, restore preview and refusal behavior, publication-proof and collection-identity carry, retry archives after partial deletion, and handling of named versus stray snapshot artifacts.

## Interfaces and data flow

- The visible test calls pass NamespaceSurvey values and persisted prefix-to-time maps into evaluate_reclaim; they expect decisions to expose action, reason, and tier. Test helpers construct survey roots, point counts, collection names, footprint sizes, and optional model maps. Temp-root classification and the activity-clock path are exercised separately from vanished-root orphan clocks.
- The tests construct MaintenanceCycleRequest with a client, time, policy, storage/snapshot/archive directories, and an active-prefix callback, then inspect cycle surveys, generations, decisions, archived snapshots, and deleted collections. Stand-ins can change counts between survey, recount, and snapshot, or raise at selected calls. A separate test admits an index job through the job manager and queries active prefixes.
- Manifest-facing calls include record_root, load_manifest, update_orphan_stamps, update_activity_stamps, and identity-recording helpers. Assertions treat orphan time, last-indexed time, observed point count, collection inventory, and per-collection identity as persisted state.
- Archive-facing tests call archive_prefix/sweep_archive or build archive fixtures, then inspect snapshot files and JSON manifests. Restore-facing tests pass an archive directory, destination root, local-mode flag, and dry-run flag; they inspect status, reason, destination prefix, remapped names, and resulting manifest/proof state.
- Survey route tests call snapshot publication/read helpers and route helpers with status, limit, and freshness arguments. A subprocess test expects an initially cold slot to be empty and the route to defer; other cases expect cache shaping or a fresh walked result to replace the slot.
- These are observed call shapes and asserted data flows from the tests. The implementations of the imported APIs and their actual external behavior remain uninspected.

## Boundaries and dependencies

- The tests isolate machine-global manifest state with an isolated_status_dir fixture and use tmp_path; the fixture implementation was not read. The archive helper is imported by the restore tests (actual module path: tests/\_storage_archive.py) and was not read.
- Qdrant interaction is represented by test-local fakes for deterministic cycle/reconciliation cases, and by QdrantClient(":memory:") for restore refusals. The test module docstrings say live-daemon coverage exists at the integration tier; no integration files or live server were inspected or run.
- Production symbols are imported from storage_reclamation, storage_archive, storage_manifest, storage_survey_ops, storage_reconciliation, storage_restore, storage_migration, storage_identity, storage_survey, server.\_state, server.\_routes_storage, \_publication_state, and the job modules. Their implementations and behavior behind imports are unverified.
- No test command was run. Assertions below describe test expectations, not passing results.
