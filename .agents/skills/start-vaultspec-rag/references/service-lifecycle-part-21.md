## Capability summary

- [src/vaultspec_rag/tests/integration/test_service_logs.py](../../../../src/vaultspec_rag/tests/integration/test_service_logs.py) tests authenticated `/logs` and `/logs/json` behavior against an isolated production HTTP app and real files. It covers grouped service/Qdrant logs, source selection, tail limits, filters, empty groups, malformed-source errors, line-limit clamping, bounded-byte truncation parity with the offline CLI, query construction for the admin transport, oversized response rejection, structured error preservation, and rollover caused by real Uvicorn access traffic.
- [src/vaultspec_rag/tests/integration/test_service_metrics.py](../../../../src/vaultspec_rag/tests/integration/test_service_metrics.py) covers counter/gauge operations and Prometheus exposition, reset/unknown-name behavior, registered maintenance metrics, counter increments from real search/reindex tool paths using an isolated daemon, and `/metrics` bearer/query-token gating and text output.
- [src/vaultspec_rag/tests/integration/test_service_search_diagnostics_http.py](../../../../src/vaultspec_rag/tests/integration/test_service_search_diagnostics_http.py) tests the direct HTTP search surface. Its scenario matrix checks production route shaping after injecting classified outcomes; a separate admission-capacity case expects a 503. Live-service cases cover canonical versus aliased/malformed source types, empty code-index diagnostics, and invalid project roots.
- [src/vaultspec_rag/tests/integration/test_service_search_diagnostics_mcp.py](../../../../src/vaultspec_rag/tests/integration/test_service_search_diagnostics_mcp.py) supplies reusable MCP concurrency helpers and tests official MCP search tools against a stub HTTP service. It checks source-to-tool mapping, exactly one canonical HTTP request, and preservation of structured readiness, result, and failure fields alongside MCP text content.
- [src/vaultspec_rag/tests/integration/test_service_search_diagnostics_rebuild.py](../../../../src/vaultspec_rag/tests/integration/test_service_search_diagnostics_rebuild.py) checks a rebuild-required response across HTTP, CLI, and MCP; then drives a real clean rebuild with concurrent matching HTTP/client/MCP searches plus unrelated-root and unrelated-source controls. It checks the unavailable response and matching job evidence during the rebuild, authoritative empty results after publication, and a nonempty search while a persisted matching rebuild remains paused after restart.
- [src/vaultspec_rag/tests/integration/test_service_search_diagnostics_reporting.py](../../../../src/vaultspec_rag/tests/integration/test_service_search_diagnostics_reporting.py) covers CLI JSON and human-readable readiness rendering for shared scenarios, live missing-index reports, request-ID correlation with structured search logs, and a short client timeout represented only as a transport failure.
- [src/vaultspec_rag/tests/integration/test_service_search_request_validation.py](../../../../src/vaultspec_rag/tests/integration/test_service_search_request_validation.py) sends authenticated requests to a live service and distinguishes empty/whitespace-query rejection from later root-resolution rejection; a filter-only query is expected to pass the empty-query guard.
- [src/vaultspec_rag/tests/integration/test_service_state.py](../../../../src/vaultspec_rag/tests/integration/test_service_state.py) checks the consolidated `get_service_state` MCP response shape and sections, plus CLI registration boundaries: `server info` and `server health` are absent while `server status` is present.
- [src/vaultspec_rag/tests/integration/test_service_storage_migration.py](../../../../src/vaultspec_rag/tests/integration/test_service_storage_migration.py) uses real local and server Qdrant clients to check document collection migration/idempotence, a fresh-process CLI migration and resource closure, orphan pruning, document survey counts, and debris classification.

## Interfaces and data flow

- The logs fixture sets an isolated status directory, constructs `create_http_app` with a known runtime token and registry, and drives it through Starlette `TestClient`; tests also invoke the CLI with `CliRunner`, `_try_http_admin`, a local HTTP server, and a spawned Uvicorn process. Assertions inspect HTTP status/body/headers, CLI output, transport error dictionaries, and on-disk log generations (logs: 68-129, 133-215, 316-444, 447-629).
- Metrics flow from direct `server.incr`/`observe` calls or MCP search/reindex tools to `server.render_prometheus` and authenticated `GET /metrics`. The real-tool checks read a baseline, wait for reindex completion, perform search/reindex, then compare exact counter values on a module-owned daemon (metrics: 64-122, 131-264, 271-346).
- Search diagnostics use shared scenario objects and canonical service envelopes in route, CLI, and MCP tests. The HTTP route cases post JSON with a bearer token; the MCP cases launch a stdio server with port/root/status-directory environment values, initialize a session, call an official tool, and observe the stub service's captured HTTP payload (HTTP: 47-104, 133-218; MCP: 60-126, 170-220, 221-420).
- The real rebuild probe creates a synthetic vault, submits a clean rebuild, then releases five synchronized probes: matching raw HTTP, unrelated-root HTTP, unrelated-source HTTP, shared-client search, and MCP search. After the job completes it checks a later search; a second service context checks a persisted paused job and an expected document result (rebuild: 301-398, 628-820, 822-985).
- Reporting and validation tests use raw HTTP or shared client helpers and correlate returned request IDs with service log lines. State tests call the admin MCP client and use `CliRunner`. Migration tests create and inspect real Qdrant collections, with a subprocess for the CLI migration path (reporting: 139-272; validation: 28-89; state: 115-164; migration: 37-72, 74-172, 175-238).
