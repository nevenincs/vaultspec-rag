## Capability summary

- [src/vaultspec_rag/cli/\_jobs_tui_controls.py](../../../../src/vaultspec_rag/cli/_jobs_tui_controls.py) implements `JobControlMixin`: pause, resume, stop, retry, and delete actions. It checks that the selected job and capability allow an action, marks the row pending, sends controls through worker-thread transport calls, and reconciles the result into pending state, a header outcome, row rendering, and a jobs refresh. State changes carry the job revision and request graceful mode. The assigned range ends at `_settle`'s notification; behavior after line 225, if present, is outside coverage.
- [src/vaultspec_rag/cli/\_jobs_tui_header.py](../../../../src/vaultspec_rag/cli/_jobs_tui_header.py) implements `HeaderRenderingMixin`, which reads app-held jobs, summary, search activity, machine signals, version and refresh state to render grouped job-state and health pills, index condition, GPU/pressure/quiesce indicators, page counts, age/errors, selected-job degradation evidence, and quiesce details. It progressively removes labels and splits groups as width narrows. The range ends at a section marker for selection/log methods; those methods are not covered.
- [src/vaultspec_rag/cli/\_jobs_tui_log.py](../../../../src/vaultspec_rag/cli/_jobs_tui_log.py) parses service log lines into `LogEntry` records for application, HTTP access, Qdrant, or raw dialects. It removes terminal escape/control bytes and bounds ordinary entries, retains sanitized source text, flags error levels and 5xx records, recognizes polling routes, renders entries with optional full values, and provides `RetainedLog` plus `JobsLogView` for repainting, polling filtering, scrolling, and next/previous error navigation.
- [src/vaultspec_rag/cli/\_jobs_tui_logs.py](../../../../src/vaultspec_rag/cli/_jobs_tui_logs.py) (assigned lines 1-225) implements the focused-log fetch/apply path and title/body helpers for focused and managed panes. Focused requests are keyed by selected job or served request, fetched on a worker, checked against subject and generation, validated, then shown with metadata and stale/error/filter indicators. The range stops before the `actions` section, so later log actions and any managed-log fetch path are not covered.
- [src/vaultspec_rag/cli/\_jobs_tui_managed_logs.py](../../../../src/vaultspec_rag/cli/_jobs_tui_managed_logs.py) supplies `ManagedLogTankView`, which holds service/Qdrant groups as separate raw records, sanitizes terminal controls without per-record length truncation, and displays server cap/truncation metadata and optional markers.
- [src/vaultspec_rag/cli/\_jobs_tui_palette.py](../../../../src/vaultspec_rag/cli/_jobs_tui_palette.py) is the interface palette source: it defines light/dark color scales, semantic tones, pill fills, style composition, and Textual themes. Importing it also installs the cancel-safe timer sleep hook.
- [src/vaultspec_rag/cli/\_jobs_tui_payload.py](../../../../src/vaultspec_rag/cli/_jobs_tui_payload.py) turns selected service replies into displayable values or error text. It validates served-search summary/list/record invariants, supports query redaction, narrows records by state, accepts only the canonical quiesce key set, recognizes gone-job replies, and maps action names to capability flags.
- [src/vaultspec_rag/cli/\_jobs_tui_state.py](../../../../src/vaultspec_rag/cli/_jobs_tui_state.py) groups in-memory state for the search, focused-log, managed-log, service-version, machine-signal, and layout lanes. `LaneStamps` issues increasing generations and rejects responses no newer than the latest applied generation.
- [src/vaultspec_rag/cli/\_jobs_tui_status.py](../../../../src/vaultspec_rag/cli/_jobs_tui_status.py) defines the optional `ServiceStatusHeader`/`SeatPool` model, gathers service facts in `fetch_service_status`, parses limiter gauges, and renders a width-adaptive `ServiceStatusBar` with persistent detail rows. It reads health, storage survey, project slots, metrics, and watcher state; unreported values remain absent. The module docstring documents a worker-thread mounting/calling pattern, but no host caller was inspected.

## Interfaces and data flow

- Control flow: `action_job_*` reaches `_actionable`, which checks context/selection/capability before dispatch. `_request_state` adds an expected revision; `_request_send` handles retry/delete. A worker calls a `_try_http_*` transport helper, then returns through `call_from_thread`; `_after_control` settles accepted, refused, gone, or unreachable outcomes and refreshes the rows/jobs ([src/vaultspec_rag/cli/\_jobs_tui_controls.py:59-129,130-150,152-225](../../../../src/vaultspec_rag/cli/_jobs_tui_controls.py#L59)).
- Header flow: the mixin reads lane values owned by its host and builds `rich.text.Text`; it does not fetch or assign the declared lanes in the covered code. Counts use service summary when available and fall back to the loaded page; unbucketed counts become an `other` bucket. Search activity appears in server watch mode ([src/vaultspec_rag/cli/\_jobs_tui_header.py:60-120,201-246,364-461](../../../../src/vaultspec_rag/cli/_jobs_tui_header.py#L60)).
- Focused-log flow: selected identity determines `("job", id)` or `("request", id)` and the request filter (`job_id` or `contains`). `fetch_logs` calls the admin transport on a thread, and `_apply_logs` rejects a changed subject or stale generation, validates the result, updates state and `JobsLogView`, then refreshes title/bindings ([src/vaultspec_rag/cli/\_jobs_tui_logs.py:55-90,92-139](../../../../src/vaultspec_rag/cli/_jobs_tui_logs.py#L55)).
- Log entry flow: `parse_log_line` sanitizes and classifies one line; `LogEntry` retains the sanitized full line plus parsed fields. `JobsLogView.show_lines` stores parsed entries, and `_paint` renders visible entries, inserts a counted marker for hidden polling runs, and records error line offsets for navigation ([src/vaultspec_rag/cli/\_jobs_tui_log.py:151-209,309-330,460-490,554-580,633-722](../../../../src/vaultspec_rag/cli/_jobs_tui_log.py#L151)).
- Managed-log display flow: callers pass validated `ManagedLogGroup` sequences to `show_groups`; the tank retains the sequence and paints each producer under its own heading with metadata, marker, and safe record text ([src/vaultspec_rag/cli/\_jobs_tui_managed_logs.py:34-72,75-98](../../../../src/vaultspec_rag/cli/_jobs_tui_managed_logs.py#L34)). The covered log-pane range has title/clear support but not the managed-log fetch caller ([src/vaultspec_rag/cli/\_jobs_tui_logs.py:192-225](../../../../src/vaultspec_rag/cli/_jobs_tui_logs.py#L192)).
- Service-status flow: `fetch_service_status(port)` performs blocking reads and returns a value object. It probes health, then uses remaining deadline for storage, projects, metrics, and watcher reads. `/metrics` is read directly through the loopback opener with the service token; gauges become ordered seat pools. `render_status_header` admits whole segments by available cell width, and `ServiceStatusBar` retains and repaints the latest result on mount/resize ([src/vaultspec_rag/cli/\_jobs_tui_status.py:219-318,320-399,507-591](../../../../src/vaultspec_rag/cli/_jobs_tui_status.py#L219)).
- The covered modules keep UI state in objects/dataclasses and retained widget records. No persistent local storage is implemented in these ranges; data is received from the service and retained for rendering. The palette resolves styles at render time ([src/vaultspec_rag/cli/\_jobs_tui_log.py:493-551,684-712](../../../../src/vaultspec_rag/cli/_jobs_tui_log.py#L493); [src/vaultspec_rag/cli/\_jobs_tui_state.py:30-132](../../../../src/vaultspec_rag/cli/_jobs_tui_state.py#L30); [src/vaultspec_rag/cli/\_jobs_tui_palette.py:235-322](../../../../src/vaultspec_rag/cli/_jobs_tui_palette.py#L235)).
