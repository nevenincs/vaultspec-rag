## Capability summary

- [src/vaultspec_rag/tests/test_monitor_browser_render.py](../../../../src/vaultspec_rag/tests/test_monitor_browser_render.py): launches the installed monitor browser against the test HTTP service and checks rendered dashboard, indexing, query, log, and repository views at desktop and narrow sizes. Expectations include responsive overflow behavior; navigation/theme controls; chart and listener resource retention; visibility-gated polling; scoped job/query logs and updates; retained data during service-discovery failures and paused polling; safe rendering of log text; nested query evidence and sorting; repository validation; terminal-job deletion; detail/expansion persistence; and pageable lists/logs. The fixture records diagnostic body/evidence artifacts and closes the browser process (lines 69–139, 292–760).
- [src/vaultspec_rag/tests/test_monitor_inventory.py](../../../../src/vaultspec_rag/tests/test_monitor_inventory.py): seeds managed storage and repository manifests, then checks direct inventory reads and stopped-service bridge responses. Expectations cover persisted repository attribution, orphan/unknown namespace classification, worktree expansion, absent live-only measurements, bounded filtering, unchanged status/storage files, unavailable-storage errors, and query validation (lines 29–195).
- [src/vaultspec_rag/tests/test_monitor_logs.py](../../../../src/vaultspec_rag/tests/test_monitor_logs.py): serves the actual read routes and drives the terminal `ServerWatchApp`. It checks that selected job/request logs refresh without changing selection, global logs combine service and Qdrant records, server truncation is represented, reader scroll position is retained, and stale or incorrectly scoped log payloads do not replace current evidence (lines 46–91, 115–295).
- [src/vaultspec_rag/tests/test_monitor_process.py](../../../../src/vaultspec_rag/tests/test_monitor_process.py): exercises the Python supervisor and CLI around process admission, port allocation, readiness-link validation, startup rollback, PID-incarnation checks, orphan cleanup, and status-lock timeouts. These are test expectations; the supervisor implementation was not inspected (lines 76–439).
- [src/vaultspec_rag/tests/test_monitor_process_integration.py](../../../../src/vaultspec_rag/tests/test_monitor_process_integration.py): requires a compiled monitor binary and checks its lifecycle, port selection after a custom backend port, discovery publication/heartbeat, capability-protected health and lifecycle endpoints, loopback binding/request confinement, and cleanup after shutdown or parent death (lines 51–263). The file marks itself as unit-tier despite its compiled-binary prerequisite (lines 46–59).
- [src/vaultspec_rag/tests/test_monitor_projection.py](../../../../src/vaultspec_rag/tests/test_monitor_projection.py): checks rendered terminal projections of queued/recent search activity, separate daemon-health and indexing conditions, TypeSafe status labels/details, timing units/counts, and invalid queued-record identity handling (lines 32–188).
- [src/vaultspec_rag/tests/test_monitor_runtime.py](../../../../src/vaultspec_rag/tests/test_monitor_runtime.py): checks a token-protected runtime-observation route for RAM, disk, model, CPU, pool, quiesce, and TCP-peer fields; null GPU measurements when unavailable; bounded JSON search evidence; retained/redacted search activity; actual validation response capture; and ledger-wide evidence eviction (lines 39–245).
- [src/vaultspec_rag/tests/test_no_mcp_server_conflation.py](../../../../src/vaultspec_rag/tests/test_no_mcp_server_conflation.py): implements a source-text guard over Python files in `cli/` and `server/` against the case-insensitive phrase “mcp server” (lines 45–77).
- [src/vaultspec_rag/tests/test_no_reexports.py](../../../../src/vaultspec_rag/tests/test_no_reexports.py): implements AST guards against non-facade pass-through exports, resurrection/import of named legacy seams, and imports from moved owners where the requested binding is not owner-defined. The facade ratchet and legacy-seam set are empty/currently fixed in this source (lines 39–64, 107–127, 194–241, 244–328).
- [src/vaultspec_rag/tests/test_no_unconsumed_definitions.py](../../../../src/vaultspec_rag/tests/test_no_unconsumed_definitions.py): implements an AST/reference scan of selected production roots and guards against definitions consumed only by tests or nowhere, while checking a documented extension-point entry and an exact removal backlog (lines 43–73, 76–193, 196–237).

## Interfaces and data flow

- Test HTTP setup: `monitor_http(isolated_status_dir)` reserves a loopback port, writes discovery status, constructs `create_http_app` with a `ServerRouteRuntime`, and starts uvicorn with lifespan disabled; it yields the port and managed status directory ([src/vaultspec_rag/tests/test_monitor_logs.py:46–91](../../../../src/vaultspec_rag/tests/test_monitor_logs.py#L46)). Browser-render tests launch Node with [dev/monitor-browser.mjs](../../../../dev/monitor-browser.mjs), the installed browser executable and a temporary profile; the helper exchanges newline-delimited JSON commands and answers over process pipes ([src/vaultspec_rag/tests/test_monitor_browser_render.py:34–67, 69–139](../../../../src/vaultspec_rag/tests/test_monitor_browser_render.py#L34)).
- Observed HTTP paths include `/repositories?limit=100`, `/storage/survey`, `/runtime-observations`, `/search-activity?request_id=…`, `/search`, `/api/monitor/jobs`, and monitor `/health` and `/lifecycle`. Tests use bearer tokens for protected calls and assert status/body fields; those assertions describe expected contracts only ([src/vaultspec_rag/tests/test_monitor_inventory.py:84–120, 175–195](../../../../src/vaultspec_rag/tests/test_monitor_inventory.py#L84); [src/vaultspec_rag/tests/test_monitor_runtime.py:56–80, 145–164, 193–203](../../../../src/vaultspec_rag/tests/test_monitor_runtime.py#L56); [src/vaultspec_rag/tests/test_monitor_process_integration.py:145–166, 195–209, 245–255](../../../../src/vaultspec_rag/tests/test_monitor_process_integration.py#L145)).
- Test state includes managed `service.json` and `monitor.json` records, managed log and Qdrant log files, collection directories and payload bytes, Git worktree registration files, process identity timestamps, and an in-memory search-activity ledger. Tests mutate or snapshot these states to assert attribution, cleanup, retention, and no-write expectations ([src/vaultspec_rag/tests/test_monitor_inventory.py:50–64, 84–124, 131–147](../../../../src/vaultspec_rag/tests/test_monitor_inventory.py#L50); [src/vaultspec_rag/tests/test_monitor_process.py:176–235, 249–307](../../../../src/vaultspec_rag/tests/test_monitor_process.py#L176); [src/vaultspec_rag/tests/test_monitor_browser_render.py:422–435, 485–519](../../../../src/vaultspec_rag/tests/test_monitor_browser_render.py#L422)).
- Rendered terminal/browser callers include `ServerWatchApp`, the browser helper, and CLI `server stop --json`; browser hash routes cover dashboard, indexing, queries, logs and repositories ([src/vaultspec_rag/tests/test_monitor_browser_render.py:149–151, 414–520](../../../../src/vaultspec_rag/tests/test_monitor_browser_render.py#L149); [src/vaultspec_rag/tests/test_monitor_logs.py:135–171](../../../../src/vaultspec_rag/tests/test_monitor_logs.py#L135); [src/vaultspec_rag/tests/test_monitor_process.py:199–204](../../../../src/vaultspec_rag/tests/test_monitor_process.py#L199); [src/vaultspec_rag/tests/test_monitor_process_integration.py:250-254](../../../../src/vaultspec_rag/tests/test_monitor_process_integration.py#L250)).
