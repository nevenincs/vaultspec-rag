## Capability summary

### Implementation

- [src/vaultspec_rag/cli/\_service_storage.py](../../../../src/vaultspec_rag/cli/_service_storage.py) registers the `server storage` survey, delete, prune, reconcile, migrate, and restore CLI commands. It adapts CLI options to storage-operation functions, renders text or JSON outcomes, and centralizes managed-server mode, transport, refusal, and JSON confirmation handling. Survey tries the running service first and falls back to a direct managed-server read. Root-scoped operations resolve a root to its namespace prefix. Delete and prune default to preview behavior; prune can separately request debris cleanup. Reconcile can wait for bounded geometry convergence. Migrate maps collection names between local and server stores and attempts provenance/manifest bookkeeping after successful applied copies. Restore previews or applies an archive into a destination root. The underlying storage operations are imported but not inspected.
- [src/vaultspec_rag/cli/\_service_watcher.py](../../../../src/vaultspec_rag/cli/_service_watcher.py) registers `server updates` status, start, stop, and timing commands. It uses service admin requests, supports text and JSON results, normalizes project paths for scoped calls, and gives status/remediation wording when a request is not achieved. It also formats configured debounce and repeat-update delays.
- [src/vaultspec_rag/cli/\_status.py](../../../../src/vaultspec_rag/cli/_status.py) registers the root `status` command. It prefers a service-reported root state and health, otherwise reads local index status and probes this installation. It renders service, compute, preprocessing, watcher, index-count, storage, and degradation information; `--verbose` adds interpreter, support-profile, and generation details. JSON mode exports structured status fields. A local-store lock has a specific error path, with a second service check before reporting it.
- [src/vaultspec_rag/cli/\_status_labels.py](../../../../src/vaultspec_rag/cli/_status_labels.py) contains deterministic health/status labels, time and job formatting, and conversion of service or index degradation signals into operator-facing findings and remedies. The assigned callers in [src/vaultspec_rag/cli/\_status.py](../../../../src/vaultspec_rag/cli/_status.py) use `render_degradation` and `reranker_label`; other consumers are not established by this slice. It has no console output or service probing, as its module docstring states.

## Interfaces and data flow

- **Storage command boundary:** Typer-decorated functions receive CLI arguments/options and emit human text or `_emit_json` envelopes. `_require_yes_for_json` rejects JSON without `--yes` for apply-capable operations; `preview = dry_run or not yes` makes omitted confirmation a preview. `_run_storage_op` checks server mode, opens/closes a managed-server client, distinguishes archive-integrity and server-refusal errors from transport failures, and emits JSON errors before exiting. A direct service survey uses `get_storage_survey`; if unavailable or unsuccessful, it calls `gather_survey` through the managed Qdrant client. (75-160, 319-442, 445-515)
- **Survey/delete/prune/reconcile:** Survey accepts `--root`, `--fresh`, `--orphaned`, and `--unknown`; root paths are resolved before dispatch, and direct survey filtering uses `root_collection_prefix`. Delete accepts exactly one prefix or `--root`, with `--allow-unknown`, `--dry-run`, `--yes`, and `--json`. A missing namespace is normalized to `already_absent`; an applied removal best-effort evicts the root from a running service. Prune invokes orphan cleanup and optionally debris cleanup; its renderer reports unknown namespaces left untouched. Reconcile invokes `reconcile_collections`, translating a positive limit to a cap and nonpositive limit to `_UNCAPPED_RECONCILE`, with configured budget and `--wait/--no-wait`; its result distinguishes preview, applied, issued, and already-converged outcomes. (198-303, 399-442, 520-765, 771-905)
- **Migration/restore:** Migration accepts root, target backend (`server`/`local`), preview/apply, and JSON options. It derives a name map, validates the configured local store path with `resolve_within`, opens local and server clients, invokes `migrate_collections`, closes both clients, then attempts identity carry and manifest re-keying for applied data. Restore accepts an archive directory and required destination root, invokes `restore_archive` through `_run_storage_op`, maps known refusal reasons to operator text, and exits nonzero for refusals or a non-dry-run preview. (911-949, 951-1129, 1135-1282)
- **Watcher command boundary:** Status accepts port, JSON, root/source/state filters, and a limit capped by the option at 256; it calls `get_watcher_state`. Project start/stop use `start_watcher`/`stop_watcher`; timing sends supplied debounce/cooldown fields to `reconfigure_watcher`. These calls resolve the default port when absent and resolve project paths. Missing service responses and admin errors produce structured failures or human remediation. (126-165, 243-342, 344-394, 397-531)
- **Status command boundary:** `handle_status` takes `CLIState.target`, requests `get_service_state` plus health when a service answers, else reads `vaultspec_rag.get_status(target)` and builds a local view. The local view probes the daemon interpreter at metadata depth normally and verify depth with `--verbose`, reads root hook configuration, and records hardware facts. The text renderer computes actionable index commands from missing counts; the JSON renderer includes service, installation, feature, storage, count, target, backend-capability, and optional generation/degradation/support-profile data. (39-88, 311-399, 432-515, 517-585)
- **Label/degradation flow:** `_status_labels` accepts health/index payload dictionaries and returns labels or `DegradedFinding` values. `degradation_findings` pairs reported degradation entries with structured evidence and commands; `degradation_lines` formats findings; `render_degradation` composes both. Assigned direct calls from [src/vaultspec_rag/cli/\_status.py](../../../../src/vaultspec_rag/cli/_status.py) are the degradation renderer and reranker label. (37-53, 87-143, 341-405, 634-885; [src/vaultspec_rag/cli/\_status.py](../../../../src/vaultspec_rag/cli/_status.py) 33, 347)
