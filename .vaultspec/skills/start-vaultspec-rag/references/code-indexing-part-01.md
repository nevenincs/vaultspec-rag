## Capability summary

- [src/vaultspec_rag/indexer/__init__.py](../../../../src/vaultspec_rag/indexer/__init__.py) re-exports the package-facing `ASTChunker`, `TextSplitter`, `LANGUAGE_MAP`, three indexer classes, `IndexResult`, and `prepare_document`. Its module docstring describes the package as scanning vault documents, extracting metadata, generating embeddings, and storing them in Qdrant with full and incremental indexing; that is a package-level documentation claim, not behavior verified in this slice.
- [src/vaultspec_rag/indexer/\_ast_chunker.py](../../../../src/vaultspec_rag/indexer/_ast_chunker.py) implements `ASTChunker`, a tree-sitter-based chunker. It parses UTF-8 source bytes, emits six-field records `(text, line_start, line_end, node_type, function_name, class_name)`, uses configured grammar node sets to identify structure, recurses into oversized nodes, splits oversized leaves by character budget, groups small siblings, and merges adjacent chunks below half the configured budget. It extracts identifiers through AST `name` fields and carries class/function context into chunks. Grammar node sets and the language table are imported from `_chunking.py`, whose implementation was not inspected.
- [src/vaultspec_rag/indexer/\_checkpoint_common.py](../../../../src/vaultspec_rag/indexer/_checkpoint_common.py) centralizes run-level checkpoint and publication decisions shared by source indexers. It fingerprints configuration, opens or resumes compatible run generations, classifies interrupted runs, brackets store mutations with receipt callbacks, recovers pending publication work, records confirmed deletions and unresolved processing outcomes, and advances proof/metadata/generation finalization. Unit construction and source-specific checkpoint details are left to subclasses, according to its module/class documentation.
- [src/vaultspec_rag/indexer/\_chunk_producer.py](../../../../src/vaultspec_rag/indexer/_chunk_producer.py) implements CPU code-file chunk production and submission through bounded work windows and a weighted producer/consumer queue. `CodeChunkProducer` handles serial and spawned worker paths, batch preprocessing groups, ordinary file results, cooperative cancellation checks, back-pressure callbacks, and early detection of consumer failure. It submits `FileChunkResult` values through caller-provided callbacks; the module says preprocessing/support accounting and the GPU consumer live in the callback/caller path, not in the producers.

## Interfaces and data flow

- Package surface: [src/vaultspec_rag/indexer/__init__.py](../../../../src/vaultspec_rag/indexer/__init__.py) imports the named classes/helpers and lists them in `__all__` (lines 18-37). Their implementation and external callers are outside this slice.
- AST chunking: `ASTChunker(chunk_size=1500).chunk(source, grammar)` gets a parser for the grammar, parses encoded source, collects AST-aligned records, and merges small results ( [src/vaultspec_rag/indexer/\_ast_chunker.py:44-90](../../../../src/vaultspec_rag/indexer/_ast_chunker.py#L44)). The method's annotated/docstring output contains text, one-based line bounds, optional node type, function name, and class name. It uses `_TOP_LEVEL_NODES`, `_CLASS_LIKE_NODES`, `_FUNCTION_LIKE_NODES`, and `_CONTAINER_NODES` imported from `_chunking.py` ([src/vaultspec_rag/indexer/\_ast_chunker.py:13-18, 72-90, 222-255](../../../../src/vaultspec_rag/indexer/_ast_chunker.py#L13)).
- Checkpoint inputs include a structural `RunOpenRequest` (root paths, resolved/run policies, operation, clean flag, model/dimension/config/backend identities, and authority), a ledger, and cooperative `RunControl` ([src/vaultspec_rag/indexer/\_checkpoint_common.py:138-176, 668-707](../../../../src/vaultspec_rag/indexer/_checkpoint_common.py#L138)). `open_generation` derives a `RunSignature`, starts a compatible generation, opens a publication receipt when applicable, and constructs the subclass. `configuration_fingerprint` hashes sorted compact JSON of dataclass fields ([src/vaultspec_rag/indexer/\_checkpoint_common.py:178-187, 668-707](../../../../src/vaultspec_rag/indexer/_checkpoint_common.py#L178)).
- Publication recovery accepts a root/source/store, run control, and `replay_source` callback. It locates the ledger, validates storage against retained proof, and settles committed or pending receipts. Uncertain/partial publication may delete affected point IDs and replay affected source paths inside a recovery-read context; complete confirmed evidence can instead be committed from the ledger ([src/vaultspec_rag/indexer/\_checkpoint_common.py:256-310, 343-416, 419-474, 549-666](../../../../src/vaultspec_rag/indexer/_checkpoint_common.py#L256)). These are implementation paths; the callback wiring and concrete store behavior are uninspected.
- A checkpoint exposes `mutation_lifecycle` / `mutation_lifecycle_for_units` returning prepare, mark-applied, and confirm callbacks for a storage mutation; deletion helpers build canonical `CommitUnit`s and record them after confirmation ([src/vaultspec_rag/indexer/\_checkpoint_common.py:853-892, 1149-1209](../../../../src/vaultspec_rag/indexer/_checkpoint_common.py#L853)). `publish_proof_transition` and `publish_generation` seal proof and advance through finalization phases, with ledger integrity/proof checks ([src/vaultspec_rag/indexer/\_checkpoint_common.py:923-975, 1233-1271](../../../../src/vaultspec_rag/indexer/_checkpoint_common.py#L923)).
- `WeightedCodeSegmentQueue` admits `CodeFileSegment | None` while bounding both queued chunk count and estimated bytes. It is condition-protected; `put` and `get` support blocking, timeout, and nonblocking behavior; an individual segment larger than configured capacity raises `ValueError` ([src/vaultspec_rag/indexer/\_chunk_producer.py:122-224](../../../../src/vaultspec_rag/indexer/_chunk_producer.py#L122)).
- `CodeChunkProducer` takes a project root, chunk execution policy, and callable reader for the current preprocess context ([src/vaultspec_rag/indexer/\_chunk_producer.py:234-262](../../../../src/vaultspec_rag/indexer/_chunk_producer.py#L234)). `partition_batch_work` matches root-relative paths and groups batch rules into manifests of at most 64 files; unmatched/non-batch files remain singles ([src/vaultspec_rag/indexer/\_chunk_producer.py:319-370](../../../../src/vaultspec_rag/indexer/_chunk_producer.py#L319)). Batch results and single-file results are passed to caller-supplied handlers/publish callbacks ([src/vaultspec_rag/indexer/\_chunk_producer.py:372-545, 669-715](../../../../src/vaultspec_rag/indexer/_chunk_producer.py#L372)).
- Ordinary single-file work uses one serial worker or a spawned pool; auto mode gates parallelism on aggregate file size, explicit positive worker counts bypass the threshold, and the worker future window is at most two per worker. If the pool breaks after work has advanced, the producer raises; if it cannot start before any progress, it falls back to serial ([src/vaultspec_rag/indexer/\_chunk_producer.py:263-317, 547-715](../../../../src/vaultspec_rag/indexer/_chunk_producer.py#L263)). Segment submission polls the consumer thread and uses run-control/run-policy checks while blocked on queue capacity ([src/vaultspec_rag/indexer/\_chunk_producer.py:90-104, 717-746](../../../../src/vaultspec_rag/indexer/_chunk_producer.py#L90)).
