## Capability summary

This slice documents test coverage and expected behavior; it does not establish that the tests pass or prove production behavior.

- [src/vaultspec_rag/tests/integration/test_install_preview_topology.py](../../../../src/vaultspec_rag/tests/integration/test_install_preview_topology.py): exercises install preview/apply parity and required MCP filesystem topology. Expectations cover safe relative symlink preservation and target reconciliation; fail-closed handling for unsafe, aliased, overlapping, hard-linked, or linked-container nodes; preview/apply error parity; transaction rollback and preservation of concurrent writes; lifecycle ordering; no-MCP/uninstall behavior; CLI JSON failure reporting; and Windows junction cases guarded by `os.name == "nt"`.
- [src/vaultspec_rag/tests/integration/test_install_provider_failures.py](../../../../src/vaultspec_rag/tests/integration/test_install_provider_failures.py): covers malformed ownership state and provider configuration failures across API and CLI reports; expects failed uninstall to preserve workspace placement/assets, and drifted or malformed extra ownership to fail closed.
- [src/vaultspec_rag/tests/integration/test_install_provisioning.py](../../../../src/vaultspec_rag/tests/integration/test_install_provisioning.py): checks provisioning outcomes and serialization/rendering, distinct skip detail, torch enrollment report fields, and dry-run behavior for the managed Qdrant binary location.
- [src/vaultspec_rag/tests/integration/test_install_safety_guards.py](../../../../src/vaultspec_rag/tests/integration/test_install_safety_guards.py): checks containment and preservation around install/uninstall, including symlinked data refusal, user content preservation, partial builtin seeding rollback/error propagation, empty-workspace uninstall no-op, global target routing, and seeded destination containment.
- [src/vaultspec_rag/tests/integration/test_install_transaction_rollback.py](../../../../src/vaultspec_rag/tests/integration/test_install_transaction_rollback.py): covers preflight blockers and exact inventory preservation; rollback after late builtin failures; symlink/junction topology and snapshot restoration; collision-safe rollback temporary files; and moving an owned dependency between project and dev dependency locations, then restoring it on uninstall.
- [src/vaultspec_rag/tests/integration/test_install_uninstall_contracts.py](../../../../src/vaultspec_rag/tests/integration/test_install_uninstall_contracts.py): specifies force/dry-run handling, MCP skip scope, provider pruning, remove-data scope, preservation of user and core provider entries/fingerprints, builtin/user-rule behavior, install/uninstall round-trip expectations, and report serialization.
- [src/vaultspec_rag/tests/integration/test_intent_ranking.py](../../../../src/vaultspec_rag/tests/integration/test_intent_ranking.py): defines an integration/quality harness over frozen-corpus evidence. It expects well-formed per-query metrics, an orientation Authoritative@3 floor, no index documents in results for a named query, and a named ADR-over-exec ordering when both appear.
- [src/vaultspec_rag/tests/integration/test_jobs_registry_basics.py](../../../../src/vaultspec_rag/tests/integration/test_jobs_registry_basics.py): despite its directory, marks these tests as unit tests. It exercises start/finish snapshots, error and unknown-ID behavior, newest-first ordering, independent nested snapshot copies, bounded retention, and concurrent writers.
- [src/vaultspec_rag/tests/integration/test_jobs_registry_quarantine.py](../../../../src/vaultspec_rag/tests/integration/test_jobs_registry_quarantine.py): marks the class as unit tests. It covers invalid or inconsistent persisted jobs, quarantine evidence, unreadable/quarantine-failure cases, startup after bad resource data, and timestamp ordering under backward-clock scenarios for state changes and admission.
- Documentation claims are limited to test-module docstrings and explanatory comments. For example, the intent-ranking docstring describes its frozen corpus and deferred strict thresholds; the quarantine docstring explains its rationale. These statements are not independently verified here. No implementation file was inspected.

## Interfaces and data flow

- Install tests call `install_run` and/or the test helper `_install` with workspace paths and flags such as `dry_run`, `upgrade`, `force`, `mode`, `install_mcp`, `configure_torch`, and `provision`. They inspect report attributes and `to_dict()`, rendered CLI output, provider sync summaries, and resulting workspace files. CLI cases invoke the imported Typer app with install/uninstall options and JSON or human output.
- Filesystem fixtures and inputs include [pyproject.toml](../../../../pyproject.toml), MCP JSON/TOML configuration, ownership/provider/workspace JSON, builtin destinations, lock files, links/junctions, and `.vault/data`. Assertions inspect bytes, inventories, node signatures, symlink targets, reports, and preserved sentinels. The tests do not reveal the implementation’s full input/output contract.
- Provisioning tests call `install_run` and inspect its provisioning outcome and rendered report; the fixture uses local-only mode and a managed status directory.
- Ranking tests consume the `frozen_corpus_evidence` fixture: query reports, ranked document IDs/types, corpus/index counts, and intent labels. The test module imports the intent enum and a document-count helper.
- Registry basics call `jobs.record_start`, `record_finish`, and `snapshot`; quarantine tests construct `JobManager` instances with a state path, invoke restore/transition/resource APIs, and call the service startup helper. Persisted-state examples use `managed-jobs.json`; assertions inspect outcomes, job snapshots, quarantine siblings, and logs.
- These are observed test call patterns and asserted expectations, not a complete description of the imported APIs.
