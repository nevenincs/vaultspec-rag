## Capability summary

This is a test-only capability slice. **Implementation evidence:** none in the assigned files. **Documentation claims:** no project documentation files were assigned or read. Test docstrings/comments describe intended contracts and, in several cases, claim a guard was shown to fail after a mutation; those claims are not independently verified here. **Test expectations:** summarized below. **Inference:** any statement about actual application behavior beyond what the tests assert would require implementation reads.

- [src/vaultspec_rag/tests/test_cli_jobs_tui_log.py](../../../../src/vaultspec_rag/tests/test_cli_jobs_tui_log.py) covers direct parsing and rendering helpers and the interactive jobs log UI. Its cases expect parsing of app, access, Qdrant, and unstructured lines; hostile-text sanitization and bounded diagnostic lines; a separate managed-log tank preserving sanitized full records and producer metadata; middle elision with expandable values; dark/light semantic tones; level styling; collapse/toggle behavior for the view's polling traffic; scroll navigation and error jumps; closed-pane key feedback; focus and zoom; and formatted request fields. The UI cases use the imported `_app`, `_job`, `_JobService`, and paint helpers from sibling test module `test_cli_jobs_tui.py` (lines 44-52), and invoke the app through Textual `run_test` (for example, lines 193-215, 251-287, 408-470, 480-635, 641-672). Handler-formatted access cases expect 5xx records to remain errors and distinguish polled GETs, mutations, and unparseable logger tails (lines 675-725).
- [src/vaultspec_rag/tests/test_cli_jobs_watch_interrupt.py](../../../../src/vaultspec_rag/tests/test_cli_jobs_watch_interrupt.py) specifies guards around `_call_interruptibly`: a `KeyboardInterrupt` must escape while a blocking refresh is outstanding, worker exceptions must propagate as the same exception, and the worker is daemonized. It also expects the watch adapter to delegate to `run_server_watch` and the shared refresh to issue a read request to `/jobs` (lines 47-174). The module docstring says the interactive jobs view owns its loop and that the start command's health poll still uses the shared wait (lines 19-22); that is test-file commentary, not independently checked implementation evidence.
- [src/vaultspec_rag/tests/test_cli_no_dotenv_load.py](../../../../src/vaultspec_rag/tests/test_cli_no_dotenv_load.py) expects importing `vaultspec_rag.cli` in a fresh interpreter to leave `dotenv` absent from `sys.modules` (lines 17-20, 32-44).
- [src/vaultspec_rag/tests/test_cli_no_mcp_import.py](../../../../src/vaultspec_rag/tests/test_cli_no_mcp_import.py) expects importing `vaultspec_rag` and `vaultspec_rag.cli.app` in a fresh interpreter to load none of `mcp`, `mcp.*`, `win32*`, `pywintypes`, or `pythoncom` (lines 20-46).
- [src/vaultspec_rag/tests/test_cli_preprocess.py](../../../../src/vaultspec_rag/tests/test_cli_preprocess.py) exercises the CLI's preprocess help, `approve`, `revoke`, `list`, `check`, `run-one`, and `status` human/JSON surfaces using a temporary workspace, TOML rule, and extractor script (lines 82-172, 175-661). Expectations include policy digest and idempotent approval, revocation, validation failures, rule fields, successful and unmatched runs, an off-mode kill switch, refusal to execute an unapproved or changed policy, and status fields/messages. It also checks the server-start notice, propagation of `--no-preprocess` to child environment, preservation of an operator environment setting, rejection of retired flags/knobs, and warning on a delegated index run (lines 667-792). These are CLI test expectations; this file alone does not establish the underlying gate or execution implementation.
- [src/vaultspec_rag/tests/test_cli_progress.py](../../../../src/vaultspec_rag/tests/test_cli_progress.py) specifies `StartupStatusReporter` output behavior: plain-stream announcements/stages/heartbeats, stage deduplication, clock-based heartbeat limiting, silence in JSON mode, visible interactive frames, shared-console print placement, nested reporter use, a dumb-terminal fallback, stdout/stderr placement, and console interactivity wiring (lines 64-379).
- [src/vaultspec_rag/tests/test_cli_progress_lifetime.py](../../../../src/vaultspec_rag/tests/test_cli_progress_lifetime.py) runs a fresh subprocess that first imports the snapshot download progress tracker inside an interactive reporter, then closes its capture stream. It expects a successful process exit, a live-region cursor sequence and label in stdout, and empty stderr (lines 17-63). This asserts a lifetime regression guard; it is not evidence that the test currently passes.
- [src/vaultspec_rag/tests/test_cli_progress_surfaces.py](../../../../src/vaultspec_rag/tests/test_cli_progress_surfaces.py) expects model download progress to combine byte and file counts, choose the smaller declared byte total, keep bars off real streams, close tracked bars, delay opening a live region until first report, and remain silent in JSON mode (lines 159-332). Qdrant provision tests expect checksum reporting before extraction, no extraction after a digest mismatch, byte progress with and without a declared size, enforcement of a stream cap, and a single JSON install envelope (lines 341-481). A structural test expects the `provision` symbol not to be bound at module scope in three named modules (lines 483-508). Reconcile tests expect each unconverged poll to report its verdict and JSON output to remain one envelope (lines 510-581). Storage tests expect progress for survey, reconciliation, migration, and orphan pruning, while JSON survey/prune/reconcile paths emit one envelope without progress text (lines 583-759).

## Interfaces and data flow

All interfaces below are observed from test call sites and expected assertions, not implementation tracing.

- The jobs-log tests call `parse_log_line`, `render_entry`, `sanitize_log_text`, `managed_log_safe_text`, `managed_log_group_metadata`, `query_managed_logs`, and `validate_managed_log_payload` directly (imports at lines 21-43; examples at 78-147, 154-190, 221-249). Other cases seed `_JobService` records, build an app, exercise keys, and inspect painted screen text/request paths (for example, lines 251-287 and 408-470).
- The interrupt tests inject blocking/failing callables and an injected wait into `_call_interruptibly`; separately, `fetch_jobs_result(JobsQuery(...))` is observed by a local GET-only server, and the watch module source is inspected for its delegation import/call (lines 70-80, 98-103, 106-148, 164-172).
- The import-boundary tests launch fresh Python interpreters with `subprocess.run` and inspect module loading (dotenv: lines 32-44; optional MCP/Windows packages: lines 20-46).
- Preprocess cases call the Typer `app` with `CliRunner.invoke`, using a temporary root, `.vaultragpreprocess.toml`, and generated extractor. They parse JSON envelopes or labeled human output and inspect the generated sentinel, environment, and status (helpers at lines 82-172; representative approval at 199-255, run at 430-544, and environment cases at 710-792).
- Progress tests inject Rich consoles backed by `StringIO`, `interactive`/`json_mode` flags, and a test clock; they inspect the exact written stream, ANSI-stripped text, or spinner glyphs (reporter helpers at [src/vaultspec_rag/tests/test_cli_progress.py](../../../../src/vaultspec_rag/tests/test_cli_progress.py) lines 34-61; stream cases at 177-379). Lifetime coverage runs a generated program in a subprocess ([src/vaultspec_rag/tests/test_cli_progress_lifetime.py](../../../../src/vaultspec_rag/tests/test_cli_progress_lifetime.py) lines 19-57).
- Progress-surface tests drive `SnapshotBars` through Hugging Face Hub's `_create_progress_bar` and `thread_map` factory paths, then pass counts to `ReporterProvisionProgress` (helpers at [src/vaultspec_rag/tests/test_cli_progress_surfaces.py](../../../../src/vaultspec_rag/tests/test_cli_progress_surfaces.py) lines 63-157; cases at 169-332). Other cases pass reporter callbacks to Qdrant download/extraction, discovery reconciliation, and storage operations, or invoke CLI JSON commands (lines 341-481, 510-581, 583-759).
