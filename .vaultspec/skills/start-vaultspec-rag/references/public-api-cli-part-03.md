## Capability summary

- [src/vaultspec_rag/cli/\_preprocess.py](../../../../src/vaultspec_rag/cli/_preprocess.py) implements the `preprocess` command group: `list`, strict `check`, `approve`, `revoke`, diagnostic `run-one`, and `status`. Handlers take the project root from `CLIState`, report through plain or shared JSON renderers, and use imported config/approval/runner functions. `run-one` checks the rule gate before matching and invokes the runner without an indexing call in this handler. `status` prefers the detected service mode and reports whether hooks would run. (Implementation; see evidence below.)
- [src/vaultspec_rag/cli/\_process.py](../../../../src/vaultspec_rag/cli/_process.py) owns service process identity checks, interruptible waiting, daemon environment and command construction, detached spawning, late-spawn discovery/cleanup, termination outcomes, and validation/reaping of a service-owned Qdrant child. It exports named helpers and result/error types in `__all__`. (Implementation.)
- [src/vaultspec_rag/cli/\_progress.py](../../../../src/vaultspec_rag/cli/_progress.py) provides `StartupStatusReporter`, a re-entrant context manager for indeterminate startup waits. It suppresses output in JSON mode, uses a live spinner when interactive output supports it, and otherwise emits plain rate-limited progress lines. (Implementation.)
- [src/vaultspec_rag/cli/\_provision_progress.py](../../../../src/vaultspec_rag/cli/_provision_progress.py) adapts provisioning stage and snapshot-download callbacks to `StartupStatusReporter`; it opens the reporter on the first event, forwards stages, and formats download counts through `progress_line`. (Implementation.)
- [src/vaultspec_rag/cli/\_render.py](../../../../src/vaultspec_rag/cli/_render.py) provides shared style/plain output helpers, JSON success/error envelopes, service/search diagnostics, search-result rendering, and install/uninstall/provisioning report rendering. Search rendering prefers source lines only when the current file still contains the indexed snippet; otherwise it falls back to the result snippet. (Implementation.)
- In-code module documentation describes intended scope: preprocess commands and their approval gate ([src/vaultspec_rag/cli/\_preprocess.py:1-18](../../../../src/vaultspec_rag/cli/_preprocess.py#L1)), service process ownership ([src/vaultspec_rag/cli/\_process.py:1-14](../../../../src/vaultspec_rag/cli/_process.py#L1)), the distinction between indeterminate startup status and determinate indexing progress ([src/vaultspec_rag/cli/\_progress.py:1-13](../../../../src/vaultspec_rag/cli/_progress.py#L1)), shared provisioning wording ([src/vaultspec_rag/cli/\_provision_progress.py:1-8](../../../../src/vaultspec_rag/cli/_provision_progress.py#L1)), and shared CLI output rendering ([src/vaultspec_rag/cli/\_render.py:1-7](../../../../src/vaultspec_rag/cli/_render.py#L1)). These are documentation claims; they were not independently checked against callers or external docs.
- No test modules were assigned or read, so this report makes no claims about test expectations or passing tests.

## Interfaces and data flow

- The six preprocess handlers are registered on `preprocess_app`. They receive a Typer context and optional `JsonMode`; `run-one` additionally accepts a source path. The root helper reads `CLIState.target` ([src/vaultspec_rag/cli/\_preprocess.py:52-56](../../../../src/vaultspec_rag/cli/_preprocess.py#L52)). List/check/status return structured rule or state data through `_emit_json`; approval and revocation call the approval-store functions; trial execution resolves a path, checks `config_hook_state`, matches one rule, and passes the source, rule, byte cap, and root to `run_preprocessor` ([src/vaultspec_rag/cli/\_preprocess.py:110-189](../../../../src/vaultspec_rag/cli/_preprocess.py#L110), `219-326`, `375-449`, `476-567`). Exact config/store/runner semantics are delegated to uninspected imports.
- [src/vaultspec_rag/cli/\_process.py](../../../../src/vaultspec_rag/cli/_process.py) builds the child environment from `child_environment(*credential_assignments(root))`, removes both package/framework root selectors, applies explicitly supplied watcher/backend/preprocess flags, and anchors selected relative directory variables ([src/vaultspec_rag/cli/\_process.py:339-445](../../../../src/vaultspec_rag/cli/_process.py#L339)). Spawn creates a nonce-bearing module command, uses the managed status directory as working directory, redirects output to an opened log, then retains/reaps the launcher and bounds late-spawn cleanup ([src/vaultspec_rag/cli/\_process.py:555-694](../../../../src/vaultspec_rag/cli/_process.py#L555)). Windows has a breakaway attempt followed by a detached-process fallback ([src/vaultspec_rag/cli/\_process.py:952-1011](../../../../src/vaultspec_rag/cli/_process.py#L952)).
- Process identity can use a service health token and PID, a launch-argument witness, or a documented legacy executable/command-line path ([src/vaultspec_rag/cli/\_process.py:123-240](../../../../src/vaultspec_rag/cli/_process.py#L123)). Late-spawn cleanup scans for the matching port and optional nonce, records process start times, and terminates witnessed candidates within a deadline ([src/vaultspec_rag/cli/\_process.py:711-950](../../../../src/vaultspec_rag/cli/_process.py#L711)). `_terminate_pid` returns `TerminationResult`; before termination it captures and validates an owned Qdrant identity, and the reap path rechecks the identity and endpoint ([src/vaultspec_rag/cli/\_process.py:84-110](../../../../src/vaultspec_rag/cli/_process.py#L84), `1014-1265`).
- `StartupStatusReporter` accepts JSON/interactive settings, an optional console, heartbeat interval, and clock. Its `announce`, `stage`, and `heartbeat` methods emit or suppress labels; nested entries share one live region ([src/vaultspec_rag/cli/\_progress.py:69-182](../../../../src/vaultspec_rag/cli/_progress.py#L69)). [src/vaultspec_rag/cli/\_provision_progress.py](../../../../src/vaultspec_rag/cli/_provision_progress.py) accepts a `StartupStatusReporter`; its `stage` and `downloading` methods forward stage labels and formatted snapshot counts, with a lazy reporter entry ([src/vaultspec_rag/cli/\_provision_progress.py:23-66](../../../../src/vaultspec_rag/cli/_provision_progress.py#L23)).
- `_emit_json` writes an envelope directly to stdout and flushes; the error helper emits a failure envelope then raises `typer.Exit` ([src/vaultspec_rag/cli/\_render.py:145-195](../../../../src/vaultspec_rag/cli/_render.py#L145)). Human rendering uses the package console. Search result inputs are dictionaries; optional `root` and line metadata permit reading current source lines, with snippet fallback ([src/vaultspec_rag/cli/\_render.py:388-503](../../../../src/vaultspec_rag/cli/_render.py#L388)). Install/uninstall renderers accept report dataclasses, and provisioning rendering reads the outcome's JSON-serializable `to_dict` view ([src/vaultspec_rag/cli/\_render.py:774-1022](../../../../src/vaultspec_rag/cli/_render.py#L774)).
- In-slice callers: [src/vaultspec_rag/cli/\_preprocess.py](../../../../src/vaultspec_rag/cli/_preprocess.py) imports `_emit_json`, `_emit_json_error_and_exit`, `_plain`, and `_print_next_action` from [src/vaultspec_rag/cli/\_render.py](../../../../src/vaultspec_rag/cli/_render.py) and calls them from its command handlers ([src/vaultspec_rag/cli/\_preprocess.py:45-46](../../../../src/vaultspec_rag/cli/_preprocess.py#L45), throughout 66-567). [src/vaultspec_rag/cli/\_provision_progress.py](../../../../src/vaultspec_rag/cli/_provision_progress.py) calls reporter context and progress methods ([src/vaultspec_rag/cli/\_provision_progress.py:38-66](../../../../src/vaultspec_rag/cli/_provision_progress.py#L38)). The assigned files do not establish the complete external caller graph for [src/vaultspec_rag/cli/\_process.py](../../../../src/vaultspec_rag/cli/_process.py), [src/vaultspec_rag/cli/\_progress.py](../../../../src/vaultspec_rag/cli/_progress.py), or [src/vaultspec_rag/cli/\_render.py](../../../../src/vaultspec_rag/cli/_render.py).
