## Capability summary

- [src/vaultspec_rag/indexer/\_codebase_indexer.py](../../../../src/vaultspec_rag/indexer/_codebase_indexer.py) owns the code-indexing orchestration surface: constructs collaborators, exposes discovery/preflight and telemetry methods, serializes full and incremental writes, and coordinates checkpointed publication, reconciliation, and results. It delegates path admission to `CodeContentDiscovery`, chunk production to `CodeChunkProducer` and `CodeConsumerPipeline`, generation state to `CodeGenerationLifecycle`, and incremental replacement to `CodeIncrementalCommit` (implementation details of these collaborators were not inspected).
- [src/vaultspec_rag/indexer/\_chunk_worker.py](../../../../src/vaultspec_rag/indexer/_chunk_worker.py) contains code-file and document-file chunking worker functions and their result/request types. It streams and hashes sources, enforces effective source-byte limits, decodes text, applies preprocessing/cache outcomes, creates AST or text chunks for code, and returns document chunks either eagerly or as a stream. It keeps a per-process `ASTChunker` singleton. Its module docstring describes it as CPU-only and says the process pool uses spawn; pool creation/execution was not inspected.
- [src/vaultspec_rag/indexer/\_chunking.py](../../../../src/vaultspec_rag/indexer/_chunking.py) provides `TextSplitter`, exact piece-offset lookup, extension-to-language/grammar mappings, the narrower conventional source-extension admission set, parser-selection defaults, shared AST node-type sets, a 10 MiB `_MAX_FILE_SIZE` constant, and null-byte binary sampling. Parser execution and admission consumers were not inspected beyond references in assigned files.
- [src/vaultspec_rag/indexer/\_codebase_preprocess.py](../../../../src/vaultspec_rag/indexer/_codebase_preprocess.py) is the `CodebasePreprocessMixin` used by `CodebaseIndexer`. It resolves preprocessing context from the run's policy, resets run-local decoder/preprocess counters, records disabled transforms as stale, removes disabled paths from executable work, and accumulates worker preprocessing outcomes.
- Test expectations: no test modules were assigned or read. No passing or failing test behavior is asserted here.

## Interfaces and data flow

- `CodebaseIndexer.__init__` resolves the project root, selects the default conventional-v1 content policy if none is provided, builds discovery, a writer lock, a stat-evidence store under the workspace data root, a `CodeChunkProducer` whose preprocess context is fetched per run, support-budget and generation-lifecycle collaborators, a consumer pipeline, and incremental-commit helper ([src/vaultspec_rag/indexer/\_codebase_indexer.py:116-242](../../../../src/vaultspec_rag/indexer/_codebase_indexer.py#L116)). `last_checkpoint`, `memory_budget_snapshot`, and `reset_memory_telemetry` expose lifecycle and memory telemetry (`:244-258`).
- Discovery-facing methods include `resolve_policy_snapshot`, full and changed-path preflight, content scan, and file scan; the indexer delegates them to `CodeContentDiscovery` ([src/vaultspec_rag/indexer/\_codebase_indexer.py:260-349](../../../../src/vaultspec_rag/indexer/_codebase_indexer.py#L260)). `_accept_preflight` validates caller-owned preflight authority before indexing (`:284-294`).
- `full_index` accepts a required reporter and `CodeIndexPreflight`, defaults authority to rebuild, accepts run control, accepts the preflight, serializes on the writer lock, and invokes the shared index lifecycle ([src/vaultspec_rag/indexer/\_codebase_indexer.py:551-603](../../../../src/vaultspec_rag/indexer/_codebase_indexer.py#L551)). The locked flow initializes preprocess state and code policy epochs, scans/partitions paths, opens a generation checkpoint, reads prior publication evidence, prepares a build collection, sends paths to the consumer pipeline, records computed source hashes in the stat gate, checks the ingest barrier, reconciles stale identities, publishes, and returns `IndexResult` (`:641-852`).
- `incremental_index` accepts an optional changed-path iterable and `CodeExecutionPreflight`; it serializes work and delegates to locked flow ([src/vaultspec_rag/indexer/\_codebase_indexer.py:854-905](../../../../src/vaultspec_rag/indexer/_codebase_indexer.py#L854)). Unscoped incremental work reads prior evidence, scans current code paths, hashes behind the stat-evidence gate, computes new/modified/deleted sets, and asks `CodeIncrementalCommit` to publish and replace (`:907-1070`, `:1182-1235`). Scoped work classifies only supplied paths, reads prior evidence for affected paths, invalidates discovery cache when membership may have changed, hashes admitted paths, then commits replacement (`:1128-1179`, `:1237-1355`). Policy membership/content epoch mismatch requires a full reindex (`:942-960`).
- Code worker API: `chunk_and_hash_file` returns a `FileChunkResult` containing normalized relative path, raw-byte blake2b hash, chunks, and optional preprocess disposition. It hashes and retains source bytes in one pass when no rule applies; with a rule it first hashes, attempts preprocessing, and rereads only for passthrough ([src/vaultspec_rag/indexer/\_chunk_worker.py:943-1042](../../../../src/vaultspec_rag/indexer/_chunk_worker.py#L943)). `_raw_file_result` decodes, returns zero chunks for invalid or blank content, or delegates to AST/text chunking (`:1045-1065`). `chunk_batch_files` hashes/cache-checks members, launches one batch preprocessor for cache misses, stores successful outputs, then maps each member to chunks, skip, or passthrough (`:1155-1208`, `:1211-1289`).
- Worker preprocessing matches a rule by relative path, keys cached output from source hash/rule/mode/output cap, revalidates cached output size, refreshes path-independent cache source paths, and maps output units or text to code chunks ([src/vaultspec_rag/indexer/\_chunk_worker.py:258-317](../../../../src/vaultspec_rag/indexer/_chunk_worker.py#L258), `:320-385`). Batch and document branches use analogous cache and output-cap handling (`:744-788`, `:1080-1153`). A rule routed to the wrong content kind raises; an unmatched path is allowed to use the upstream default (`:155-172`).
- Document worker API: `stream_document_and_hash_file` takes an explicitly admitted path, root, and `DocumentChunkingOptions`; it enforces a document target rule, effective source cap, and run checkpoints. Raw input is validated/hashed, then returned as an incremental chunk iterator; preprocess output becomes document-native chunks, skip returns none, and passthrough falls back to raw streaming while verifying source identity ([src/vaultspec_rag/indexer/\_chunk_worker.py:612-671](../../../../src/vaultspec_rag/indexer/_chunk_worker.py#L612), `:674-741`, `:791-913`). Document chunks preserve source path, content fingerprint, ordinal, extractor information, metadata, and (for emitted units) title, section, anchor, and locator; point IDs derive from source, ordinal, fingerprint, locator, and fragment ordinal (`:526-558`, `:674-741`).
- Code chunking selects language and optional grammar by suffix; AST parsing failures fall back to `TextSplitter`. AST chunks carry source-relative path, language, line span, node/function/class labels, content hash, and an emit ordinal in the ID. Text chunks use zero overlap, locate exact substrings, and derive line spans and IDs ([src/vaultspec_rag/indexer/\_chunk_worker.py:916-940](../../../../src/vaultspec_rag/indexer/_chunk_worker.py#L916), `:1292-1389`).
- `TextSplitter` recursively prefers language-specific structural separators, then falls back to forced character slicing; configurable size/overlap are used by code and document flows. `locate_pieces` searches each emitted piece verbatim and in order, raising if it cannot locate a piece ([src/vaultspec_rag/indexer/\_chunking.py:35-187](../../../../src/vaultspec_rag/indexer/_chunking.py#L35)). `LANGUAGE_MAP` maps extensions to language and optional grammar; `select_parser` falls back to `("text", None)`, while conventional source admission is a separate smaller set (`:194-275`).
- Source read state and outcomes: `_stream_source` hashes in 1 MiB blocks, optionally retains bytes, checks cooperative control and maximum bytes, converts missing files to a distinct vanished disposition, converts source-identity failures to unavailable, and propagates other I/O failures ([src/vaultspec_rag/indexer/\_chunk_worker.py:57-70](../../../../src/vaultspec_rag/indexer/_chunk_worker.py#L57), `:97-152`). Positive non-boolean prep/rule caps are combined by minimum (`:97-111`). A vanished source is marked `vanished`; an unmatched or skippable rule refusal is skipped; a matched `on_error="fail"` refusal raises `PreprocessAbortError` (`:175-193`).
