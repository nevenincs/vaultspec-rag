## Capability summary

- [src/vaultspec_rag/tests/integration/test_jobs_registry_recovery.py](../../../../src/vaultspec_rag/tests/integration/test_jobs_registry_recovery.py): exercises the jobs registry union of canonical job history and activity records, record resolution/deletion, truthful action capabilities, ownership-aware interrupted-run recovery, and JobManager filesystem persistence/recovery. Coverage includes state round trips and transition reloads, attempt-task identity, terminal retention, atomic replacement, persistence failure/flush, state validation/quarantine, newer-build preservation, lowered-capacity recovery, and admission refusal (59-201, 203-290, 292-1201).
- [src/vaultspec_rag/tests/integration/test_jobs_registry_routes.py](../../../../src/vaultspec_rag/tests/integration/test_jobs_registry_routes.py): drives MCP vault and code reindex tools against a live service, seeding rebuild publication authority over HTTP and checking that each tool-created job reaches a terminal “done” row with the expected source, trigger, finish time, and result (19-77).
- [src/vaultspec_rag/tests/integration/test_machine_singleton.py](../../../../src/vaultspec_rag/tests/integration/test_machine_singleton.py): tests machine lock lease acquisition/release and discovery-pointer ownership, then starts a real daemon subprocess while a foreign process holds the lock to assert the losing daemon refuses before publishing or starting service components (59-307).
- [src/vaultspec_rag/tests/integration/test_mps_backend.py](../../../../src/vaultspec_rag/tests/integration/test_mps_backend.py): hardware acceptance case for configured dense, sparse, and reranker model residency and real forward operations on Apple silicon MPS, with fallback and model-cache network access disabled (18-116).
- [src/vaultspec_rag/tests/integration/test_performance.py](../../../../src/vaultspec_rag/tests/integration/test_performance.py): measures query, embedding, parse, graph, indexing, and storage bounds; checks graph cache reuse/expiry, indexed document count, full-index memory and time, and no-op incremental indexing (31-364).
- [src/vaultspec_rag/tests/integration/test_policy_snapshot.py](../../../../src/vaultspec_rag/tests/integration/test_policy_snapshot.py): creates a controlled policy/config mutation during extraction and checks that active indexing, publication fingerprints, and searchable output retain the entry snapshot while a fresh policy resolution sees the replacement config (48-314).

## Interfaces and data flow

- Jobs registry tests call the `jobs` facade and `JobManager` with `JobSpec`/`JobInitiator`, desired-state transitions, attempt tasks and control tokens. They inspect service snapshots, activity records, outcomes/codes, and manager state (19-37, 59-201, 292-1201). Test state is written to temporary `managed-jobs.json` or `jobs-active.json` files; tests re-open those files through manager restoration or the persistence loader. One test manually alters persisted payloads to model interrupted, invalid, or newer-version state (209-289, 297-1201).
- Route coverage sends HTTP reindex requests using source, port, root, publication authority, and MCP initiator metadata, then invokes `tools.reindex_vault` or `tools.reindex_codebase`; it polls by returned `job_id` and checks terminal job fields (19-77). The live-service fixture and polling helper implementation are uninspected.
- Singleton coverage uses the machine-lock functions and test helpers with an isolated lock/storage path. A subprocess is the foreign lock holder; the daemon subprocess receives isolated status/Qdrant paths and a loopback port. Observed outputs are holder PIDs, lock probes, discovery/status files, logs, process return code, and listener probes (59-307). Actual lock semantics and daemon startup order are assertions/documentation in this test only.
- MPS coverage sets offline and feature environment variables, resets config, loads an accelerator and a ServiceRegistry model stack, then calls dense/sparse encoding and reranker prediction. Expected outputs are device/backend fields, vector/sparse values, and finite scores (40-116). Cache provisioning and model implementations are uninspected.
- Performance cases consume fixture-provided model/store/indexer/root/result objects and measure wall time, process RSS, on-disk store bytes, result counts, and cached graph identity (45-364). Fixture construction and benchmark environment are uninspected.
- Policy-snapshot coverage writes two TOML policy states, binary/HTML inputs, a temporary extractor program, and synchronization flags. It preflights an index operation, runs indexing in a worker thread, changes environment/config while extraction waits, then checks the result, active resolved policy, publication compatibility key, fresh resolution, and search hits/snippets (57-65, 85-155, 178-260, 263-314). Approval helper, policy resolution, extraction, publication, and search implementations are uninspected.
