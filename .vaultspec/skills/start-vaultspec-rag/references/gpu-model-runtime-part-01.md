## Capability summary

All observed behavior below is a **test expectation**, not confirmation that the implementation currently passes.

- [src/vaultspec_rag/tests/test_gpu_borrow_cli.py](../../../../src/vaultspec_rag/tests/test_gpu_borrow_cli.py) exercises explicit GPU borrower coordination with a production service: work observes a safe quiesced state, then resume and lease release are expected, including after work raises. A lost resume acknowledgement is expected to retain the lease until process-death recovery. CLI expectations include requiring explicit `--borrow-gpu` when no service is available, rejecting obsolete `--allow-fallback`, and importing borrower modules without importing torch (24-82, 85-172, 175-221).
- [src/vaultspec_rag/tests/test_gpu_borrow_lease.py](../../../../src/vaultspec_rag/tests/test_gpu_borrow_lease.py) covers OS-backed lease contention and crash release; authenticated pause/resume routes tied to a live matching capability; recovery of a lost bound lease; safe GPU lending and reclaim; refusal when a loan cannot be recorded; separation of operator and borrower pause ownership; idempotent borrower retries; and a public bound witness that omits holder identity. It also checks concurrent lease-record readability, compatibility with compact prior records and ordinary JSON readers, quiesce-envelope mismatch handling, and operator-facing pause refusal messages (287-440, 443-642, 643-805, 808-949).
- [src/vaultspec_rag/tests/test_gpu_owner.py](../../../../src/vaultspec_rag/tests/test_gpu_owner.py) exercises a real owner anchor across processes: owner refusal, lending to a process tree, pid/start-time matching, service-lock refusal, unavailable-anchor refusal, and non-claiming observation. It also expects accelerator loading and CLI server/search paths to enforce ownership, human/JSON error rendering to preserve the refusal, and ownership-module import to stay torch-free (157-404).
- [src/vaultspec_rag/tests/test_gpu_session_lock.py](../../../../src/vaultspec_rag/tests/test_gpu_session_lock.py) covers the borrower coordinator against real loopback pause/resume routes and child processes, including contention, release ordering, and retaining a lease after unacknowledged resume. A nested pytest selection is expected to refuse an unprovisioned Qdrant prerequisite before its test body runs; imports are expected to remain torch-free (220-355).
- [src/vaultspec_rag/tests/test_graph_cache.py](../../../../src/vaultspec_rag/tests/test_graph_cache.py) expects graph caching by root and TTL, invalidation, retry after construction failure, one construction under concurrent access, and root-change rebuilds. It separately exercises `VaultSearcher` delegation to a supplied graph provider and its internal lock/TTL fallback (39-296).
- [src/vaultspec_rag/tests/test_hardware_anchor.py](../../../../src/vaultspec_rag/tests/test_hardware_anchor.py) checks that hardware-anchor and load-window paths ignore process-relocatable environment variables, and that shared/private anchor claims preserve contention and permission boundaries. Platform-specific cases cover POSIX mode bits and Windows ACL grants, preservation, inheritance, and delete restrictions; an unresolvable load-window path is expected to degrade rather than block every load (79-512).
- [src/vaultspec_rag/tests/test_hardware_probe.py](../../../../src/vaultspec_rag/tests/test_hardware_probe.py) expects driver output to identify an NVIDIA device and memory, empty output to mean no device, absent/failing/hung utilities to yield unknown, and macOS classification to use the machine architecture (24-88).
- [src/vaultspec_rag/tests/test_health_degraded_clears.py](../../../../src/vaultspec_rag/tests/test_health_degraded_clears.py) expects a failed job to degrade health only until a later success for the same source and normalized project; another source/project does not clear it, and a subsequent failure degrades again. Full-reindex-required failures remain visible in the rollup but are excluded from the degraded verdict (74-278).
- [src/vaultspec_rag/tests/test_hook_sandbox.py](../../../../src/vaultspec_rag/tests/test_hook_sandbox.py) exercises child-environment filtering and subprocess launch behavior: environment allow-listing, retention of PATH, removal of credential-bearing and project-specific variables, propagation of caller-supplied values, specified cwd, and separately captured stdout/stderr (59-196).
- [src/vaultspec_rag/tests/test_host_install_command.py](../../../../src/vaultspec_rag/tests/test_host_install_command.py) expects CUDA-index arguments for Windows/Linux install commands, the standard install command for Apple silicon, and the Windows/macOS generated commands to appear in README (20-43).
- [src/vaultspec_rag/tests/test_html_strip.py](../../../../src/vaultspec_rag/tests/test_html_strip.py) expects HTML text normalization to remove tags and script/style bodies, decode entities, preserve block separation, tolerate malformed markup, honor the worker's strip toggle, and chunk listed text-like extensions (18-81).

## Interfaces and data flow

- Test entry points call imported package APIs directly, invoke the Typer CLI with `CliRunner`, or start real child interpreters. Borrower tests acquire/release a lease and exchange capability values through child markers; service tests send authenticated JSON to `/pause` and `/resume`, then inspect response envelopes and registry snapshots ([src/vaultspec_rag/tests/test_gpu_borrow_cli.py:31-80, 128-172](../../../../src/vaultspec_rag/tests/test_gpu_borrow_cli.py#L31); [src/vaultspec_rag/tests/test_gpu_borrow_lease.py:76-284, 305-440](../../../../src/vaultspec_rag/tests/test_gpu_borrow_lease.py#L76); [src/vaultspec_rag/tests/test_gpu_session_lock.py:58-217, 220-288](../../../../src/vaultspec_rag/tests/test_gpu_session_lock.py#L58)).
- Owner and anchor tests use temporary anchor paths and spawned holders; observations are typed states or records. Hardware probing supplies a fake executable command plus platform/machine inputs. Hook tests supply argv, cwd, and environment to child processes and collect both pipes ([src/vaultspec_rag/tests/test_gpu_owner.py:40-149](../../../../src/vaultspec_rag/tests/test_gpu_owner.py#L40); [src/vaultspec_rag/tests/test_hardware_anchor.py:61-99, 102-185](../../../../src/vaultspec_rag/tests/test_hardware_anchor.py#L61); [src/vaultspec_rag/tests/test_hardware_probe.py:20-88](../../../../src/vaultspec_rag/tests/test_hardware_probe.py#L20); [src/vaultspec_rag/tests/test_hook_sandbox.py:31-56, 99-196](../../../../src/vaultspec_rag/tests/test_hook_sandbox.py#L31)).
- Job-health tests record start/finish events through the jobs API, obtain `_jobs_health` output, and compare typed degradation reasons and rollup fields ([src/vaultspec_rag/tests/test_health_degraded_clears.py:52-71, 80-278](../../../../src/vaultspec_rag/tests/test_health_degraded_clears.py#L52)). Cache tests call `GraphCache.get/invalidate` and `VaultSearcher._get_graph`, asserting graph identity across calls and threads ([src/vaultspec_rag/tests/test_graph_cache.py:39-296](../../../../src/vaultspec_rag/tests/test_graph_cache.py#L39)).
- Storage/integration surfaces named by the tests include OS lock files, GPU owner/load-window anchors, service status discovery, HTTP routes, job records, temporary project/vault trees, and child-process environment/cwd. Their implementation and persistence details remain uninspected.
