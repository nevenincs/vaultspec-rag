## Interfaces and data flow

- Static guards obtain production paths from `_process_probe_guard_helpers._production_sources()`; AST/source predicates return offender descriptions that assertions require to be empty. The canonical-ownership module also uses parsed function bodies, module imports, and literal collections to compare repeated shapes and vocabularies (canonical ownership, 28-186, 941-951; OS guards, 26-120; ownership guards, 127-149, 234-302, 322-420).
- Runtime tests import named production symbols and check their outputs or inspect source with `inspect.getsource`. Examples include the shared CLI JSON help constants (320-377), route and schema membership (204-248, 487-508, 653-670), status paths (550-564), and operator command rendering and shell quoting (595-663).
- Scan-cost tests spawn subprocesses, locate them by command-line marker, then read process fields from mapping-like entries. The expectations cover `cmdline`-first scanning, deferred `ppid` access, daemon image gating, and holder classification (35-56, 59-138, 140-223, 225-251). These are test expectations; actual runtime behavior was not independently inspected.
- The source tests mention shared status files, lock files, JSON sidecars, job state, and workspace paths, but no storage or service implementation was read.
