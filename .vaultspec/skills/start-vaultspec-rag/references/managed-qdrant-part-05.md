## Capability summary

- [src/vaultspec_rag/tests/test_qdrant_local_lifetime.py](../../../../src/vaultspec_rag/tests/test_qdrant_local_lifetime.py) specifies that deleting a local collection releases its SQLite owner while a separate collection remains usable, and that the close helper leaves a remote client alone (19-70). It drives the local case in a fresh subprocess with warnings treated as errors (19-62).
- [src/vaultspec_rag/tests/test_qdrant_offline_install.py](../../../../src/vaultspec_rag/tests/test_qdrant_offline_install.py) covers installation from an operator-supplied local archive across supported archive shapes. Its expectations include no network request, preservation of the input file, archive and executable digest checks, safe replacement/manifest results, and cleanup of staging files (145-324). It also specifies `provision(archive=...)` refusal and dry-run behavior, path restrictions, upgrade requirements, and version listing/verification (327-498). These are test expectations; the install implementation was not read.
- [src/vaultspec_rag/tests/test_qdrant_port_release.py](../../../../src/vaultspec_rag/tests/test_qdrant_port_release.py) specifies loopback-based checks for detecting listening ports and waiting for release after a child is reaped, including held, free, and released-during-wait cases (25-89).
- [src/vaultspec_rag/tests/test_qdrant_ready_timeout.py](../../../../src/vaultspec_rag/tests/test_qdrant_ready_timeout.py) specifies environment override, malformed/non-positive fallback to the settings default, and a minimum default of 180 seconds (14-81).
- [src/vaultspec_rag/tests/test_qdrant_restart_accounting.py](../../../../src/vaultspec_rag/tests/test_qdrant_restart_accounting.py) specifies that refused restart attempts do not spend the one process-started restart, are retried with a bound, and carry refusal causes into supervisor state and readiness detail (1-9, 92-200).
- [src/vaultspec_rag/tests/test_qdrant_runtime.py](../../../../src/vaultspec_rag/tests/test_qdrant_runtime.py) specifies platform-to-release-asset mapping, digest-table invariants and server/client version alignment; managed-install verdict handling; verified extraction and traversal containment; resolution and pre-exec refusal of unverified, unusable, or implicit PATH/CWD binaries; operator path/digest pairing; provisioning and listing behavior; configuration defaults/overrides; and child path rendering (104-870). It also covers checksum refusal and cleanup (272-297).
- [src/vaultspec_rag/tests/test_qdrant_spawn_trust.py](../../../../src/vaultspec_rag/tests/test_qdrant_spawn_trust.py) specifies digest and file-shape checks at process creation, re-checks on restart/recovery spawns, managed-directory foreign-file refusal, operator-directory exemption, attached-server non-executability, and the stable source vocabulary (111-519). AST assertions specify that subprocess creation occurs inside an executable hold, uses the held launch path, and checks for changes after process creation (523-653).

## Interfaces and data flow

- Test inputs are environment settings, temporary managed-install directories and archive files, stand-in launchers, real loopback sockets, and Qdrant client/local storage. Fixtures relocate singleton directories and clear or override relevant environment variables (runtime 67-102; offline install 73-107; restart accounting 52-80).
- The tests call resolution, provisioning, extraction, verification, supervisor start/spawn/restart/state, the service liveness tick, readiness computation, and local collection close. Observed outputs asserted by the sources include provision reports, resolved binary records/errors, supervisor state/counters, readiness rows, process markers, filesystem contents, and socket probe results (offline install 145-498; runtime 272-870; restart accounting 92-200; spawn trust 111-653).
- The tests model installation state with files and manifests, but explicitly assert that manifest claims alone do not establish trust; committed or declared digests are expectations at resolution/spawn boundaries (runtime 299-403, 460-579; offline install 449-498; spawn trust 111-180).
