## Capability summary

- [src/vaultspec_rag/storage_archive.py](../../../../src/vaultspec_rag/storage_archive.py) writes a prefix's Qdrant snapshots into a namespace archive, writes a portable snapshot manifest with collection identity and available publication proofs, verifies the completed archive, and sweeps completed archives by age and byte cap. Its module docstring describes archival as a prerequisite for destructive reclamation and says reclamation decisions remain with the caller (1–10). `archive_prefix` requires a manifest attribution, snapshots each matching live collection, checks publication proof counts, preserves eligible records from prior attempts, publishes the manifest, removes unnamed snapshot artifacts, and verifies file presence and live counts before returning (114–211). `_export_publication_proofs` uses active vault/document collections and the served code pointer; an unavailable proof is omitted rather than invented (55–111). Manifest parsing validates records and prevents snapshot filenames from escaping the archive directory (343–459). `sweep_archive` deletes expired completed archives first, then evicts oldest-first to meet the size cap (462–540).
- [src/vaultspec_rag/storage_identity.py](../../../../src/vaultspec_rag/storage_identity.py) provides the backend-dispatching `load_identity`, `record_identity`, and `sidecar_path` interfaces (37–41). Server identity is kept on the root's manifest entry; local identity is stored in a per-root `collection-identity.json` sidecar (1–23, 54–56, 84–124). Missing or unusable local evidence reads as absent; recording is best effort, with an in-process lock and atomic sidecar write (59–81, 127–183).
- [src/vaultspec_rag/storage_manifest.py](../../../../src/vaultspec_rag/storage_manifest.py) defines the persisted root/namespace records, archive records, and reconciliation result (79–187). It reads and atomically writes a version-2 root map in the managed status directory (244–250, 335–394); missing, unreadable, or incompatible manifests resolve to an empty mapping, and unusable records are skipped (293–367). Operations record roots and identities, preserve archived identity on restore, narrow records after partial collection destruction, remove/rekey entries, classify roots, maintain orphan and activity clocks, and remove stale entries only when both root and data are gone (397–881).
- [src/vaultspec_rag/storage_migration.py](../../../../src/vaultspec_rag/storage_migration.py) exposes `migrate_collections` and `MigrateResult` for copying mapped collections between Qdrant backends (37–54, 109–119). It recreates the destination vector schema, copies points with payload and vectors in pages, and compares destination and source counts; absent sources, existing targets, dry runs, and copy failures have explicit results (56–106, 121–180). Optional follow-up publishes a migrated served-code pointer only after successful copies, and `carry_migrated_identity` transfers recorded source provenance to successfully migrated target names through the identity accessors (183–276).
- [src/vaultspec_rag/storage_reclamation.py](../../../../src/vaultspec_rag/storage_reclamation.py) defines reclamation policy/results, evaluates orphan and live temporary-rooted idle tiers, and runs scheduled maintenance (36–112, 314–447, 498–534, 794–927). Before a destructive action it requires a readable active-job probe, no active index job for the prefix, and a fresh whole-prefix point count equal to the survey; data-bearing collections are archived and recounted before deletion (599–720). The cycle advances manifest clocks, evaluates decisions, reclaims superseded code generations, applies namespace reclamation, sweeps archives, optionally reconciles geometry, and returns survey and health rollups (794–927). Separate generation helpers resolve current served-generation evidence, consult reader liveness and grace stamps, and drop only approved collections (930–1118).
- No documentation-only or test files were assigned. The docstrings above are documentation claims embedded in implementation files; no test expectations or passing-test status can be reported from this slice.

## Interfaces and data flow

- Namespace archive flow: `archive_prefix(client, prefix, snapshots_dir, archive_dir)` returns snapshot and manifest paths. It reads the manifest attribution and identity, derives publication proofs from the root's publication evidence, snapshots and moves each matching Qdrant collection, writes `snapshot-manifest.json`, then checks its artifacts and live point counts ([src/vaultspec_rag/storage_archive.py:55–211](../../../../src/vaultspec_rag/storage_archive.py#L55); [src/vaultspec_rag/storage_manifest.py:189–236](../../../../src/vaultspec_rag/storage_manifest.py#L189)). `sweep_archive` accepts a clock, retention days, and byte limit and returns deleted archive directories ([src/vaultspec_rag/storage_archive.py:462–540](../../../../src/vaultspec_rag/storage_archive.py#L462)).
- Identity flow: callers provide root, backend, exact collection name, and optionally local directory to `load_identity` / `record_identity`. Server calls dispatch to the storage manifest; local calls use a sidecar beneath the supplied directory. Records are `CollectionIdentity` payloads ([src/vaultspec_rag/storage_identity.py:54–56, 84–183](../../../../src/vaultspec_rag/storage_identity.py#L54); [src/vaultspec_rag/storage_manifest.py:471–518](../../../../src/vaultspec_rag/storage_manifest.py#L471)).
- Manifest flow: `record_root`, identity and restore recorders, rekey/removal/narrowing operations, and clock updates perform locked read-modify-write through `load_manifest` and `_write_manifest`; the manifest file is under `managed_status_dir()` ([src/vaultspec_rag/storage_manifest.py:244–250, 335–394, 397–613, 659–881](../../../../src/vaultspec_rag/storage_manifest.py#L244)). Root classification uses filesystem existence and the root anchor to distinguish live, orphaned, and unverifiable roots (616–656).
- Migration flow: a source-to-target name map drives per-collection results. A real copy reads Qdrant collection configuration and pages `scroll(with_vectors=True)` into `upload_points`; optional root handling publishes the served-code pointer and `carry_migrated_identity` copies known provenance to the destination ([src/vaultspec_rag/storage_migration.py:56–106, 121–180, 183–276](../../../../src/vaultspec_rag/storage_migration.py#L56)).
- Maintenance flow: `run_maintenance_cycle` gathers namespace surveys, updates orphan/activity stamps, evaluates eligible orphan or optional live-temp idle decisions, then processes superseded generations. For eligible namespace decisions it rechecks liveness and points, archives data-tier namespaces and recounts, calls `delete_prefix`, applies archive retention, optionally reconciles collection geometry, and returns decisions and rollups ([src/vaultspec_rag/storage_reclamation.py:794–927](../../../../src/vaultspec_rag/storage_reclamation.py#L794)). A failed liveness or count probe defers rather than authorizing a drop (148–199, 689–720).
- Superseded-generation flow: cycle roots are paired with derived code collection names; `reclaim_superseded_generations` lists live collections, surveys served-generation status, applies grace/reader decisions, drops approved collections, and returns advanced stamps for the cycle caller to persist (723–777, 930–1118).

## Evidence

- Archives require a manifest-attributed namespace and return only after snapshot publication, cleanup of unnamed snapshots, and verification — [src/vaultspec_rag/storage_archive.py:114-211](../../../../src/vaultspec_rag/storage_archive.py#L114) — implementation.
- Archive publication proofs are attached for currently active collections when readable, while unprovable publication state is skipped — [src/vaultspec_rag/storage_archive.py:55-111](../../../../src/vaultspec_rag/storage_archive.py#L55) — implementation.
- Re-archive carries only old records whose names and files remain valid; snapshot-only stale artifacts are removed — [src/vaultspec_rag/storage_archive.py:214-305](../../../../src/vaultspec_rag/storage_archive.py#L214) — implementation.
- Retention is driven by manifest `completed_at`, then by oldest archive first under the byte cap — [src/vaultspec_rag/storage_archive.py:462-531](../../../../src/vaultspec_rag/storage_archive.py#L462) — implementation.
- Collection identity has disjoint server-manifest and local-sidecar homes, and absent identity remains absent — [src/vaultspec_rag/storage_identity.py:1-23,54-124](../../../../src/vaultspec_rag/storage_identity.py#L1) — documentation claim plus implementation at 54-124.
- Sidecar updates are serialized in-process and atomically written; identity recording failures are swallowed as best-effort — [src/vaultspec_rag/storage_identity.py:127-183](../../../../src/vaultspec_rag/storage_identity.py#L127) — implementation.
- The version-2 manifest is atomically persisted; missing/corrupt top-level data loads as empty and invalid entries are skipped — [src/vaultspec_rag/storage_manifest.py:293-394](../../../../src/vaultspec_rag/storage_manifest.py#L293) — implementation.
- Re-recording a root preserves schema and identity evidence rather than restamping it; collection creation is the server identity/schema stamping point — [src/vaultspec_rag/storage_manifest.py:397-518](../../../../src/vaultspec_rag/storage_manifest.py#L397) — implementation and docstring claims.
- Restore persists archived schema/identity without stamping current values; partial destruction narrows collection and identity records — [src/vaultspec_rag/storage_manifest.py:521-595](../../../../src/vaultspec_rag/storage_manifest.py#L521) — implementation.
- A root is orphaned only when absent and its anchor remains reachable; unreachable roots are unverifiable — [src/vaultspec_rag/storage_manifest.py:616-656](../../../../src/vaultspec_rag/storage_manifest.py#L616) — implementation.
- Orphan and idle clocks are persisted from survey observations; idle time advances only when consecutive verified counts hold still and the root is not unverifiable — [src/vaultspec_rag/storage_manifest.py:659-788](../../../../src/vaultspec_rag/storage_manifest.py#L659) — implementation.
- Manifest reconciliation removes an entry only if both the root is orphaned and its prefix is absent from known live server prefixes — [src/vaultspec_rag/storage_manifest.py:845-881](../../../../src/vaultspec_rag/storage_manifest.py#L845) — implementation.
- Collection migration recreates schema, copies paged vectors/payloads, and verifies count; targets already present are skipped — [src/vaultspec_rag/storage_migration.py:56-106,121-180](../../../../src/vaultspec_rag/storage_migration.py#L56) — implementation.
- Migrated served-code publication is suppressed if any result failed; identity carry is limited to migrated pairs with readable source provenance — [src/vaultspec_rag/storage_migration.py:183-276](../../../../src/vaultspec_rag/storage_migration.py#L183) — implementation.

- Destruction requires a conclusive inactive-job probe and a matching fresh point count; point-bearing reclamation also verifies stability across archiving — [src/vaultspec_rag/storage_reclamation.py:536-595,599-720](../../../../src/vaultspec_rag/storage_reclamation.py#L536) — implementation.
