## Interfaces and data flow

- QdrantSupervisor(binary, \*\*options) accepts an optional resolved-binary object and options for HTTP/gRPC ports, storage, log retention/path, migration origin, and API key (112-132, 386-441). A missing binary means attached mode. The supervisor generates or retains one API key for its lifetime, including restarts (407-434).
- spawn() builds a restricted child environment from a fixed OS-variable allowlist plus explicit QDRANT\_\_\* values for loopback REST/gRPC listeners, API key, storage/snapshots paths, disabled telemetry, and configured collection-load concurrency. It creates storage/snapshot directories, publishes the managed key, invokes spawn_verified, optionally assigns the Windows job, and starts the output drain (453-559). The path helper converts Windows paths to extended-length syntax (165-188).
- The drain reads 64 KiB chunks, decodes UTF-8 with replacement, keeps a bounded recent-output ring/progress count, and writes raw bytes through an optional rotating sink. A sink failure disables persistence but leaves pipe draining/capture active. A daemon thread owns this work; stop/spawn guard against overlapping writers (94-102, 419-430, 547-638).
- wait_ready(timeout) probes the loopback listener's /readyz endpoint, returns on HTTP 200, child death, no-progress timeout, or a total ceiling of four times the patience value. Output-line progress renews the patience deadline. With no explicit timeout, the configured value falls back to the default on malformed or non-positive input (278-303, 640-761, 662-731).
- start() spawns and waits; after a failed readiness check it stops the child, and only attempts quarantine when the child died, auto-quarantine is enabled, and the per-start limit is not reached. It then reports the captured tail or retries after a successful move (763-858). A ready server is additionally checked for data-plane authentication; an unprotected server is stopped and rejected (942-961, 795-804).
- restart() stops first, records refused attempts separately from starts, and counts a restart only after a process is spawned. It waits for readiness and republishes identity after a successful, authenticated restart. One started restart or five consecutive refused attempts exhaust automatic restart allowance (860-940).
- stop() ends the process tree and joins the drain, returning true only when both converge; a live drain remains referenced as a single-writer guard. is_alive() uses endpoint readiness in attached mode and child-process exit state in owned mode (968-1007).
- state() returns a QdrantRuntimeState with server mode, URL, PID, liveness, port, pinned version, restart count, and extra fields for quarantine listing, migration origin, binary source, and latest restart refusal. server_version() reads the root route’s JSON version or returns an empty string if unreachable (1009-1065).
- start_supervised_from_config() reads settings, probes Qdrant, reads identity, and delegates the action decision. It attaches only after credential checks; refuses a classified conflict; or follows orphan-reap then spawn. The spawn path resolves a binary, warns for operator-supplied binaries, judges store format, configures the supervisor, starts it, sets it active, writes identity, and stamps the opened store version (1242-1428).
- active_supervisor() and set_active_supervisor() expose a process-global supervisor. runtime_state() returns its live state when present; otherwise it reports remote mode when qdrant_url is set and local mode otherwise (1431-1466).
