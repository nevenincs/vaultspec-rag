## Capability summary

All eight files are tests. No implementation responsibility or documentation claim was directly inspected.

- [src/vaultspec_rag/tests/test_stat_gate.py](../../../../src/vaultspec_rag/tests/test_stat_gate.py): tests stat-evidence reuse and rehash decisions, racy timestamp refusal, pruning, missing-file handling, batched hashing order/failure/tick behavior, pooled hashing, and binding externally computed hashes. It also exercises expected wiring through `CodebaseIndexer._hash_changed_paths` and `VaultIndexer._hash_documents`. `TestDocumentIndexerGateWiring` is an empty class in this range, so it contains no document-indexer assertion.
- [src/vaultspec_rag/tests/test_status_service_skew.py](../../../../src/vaultspec_rag/tests/test_status_service_skew.py): sets up a real loopback HTTP server with selected `/service-state` and `/health` answers, then tests CLI status on an older/unreadable service, selection of the running service's preprocess mode, the no-answer fallback, and that `/health` avoids installation and hardware probes.
- [src/vaultspec_rag/tests/test_stdio_lifetime.py](../../../../src/vaultspec_rag/tests/test_stdio_lifetime.py): tests ancestor PID walk bounds/cycles, watchdog enable/disable parsing and installation, Windows process/pipe anchors, POSIX reparent and explicit-PID liveness behavior, emitted exit events, cleanup helpers, and precedence between the package and framework environment switches. Windows and POSIX portions are platform-gated.
- [src/vaultspec_rag/tests/test_stdio_retained_ancestor.py](../../../../src/vaultspec_rag/tests/test_stdio_retained_ancestor.py): Windows-only subprocess tests for rejecting a retained but dead discovered ancestor, allowing precise handles to signal on real process death, and closing already-open handles while preserving an invalid-handle error.
- [src/vaultspec_rag/tests/test_storage_adversarial.py](../../../../src/vaultspec_rag/tests/test_storage_adversarial.py): tests CLI JSON/`--yes` guards, path traversal rejection, reconcile result rendering, restore refusal and preview envelopes, and exactly one structured fault envelope for unreachable storage. Its module docstring says the server-backed prune protection is covered in integration tests; that suite was not inspected.
- [src/vaultspec_rag/tests/test_storage_identity.py](../../../../src/vaultspec_rag/tests/test_storage_identity.py): tests identity stamping and retrieval for server manifests and local sidecars; preservation of stale schema/identity evidence across root updates and rekey; three-valued conformance; local-store ensure behavior for width, dense-model, sparse-model, and missing-stamp cases; sparse clean-rebuild recovery; and when served verdicts change during verified publication under the lifecycle lock.
- [src/vaultspec_rag/tests/test_storage_maintenance_tick.py](../../../../src/vaultspec_rag/tests/test_storage_maintenance_tick.py): tests that a maintenance job record reaches an error phase when a malformed Qdrant URL makes client construction raise.
- [src/vaultspec_rag/tests/test_storage_manifest.py](../../../../src/vaultspec_rag/tests/test_storage_manifest.py): tests root-prefix manifest round trips, safe root classification and reconciliation, rekey/removal, and snapshot-manifest identity/null/completion-time fields.

## Interfaces and data flow

The following are interfaces exercised or constructed by these tests; their implementations were not inspected.

- The stat-gate tests load a `StatEvidenceGate` sidecar, probe with `os.stat` data, digest and record on a miss, persist evidence, prune absent relative keys, and call `hash_paths` with ordered `(relative key, Path)` pairs. Expected batch results expose `hashes` and `failures`; an optional reporter receives progress advances. The indexer wiring tests pass path maps into `_hash_changed_paths` or `_hash_documents` and check sidecar evidence afterward ([src/vaultspec_rag/tests/test_stat_gate.py:32-46, 129-146, 188-263, 315-402](../../../../src/vaultspec_rag/tests/test_stat_gate.py#L32)).
- The status tests register a temporary service status directory and Qdrant path, then direct a real CLI invocation or `_running_service_preprocess_mode()` through a loopback server with chosen routes. The health test constructs an HTTP app and requests `/health` ([src/vaultspec_rag/tests/test_status_service_skew.py:42-74, 76-96, 130-190](../../../../src/vaultspec_rag/tests/test_status_service_skew.py#L42)).
- The watchdog tests exercise PID/handle functions and real subprocesses. They inspect JSON event fields written to child stderr and process exit status; environment inputs include the package-scoped switch and `VAULTSPEC_STDIO_WATCHDOG` (`[src/vaultspec_rag/tests/test_stdio_lifetime.py:50-103, 106-201, 274-442, 466-535](../../../../src/vaultspec_rag/tests/test_stdio_lifetime.py#L50); [src/vaultspec_rag/tests/test_stdio_retained_ancestor.py:26-201](../../../../src/vaultspec_rag/tests/test_stdio_retained_ancestor.py#L26)`).
- Storage CLI tests call rendering/guard helpers or invoke `app` with `server storage restore`, `survey`, and `prune` arguments. JSON expectations use one-line envelopes with `ok`, `command`, `error`, and `data` fields ([src/vaultspec_rag/tests/test_storage_adversarial.py:36-76, 88-236, 253-438, 440-496](../../../../src/vaultspec_rag/tests/test_storage_adversarial.py#L36)).
- Identity tests write JSON through manifest/sidecar-facing APIs and open `VaultStore` to ensure collections and inspect conformance. A code replacement helper creates a build target, records a segment acknowledgement, publishes it, and checks served collection and publication-proof state ([src/vaultspec_rag/tests/test_storage_identity.py:81-202, 238-288, 291-511, 560-719](../../../../src/vaultspec_rag/tests/test_storage_identity.py#L81)).
- Manifest tests call record/load/classify/reconcile/rekey/remove and write snapshot metadata under an isolated managed status directory ([src/vaultspec_rag/tests/test_storage_manifest.py:39-46, 49-238, 240-346](../../../../src/vaultspec_rag/tests/test_storage_manifest.py#L39)). The maintenance test resets the job registry, sets a malformed endpoint, calls `_storage_maintenance_tick_sync`, and inspects the resulting maintenance record ([src/vaultspec_rag/tests/test_storage_maintenance_tick.py:16-38](../../../../src/vaultspec_rag/tests/test_storage_maintenance_tick.py#L16)).
