## Capability summary

- [src/vaultspec_rag/qdrant_runtime/\_provision.py](../../../../src/vaultspec_rag/qdrant_runtime/_provision.py) owns managed Qdrant release planning and installation. It chooses an asset through the resolver, can preview without network or filesystem writes, installs from HTTPS or an operator-provided local archive, verifies archive and executable SHA-256 pins, stages files beside the target, atomically replaces the executable only after verification, then writes a manifest. It supports existing-install refusal/upgrade rules, manifest repair, free-space admission, progress and actionable failure reports, process-wide provisioning exclusion, abandoned-stage cleanup, a bounded version listing, and removal of managed version directories. The module's public names are listed at lines 90-97.
- [src/vaultspec_rag/qdrant_runtime/\_resolve.py](../../../../src/vaultspec_rag/qdrant_runtime/_resolve.py) maps supported platform/architecture pairs to pinned release assets and resolves the active binary from the operator settings or managed install. It also probes the loopback Qdrant endpoint, reads and writes the managed identity sidecar, classifies owner incarnations and port states, decides attach/refuse/reap/spawn policy, validates attachment witnesses, and reaps an orphaned child. Public names are listed at lines 75-103.
- [src/vaultspec_rag/qdrant_runtime/\_spawn_trust.py](../../../../src/vaultspec_rag/qdrant_runtime/_spawn_trust.py) revalidates and holds a resolved executable across process creation, launches it from that held file, and checks a managed install's neighboring files before and just after spawn. It exposes verification, verified spawn, and an operator-binary warning function (lines 63-67).
- [src/vaultspec_rag/qdrant_runtime/\_store_format.py](../../../../src/vaultspec_rag/qdrant_runtime/_store_format.py) records which Qdrant version successfully opened a storage directory and decides whether a candidate version may open it. It also reports quarantined collection directories. Public names are listed at lines 44-52.
- No test modules were in the assigned slice. No test expectations can be reported as inspected evidence.

## Interfaces and data flow

- `provision(upgrade=False, dry_run=False, archive=None, on_progress=...)` returns a `ProvisionReport`. It builds a request from `qdrant_bin_dir()`, plans first, returns a refusal/unchanged report directly, previews a planned repair or install for dry-run, or takes the provisioning lock, sweeps abandoned staging, plans again under the lock, and repairs or installs ( [src/vaultspec_rag/qdrant_runtime/\_provision.py:1237-1317](../../../../src/vaultspec_rag/qdrant_runtime/_provision.py#L1237)). The archive path must be outside the managed directory; a local archive is read in place and is neither moved nor deleted (`986-1007`, `510-551`).
- Install data flow: `_verified_archive` obtains and hashes the network or local archive; `_binary_member` accepts exactly one regular executable member by basename; `_stage_verified_executable` checks the member's recorded size against available space, writes a staging file, then hashes it; `_install` replaces the target and writes the manifest last ([src/vaultspec_rag/qdrant_runtime/\_provision.py:358-410](../../../../src/vaultspec_rag/qdrant_runtime/_provision.py#L358), `510-625`, `908-963`). Network transfers use the imported bounded downloader and configured redirect hosts (`553-582`). `extract_verified_archive` is a separate public archive helper that hashes before extraction (`421-476`).
- `provisioned_versions()` returns up to 10 version-entry dictionaries, with `verified`, `source`, `provisioned_at`, and `problem` fields; only the current pinned version can be verified. `clean_provisioned(keep_current=False)` returns removed version names and skips symlinked/non-directory entries ([src/vaultspec_rag/qdrant_runtime/\_provision.py:1320-1403](../../../../src/vaultspec_rag/qdrant_runtime/_provision.py#L1320)).
- `asset_for_platform(platform=None, machine=None)` returns a pinned asset or raises `UnsupportedPlatformError`; `binary_filename()` and `qdrant_bin_dir(version=...)` select the executable name and managed version path ([src/vaultspec_rag/qdrant_runtime/\_resolve.py:187-257](../../../../src/vaultspec_rag/qdrant_runtime/_resolve.py#L187)). `resolve_binary(version=...)` returns `ResolvedBinary | None`; operator settings take precedence and a managed executable is returned only if its content matches the pin ([src/vaultspec_rag/qdrant_runtime/\_resolve.py:831-973](../../../../src/vaultspec_rag/qdrant_runtime/_resolve.py#L831)). `read_manifest()` and `read_qdrant_identity()` return a parsed dictionary/identity or `None` on absence or unreadable/malformed input (`260-278`, `375-410`).
- Endpoint and lifecycle interfaces: `probe_qdrant_endpoint(port, timeout=...)` returns listening/ready/version ([src/vaultspec_rag/qdrant_runtime/\_resolve.py:106-171](../../../../src/vaultspec_rag/qdrant_runtime/_resolve.py#L106)); `classify_qdrant_state()` returns one of absent, stale identity, managed orphan, managed running, owner unverified, or foreign, and `decide_qdrant_action(...)` returns an action plus reason (`697-796`). `verify_attachable(...)` returns `(bool, reason)` after endpoint, identity, version/storage/port, process-incarnation, image, and listener checks (`591-694`). `write_qdrant_identity(...)` atomically publishes storage/version, owner and child PIDs, port, and start-time witnesses; `reap_qdrant_orphan(...)` reports whether the target is gone (`497-588`).
- `verify_resolved_binary(resolved)` checks without spawning; `spawn_verified(resolved, env, cwd)` returns `Popen[bytes]` with combined output piped to the caller. It uses the held executable as `executable`, sets stdin to `DEVNULL`, pins cwd, creates a process group/session, and kills the child if the post-start check fails ([src/vaultspec_rag/qdrant_runtime/\_spawn_trust.py:153-266](../../../../src/vaultspec_rag/qdrant_runtime/_spawn_trust.py#L153)).
- `store_format_path`, `read_store_format`, and `write_store_format` address an in-store JSON stamp. `judge_store_format(storage_dir, spawning_version, identity=None)` returns a `StoreFormatVerdict`; `may_spawn` is false only for nonconforming, while `may_auto_quarantine` is true only for conforming. A permitted version-crossing verdict sets `migrates_store=True` ([src/vaultspec_rag/qdrant_runtime/\_store_format.py:64-183](../../../../src/vaultspec_rag/qdrant_runtime/_store_format.py#L64), `257-378`).
