## Capability summary

- [src/vaultspec_rag/search/__init__.py](../../../../src/vaultspec_rag/search/__init__.py) re-exports package-facing search models, VaultSearcher, query parser, graph reranker, filter-validation symbols, and combined-domain outcome types. Its module docstring describes this package as the former monolith's unchanged public surface.
- [src/vaultspec_rag/search/\_models.py](../../../../src/vaultspec_rag/search/_models.py) defines ParsedQuery, passage spans, vault/codebase SearchResult, and independent-document DocumentSearchResult. Results carry source-specific metadata, score, display snippet, full rerank content, and (for vault hits) candidate passages.
- [src/vaultspec_rag/search/\_parsing.py](../../../../src/vaultspec_rag/search/_parsing.py) extracts inline type, feature, date, tag, language, path, function, class, node-type, intent, status, and noise-domain tokens into canonical filter keys and returns cleaned query text. Repeated exclude/only/include tokens accumulate.
- [src/vaultspec_rag/search/\_options.py](../../../../src/vaultspec_rag/search/_options.py) defines typed keyword surfaces and frozen option values for vault, codebase, document, and combined search, plus searcher construction dependencies. CombinedSearchOptions.from_arguments partitions selected flat arguments by domain.
- [src/vaultspec_rag/search/\_searcher.py](../../../../src/vaultspec_rag/search/_searcher.py) owns query encoding/cache lookup, GPU serialization, lazy CrossEncoder loading, graph caching, timed single-domain entry points, and combined search orchestration. Vault, codebase, and document pipelines each call their corresponding store search, map rows, and apply domain-specific ranking and filtering.
- [src/vaultspec_rag/search/\_result_shaping.py](../../../../src/vaultspec_rag/search/_result_shaping.py) supplies locator rendering, vault path normalization, inline/explicit domain-token merging, chunk grouping, passage selection, phase-timing helpers, path-glob expansion/filtering, raw-row mapping, deterministic combined top-k selection, and preference-score adjustment.
- [src/vaultspec_rag/search/\_postprocess.py](../../../../src/vaultspec_rag/search/_postprocess.py) classifies preference categories through the shared domain classifier and collapses near-tied locale variants while annotating the surviving snippet.
- [src/vaultspec_rag/search/\_rerank.py](../../../../src/vaultspec_rag/search/_rerank.py) applies bounded vault-graph nudges for incoming links and neighboring feature tags; codebase results pass through.
- [src/vaultspec_rag/search/\_intent_rank.py](../../../../src/vaultspec_rag/search/_intent_rank.py) applies configured vault type/status multipliers, a per-type cap, and an optional ADR status filter. Codebase results are retained unchanged by these helpers.
- [src/vaultspec_rag/search/\_noise.py](../../../../src/vaultspec_rag/search/_noise.py) resolves persistent and per-call code-domain hide/only/demote policy, classifies legacy payloads from their paths, filters raw candidates, and subtracts a score penalty for demoted domains.
- [src/vaultspec_rag/search/\_outcomes.py](../../../../src/vaultspec_rag/search/_outcomes.py) models success or failure per selected search domain and a combined outcome that preserves partial failure, exposes source-readiness facts, and deterministically selects a combined result page.
- [src/vaultspec_rag/search/\_typesafe_answers.py](../../../../src/vaultspec_rag/search/_typesafe_answers.py) defines answer/evaluation values and validates hosted choice, score, and Noul judgments against submitted question definitions, including probability distributions, score legends, and token usage.
- [src/vaultspec_rag/search/\_typesafe_cache.py](../../../../src/vaultspec_rag/search/_typesafe_cache.py) implements an in-memory response LRU bounded by TTL, entry count, and body bytes; keys are byte digests.
- [src/vaultspec_rag/search/\_typesafe_context.py](../../../../src/vaultspec_rag/search/_typesafe_context.py) keeps one classification session in a request-local ContextVar so nested/compound searches can reuse it and resets the scope on exit.

## Interfaces and data flow

- Public package entry points include parse_query, rerank_with_graph, validate_search_filters, and VaultSearcher ([src/vaultspec_rag/search/__init__.py:14-24, 26-38](../../../../src/vaultspec_rag/search/__init__.py#L14)). The searcher exposes untimed and timed vault, codebase, document, and combined methods ([src/vaultspec_rag/search/\_searcher.py:974-999, 1065-1073, 1074-1121, 1114-1191, 1193-1241, 1328-1335](../../../../src/vaultspec_rag/search/_searcher.py#L974)).
- A query is parsed first; cleaned text and filters travel in \_EncodedSearchQuery. Dense and optionally sparse vectors are cached by (surface, query_text); a cache entry lacking sparse data is recomputed when sparse encoding is enabled ([src/vaultspec_rag/search/\_searcher.py:130-141, 915-972](../../../../src/vaultspec_rag/search/_searcher.py#L130)). Timed surface calls gather options, enter a classification scope, run the domain pipeline, and record timings ([src/vaultspec_rag/search/\_searcher.py:1001-1063](../../../../src/vaultspec_rag/search/_searcher.py#L1001)).
- Vault search builds metadata filters, retrieves hybrid candidates, drops index-type rows, maps full row content, reranks the full candidate window, groups chunks by document, applies graph and intent ranking plus any status filter, then selects query-relevant passages for the returned page ([src/vaultspec_rag/search/\_searcher.py:560-664](../../../../src/vaultspec_rag/search/_searcher.py#L560)).
- Code search merges inline and explicit noise-domain controls, pushes hide/only restrictions into the codebase store request, applies path globs and fallback domain filtering afterward, and widens retrieval until the page fills, raw results run out, or a cap is reached. It then maps, reranks, demotes, applies optional preference nudges and locale deduplication, and truncates to top-k ([src/vaultspec_rag/search/\_searcher.py:690-773, 775-913](../../../../src/vaultspec_rag/search/_searcher.py#L690)).
- Document search passes document metadata filters to its collection, maps independent document rows and locators, and reranks/classifies them ([src/vaultspec_rag/search/\_searcher.py:1123-1182](../../../../src/vaultspec_rag/search/_searcher.py#L1123)).
- Combined search parses and encodes once, gives each domain the same per-domain top-k value (at least one), queries vault/code/document sequentially, and selects a stable global page by score, source order, path, then ID. When no classifier session is present, it also calls the content reranker on the collected candidates before final selection ([src/vaultspec_rag/search/\_searcher.py:1202-1241, 1243-1326](../../../../src/vaultspec_rag/search/_searcher.py#L1202); [src/vaultspec_rag/search/\_result_shaping.py:473-487](../../../../src/vaultspec_rag/search/_result_shaping.py#L473)).
- The CrossEncoder receives rerank_text (falling back to snippet) bounded by configured max length times six characters. Prediction runs under the GPU section, halves its batch size on recognized OOM, and retries down to batch size one ([src/vaultspec_rag/search/\_searcher.py:293-384](../../../../src/vaultspec_rag/search/_searcher.py#L293)).
- Combined outcome values expose per-domain error details, partial/overall success, selected results, readiness aggregation, and a wire status payload ([src/vaultspec_rag/search/\_outcomes.py:52-179](../../../../src/vaultspec_rag/search/_outcomes.py#L52)). No caller of CombinedSearchOutcome appears in the assigned ranges.

- Imports whose implementations were not inspected include search.\_validation; search.\_typesafe_policy and search.\_typesafe_transport; \_domain; \_store_search; \_store_models; \_search_state; \_source_types; config.\_settings; embeddings; \_gpu; job_control; store_runtime; and vaultspec_core.graph. Their names show boundaries only; behavior behind them is unverified.
- CombinedSearchOptionArguments inherits like_ids and unlike_ids fields, but the visible from_arguments construction does not copy them into per-domain option values. This is a code observation, not verified user-visible behavior; impact needs the combined-option call path and relevant tests.
