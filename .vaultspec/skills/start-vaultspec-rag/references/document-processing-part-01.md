## Capability summary

- [src/vaultspec_rag/indexer/\_html.py](../../../../src/vaultspec_rag/indexer/_html.py) provides dependency-free HTML-to-visible-text normalization for indexing. It suppresses script/style/head-like bodies, adds line structure around block elements, collapses repeated blank lines and trims lines; selected parse failures preserve the original HTML (lines 1-9, 20-21, 59-120).
- [src/vaultspec_rag/indexer/\_ignore_specs.py](../../../../src/vaultspec_rag/indexer/_ignore_specs.py) gathers hardcoded and nested `.gitignore` exclusions plus root `.vaultragignore`, compiles matchers, and exposes shared membership checks. It prunes ignored directories during `.gitignore` discovery, prefixes nested patterns, keeps fixed exclusions last, and has a separate builder that merges CLI extra excludes (lines 24-32, 35-97, 100-167).
- [src/vaultspec_rag/indexer/\_incremental_commit.py](../../../../src/vaultspec_rag/indexer/_incremental_commit.py) centralizes incremental supersede, publish, cleanup, obsolete-ID deletion, and generation metadata publication. Typed request/result records carry the paths, hashes, pipeline run, reporter, checkpoint, and run-control state (lines 36-87, 112-150, 152-213, 215-300).
- [src/vaultspec_rag/indexer/\_index_lifecycle.py](../../../../src/vaultspec_rag/indexer/_index_lifecycle.py) wraps an indexer's locked body with cancellation checks, `service.index` started/failed/completed events, and manifest activity-clock touches at run start and after successful body completion. It supports shared incremental mode labels and optional completion fields (lines 33-80, 83-159).
- [src/vaultspec_rag/indexer/\_index_schema.py](../../../../src/vaultspec_rag/indexer/_index_schema.py) defines exported schema identity constants: code embedding schema 2, document embedding schema 1, and vault point schema 3 (lines 1-13).
- [src/vaultspec_rag/indexer/\_pool_guard.py](../../../../src/vaultspec_rag/indexer/_pool_guard.py) owns guarded spawn-pool construction. It temporarily enables Python safe-path mode for workers with reference-counted restoration, rejects an unsafe `-E` parent configuration, installs a worker parent-death watcher, and wraps `ProcessPoolExecutor` creation in one context manager (lines 58-84, 87-124, 129-179).
- [src/vaultspec_rag/indexer/\_preprocess_approval.py](../../../../src/vaultspec_rag/indexer/_preprocess_approval.py) persists per-root operator approval bound to canonical root identity and policy-byte digest. It reads a managed status store fail-closed, drops malformed records, writes atomically with private/durable options, and exposes read/check/approve/revoke operations (lines 1-21, 49-55, 73-79, 82-176, 179-238).
- [src/vaultspec_rag/indexer/\_preprocess_cache.py](../../../../src/vaultspec_rag/indexer/_preprocess_cache.py) stores successful validated preprocessor outputs in sharded JSON files below the data directory. Its identity combines source hash, path semantics, and a fingerprint of execution semantics; corrupt, mismatched, or invalid entries become misses, and write errors are swallowed as cache-optimization failures (lines 1-21, 59-70, 73-143, 146-219).
- [src/vaultspec_rag/indexer/\_preprocess_config.py](../../../../src/vaultspec_rag/indexer/_preprocess_config.py) loads root `.vaultragpreprocess.toml`, resolves rules, orders and matches them by priority then declaration order, checks approval and hook state, validates invocation forms/options, and materializes worker-facing picklable rule/context shapes. It supports command or `module:callable` entry-point rules, single or batch commands, target/version, error disposition, timeout, source/output limits, cache path independence, and strict/non-strict config handling (lines 1-21, 47-81, 103-158, 160-263, 266-290, 292-379, 386-684, 687-732).
- [src/vaultspec_rag/indexer/\_preprocess_entry.py](../../../../src/vaultspec_rag/indexer/_preprocess_entry.py) is the subprocess CLI for an entry-point extractor. It imports the callable, passes it a source path, serializes its returned model or JSON-compatible object to stdout, and maps resolution/call/serialization failures to nonzero exit codes (lines 1-25, 38-91).
- [src/vaultspec_rag/indexer/\_preprocess_glue.py](../../../../src/vaultspec_rag/indexer/_preprocess_glue.py) builds `PreprocessContext` from an active resolved policy, identifies active rule count, and tallies worker success/skip results (lines 1-8, 25-50, 53-71).
- [src/vaultspec_rag/indexer/\_preprocess_runner.py](../../../../src/vaultspec_rag/indexer/_preprocess_runner.py) executes command and entry-point hooks as bounded child processes, validates single-file and batch output against the schema, validates source binding and emitted-text caps, and resolves errors through each rule's skip/fail/passthrough policy. It includes curated child-environment setup, cooperative checkpoints, bounded stdout/stderr pipe readers, timeout/process-tree cleanup, and temporary batch manifests (lines 1-22, 62-88, 98-129, 164-261, 270-467, 470-652, 655-928).
- [src/vaultspec_rag/indexer/\_preprocess_schema.py](../../../../src/vaultspec_rag/indexer/_preprocess_schema.py) defines the versioned host-to-extractor invocation envelope and extractor-to-indexer output contract, including typed locators, text/units XOR, metadata limits, and an explicit rejection for output schema versions newer than supported (lines 1-15, 41-78, 81-102, 104-140, 143-232).

## Interfaces and data flow

- Index lifecycle callers supply `IndexLifecycleRequest` and a zero-argument body; the wrapper checkpoints around event/activity stamps and body execution, returns the body's `IndexResult`, and emits common count/duration fields plus optional domain fields ( [src/vaultspec_rag/indexer/\_index_lifecycle.py:37-54,83-159](../../../../src/vaultspec_rag/indexer/_index_lifecycle.py#L37)).
- Incremental publication starts from a hash mapping plus `to_index`, attempted paths, and a pipeline run. It supersedes only the selected hash subset, records prior/current IDs, invokes the injected chunk-and-embed callable, then later removes obsolete IDs and publishes through the injected generation lifecycle ([src/vaultspec_rag/indexer/\_incremental_commit.py:50-84,112-150,264-300](../../../../src/vaultspec_rag/indexer/_incremental_commit.py#L50)). Failed ordinary publication attempts try to delete newly introduced IDs while protecting checkpoint-ledger IDs; `UnsettledCodeConsumerError` is re-raised without this cleanup path ([src/vaultspec_rag/indexer/\_incremental_commit.py:152-199](../../../../src/vaultspec_rag/indexer/_incremental_commit.py#L152)).
- Ignore matching accepts project-relative paths and compiled `pathspec` specs. `.gitignore` collection recursively reads reachable ignore files while pruning ignored directories; `.vaultragignore` collection is root-only, and the builder appends transient `extra_excludes` ([src/vaultspec_rag/indexer/\_ignore_specs.py:24-32,35-97,122-167](../../../../src/vaultspec_rag/indexer/_ignore_specs.py#L24)).
- Preprocessing resolves a policy into `PreprocessRule` values; `PreprocessConfig.match()` chooses the first matching ordered rule. `PreprocessContext` carries config, cache root, project root, emitted-byte cap, and optional source cap to the worker ([src/vaultspec_rag/indexer/\_preprocess_config.py:103-158,160-263,266-290](../../../../src/vaultspec_rag/indexer/_preprocess_config.py#L103)). The glue materializes that context only for `PreprocessHookState.ACTIVE` ([src/vaultspec_rag/indexer/\_preprocess_glue.py:25-45](../../../../src/vaultspec_rag/indexer/_preprocess_glue.py#L25)).
- The runner creates a canonical invocation envelope with project-relative source paths, options, extractor version, target, and mode; it places canonical JSON in the configured environment variable, launches in the project cwd, and consumes JSON stdout. Single outputs and each batch element are schema-checked, bound to their invoked source, and checked against the per-file emitted-text cap ([src/vaultspec_rag/indexer/\_preprocess_runner.py:213-260,470-583,732-851](../../../../src/vaultspec_rag/indexer/_preprocess_runner.py#L213); [src/vaultspec_rag/indexer/\_preprocess_schema.py:51-78,210-232](../../../../src/vaultspec_rag/indexer/_preprocess_schema.py#L51)). Batch commands receive a temporary newline-delimited path manifest, and results are mapped back to one outcome per requested path ([src/vaultspec_rag/indexer/\_preprocess_runner.py:669-730,854-928](../../../../src/vaultspec_rag/indexer/_preprocess_runner.py#L669)).
- A successful output may be cached using an identity derived from source/rule execution semantics. Cache entries live at `<cache_root>/<key-prefix>/<key>.json`; `preprocess_cache_dir(data_root)` selects `data_root/preprocess-cache` ([src/vaultspec_rag/indexer/\_preprocess_cache.py:63-70,96-143,146-219](../../../../src/vaultspec_rag/indexer/_preprocess_cache.py#L63)).
- Approval records are keyed by canonical root key and contain canonical root path, policy digest, and approval timestamp; `policy_is_approved` requires a non-`None` digest equal to the recorded digest ([src/vaultspec_rag/indexer/\_preprocess_approval.py:58-70,132-157,179-193](../../../../src/vaultspec_rag/indexer/_preprocess_approval.py#L58)).
- No test source was in scope, so no test expectations or pass/fail evidence can be reported.

## Boundaries and dependencies

- Relationships visible in the inspected code: `_preprocess_config` calls approval checking and uses `ContentKind`/`JobErrorKind`; `_preprocess_cache` uses output validation/schema constants; `_preprocess_glue` joins resolved policy, config, cache path, and worker result types; `_preprocess_runner` uses the schema, hook-environment/process-launch helpers, and process-tree cleanup; `_preprocess_entry` is the runner's named script; `_ignore_specs` obtains config settings; `_incremental_commit` joins pipeline, run-ledger, lifecycle, store, and streaming mutation APIs; `_index_lifecycle` joins logging events, run operation labels, and store activity stamps. Implementations behind these dependencies were not inspected.
- The modules document that `CodebaseIndexer` delegates ignore and preprocess glue work, and that indexer run entry points use the common lifecycle, but the actual call sites are outside this slice ([src/vaultspec_rag/indexer/\_ignore_specs.py:1-8](../../../../src/vaultspec_rag/indexer/_ignore_specs.py#L1); [src/vaultspec_rag/indexer/\_preprocess_glue.py:1-8](../../../../src/vaultspec_rag/indexer/_preprocess_glue.py#L1); [src/vaultspec_rag/indexer/\_index_lifecycle.py:1-13](../../../../src/vaultspec_rag/indexer/_index_lifecycle.py#L1)). The injected `chunk_and_embed`, store, and generation lifecycle are the visible incremental extension points ([src/vaultspec_rag/indexer/\_incremental_commit.py:89-110](../../../../src/vaultspec_rag/indexer/_incremental_commit.py#L89)). These are documentation/interface claims, not independently confirmed caller traces.
- Documentation/code mismatch: [src/vaultspec_rag/indexer/\_preprocess_cache.py](../../../../src/vaultspec_rag/indexer/_preprocess_cache.py) describes the key as `blake2b(source_hash | command | schema_version)` (lines 15-21), while `PreprocessCacheIdentity.from_rule()` fingerprints command/entry-point, options, extractor version, target, mode, emitted-byte cap, and output schema, then the key also incorporates source path unless path-independent (lines 96-138). The implementation has the broader identity.
- Documentation/code mismatch: [src/vaultspec_rag/indexer/\_preprocess_config.py](../../../../src/vaultspec_rag/indexer/_preprocess_config.py) says malformed individual rules are dropped in non-strict mode (lines 17-21), but missing/invalid `target`, missing/invalid `extractor_version`, and config schema versions below or above supported raise `PreprocessPolicyError` directly, including outside the local `strict` rejection path (lines 349-360, 526-570). This narrows the documented degrade behavior.
