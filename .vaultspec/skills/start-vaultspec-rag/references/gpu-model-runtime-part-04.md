## Capability summary

**Implementation.** [src/vaultspec_rag/indexer/\_stat_gate.py](../../../../src/vaultspec_rag/indexer/_stat_gate.py) supplies a point-addressed SQLite cache for content hashes. It reuses a digest only when size and nanosecond mtime match and the mtime clears a two-second racy-write window; a miss hashes content and records evidence only if the post-read stat still matches. It offers serial or bounded-pool reads, ordered results and per-file `OSError` reporting, progress/control checkpoints, optional full-membership pruning, and a helper to bank hashes computed elsewhere. The digest function is injected so a domain can define what is hashed. The incremental mixin’s `_hash_documents` is a visible caller of `hash_paths`.

[src/vaultspec_rag/indexer/\_streaming_types.py](../../../../src/vaultspec_rag/indexer/_streaming_types.py) is the shared vocabulary for the streaming pipeline: immutable requests for vault, document, and code writes; mutation-lifecycle callbacks; byte-weighted document/code slices and file-local code segments with validation; plus structural protocols for CPU transfer, dense rows, list conversion, and sparse vectors. [src/vaultspec_rag/indexer/\_streaming.py](../../../../src/vaultspec_rag/indexer/_streaming.py) implements the consumers: dense/sparse vector encoding and CPU conversion, optional donor-vector adoption, cleanup of vector fields, CUDA-cache release, store mutation bracketing, progress telemetry, and synchronous or queued writes. `_SliceWriter` is a single bounded writer that preserves task order, releases slice vectors after settlement, records the first failure, and has bounded shutdown/abandon paths. Vault streaming splits documents, sorts chunks by embed-text length, streams bounded slices through encoding and upsert, and returns per-document chunk counts. Document-only and code slice helpers perform their corresponding encode/upsert operations.

[src/vaultspec_rag/indexer/\_support_budget.py](../../../../src/vaultspec_rag/indexer/_support_budget.py) combines a code workload measurement with its admitted memory budget. It measures source files/bytes by stat, records extracted bytes, generated chunks and weighted bytes, samples RSS/CUDA high-water, captures forward peaks, routes CUDA OOM through the budget, and raises a corpus-limit `JobError` on the first exceeded configured dimension.

[src/vaultspec_rag/indexer/\_vault_fingerprint.py](../../../../src/vaultspec_rag/indexer/_vault_fingerprint.py) encodes a versioned identity with raw-file, normalized parsed-body, and indexed-metadata digests. It classifies identities as unchanged, metadata-only, or body changes; missing or unsupported identities fail toward body work. Invalid UTF-8 and unrecognized document types yield only the raw digest. [src/vaultspec_rag/indexer/\_vault_checkpoint.py](../../../../src/vaultspec_rag/indexer/_vault_checkpoint.py) opens a vault run generation against a signature containing root, collection, model/schema, content/membership, and backend identity; it creates commit units for chunks, reconciles resumed rebuild paths, filters already-confirmed chunks, supplies mutation lifecycles, records confirmed units, and builds proof evidence from confirmed upsert units. Its base-class behavior is outside this slice.

[src/vaultspec_rag/indexer/\_vault_incremental.py](../../../../src/vaultspec_rag/indexer/_vault_incremental.py) provides `VaultIncrementalMixin` operations for scanning document paths, fetching named publication evidence in bounded batches, checking storage against proof, hashing and preparing documents with bounded workers, classifying body versus metadata changes, and reconciling new/changed/deleted paths. Metadata-only refresh rebuilds payloads only when prepared chunk ordinals exactly match stored ordinals; uncertain shape is deferred into the body re-embed branch. Scoped reconciliation uses the supplied changed paths, deletes only candidates present in prior proof, and republishes the generation. Its visible internal callers include `_hash_documents` → `_stat_gate.hash_paths`, `_encode_incremental_documents` → `_stream_encode_and_upsert_vault`, and `_scoped_incremental_locked` → the shared reconcile helpers.

**Documentation claims.** The module and method docstrings describe stat evidence as advisory and content hash as indexing authority; the vault fingerprint’s body/metadata split as the basis for avoiding needless vector work; slice streaming as a peak-memory bound; writer ordering as overlap between encoding and storage; and weighted work/memory limits as support-profile enforcement. These are code comments/docstrings, not independently verified operational claims.

**Test expectations.** No test source was read, so there are no test expectations or passing-test claims in this report.

**Inference.** The seven modules form a cooperating indexing slice: `_vault_incremental` classifies and schedules work, `_vault_fingerprint` defines vault change identity, `_vault_checkpoint` carries publication/receipt authority, `_streaming_types` and `_streaming` carry encoded mutations, `_stat_gate` avoids some repeat reads, and `_support_budget` measures/enforces code indexing limits. This relationship is inferred from the visible imports and calls; public entrypoints outside the assigned ranges were not traced.

## Interfaces and data flow

- Hash path: document IDs and paths enter `VaultIncrementalMixin._hash_documents`; it acquires `StatEvidenceStore`, calls `hash_paths`, raises or logs failures according to strict/replay policy, prunes only for full membership, persists evidence, and returns hashes. `BatchHashOutcome` contains ordered hashes and `(key, OSError)` failures. `record_computed_hashes` accepts externally computed key/path/hash triples, a lower time bound, and optional full-membership keep set.
- Vault change path: paths are scanned or supplied as scoped changes; publication proof supplies prior content identities and point IDs; current fingerprints are classified; parsing/chunking and `VaultRunCheckpoint` units feed `_stream_encode_and_upsert_vault` or a payload-only write; deletes and confirmed updates are recorded before generation publication. `_scoped_incremental_locked` returns `IndexResult` counts, duration, device, and optional reuse statistics.
- Encode/write path: request dataclasses carry chunks, model, store, GPU lock, write policy, run control, callbacks, and optional reuse/checkpoint lifecycle. Encoded dense/sparse fields are placed on chunks, store writes use `VaultStore` methods, and vector-bearing fields are cleared inline or by the writer after the write settles. The model, store methods, callback persistence, and backend semantics are not inspected here.
- Code admission path: `CodeSupportBudget` binds an `EmbeddingModel`, admits ceilings from support limits, samples `MemoryBudget`, merges resource high-water into `SupportMeasurement`, and iterates measured `CodeFileSegment`s.

## Boundaries and dependencies

- Local relationships observed: `_vault_incremental` imports `_stat_gate`, `_vault_fingerprint`, `_streaming`, `_streaming_types`, `_vault_checkpoint`, and vault preparation helpers. `_vault_checkpoint` uses the fingerprint scheme tag. `_streaming` consumes request types from `_streaming_types`; those types refer to `_SliceWriter` and `VaultRunCheckpoint` under `TYPE_CHECKING` to avoid runtime coupling. `_support_budget` consumes `CodeFileSegment` under `TYPE_CHECKING`.
- Runtime collaborators visible but uninspected: `VaultStore` and its write/proof-facing methods; `EmbeddingModel` and bucket/GPU-lock behavior; `_vault_prep` parsing/chunking/preparation; `_checkpoint_common.RunCheckpointBase`; run ledger/proof/policy/configuration; `MemoryBudget` and resource ceilings; source-path helper; job control and progress reporter. Their implementation must not be inferred from these call sites.
- The only external scan implementation named is `vaultspec_core.vaultcore.scan_vault`/`get_doc_type`; their traversal and recognition rules were not inspected.
