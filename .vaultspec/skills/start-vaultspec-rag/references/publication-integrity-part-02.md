## Capability summary

- [src/vaultspec_rag/indexer/\_publication_proof.py](../../../../src/vaultspec_rag/indexer/_publication_proof.py) defines the immutable values and typed errors for exact publication evidence. It models compatibility identity (source, root, backend, collection, schemas and policy/content identities), read tokens fenced by revision and reservation sequence, normalized per-path evidence with canonical point IDs, the eight path outcomes, signed aggregate deltas, and non-negative proof aggregates. Constructors validate their invariants; ProofReadToken rejects open receipts and detects compatibility or state changes across a backend read. The file also exports receipt/mutation/provenance states and categorized unverifiability errors for ledger and publication consumers. No ledger implementation is included here.
- [src/vaultspec_rag/indexer/\_resolved_policy.py](../../../../src/vaultspec_rag/indexer/_resolved_policy.py) resolves mutable inputs into an immutable, reconstructible per-operation policy. It freezes supported preprocess option values into explicitly tagged canonical tuples, validates and thaws them for worker rules, captures decoder/chunking settings, and builds ignore and preprocess matchers plus normalized fingerprints. ResolvedIndexPolicy validates schema and mode fields and rejects conflicting route/preprocess targets. It exposes hook approval state, path-to-rule matching, transform-disabled/stale-note behavior, classification, and per-content-kind fingerprints. resolve_index_policy combines caller options with global settings, strict preprocess-rule loading and approval, collected ignore patterns, and chunking configuration. Only this module's use of ResolvedIndexPolicy.classify is visible among the assigned files.
- [src/vaultspec_rag/indexer/\_resource_ceilings.py](../../../../src/vaultspec_rag/indexer/_resource_ceilings.py) derives one run's RSS and CUDA memory ceilings from configuration, optional support-profile limits, and device/model baseline. It returns AdmittedCeilings; its CUDA-enforced view is absent for non-CUDA execution. CUDA runs reset peak stats, sample the resident baseline, derive the ceiling, and fail admission with a typed job error if no positive headroom remains. The module documents sharing this derivation between code and document indexers, but their call sites are outside this slice.
- [src/vaultspec_rag/indexer/\_reuse.py](../../../../src/vaultspec_rag/indexer/_reuse.py) resolves donor collections once per run and adopts stored vectors only after evidence checks. resolve_donor_reuse returns no telemetry/context when disabled; when enabled it discovers candidates, evaluates eligibility and read support, applies candidate/inspection caps, and degrades discovery or eligibility failures to no donors. DonorReuseContext queries outstanding string IDs in donor order. A hit requires exact reconstructed embedding evidence and, when required, a sparse vector; it copies vectors onto the local chunk while leaving payload construction to callers. Read failures and mismatches remain encode misses. ReuseStats tracks hit/miss counts and JSON-ready telemetry, estimating saved GPU seconds from same-run encode timing or a fallback rate.
- [src/vaultspec_rag/indexer/\_route_migration.py](../../../../src/vaultspec_rag/indexer/_route_migration.py) implements bounded cleanup when current routing moves source paths between code and document collections. RouteMigrationJournal persists destination-confirmed deletion obligations in SQLite with deterministic IDs, origin point IDs, destination generation and phase. Scans page stored rows, freshly classify paths through the resolved policy, and optionally select at most one bounded batch of source paths. Reconciliation checks generation/file state and destination point evidence before deleting origin points, recording progress, or purging stale rows. It supports scoped and complete-destination reconciliation, cleanup after destination confirmation, prior-owner lookup through publication proofs, and replay of pending journal entries after interruption. The storage and ledger contracts it invokes are uninspected.
- [src/vaultspec_rag/indexer/\_run_checkpoint.py](../../../../src/vaultspec_rag/indexer/_run_checkpoint.py) supplies code-specific checkpoint values and behavior atop RunCheckpointBase. CodeRunConfiguration validates compatibility/write limits; CodeRunOpenRequest groups the inputs for opening a generation. CodeRunCheckpoint maps a streamed code segment to a ledger commit unit, recognizes committed resume work, records storage-confirmed segment units, reports indexed paths whose digests drifted, exposes superseded/retained upsert evidence, retires or reopens path evidence, and records policy-rejected file state. The base checkpoint and ledger semantics are outside this assignment.

## Interfaces and data flow

- Proof flow: a caller constructs a ProofCompatibilityKey, reads a token from an atomic ledger snapshot with ProofReadToken.from_snapshot, reads backend state, then calls validate against a second snapshot. ProofEvidence/PathDelta describe exact per-path changes; ProofAggregate.apply applies the corresponding breadth adjustment. The assigned files do not show the ledger methods that create or persist these values.
- Policy flow: callers provide IndexPolicyResolutionOptions and a root to resolve_index_policy. The result carries the canonical root, content policy, preprocessing/decoder/chunking settings, ignore patterns, approval state and fingerprints. In the assigned code, route scans call policy.classify(path) and use ResolvedIndexPolicy to resolve the current kind/admission.
- Memory flow: callers pass the model and optional profile limits to admit_index_ceilings; the returned RSS/CUDA figures can be consumed by downstream budget objects. Those consumers are not in the assigned ranges.
- Reuse flow: callers resolve (ReuseStats | None, DonorReuseContext | None) once, then pass chunk sequences to adopt_verified_vectors; the returned Boolean mask aligns with the input sequence. The assigned source says vectors alone are adopted and the ordinary encode path handles misses, but does not show that caller's encode seam.
- Route flow: iter_stored_route_pages supplies pages of StoredRouteRow. reconcile_checkpoint_routes checks relevant file states and destination evidence, then journals and deletes origin IDs. reconcile_generation_storage coordinates pending replay, optional same-kind purge, and cross-kind reconciliation, returning (resumed, purged, migrated) counts. Internally, reconcile_scoped_routes calls reconcile_origin_after_destination; the generation-level function calls resume_pending_migrations, purge_unpublished_rows, and reconcile_checkpoint_routes.
- Code checkpoint flow: a segment becomes a CommitUnit; the checkpoint records it only after the associated store mutation is confirmed, and records indexed-file state once ledger evidence says a path is complete. Resume, drift, retirement, and policy rejection methods mediate additional ledger evidence. The caller that confirms store writes is not in this slice.
