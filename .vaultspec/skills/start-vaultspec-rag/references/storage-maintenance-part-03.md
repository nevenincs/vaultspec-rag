## Capability summary

**Implementation**

- [src/vaultspec_rag/storage_reconciliation.py](../../../../src/vaultspec_rag/storage_reconciliation.py) defines collection geometry records and performs managed-server ownership checks, geometry reads, capped drift selection, per-collection optimizer updates, and convergence measurement. It selects drift by configured segment target, orders by known footprint descending, checks free-space headroom before mutation, rechecks attribution at the update boundary, and can preview or reconcile a batch (253-345, 378-473, 476-642, 645-758).
- [src/vaultspec_rag/storage_restore.py](../../../../src/vaultspec_rag/storage_restore.py) validates a complete archive and its snapshot members, reads publication proof records, refuses an occupied or unsupported destination, restores each snapshot into a new namespace, records restored metadata/proofs, and attempts cleanup on failure (63-141, 196-383, 386-418, 420-510, 513-571).
- [src/vaultspec_rag/storage_safety.py](../../../../src/vaultspec_rag/storage_safety.py) provides `StorageSafetyError` and `resolve_within`, which resolves target and base paths and rejects a target outside the base (23-58).
- [src/vaultspec_rag/storage_survey.py](../../../../src/vaultspec_rag/storage_survey.py) groups collection names by root prefix, joins groups to manifest entries, and returns `NamespaceSurvey` records with point counts, kind breakdowns, footprints, model stamps, and optional generation/temp-root facts. It also classifies canonical prefixes and temp-rooted paths (51-53, 56-91, 94-143, 146-265).
- [src/vaultspec_rag/storage_survey_ops.py](../../../../src/vaultspec_rag/storage_survey_ops.py) supplies footprint/debris measurement, whole-backend totals, live and disk survey gathering, root claim cleanup, prefix deletion, explicit debris pruning, and orphan pruning. Prefix deletion validates a canonical prefix and attribution before dropping; debris deletion rechecks that a directory has not become live (68-115, 118-198, 201-261, 273-338, 340-385, 388-551).
- [src/vaultspec_rag/store_catalog.py](../../../../src/vaultspec_rag/store_catalog.py) implements `_VaultCatalogMixin`, the catalog/read side of a store host. It scans chunk ordinals, removes stale tails and pre-chunking points, reads bounded code/document pages and index-audit pages, checks identities, counts collections without creating missing ones, retrieves documents, lists document heads, and maps string IDs to stable integers (29-43, 58-115, 117-330, 332-584, 586-731, 733-851).

## Interfaces and data flow

- Reconciliation accepts a Qdrant client plus optional storage path and policy controls. `read_geometry` enumerates collections and joins names to a loaded manifest; `plan_reconcile` returns selected entries and remaining drift; `reconcile_collection` applies one update and optionally waits; `reconcile_collections` combines these into per-collection results and a batch total ([src/vaultspec_rag/storage_reconciliation.py:253-308,311-345,476-482,645-758](../../../../src/vaultspec_rag/storage_reconciliation.py#L253)). It uses `storage_survey._prefix_of`/`is_canonical_prefix`, `storage_manifest.load_manifest`/`classify_root`, and filesystem footprint/free-space helpers ([src/vaultspec_rag/storage_reconciliation.py:11-17,207-250,546-587](../../../../src/vaultspec_rag/storage_reconciliation.py#L11)).
- Archive input is a directory containing a manifest and named `.snapshot` files. `read_archive` returns an `ArchiveRead` with prefix, schema version, collections, identities, and proofs; `restore_archive` maps source names under the selected destination prefix, requires an empty namespace, uploads snapshots, writes publication/manifest state, and returns a `RestoreResult` ([src/vaultspec_rag/storage_restore.py:147-194,237-268,271-383,513-571](../../../../src/vaultspec_rag/storage_restore.py#L147)).
- Survey inputs are collection names, a manifest mapping, optional per-collection counts (including `None` for an attempted failed count), and footprints. `classify_namespaces` returns status-sorted `NamespaceSurvey` data; `gather_survey` obtains live names/counts and disk sizes, then adds debris; `gather_disk_survey` classifies disk directories without a server ([src/vaultspec_rag/storage_survey.py:94-143,187-265](../../../../src/vaultspec_rag/storage_survey.py#L94); [src/vaultspec_rag/storage_survey_ops.py:273-338](../../../../src/vaultspec_rag/storage_survey_ops.py#L273)).
- Destructive survey operations return `DeleteResult`/`PruneResult`; `delete_prefix` can dry-run or remove matching collections and the manifest prefix, while `prune_orphaned` targets only orphaned survey entries. `prune_debris` removes unmatched directories only after a live-name recheck ([src/vaultspec_rag/storage_survey_ops.py:32-65,201-261,437-510,513-551](../../../../src/vaultspec_rag/storage_survey_ops.py#L32)).
- The catalog mixin operates on three host-provided collection names and a Qdrant client through locks, scroll/retrieve/delete helpers, existence checks, reconciliation, and retry support ([src/vaultspec_rag/store_catalog.py:58-115](../../../../src/vaultspec_rag/store_catalog.py#L58)). Payload fields include `doc_id`, `chunk_ordinal`, `doc_content`, `path`/`source_path`, and `chunk_id`; methods return document views, counts/IDs, or bounded `(rows, next_offset)` pages ([src/vaultspec_rag/store_catalog.py:117-182,332-477,493-584,617-731,733-844](../../../../src/vaultspec_rag/store_catalog.py#L117)).

## Boundaries and dependencies

- Reconciliation explicitly gates on a managed loopback endpoint and manifest attribution; unknown or remote ownership is skipped. The batch cap and per-collection wait budget bound work. Footprints are optional when the server storage directory cannot be resolved ([src/vaultspec_rag/storage_reconciliation.py:235-250,253-308,311-345,546-587,645-758](../../../../src/vaultspec_rag/storage_reconciliation.py#L235)).
- Archive reads are designed to reject symlink/reparse members, non-regular or empty files, path escapes, malformed records/proofs, duplicate collection names, and unlisted snapshot artifacts. Restore refuses local mode, invalid destinations, occupied destinations, and Windows server restoration. The direct Qdrant and state-writing behavior is visible, but imported implementations are uninspected ([src/vaultspec_rag/storage_restore.py:63-141,196-268,271-383,420-461,487-571](../../../../src/vaultspec_rag/storage_restore.py#L63)).
- `resolve_within` is not imported or called by any of the other assigned modules. Its consumers, if any, are outside this slice ([src/vaultspec_rag/storage_safety.py:21-58](../../../../src/vaultspec_rag/storage_safety.py#L21); compare assigned import sections at [src/vaultspec_rag/storage_reconciliation.py:5-17](../../../../src/vaultspec_rag/storage_reconciliation.py#L5), [src/vaultspec_rag/storage_restore.py:5-35](../../../../src/vaultspec_rag/storage_restore.py#L5), [src/vaultspec_rag/storage_survey_ops.py:5-16](../../../../src/vaultspec_rag/storage_survey_ops.py#L5)). This is a boundary observation, not a claim that no consumer exists elsewhere.
- Survey classification depends on the prefix regex, manifest classification, config environment values, and optional generation data. Operational gathering adds Qdrant counts and filesystem traversal; disk-only gathering omits server counts ([src/vaultspec_rag/storage_survey.py:25-40,51-91,187-265](../../../../src/vaultspec_rag/storage_survey.py#L25); [src/vaultspec_rag/storage_survey_ops.py:68-115,273-338](../../../../src/vaultspec_rag/storage_survey_ops.py#L68)).
- Catalog behavior is a mixin contract: the concrete host implementations of client/lifecycle/locking/scroll/retrieve/delete/retry helpers are type-checking declarations only here. No concrete host or caller was inspected ([src/vaultspec_rag/store_catalog.py:58-115](../../../../src/vaultspec_rag/store_catalog.py#L58)).
- Other referenced modules and integrations are uninspected dependencies, including `storage_manifest`, `store_schema`, `_store_models`, `_store_writes`, config/settings, Qdrant runtime/client APIs, indexer publication/ledger models, and store runtime. No behavior beyond the assigned code is asserted.
