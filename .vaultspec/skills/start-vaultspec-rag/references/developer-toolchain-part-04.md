- **Initialization entry point and contract:** [dev/init/__main__.py](../../../../dev/init/__main__.py) maps CLI selections to phases, probes host requirements and runs preflight, skips current phases using stamps, runs selected phases in order with fail-fast phase handling, reports later phases as skipped after a failure, handles read-only `check`, and emits/writes a report (lines 84-398). [dev/init/contract.py](../../../../dev/init/contract.py) defines phase/step/result/outcome records, status and environment-variable constants, optional NDJSON output, and report serialization shape (lines 25-265).
- **Initialization plan and supporting modules:** [dev/init/plan.py](../../../../dev/init/plan.py) declares required host tools, `.env` preflight, GPU-stack-specific Python sync, a skipped Node phase, and framework/actionlint tool steps with declared inputs and artifacts (lines 34-186). [dev/init/probe.py](../../../../dev/init/probe.py) discovers executables, parses dotted versions, checks optional minimum versions, and returns one finding per declared requirement (lines 29-205). [dev/init/process.py](../../../../dev/init/process.py) resolves and runs each step without a shell, captures/echoes output, retains a failure tail, and maps failure text/status to contract exit codes; advisory failures are tolerated (lines 43-214). [dev/init/stamp.py](../../../../dev/init/stamp.py) computes per-phase digests from contract version, package source, interpreter version, resolved plan argv and declared inputs; it records digests, checks artifacts, and reports staleness (lines 41-251). [dev/init/venv.py](../../../../dev/init/venv.py) is a small standalone helper that finds the platform interpreter path, leaves an existing environment in place, or invokes `uv venv` when absent (lines 25-84); the assigned plan does not show this helper as a current phase step.
- **Environment-file provisioning:** [dev/init/dotenv.py](../../../../dev/init/dotenv.py) reads simple live `NAME=value` assignments, renders values into the structure/order of an example, preserves undeclared values in a trailing block, optionally seeds a new file from the `main` worktree, refuses unreadable lines without rewriting, and publishes changes through a temporary sibling plus replace (lines 54-280). Its module CLI accepts example and target paths, finds a seed, and returns the provisioning result (lines 283-309).
- **Browser monitor harness:** [dev/monitor-browser.mjs](../../../../dev/monitor-browser.mjs) starts a local Vite server when no URL is supplied, launches an installed browser headlessly with an isolated profile, connects through the browser debugging protocol, waits for the app root to draw with bounded navigation retries, records errors/network evidence and blocks cross-origin requests in delivered-URL mode, then serves JSON-line commands for evaluation, waiting, resizing, screenshots, memory counts, background-tab behavior, evidence retrieval, and closure (lines 8-28, 62-201, 202-284). Its actual callers are not in the assigned sources.
- **Shared development process runner:** [dev/runner.py](../../../../dev/runner.py) provides declarative command, native-tool-or-Docker, optional-tool, output-header, and intra-verb-reference step records; it runs argument vectors with environment overlays and optional working directories, resolves executables, implements Docker/skip behavior, and builds standard `uv run --no-sync` or dev-module commands (lines 39-281). Its module docstring says `dev.toolchain` states the toolchain as a table, but that caller was not inspected (lines 1-15).

## Interfaces and data flow

- **Initialization CLI:** `python -m dev.init [all|python|node|tools|check] [--json] [--force]` is the implemented command shape; omitted selection defaults to `all`. JSON and force flags also consult `VAULTSPEC_INIT_JSON` and `VAULTSPEC_INIT_FORCE` (entry-point implementation: [dev/init/__main__.py:84-111,264-300](../../../../dev/init/__main__.py#L84); constants: [dev/init/contract.py:36-42](../../../../dev/init/contract.py#L36)). The README's `just` recipe names and argument-free contract are documentation claims; the justfile was not inspected ([dev/init/README.md:1-24](../../../../dev/init/README.md#L1)).
- On non-check runs, entry point calls `plan.REQUIREMENTS` through `probe.check_all`, then runs every `plan.PREFLIGHT` step. A blocking missing requirement returns the host-tool-missing code before phases; a preflight failure stops phase execution. The current plan declares `uv` as the requirement and a Python-module dotenv command as preflight ([dev/init/__main__.py:114-170](../../../../dev/init/__main__.py#L114); [dev/init/plan.py:34-61](../../../../dev/init/plan.py#L34)).
- For each selected phase the entry point reads stamp digests, skips a phase only when `is_current` accepts its digest and artifacts, otherwise runs its commands in sequence and stops that phase at its first nonzero result. A failed phase becomes the cause for marking later selected phases skipped. Successful phase digests are updated and written after the selection loop ([dev/init/__main__.py:173-226,314-357](../../../../dev/init/__main__.py#L173); [dev/init/stamp.py:118-140,143-153,210-225](../../../../dev/init/stamp.py#L118)).
- `init check` computes staleness for the declared phase plan, reports fresh/stale/skipped states and remediation, and calls report finalization with `write_file=False`; implementation thus avoids writing the report on this path ([dev/init/__main__.py:229-261,302-312,363-390](../../../../dev/init/__main__.py#L229)). Other runs build a report and attempt to write it, with the path chosen as `.venv/init-report.json` when `.venv` exists or root `.init-report.json` otherwise ([dev/init/stamp.py:63-81](../../../../dev/init/stamp.py#L63); [dev/init/__main__.py:349-390](../../../../dev/init/__main__.py#L349)). Report fields include schema version, repository identity/path, platform, Python version, selection, outcome, per-phase results, and remediation ([dev/init/contract.py:234-265](../../../../dev/init/contract.py#L234)).
- Human messages go to stderr. When enabled, machine events are JSON lines on stdout with an event type and elapsed milliseconds; the entry point emits run, host-tool, preflight-step, phase, and step events through `Emitter` ([dev/init/contract.py:170-215](../../../../dev/init/contract.py#L170); [dev/init/__main__.py:144-169,191-225,300-357,390-394](../../../../dev/init/__main__.py#L144)).
- `.env` provisioning takes an example and target path. For an existing target, only its values are read and reused; for a missing target, the optional `git worktree list --porcelain` lookup can provide a seed, filtered to names declared by the example. Unknown values in an existing target remain in a trailing block; unknown seed values are not copied. Invalid lines cause a nonzero return before writing. A byte-equal rendered existing file is left unchanged ([dev/init/dotenv.py:102-125,159-194,213-280](../../../../dev/init/dotenv.py#L102)).
- [dev/monitor-browser.mjs](../../../../dev/monitor-browser.mjs) takes browser executable, profile directory, and optional delivered URL as process arguments ([dev/monitor-browser.mjs:8-28](../../../../dev/monitor-browser.mjs#L8)). It writes a ready JSON record, accepts one JSON command per stdin line, and responds with `{ok,value}` or `{ok:false,message}`; screenshot writes a PNG to the requested path and the evidence operation returns collected error/network arrays ([dev/monitor-browser.mjs:202-265](../../../../dev/monitor-browser.mjs#L202)).
- [dev/runner.py](../../../../dev/runner.py) accepts already-split argument vectors, an optional environment overlay, and cwd; it returns process status or its `TOOL_MISSING` contract value. Tool wrappers select native executable, Docker fallback, or advisory skip, and `Cmd` / `Ref` / `Echo` records are data shapes for callers ([dev/runner.py:53-141,144-187,190-281](../../../../dev/runner.py#L53)).
