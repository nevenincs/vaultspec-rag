## Capability summary

- The slice is a unit-test capability map, not implementation evidence. Its direct callers include `ASTChunker`, chunk-worker helpers, `install_run`, `uninstall_run`, `reconcile_mcp_extra`, `infer_rag_upgrade_mode`, config persistence/resolution functions, skip validators, and selected `vaultspec_core` functions. Their implementation modules were not inspected.
- [src/vaultspec_rag/tests/test_indexer_unit_chunking.py](../../../../src/vaultspec_rag/tests/test_indexer_unit_chunking.py) covers AST and text splitting expectations: Python and multi-language boundaries, line spans, Unicode and oversized leaves, chunk identity/hash and metadata, language/grammar lookup, splitter fallback, vanished sources, and exact content reconstruction across repeated separators.
- [src/vaultspec_rag/tests/test_indexing_lifetimes.py](../../../../src/vaultspec_rag/tests/test_indexing_lifetimes.py) covers SQLite stat-evidence gate closure for code/document/vault/index-record callers, including persistence errors, cancellation, read failure, and failed schema initialization; it also exercises real subprocess pipe closure for preprocessor success, timeout, and cancellation.

- [src/vaultspec_rag/tests/test_install_mcp_extra.py](../../../../src/vaultspec_rag/tests/test_install_mcp_extra.py) covers MCP-extra enrollment and removal, the distinction between the programmatic default-off and CLI default-on, runtime/dev/tool placement, dry-run previews, owned requirement restoration/movement, preservation of unowned requirements, and non-destructive conflict cases.
- [src/vaultspec_rag/tests/test_install_mode.py](../../../../src/vaultspec_rag/tests/test_install_mode.py) covers package-mode selection, persistence, MCP launch rendering for Claude and Codex targets, upgrade inference and migration, mixed core/rag workspaces, dependency-leak advisories, local-only marker separation, and cleanup/preview of legacy runtime sentinels.
- [src/vaultspec_rag/tests/test_install_provision.py](../../../../src/vaultspec_rag/tests/test_install_provision.py) covers local-only marker round trips and resolution precedence, install-time provisioning outcomes, CLI opt-outs for models/Qdrant, no-provision behavior, and provisioning report serialization.
- [src/vaultspec_rag/tests/test_install_skip_validation.py](../../../../src/vaultspec_rag/tests/test_install_skip_validation.py) covers rag's skip-token vocabulary against its expected domain and core's accepted tokens, plus rejection before install/uninstall workspace writes.

## Interfaces and data flow

- Chunk tests pass source strings and language labels to `ASTChunker.chunk`; lower-level checks call `_split_large_leaf`, `_chunk_worker.chunk_with_ast` / `chunk_and_hash_file`, and `TextSplitter.split_text`. Assertions inspect chunk tuples/objects, line spans, metadata, IDs, language fields, and skip/error outcomes. Temporary source files are used where file-worker behavior is under test ([src/vaultspec_rag/tests/test_indexer_unit_chunking.py:37-78, 113-160, 196-228, 265-293, 494-623](../../../../src/vaultspec_rag/tests/test_indexer_unit_chunking.py#L37)).
- Lifetime tests construct indexer instances with real temporary roots and an observed SQLite-backed stat-evidence store, invoke the code/document/vault hash or selection paths, and inspect retained connections. A real child process with stdout/stderr pipes is passed to the preprocessor drain helper ([src/vaultspec_rag/tests/test_indexing_lifetimes.py:34-48, 55-108, 111-150, 153-210](../../../../src/vaultspec_rag/tests/test_indexing_lifetimes.py#L34)).
- Install tests chiefly pass a workspace path plus options to `install_run` / `uninstall_run`, then inspect returned reports and files under temporary workspaces. Relevant state includes [pyproject.toml](../../../../pyproject.toml), `.vaultspec/workspace.json`, provider MCP targets (`.mcp.json` and `.codex/config.toml`), and the per-user status marker. Some tests use the CLI runner and parse its JSON output (`[src/vaultspec_rag/tests/test_install_json_envelope.py:27-51, 54-138](../../../../src/vaultspec_rag/tests/test_install_json_envelope.py#L27); `[src/vaultspec_rag/tests/test_install_mode.py:105-152, 171-190](../../../../src/vaultspec_rag/tests/test_install_mode.py#L105); [src/vaultspec_rag/tests/test_install_provision.py:328-352](../../../../src/vaultspec_rag/tests/test_install_provision.py#L328)).
- The provisioning tests isolate the status directory through fixtures or environment variables, then examine marker JSON and resolved configuration, while dry-run CLI cases inspect the provisioning member of the install envelope ([src/vaultspec_rag/tests/test_install_provision.py:48-72, 75-187, 189-316, 319-432](../../../../src/vaultspec_rag/tests/test_install_provision.py#L48)).
- The observed external/core surfaces in these tests are `vaultspec_core` install-mode, envelope, provider-registry, manifest, MCP-rendering, and workspace-mode APIs. Their behavior beyond the explicit assertions is uninspected.
