## Capability summary

- [src/vaultspec_rag/job_manager/manager.py](../../../../src/vaultspec_rag/job_manager/manager.py) composes the execution, records, progress, control, and persistence responsibility classes into JobManager. Its initializer validates nonterminal and terminal-history bounds, resolves the configured state path or accepts an explicit/in-memory path, and initializes synchronization, active/terminal records, dispatcher bookkeeping, service-loop and shutdown state, quiesce claims, and persistence generations ([src/vaultspec_rag/job_manager/manager.py:35-112](../../../../src/vaultspec_rag/job_manager/manager.py#L35)). Its visible lifecycle API binds controller notifications and manages startup, abort, shutdown, and lifecycle-bound properties ([src/vaultspec_rag/job_manager/manager.py:113-218](../../../../src/vaultspec_rag/job_manager/manager.py#L113)). Coverage note: [src/vaultspec_rag/job_manager/manager.py](../../../../src/vaultspec_rag/job_manager/manager.py) ends at assigned line 218; there is no unassigned remainder. Lines 208-218 complete the persistence-dirty property, which returns false for an in-memory manager and otherwise checks dirty state or unequal flushed/state generations.
- [src/vaultspec_rag/job_manager/\_records.py](../../../../src/vaultspec_rag/job_manager/_records.py) owns job admission, active-work deduplication, exact-ID lookup, list views, terminal archival and bounded history, immutable snapshots, and process identity/resource snapshot construction ([src/vaultspec_rag/job_manager/\_records.py:50-247](../../../../src/vaultspec_rag/job_manager/_records.py#L50)).
- [src/vaultspec_rag/job_manager/\_progress.py](../../../../src/vaultspec_rag/job_manager/_progress.py) owns attempt start, progress publication and flush coordination, explicit persistence flush, worker/resource/resilience updates, and exact-attempt physical resource release ([src/vaultspec_rag/job_manager/\_progress.py:38-437](../../../../src/vaultspec_rag/job_manager/_progress.py#L38)).
- [src/vaultspec_rag/job_manager/models.py](../../../../src/vaultspec_rag/job_manager/models.py) defines immutable execution/shutdown/recovery records, dispatch claims, progress and resource update inputs, and the attempt context that forwards progress/resource/resilience reports to its manager ([src/vaultspec_rag/job_manager/models.py:24-171](../../../../src/vaultspec_rag/job_manager/models.py#L24)).
- [src/vaultspec_rag/job_manager/state.py](../../../../src/vaultspec_rag/job_manager/state.py) declares the cross-owner static protocol, lifecycle/path markers, dispatch and attempt records, runtime ownership, and the shared managed-job record. Runtime-owner replacement releases a compute ticket when it is not carried forward ([src/vaultspec_rag/job_manager/state.py:46-263](../../../../src/vaultspec_rag/job_manager/state.py#L46)).

## Interfaces and data flow

- Construction takes optional max_nonterminal, max_terminal_history, and state_path, plus a required quiesce controller and optional controller-target callback. The configured path resolves to the managed status directory plus jobs-state.json; explicit None selects in-memory mode ([src/vaultspec_rag/job_manager/manager.py:47-79](../../../../src/vaultspec_rag/job_manager/manager.py#L47); [src/vaultspec_rag/job_manager/state.py:46-47](../../../../src/vaultspec_rag/job_manager/state.py#L46)). Constructor validation rejects boolean or sub-one capacity values ([src/vaultspec_rag/job_manager/manager.py:58-67](../../../../src/vaultspec_rag/job_manager/manager.py#L58)).
- create(spec, initiator, job_id?) validates the specification through an imported helper, deduplicates equivalent active work, enforces the active bound, generates an ID if absent, creates a queued/running-desired snapshot and unowned runtime, then persists; it returns a JobOutcome for validation, deduplication, capacity, ID conflict, persistence failure, or accepted admission ([src/vaultspec_rag/job_manager/\_records.py:63-166](../../../../src/vaultspec_rag/job_manager/_records.py#L63)). The semantics of the imported validation and identity functions are outside this slice.
- Reads use full exact IDs: get checks active and retained terminal records; active, terminal, and list_jobs return snapshot copies, with active jobs sorted newest-first and terminal history newest-first ([src/vaultspec_rag/job_manager/\_records.py:168-199](../../../../src/vaultspec_rag/job_manager/_records.py#L168)). Active-equivalence matching compares imported work identities ([src/vaultspec_rag/job_manager/\_records.py:201-206](../../../../src/vaultspec_rag/job_manager/_records.py#L201)).
- start_attempt(job_id, task, control) requires an existing queued job with desired state running, accepting dispatch, and no task owner. It acquires a quiesce ticket, attaches task/control/ticket, changes the snapshot to running, and persists with backup restoration on an unpublished persistence failure ([src/vaultspec_rag/job_manager/\_progress.py:39-118](../../../../src/vaultspec_rag/job_manager/_progress.py#L39)). Ticket behavior itself is owned by the uninspected quiesce integration.
- A JobAttemptContext contains manager, exact job ID, attempt number, task, control token, and run authority. Its progress method builds a ProgressUpdate; resource and resilience methods forward to manager operations using the same task identity ([src/vaultspec_rag/job_manager/models.py:133-171](../../../../src/vaultspec_rag/job_manager/models.py#L133)). update_progress normalizes the label and constructs canonical JobProgress; it ignores stale task/attempt publications, rejects non-live attempts, mutates the snapshot revision, notes a generation, and may complete a coalesced persistence flush after releasing the manager lock ([src/vaultspec_rag/job_manager/\_progress.py:120-189, 412-437](../../../../src/vaultspec_rag/job_manager/_progress.py#L120)).
- Explicit flush_persistence reports disabled, clean, flushed, or persistence-error outcomes ([src/vaultspec_rag/job_manager/\_progress.py:191-220](../../../../src/vaultspec_rag/job_manager/_progress.py#L191)). Other update APIs accept only the currently attached task, except terminal resilience, which checks an exact terminal attempt number. Worker, resource, and resilience mutations persist; failed unpublished writes restore captured state. Physical resource release clears worker/ticket and held-resource flags and persists, while retaining cleared in-memory ownership if persistence fails, per the inline comment ([src/vaultspec_rag/job_manager/\_progress.py:222-410](../../../../src/vaultspec_rag/job_manager/_progress.py#L222)).
- Runtime storage is split into an active map, terminal deque, dispatcher map, and per-job snapshot/runtime owner. Archival removes the job from active/dispatchers, drops runtime ownership, appends it to terminal history, and evicts oldest records above the configured limit ([src/vaultspec_rag/job_manager/\_records.py:208-222](../../../../src/vaultspec_rag/job_manager/_records.py#L208)). A public snapshot overlays current task/worker activity onto the stored runtime snapshot ([src/vaultspec_rag/job_manager/\_records.py:224-236](../../../../src/vaultspec_rag/job_manager/_records.py#L224)).
