## Capability summary

- [src/vaultspec_rag/embeddings.py](../../../../src/vaultspec_rag/embeddings.py): Owns the GPU-backed dense and sparse embedding wrapper. It checks the CUDA inference stack, loads dense/reranker/sparse models from checked local snapshots, uses fp16 and safetensors settings, and offers an opt-in ONNX dense path with a torch fallback (426-466, 592-674, 676-793). Sparse model loading is skipped when sparse indexing is disabled (766-782). It provides a thread-safe bounded LRU query cache, bucket planning by estimated padded token footprint, independent learned dense/sparse ceilings, OOM cache release/replanning, and per-bucket progress callbacks (62-119, 121-234, 268-400, 887-989). Public paths encode dense documents on device, dense queries, sparse documents, and sparse queries; sparse tensors are converted from scipy, torch COO/CSR/dense, or numpy forms into SparseResult lists (469-545, 1007-1052, 1077-1113, 1115-1228). GPU lock holds cover forward work; conversion and transfers are performed outside the sparse forward lock (991-1005, 1186-1204).
- [src/vaultspec_rag/generation_stamps.py](../../../../src/vaultspec_rag/generation_stamps.py): Persists collection-to-first-seen timestamps in generation-grace.json, beside the storage manifest. Missing, malformed, or unreadable data returns an empty map, restarting grace conservatively; writes use the atomic JSON writer (33-75).
- [src/vaultspec_rag/generation_survey.py](../../../../src/vaultspec_rag/generation_survey.py): Represents per-root served and unreferenced code collections, serializes/deserializes those fields, surveys storage against verifiable served pointers and committed publication proof, and computes reclaim decisions and grace-stamp advancement (46-133, 136-180, 183-286). The survey reports candidates and does not itself drop storage (module documentation 1-18). Reclaim decisions hold on unverifiable pointers or active readers, then require a valid stamp old enough for the configured grace interval (214-252).
- [src/vaultspec_rag/gpu_borrow_lease.py](../../../../src/vaultspec_rag/gpu_borrow_lease.py): Implements a process-held advisory lease for an external GPU borrower, separate from the service's own lock. It claims an anchor, publishes a PID plus random URL-safe capability in a fixed-width record, retains the handle in a process-local registry, verifies status with constant-time capability comparison, and releases only the exact retained handle (41-49, 61-76, 79-156, 159-213).
- [src/vaultspec_rag/graph_cache.py](../../../../src/vaultspec_rag/graph_cache.py): Caches a VaultGraph by root with a configurable TTL. A lock plus a second stale check serializes construction; failures clear the graph and set a shorter retry interval; explicit invalidation clears state (27-110).
- [src/vaultspec_rag/index_profiles.py](../../../../src/vaultspec_rag/index_profiles.py): Defines closed code/document indexing domains, measured dimensions, profile limits, and named managed-service and embedded-local profiles with backend, RAM, disk, and domain-specific limits (29-258). It exports JSON-safe profile status and admission validation for backend, RAM, store-volume free space, separate workspace-volume write floor, and measured domain dimensions (261-459). CUDA bytes remain reported in limits/status but are explicitly omitted from corpus-dimension admission (106-127).
- [src/vaultspec_rag/job_control.py](../../../../src/vaultspec_rag/job_control.py): Defines the synchronous run-control protocol and token for cooperative pause, cancel, shutdown, and quiesce signals; supports protected mutation spans and snapshots of desired/delivered requests (109-328). It also scopes and accumulates GPU-lock wait time through a context variable and provides timed_gpu_lock (40-107).
- [src/vaultspec_rag/job_dispatch.py](../../../../src/vaultspec_rag/job_dispatch.py): Binds durable indexing jobs to manager-owned production execution. It validates the persisted source/mode/authority contract, routes vault jobs separately from code/document jobs, redoes code/document admission at execution time, acquires a registry compute lease, records resource flags, binds the appropriate indexer method, and converts results into job outcomes (47-215, 218-368). It requires an actual successful published generation before accepting a result, while allowing certified publication to win over a concurrent cooperative unwind (371-420, 601-634). It builds admitted/checkpoint resilience snapshots and publishes them from checkpoint observations and finalization (423-683).

## Interfaces and data flow

- Embedding construction starts with EmbeddingModel(model_name=None); it obtains accelerator/config/model repo information and checked snapshots, then initializes dense/sparse model state and encode budgets (676-823). Dense and sparse document APIs truncate input to configured character limits, plan buckets, encode one bucket per forward, and return device dense tensors or sparse result lists in input order (1007-1052, 1115-1204). Query APIs return one normalized dense vector or one sparse result (1077-1113, 1206-1228). QueryEmbeddingCache keys are pairs of surface and cleaned query text, with a defensive copy of sparse lists (62-119).
- Generation survey accepts a mapping of root paths to derived collection names plus existing collection names, and returns verifiable per-root RootGenerations; generation fields can be encoded for status payloads and decoded without recomputing namespace authority (60-133). Reclaim input is an observed context of stamps, current time, grace hours, reader presence, and pointer verifiability; stamp advancement takes unreferenced/held/live sets and an ISO time (203-286). Persistence is separate: the stamp module loads and replaces the whole map atomically (38-75).
- Borrower lease acquisition returns a process-local GPUBorrowLease or None on contention; the status API distinguishes held, not-held, invalid-capability, and unavailable conditions (52-68, 97-156). The PID helper exposes a holder PID only after the capability verifies as held (159-173).
- Profile admission takes profile name, domain, corpus measurement, and host/storage observations, then returns the selected profile or raises a typed JobError (410-459). Status serializes profile limits and accepted backends (273-298).
- Job dispatch receives IndexJobBinding (manager, job id, registry, admission objects, callbacks), reads the durable job snapshot, and binds a runner through the manager (47-64, 169-215). Execution passes a JobAttemptContext and immutable dispatch contract through admission, lease, indexer, publication, and result conversion; resource updates mark lease/writer/pipeline state around their respective scopes (218-368). Checkpoint observations project committed run and resource facts to resilience state; the attempt must be terminally successful with publication or compaction finalization to return a generation ID (486-683).
- The embedding and dispatch paths use timed_gpu_lock; dispatch accesses run-control through its context. These are direct relationships among assigned files ([src/vaultspec_rag/embeddings.py](../../../../src/vaultspec_rag/embeddings.py) 19-21, 1001-1005, 1186-1204; [src/vaultspec_rag/job_dispatch.py](../../../../src/vaultspec_rag/job_dispatch.py) 300-317).
