## Capability summary

- [src/vaultspec_rag/mcp/__init__.py](../../../../src/vaultspec_rag/mcp/__init__.py): imports the resource and tool modules, then imports the shared server object; exposes those three names through `__all__`. The module imports trigger registration decorators in the child modules (inference from imports plus their module documentation).
- [src/vaultspec_rag/mcp/\_mcp.py](../../../../src/vaultspec_rag/mcp/_mcp.py): creates the shared `MCPServer` named “VaultSpec Search”, passing the local package version as its server version. Its docstring says this keeps the advertised release aligned with the daemon; the daemon-side accessor is outside the slice.
- [src/vaultspec_rag/mcp/\_resources.py](../../../../src/vaultspec_rag/mcp/_resources.py): registers a `vault://{+doc_id}` resource to fetch document text and an `analyze_feature` prompt template. The resource requires a compatible reachable service, resolves the project root, delegates a synchronous transport call, and maps service/tool errors to resource/file/runtime exceptions. The prompt returns instructions to search the vault and codebase and compare implementation with design.
- [src/vaultspec_rag/mcp/\_roots.py](../../../../src/vaultspec_rag/mcp/_roots.py): resolves the project root for MCP requests. It accepts a nonblank explicit path, otherwise calls `named_root()`, then validates/resolves via `resolve_workspace`; it returns the resolved target directory or raises a structured `project_root_unresolved` runtime error. The documented precedence is explicit argument, `VAULTSPEC_RAG_ROOT`, then working directory; the implementation details of the imported named-root and workspace resolvers are uninspected.
- [src/vaultspec_rag/mcp/\_tools.py](../../../../src/vaultspec_rag/mcp/_tools.py): registers search, file retrieval, reindex, status, and clean tools. It defines strict readiness/output models, normalizes source values, appends domain filter tokens, checks service reachability and version compatibility, offloads synchronous service-client calls to a worker thread, and maps service responses/errors. Search and retrieval tools carry read-only annotations; reindex tools carry refresh annotations; clean tools carry destructive annotations. `restrict_to_read_only_tools()` removes registered tools lacking a read-only hint, though its launch-time caller is outside this slice.

## Interfaces and data flow

- Shared server and registration: package initialization imports `_resources` and `_tools`; both import `mcp` from [src/vaultspec_rag/mcp/\_mcp.py](../../../../src/vaultspec_rag/mcp/_mcp.py). Their decorators register resource, prompt, and tool handlers on that server ([src/vaultspec_rag/mcp/__init__.py:3-6](../../../../src/vaultspec_rag/mcp/__init__.py#L3), [src/vaultspec_rag/mcp/\_mcp.py:11-15](../../../../src/vaultspec_rag/mcp/_mcp.py#L11), [src/vaultspec_rag/mcp/\_resources.py:24-25,68-69](../../../../src/vaultspec_rag/mcp/_resources.py#L24), [src/vaultspec_rag/mcp/\_tools.py:15-16,380-381](../../../../src/vaultspec_rag/mcp/_tools.py#L15)).
- Root input: tool/resource handlers accept an optional `project_root` (the document resource supplies `None`). Root selection returns an absolute target path string to transport calls or reports resolution failure ([src/vaultspec_rag/mcp/\_roots.py:35-46,49-84](../../../../src/vaultspec_rag/mcp/_roots.py#L35); [src/vaultspec_rag/mcp/\_tools.py:393-394,415-416](../../../../src/vaultspec_rag/mcp/_tools.py#L393); \`[src/vaultspec_rag/mcp/\_resources.py:48-56](../../../../src/vaultspec_rag/mcp/_resources.py#L48))).
- Service boundary: handlers obtain a port through `_require_port`, call synchronous service-client functions through `_delegate`, and receive decoded response values. The adapter maps unavailable service state to `ToolError`; version compatibility is checked before a tool call. The actual HTTP routes, serialization, and compatibility algorithm are in uninspected helpers ([src/vaultspec_rag/mcp/\_tools.py:327-377](../../../../src/vaultspec_rag/mcp/_tools.py#L327)).
- Search inputs/outputs: `search_vault`, `search_codebase`, `search_documents`, and `search_combined` accept query, default top-k 10, optional domain-specific filters, freshness policy/wait, and optional root. They call `try_http_search` and validate the response as `SearchResults` ([src/vaultspec_rag/mcp/\_tools.py:202-205,380-427,430-492,494-527,529-605](../../../../src/vaultspec_rag/mcp/_tools.py#L202)). Vault filters cover document type, feature, date, tag, intent, and feedback IDs. Code filters cover language/path/syntax names, include/exclude paths, locale deduplication, preference, domain tokens, and feedback IDs. Document filters cover source path, extractor ID/version, and locator kind. Combined search accepts all three groups and an `include_documents` switch.
- Search response contract: readiness models carry source-level availability, freshness, absence authority, generation/revision evidence, wait policy/observations, evidence, reason, retryability, and remediation; the aggregate carries counts and degraded sources. `SearchResults` allows extra diagnostic fields, requires results on success, and requires an error envelope without results on failure ([src/vaultspec_rag/mcp/\_tools.py:60-183](../../../../src/vaultspec_rag/mcp/_tools.py#L60)).
- Other tool outputs: `get_code_file(path, project_root)` returns content, raises `ValueError` for an error response, or returns an empty string if neither field exists ([src/vaultspec_rag/mcp/\_tools.py:608-631](../../../../src/vaultspec_rag/mcp/_tools.py#L608)). Reindex wrappers cover vault, code, documents, and all domains, returning the delegated mapping unless a non-partial failure becomes `RuntimeError` ([src/vaultspec_rag/mcp/\_tools.py:634-687](../../../../src/vaultspec_rag/mcp/_tools.py#L634)). `get_index_status` returns a parsed `ServiceStateReport` or raises `ToolError` if parsing fails ([src/vaultspec_rag/mcp/\_tools.py:690-718](../../../../src/vaultspec_rag/mcp/_tools.py#L690)). Clean wrappers cover documents and all domains; non-partial failures become `RuntimeError` ([src/vaultspec_rag/mcp/\_tools.py:721-755](../../../../src/vaultspec_rag/mcp/_tools.py#L721)).
- Resource data flow: `get_vault_document(doc_id)` delegates to `_try_http_vault_document`; it returns stringified content, raises `FileNotFoundError` for `not_found`, and raises `RuntimeError` for other structured errors ([src/vaultspec_rag/mcp/\_resources.py:24-65](../../../../src/vaultspec_rag/mcp/_resources.py#L24)). A `ToolError` is converted to `ResourceError` (`[src/vaultspec_rag/mcp/_resources.py:48-65](../../../../src/vaultspec_rag/mcp/_resources.py#L48))). The resource docstring says reserved expansion preserves nested document stems and traversal is refused before this function (`[src/vaultspec_rag/mcp/\_resources.py:30-34](../../../../src/vaultspec_rag/mcp/_resources.py#L30))); enforcement is outside the slice.
- State and storage: this slice shows no direct persistence. It delegates search/admin/reindex/clean/document retrieval to service-client helpers. Persistence and index semantics are uninspected.
