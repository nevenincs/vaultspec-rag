## Capability summary

- [src/vaultspec_rag/pressure.py](../../../../src/vaultspec_rag/pressure.py) defines machine-pressure input signals, raw tier classification, and a thread-safe singleton evaluator with sample cadence, escalation, clearing, and stale-evidence handling. Its module documentation says the tier is surfaced for rendering and does not drive resource deferral or refusal (lines 1-12); no consuming surface was in scope.
- [src/vaultspec_rag/progress.py](../../../../src/vaultspec_rag/progress.py) defines the indexer-facing ProgressReporter protocol, a no-op adapter, and a Rich adapter. The adapter uses a live bar where supports_live is true and plain phase lines otherwise; it locks fallback counters for worker-thread updates. Forward-boundary and confirmed-chunk methods are no-ops here because the docstrings say those signals feed service telemetry (lines 41-80, 108-117, 217-233).
- [src/vaultspec_rag/registry.py](../../../../src/vaultspec_rag/registry.py) provides the process-level ServiceRegistry singleton with a lock, updates an already-imported vaultspec_rag.server package alias when constructing it, and can discard its cached job manager without creating a registry (lines 21-69).
- [src/vaultspec_rag/runtime_observations.py](../../../../src/vaultspec_rag/runtime_observations.py) builds an on-demand process observation containing process and host CPU, GPU, RAM, disk, and a bounded list of established TCP peers on the supplied port. Host CPU reads are cached for five seconds and primed per calling thread (lines 17-44, 47-70, 73-124).
- [src/vaultspec_rag/service.py](../../../../src/vaultspec_rag/service.py) owns shared model/reranker state and per-root project slots. It controls slot admission and eviction, per-root store serialization, warm and transient store leases, lazy compute runtime construction, job-manager/readiness wiring, lifecycle shutdown/reopen, and health/model observations (lines 66-149, 392-452, 471-748, 780-989, 1002-1136, 1157-1344).
- [src/vaultspec_rag/service_quiesce.py](../../../../src/vaultspec_rag/service_quiesce.py) is a torch-free lifecycle controller for closing compute admission, tracking epoch-bound tickets, acknowledging drain and GPU release, recording pause/warm failures, and reopening admission after warmup. It defines the public state and transition vocabularies and adapter-neutral snapshot envelope (lines 1-7, 37-76, 153-205, 262-309, 334-609).

## Interfaces and data flow

- Pressure input is a MachinePressureSignals value; PressureEvaluator.observe(signals, now=...) returns a mapping with tier and entered_at. The module singleton is obtained from get_pressure_evaluator(). Elevated evidence is a stretched in-flight forward, simultaneous GPU utilization and memory at or above 90%, a live backend probe at least half its bound, or encode waiters. Critical evidence is an unanswered/failed probed backend, a dead thread under an in-flight forward, one disk-full/preflight failure, or at least two timeout/unavailable store failures. Accepted samples are at least five seconds apart; three consecutive over-tier samples escalate, calmer evidence releases one rung per degraded-threshold quiet window, and a gap of at least 15 seconds or backwards clock lapses stale state to nominal ([src/vaultspec_rag/pressure.py:39-82, 85-109, 112-201, 225-333](../../../../src/vaultspec_rag/pressure.py#L39)). These are implementation findings; the signal producers and consuming surfaces are outside this slice.
- Progress consumers implement the protocol's phase, completion, logging, confirmed-chunk, and forward-boundary methods ([src/vaultspec_rag/progress.py:41-80](../../../../src/vaultspec_rag/progress.py#L41)). The included null adapter discards calls; the Rich adapter accepts a Console, selects live mode via supports_live, updates one progress task in live mode, and writes plain start/done lines in fallback mode ([src/vaultspec_rag/progress.py:83-105, 108-233](../../../../src/vaultspec_rag/progress.py#L83)). The docstring says indexer modules consume this protocol, but no caller was read ([src/vaultspec_rag/progress.py:1-10, 41-48](../../../../src/vaultspec_rag/progress.py#L1)).
- get_registry() constructs one ServiceRegistry on first access under a double-checked lock. If the server package is already loaded it rebinds that package's cached \_registry attribute. discard_job_manager() forwards to the existing registry only ([src/vaultspec_rag/registry.py:21-69](../../../../src/vaultspec_rag/registry.py#L21)).
- runtime_observations(port=...) composes helper readings into {ok, observed_at, pid, cpu, ram, gpu, disk, clients}. Client records contain host, port, and established status; results are sorted and limited to 64, with totals and truncation reported ([src/vaultspec_rag/runtime_observations.py:73-124](../../../../src/vaultspec_rag/runtime_observations.py#L73)). Disk and TCP access failures yield unavailable result fields with the exception type as reason ([src/vaultspec_rag/runtime_observations.py:47-70, 73-104](../../../../src/vaultspec_rag/runtime_observations.py#L47)).
- The service registry resolves project roots and manages project slots backed by VaultStore and GraphCache; the configured project cap accounts for both published slots and in-flight construction reservations ([src/vaultspec_rag/service.py:92-149, 471-560](../../../../src/vaultspec_rag/service.py#L92)). A cold read-only store lease is transient and closed after use; maintenance gets an exclusive store, while warm store reads pin the slot ([src/vaultspec_rag/service.py:780-907](../../../../src/vaultspec_rag/service.py#L780)). A compute lease obtains a controller ticket before the project lease/runtime, and a search lease wraps that compute lease ([src/vaultspec_rag/service.py:943-965](../../../../src/vaultspec_rag/service.py#L943)). Runtime creation loads the shared embedding model, optionally obtains the reranker, then wires a searcher and vault/code/document indexers to the slot store, GPU lock, graph cache, and readiness publication callbacks ([src/vaultspec_rag/service.py:1033-1136](../../../../src/vaultspec_rag/service.py#L1033)).
- ServiceQuiesceController.acquire_ticket() accepts work only in RUNNING and returns an epoch-scoped ComputeTicket; release is idempotent and wakes drain waiters. Pause closes admission; drain must empty tickets before GPU-release acknowledgement can mark QUIESCED/safe-to-borrow. Warming remains closed until complete_warming() advances the epoch and returns to RUNNING. Failure and abort paths retain or restore closed/open states as encoded by the controller ([src/vaultspec_rag/service_quiesce.py:262-360, 362-458, 460-565, 567-601](../../../../src/vaultspec_rag/service_quiesce.py#L262)). ServiceRegistry owns one controller and exposes ticket acquisition; other transition orchestration is delegated to imported mixins and was not inspected ([src/vaultspec_rag/service.py:125-139, 327-334](../../../../src/vaultspec_rag/service.py#L125)).
