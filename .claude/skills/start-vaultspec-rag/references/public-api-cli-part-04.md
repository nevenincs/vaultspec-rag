## Interfaces and data flow

- Tests generally call the Typer app through CliRunner; subprocesses are used where import order, environment resolution, or signals matter. The named-root subprocess runs python -m vaultspec_rag preprocess status --json from a valid workspace and reads the resolved root from JSON ([src/vaultspec_rag/tests/test_cli_env_named_root.py:92-160,186-294](../../../../src/vaultspec_rag/tests/test_cli_env_named_root.py#L92)).
- Delegation tests construct loopback HTTP servers and inspect received JSON. Search expects /search; indexing expects /reindex with source, project root, clean/rebuild authority, and initiator fields ([src/vaultspec_rag/tests/test_cli_auto_delegation.py:71-90,155-227](../../../../src/vaultspec_rag/tests/test_cli_auto_delegation.py#L71); [src/vaultspec_rag/tests/test_cli_index_summary.py:28-50,58-149](../../../../src/vaultspec_rag/tests/test_cli_index_summary.py#L28)). Fallback-refusal probes supply a dead port or a quiesced response ([src/vaultspec_rag/tests/test_cli_index_fallback_refusal.py:16-138](../../../../src/vaultspec_rag/tests/test_cli_index_fallback_refusal.py#L16)).
- Audit tests assert the request path/payload, separate audit-verification authority from publication, and inspect success/drift envelopes ([src/vaultspec_rag/tests/test_cli_index.py:475-669](../../../../src/vaultspec_rag/tests/test_cli_index.py#L475)). Dry-run cases use a temporary project and inspect human or JSON file-list output ([src/vaultspec_rag/tests/test_cli_index.py:48-273](../../../../src/vaultspec_rag/tests/test_cli_index.py#L48)).
- Install tests build temporary projects and pyproject files, then inspect CLI output, report dictionaries, and exit codes; some isolate GPU/provider outcomes with monkeypatches ([src/vaultspec_rag/tests/test_cli_install.py:31-60,192-399,532-649,652-897](../../../../src/vaultspec_rag/tests/test_cli_install.py#L31)).
- Interrupted-fetch cases run a child interpreter against a silent loopback source, signal after the request arrives, parse one JSON envelope, and check selected state such as absence of a service record or staging file ([src/vaultspec_rag/tests/test_cli_interrupted_fetch.py:45-146,222-336](../../../../src/vaultspec_rag/tests/test_cli_interrupted_fetch.py#L45)). Tests configure temporary status/cache/storage locations; production storage behavior is not established.
- Clean and help cases observe command output and exit status only ([src/vaultspec_rag/tests/test_cli_clean.py:22-91](../../../../src/vaultspec_rag/tests/test_cli_clean.py#L22); [src/vaultspec_rag/tests/test_cli_help_import_order.py:37-106](../../../../src/vaultspec_rag/tests/test_cli_help_import_order.py#L37)).
