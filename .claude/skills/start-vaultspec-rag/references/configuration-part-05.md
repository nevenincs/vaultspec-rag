## Capability summary

- [src/vaultspec_rag/tests/test_cli_service_watch.py](../../../../src/vaultspec_rag/tests/test_cli_service_watch.py) exercises the service child environment builder with unset, enabled, and disabled watcher flags; debounce/cooldown string conversion; preservation of operator environment when a flag is absent; explicit override behavior; removal of `RAG_ROOT`; and local-only/Qdrant backend selection (`decide_backend`).
- [src/vaultspec_rag/tests/test_cli_start_outcomes.py](../../../../src/vaultspec_rag/tests/test_cli_start_outcomes.py) covers the readiness wait's expected dead-process, timeout, and interrupt failures, including one JSON envelope and nonzero exit; it also covers a serving but degraded health response as success and checks that a daemon phase appears in interactive console output.
- [src/vaultspec_rag/tests/test_cli_startup_interrupt.py](../../../../src/vaultspec_rag/tests/test_cli_startup_interrupt.py) guards deferred CLI-surface import and startup interruption: a fresh import is expected to exclude CLI/Typer/Click/Rich, while an interrupt during import is expected to exit 130, write its notice only to stderr, and avoid a traceback.
- [src/vaultspec_rag/tests/test_cli_status.py](../../../../src/vaultspec_rag/tests/test_cli_status.py) covers project and server status output, index and compute labels, follow-up actions, verbose fields, service-state retrieval, lock errors, connect and heartbeat helpers, service identity tokens, lifecycle/phase interpretation, degraded singleton discovery, doctor agreement, verified compute status, health-based exit codes, and installation receipt guidance.
- [src/vaultspec_rag/tests/test_cli_storage_generation_diagnostics.py](../../../../src/vaultspec_rag/tests/test_cli_storage_generation_diagnostics.py) covers storage-survey generation facts, model stamps, point counts and verification, temporary-root facts, and unknown/malformed evidence through JSON and human CLI adapters.
- [src/vaultspec_rag/tests/test_cli_storage_migrate.py](../../../../src/vaultspec_rag/tests/test_cli_storage_migrate.py) covers migration result rendering and command outcomes for failed, migrated, skipped, and dry-run/preview results, including JSON envelopes and confirmation behavior.
- [src/vaultspec_rag/tests/test_cli_styled_output.py](../../../../src/vaultspec_rag/tests/test_cli_styled_output.py) covers literal bracketed data, plain piped output, terminal color for next-action commands, and bold search-hit headings.
- [src/vaultspec_rag/tests/test_cli_warmup.py](../../../../src/vaultspec_rag/tests/test_cli_warmup.py) is marked integration and specifies expected warmup CUDA/model output, including three verified models and their repository identifiers. The source was read; these checks were not run.
- [src/vaultspec_rag/tests/test_cli_watcher.py](../../../../src/vaultspec_rag/tests/test_cli_watcher.py) covers the user-facing `server updates` status/start/stop/timing surface, HTTP request and response shapes, unavailable-service exits, help terminology, timeout/pending/disabled outcomes, path resolution, and an exact CLI/MCP tool-set parity assertion.
- [src/vaultspec_rag/tests/test_client_provisions_nothing.py](../../../../src/vaultspec_rag/tests/test_client_provisions_nothing.py) covers client-role refusals/skips for `server start`, install provisioning, `server warmup`, and `server qdrant install` (including a local archive), with assertions that provisioning tripwires, managed paths, and model caches remain untouched.

## Interfaces and data flow

- The service-environment tests construct `_ServiceChildEnvRequest`, optionally call `decide_backend`, and assert the returned environment mapping ([src/vaultspec_rag/tests/test_cli_service_watch.py:14-18, 22-120](../../../../src/vaultspec_rag/tests/test_cli_service_watch.py#L14)). The asserted inputs include `watch`, debounce/cooldown, `local_only`, and `qdrant`.
- Readiness tests call `_await_service_ready` with a pid, port, log path, mode, start time, optional progress reporter, and deadline; a local HTTP server or closed loopback port supplies health behavior, and the tests inspect `typer.Exit` and JSON/human output ([src/vaultspec_rag/tests/test_cli_start_outcomes.py:86-217, 226-291](../../../../src/vaultspec_rag/tests/test_cli_start_outcomes.py#L86)).
- Startup-import tests use a child Python process and an import finder that raises `KeyboardInterrupt` when `vaultspec_rag.cli` is imported ([src/vaultspec_rag/tests/test_cli_startup_interrupt.py:45-108](../../../../src/vaultspec_rag/tests/test_cli_startup_interrupt.py#L45)).
- Status tests invoke the Typer app or status helpers against prepared state and temporary status/storage directories. They use a local HTTP server for `/service-state`, health, and service identity checks, and inspect labels, JSON status data, and exit codes ([src/vaultspec_rag/tests/test_cli_status.py:298-400, 411-800, 808-975, 1007-1098](../../../../src/vaultspec_rag/tests/test_cli_status.py#L298)).
- The updates tests invoke `server updates` against local HTTP handlers. They assert GET `/watcher` query filters and POST `/watcher/start`, `/watcher/stop`, and `/watcher/reconfigure` bodies, then inspect prose or JSON responses ([src/vaultspec_rag/tests/test_cli_watcher.py:64-155, 173-265, 421-579, 752-791](../../../../src/vaultspec_rag/tests/test_cli_watcher.py#L64)). A dead port is used for expected unavailable-service paths ([src/vaultspec_rag/tests/test_cli_watcher.py:37-39, 293-311](../../../../src/vaultspec_rag/tests/test_cli_watcher.py#L37)).
- Storage-survey tests construct survey payloads and replace `_try_http_admin` with a local recording transport before invoking the CLI; migration tests pass `MigrateResult` values and use scripted store seams for command outcome coverage (`[src/vaultspec_rag/tests/test_cli_storage_generation_diagnostics.py:35-48, 51-109](../../../../src/vaultspec_rag/tests/test_cli_storage_generation_diagnostics.py#L35); [src/vaultspec_rag/tests/test_cli_storage_migrate.py:35-81, 84-153](../../../../src/vaultspec_rag/tests/test_cli_storage_migrate.py#L35)`).
- Client provisioning tests set the client installation fixture, use a tripwire for Qdrant provisioning, an offline empty model cache, temporary workspaces, and an occupied loopback port; the asserted outputs include JSON errors/reports and unchanged filesystem trees ([src/vaultspec_rag/tests/test_client_provisions_nothing.py:30-88, 90-229](../../../../src/vaultspec_rag/tests/test_client_provisions_nothing.py#L30)).
