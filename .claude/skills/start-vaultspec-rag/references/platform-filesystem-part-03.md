## Capability summary

All capabilities below are represented by test expectations; no production implementation was inspected.

- [src/vaultspec_rag/tests/test_operator_directory_guard.py](../../../../src/vaultspec_rag/tests/test_operator_directory_guard.py): probes that filesystem mutation beneath configured operator roots is refused while reads remain possible; checks refused and permitted `uv` sync, pip, tool, run, project-writing verbs, and venv cases against temporary/foreign paths. It also exercises Windows command-line argument splitting and project-to-`.venv` discovery.
- [src/vaultspec_rag/tests/test_operator_list_pages.py](../../../../src/vaultspec_rag/tests/test_operator_list_pages.py): checks filtering, sorting, bounds and paging for job listings; search-activity records across active and completed lanes; managed logs across rotations with request-id/text filters; and forwarding list parameters through HTTP routes.
- [src/vaultspec_rag/tests/test_operator_repositories.py](../../../../src/vaultspec_rag/tests/test_operator_repositories.py): checks authenticated repository enrollment and inventory, validation before persistence, repeated enrollment, stopping-state refusal, eviction input validation and responsiveness during a registry lock wait, Git worktree grouping, inventory limits/filtering, and vanished enrolled roots.
- [src/vaultspec_rag/tests/test_operator_state.py](../../../../src/vaultspec_rag/tests/test_operator_state.py): checks labels/remediation and start-blocking rules for operator-state enums, service lifecycle exit codes, and that child-process imports of the state vocabulary do not load torch.
- [src/vaultspec_rag/tests/test_operator_state_models.py](../../../../src/vaultspec_rag/tests/test_operator_state_models.py): checks JSON round trips, enum wire values, rejection of unknown fields/state values, client parsing of health/service-state reports, and fail-closed parsing of malformed or newer-release payloads.
- [src/vaultspec_rag/tests/test_packaging_metadata.py](../../../../src/vaultspec_rag/tests/test_packaging_metadata.py): checks installed distribution dependency extras and exclusions, a built wheel's base dependency resolution, the MCP console entry point and builtin payload, and the declared vaultspec-core floor.
- [src/vaultspec_rag/tests/test_paused_surface_legibility.py](../../../../src/vaultspec_rag/tests/test_paused_surface_legibility.py): checks CLI labels/actions for operator and borrower holds, held-job legibility, and forwarding structured service error fields in JSON mode.
- [src/vaultspec_rag/tests/test_pid_image.py](../../../../src/vaultspec_rag/tests/test_pid_image.py): checks psutil and selected public process-image lookups against real child processes, missing-process results, image-name matching, and cleanup of the child process tree.
- [src/vaultspec_rag/tests/test_pid_liveness.py](../../../../src/vaultspec_rag/tests/test_pid_liveness.py): checks liveness for real accessible/inaccessible and absent processes on Windows/POSIX, non-positive pids, and identity between the CLI and package liveness function.
- [src/vaultspec_rag/tests/test_pin_table_writers.py](../../../../src/vaultspec_rag/tests/test_pin_table_writers.py): statically scans Python sources for writes to Qdrant pin tables and undeclared use of the test seam; checks scanner cases, temporary digest pinning/restoration (including failure, interruption and nesting), and agreement with committed pin values.
- [src/vaultspec_rag/tests/test_plain_directory.py](../../../../src/vaultspec_rag/tests/test_plain_directory.py): checks rejecting linked/non-directory ancestors and paths escaping a root, creating plain directories, held-directory operations, safety against link swaps, and the Windows held-name behavior.
- [src/vaultspec_rag/tests/test_point_file_sync.py](../../../../src/vaultspec_rag/tests/test_point_file_sync.py): checks that the harness changes SQLite synchronous mode for the Qdrant point file, preserves the ordinary SQLite default, and gives a `durable` test the ordinary setting.
- [src/vaultspec_rag/tests/test_pool_orphan_guard.py](../../../../src/vaultspec_rag/tests/test_pool_orphan_guard.py): starts workers through the production pool constructor in a child driver, hard-kills the owner, and expects all workers to exit; cleanup is included for assertion failures.
- [src/vaultspec_rag/tests/test_preprocess_approval.py](../../../../src/vaultspec_rag/tests/test_preprocess_approval.py): checks that approvals live in the status directory and bind a canonical root to one exact digest; also checks per-root updates/revocation, fail-closed handling of damaged or unreadable data, private file permissions, and no leftover temporary file.

## Interfaces and data flow

- Pytest functions and fixtures are the entry points. Tests call package functions and models directly, or construct a Starlette `TestClient` around the service app.
- HTTP contracts exercised include `GET /jobs`, `GET /search-activity`, `GET /logs/json`, `GET /repositories`, `POST /repositories/enroll`, and `POST /projects/evict`. Tests pass bearer tokens, query/page filters or JSON bodies and inspect status codes and response fields.
- State/storage touched by the test contracts includes the repository manifest, service logs and rotations, SQLite files, Qdrant pin mappings, and a JSON preprocess-approval store under an isolated status directory. Several tests use `tmp_path` or `isolated_status_dir` to isolate these records.
- External boundaries exercised in test sources include `uv` subprocesses, real Git repositories/worktrees, spawned Python processes, psutil, Qdrant's local persistence class, and installed package metadata. These are test interactions; their runtime behavior was not independently checked here.
