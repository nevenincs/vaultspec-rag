## Capability summary

- [src/vaultspec_rag/indexer/\_config_epoch.py](../../../../src/vaultspec_rag/indexer/_config_epoch.py) provides stable configuration identities using canonical compact JSON and BLAKE2b. It returns aggregate and code/document-specific fingerprints for persistent membership, operation membership, content semantics, execution mode, and an aggregate snapshot. Persistent membership includes source profile/routes, ignore patterns, and preprocess-rule membership/order; operation membership also includes extra excludes. Content fingerprints include decoder, newline, HTML stripping, parser/raw-chunk version markers, preprocessing invocation fields, emitted-byte bounds when relevant, and document chunking settings for the document kind. A separate helper fingerprints the vault chunk-size setting. The module says it stays stdlib-only at runtime for CPU-only worker imports.
- [src/vaultspec_rag/indexer/\_content_policy.py](../../../../src/vaultspec_rag/indexer/_content_policy.py) defines the shared closed vocabulary for code/document ownership, admission outcomes, reason tokens, source profiles, routes, and classified parser selection. Routes validate their syntax when created, and conflicting targets are rejected. Classification first rejects ignored paths; matching explicit routes/transforms determine ownership subject to conflict checks; the explicit-only profile rejects unmatched paths; the conventional profile admits only conventional source suffixes as code. Parser selection is represented separately from the ownership disposition.
- [src/vaultspec_rag/indexer/\_content_discovery.py](../../../../src/vaultspec_rag/indexer/_content_discovery.py) owns read-only code discovery and preflight validation. It resolves one policy snapshot, walks with ignore-aware directory pruning, classifies and probes files, returns admitted code paths plus structured counts and bounded samples, and creates full-tree or exact changed-path preflights. It validates that caller-supplied paths remain canonical, in-root, and admitted under the preflight policy. A membership scan cache is keyed by policy fingerprint and accounts for sample-limit completeness. Raw code is rejected for oversize or binary probes unless a transform matches. Only admitted code contributes support measurement; documents are not included in the code-file projection.
- [src/vaultspec_rag/indexer/\_consumer_pipeline.py](../../../../src/vaultspec_rag/indexer/_consumer_pipeline.py) coordinates bounded CPU chunk production with one consumer thread that encodes and writes weighted code slices. It freezes runtime limits, resolves donor reuse, performs a disk-headroom preflight, runs producer batch and single work into a weighted queue, skips committed segments, checkpoints storage-confirmed slices, tracks file progress and content hashes, records stable empty/skipped/vanished outcomes, propagates typed failures, and bounds consumer shutdown. Its documented ownership boundary leaves support measurement, memory budget, and preprocess accounting with the indexer, reached through callbacks.
- [src/vaultspec_rag/indexer/\_document_checkpoint.py](../../../../src/vaultspec_rag/indexer/_document_checkpoint.py) specializes the shared run-checkpoint base for document generations. It declares document collection/source/embedding identities, packages compatibility inputs for opening a run, validates positive sizing and dimension fields, projects a document slice to an UPSERT commit unit, checks whether exact slices are already committed, records storage-confirmed units and durable progress, and marks a running generation failed while retaining it for resume.
- [src/vaultspec_rag/indexer/\_document_file.py](../../../../src/vaultspec_rag/indexer/_document_file.py) defines immutable per-path document metadata: normalized source path, non-empty content fingerprint, and a non-empty tuple of unique point IDs. Construction enforces those invariants.
- [src/vaultspec_rag/indexer/\_document_identity.py](../../../../src/vaultspec_rag/indexer/_document_identity.py) normalizes document source paths to project-relative POSIX identities and derives deterministic collection-local document point IDs from a versioned canonical payload containing source path, locator or unit ordinal, fragment ordinal, and content fingerprint. Both locator and ordinal branches include the fragment ordinal; IDs are BLAKE2b-derived. The module documents ID version 2 as a re-key for fragment-aware identity.

## Interfaces and data flow

- Admission interface: classify_content accepts a relative path, ignored flag, root content policy, and optional transform kind; it returns ClassifiedContent with an AdmissionDisposition (kind, admitted flag, reason) and, for admitted content, parser language/grammar. Discovery calls this policy boundary for each path and uses source-file stat/probe results to refine raw-code admission.
- Discovery interface: CodeContentDiscovery binds a resolved root, optional RootContentPolicy (default conventional-v1), and extra exclusion patterns. preflight_content returns CodeIndexPreflight containing the resolved policy and structured scan. preflight_changed_paths normalizes and classifies an exact set into CodeScopedPreflight with a source-count/byte measurement. accept_preflight validates root, policy, scope, and full-scan file authority, returning the policy plus either the full admitted paths or a scoped-work marker. scan_codebase/scan_files expose list projections; scan_admission returns the structured result.
- Code indexing interface: CodePipelineBindings bind root/model/store/producer/lifecycle/locks and callbacks; CodePipelineRun supplies reporter, checkpoint, limits, content epoch, target collection, ingest-wait flag, and run control. resolve_limits reads configured segment/queue/embedding limits and model sparse dimension. run takes paths plus the run context and returns ChunkEmbedResult (new IDs, total, path-to-content-hash metadata, reuse statistics). In the implementation, per-file results are segmented, weighted slices are queued, then encoded/upserted by the consumer; confirmed mutations flow through generation/checkpoint lifecycle callbacks.
- Document identity and checkpoint interfaces: document_point_id consumes source path, unit ordinal, content fingerprint, optional locator and fragment ordinal. DocumentFileMetadata stores the resulting identity evidence. DocumentRunOpenRequest groups root, resolved index policy, run policy/operation, clean flag, model/backend identity, dimensions, configuration, and authority inputs; DocumentRunCheckpoint methods bridge generated slices to ledger units and durable progress.
- Storage/state visible in these ranges: the code consumer reads prior code point IDs from the run ledger, counts code points for build headroom when a build target is present, and supplies store-write/checkpoint lifecycle hooks during slice upserts. The document checkpoint delegates to its ledger and run policy. The backing ledger/store implementations are outside the assigned ranges.
