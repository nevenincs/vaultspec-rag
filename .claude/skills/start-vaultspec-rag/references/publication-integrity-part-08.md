## Capability summary

- [src/vaultspec_rag/tests/test_incremental_receipt_recovery.py](../../../../src/vaultspec_rag/tests/test_incremental_receipt_recovery.py) exercises the test-facing integration of `DocumentRunCheckpoint`, `RunLedger`, publication receipts/proofs, SQLite-backed run state, and a local Qdrant collection. Its cases cover repeated and interrupted no-op finalization; mutation-free receipt rollback; recovery/commit of sealed receipts during rebuild; durable progress accounting; explicit authority and full-signature identity checks; readiness from matching indexed file state; resume after proof commit; rejection of changed proof, vanished receipts, unsealed mutations, and unjournaled storage units; and proof-gated generation publication (helpers/fixtures 23-132; principal cases 141-319, 320-437, 439-580, 583-817).
- [src/vaultspec_rag/tests/test_incremental_route_reconciliation.py](../../../../src/vaultspec_rag/tests/test_incremental_route_reconciliation.py) builds a real `VaultStore` test fixture with an explicit `*.txt` document / `*.py` code policy. It covers scoped reconciliation of changed paths, no content scans on no-op, bounded path batches, source-path filtering, cross-kind cleanup only when the destination is present, and rejection of private origin collections (fixture/helpers 55-232; cases 235-487). Scroll observation records which store methods are called and their path selections (68-99).
- [src/vaultspec_rag/tests/test_index_cuda_reservation_credit.py](../../../../src/vaultspec_rag/tests/test_index_cuda_reservation_credit.py) characterizes `resolve_index_cuda_ceiling_mib` and `MemoryBudget.observe` with a mocked guarded device observation. It covers allocator reservation credit, actual allocated-peak enforcement, explicit zero versus unreadable reservation, total-memory clamping, configuration overrides, missing device readings, CPU-only, and Torch-absent fallbacks (15-28, 31-81, 84-196).
- [src/vaultspec_rag/tests/test_index_lifecycle.py](../../../../src/vaultspec_rag/tests/test_index_lifecycle.py) specifies expectations for the shared `run_index_lifecycle` wrapper: activity stamps before and after a run, preservation of a start stamp on failure, structured started/completed/failed events, completion extras, and a document-stamp-to-reclamation path. Structural guards enumerate indexer classes and require their `full_index`/`incremental_index` methods to route through the shared lifecycle, avoid direct stamping and mode spellings, and leave the event namespace to `_index_lifecycle.py` (52-159; 162-344; 346-482).
- [src/vaultspec_rag/tests/test_index_profiles.py](../../../../src/vaultspec_rag/tests/test_index_profiles.py) specifies support-profile selection/admission and status expectations. It covers independent code/document dimensions, weighted corpus measurement across calls, declared managed/embedded limits, backend/RAM/disk and corpus refusals, free-space measurement targets, same-volume handling, readable refusal details, a lower-floor profile suggestion only when the backend is accepted, and domain status dimensions (37-138, 141-203, 206-265, 268-506, 507-521).
- [src/vaultspec_rag/tests/test_index_resource_ceilings.py](../../../../src/vaultspec_rag/tests/test_index_resource_ceilings.py) characterizes how code and document indexer test factories freeze `MemoryBudget`: RSS uses the tighter profile/configuration limit; CUDA ceilings/baselines require CUDA; a positive configured CUDA ceiling is expected to be authoritative; admission snapshots are expected before dispatch; and no-headroom refusal details are exercised (37-145, 148-447). Its configured-ceiling test class is marked `cuda` (258-326); no GPU test was run.

## Interfaces and data flow

- Receipt recovery test flow: helper code opens local Qdrant storage, creates `served`, creates a `RunLedger` at `runs.sqlite3`, opens compatible generations/checkpoints, and writes `CommitUnit` mutations through checkpoint lifecycle prepare/apply/confirm/record steps. Tests then inspect receipt/proof/generation state and collection counts, including direct SQLite edits/triggers for refusal cases (54-132, 225-319, 323-387, 515-580, 613-817). These are test caller sequences; ledger semantics are not inspected here.
- Route test flow: a temporary-root `VaultStore` and resolved `RootContentPolicy` feed `DocumentRunOpenRequest` and `DocumentRunCheckpoint`; helpers write document chunks through mutation lifecycle records, then call `reconcile_generation_storage` or `reconcile_checkpoint_routes`. Tests inspect returned three-item tuples, stored IDs, and observed `scroll_*` calls. The route scanner is also called directly with `RouteScanOptions(source_paths=...)` and with an explicit collection (101-232, 258-289, 302-363, 408-438, 463-487). Tuple component meanings are not established by these tests alone.
- Resource admission flow: `SupportMeasurement`, backend/RAM values, and `VolumeReading` records are assembled into `AdmissionEnvironment`, passed to `validate_profile_admission`, and inspected through returned profile or `JobError`; profile status is read through `index_support_profile_status` (141-171, 181-265, 316-465, 507-521). The weighted-code fixture creates source via benchmark helper `module_source`, chunks it, segments it, and feeds repeated segments to `CodeSupportBudget.measure_code_segments` (37-123).
- Memory flow: code/document test factories instantiate `CodebaseIndexer` or `DocumentIndexer`, supply profile limits and a device shape, then inspect a frozen budget or admission snapshot. Separate CUDA reservation tests replace only `memory_probe.cuda_device_memory` and call the resolver / `MemoryBudget.observe` (68-120, 133-145, 148-255, 258-365, 385-447; reservation module 21-28, 31-81, 180-196).
- Lifecycle flow: test helpers call `run_index_lifecycle` with an `IndexLifecycleRequest` carrying logger, store, source, mode, clean flag, root, and `NO_RUN_CONTROL`; tests inspect a persisted manifest entry and structured event fields. The reclamation test feeds the manifest-derived survey and stamp into `classify_namespaces` and `evaluate_reclaim` (115-159, 221-285, 288-344).
