## Capability summary

This package contains performance-marked pytest measurements, operator-invoked live-service benchmarks, production-path acceptance harnesses, and captured JSON result artifacts. Performance tags and benchmark source assertions describe intended checks; they do not establish that a test passed or that a captured run is reproducible.

- [src/vaultspec_rag/tests/benchmarks/bench_codebase_chunking.py](../../../../src/vaultspec_rag/tests/benchmarks/bench_codebase_chunking.py) builds a 2,000-file synthetic Python tree, chunks it serially and with a process-worker count based on available CPUs, compares chunk IDs, checks for logged chunk failures, and on a multi-core host expects parallel elapsed time to be lower.
- [src/vaultspec_rag/tests/benchmarks/bench_concurrency.py](../../../../src/vaultspec_rag/tests/benchmarks/bench_concurrency.py) is a standalone live-service load driver. It discovers the service port/token from configured status storage, warms each supplied root, sends concurrent search requests through a bounded thread pool, aggregates client latency and server timing fields, optionally starts a code reindex, measures the in-memory readiness registry separately, and prints or writes a JSON report. Scenario builders cover same-root vault, code, mixed, immediate-readiness, and bounded-readiness requests; cross-root mixed is added when multiple roots are supplied.
- [src/vaultspec_rag/tests/benchmarks/bench_document_index_resilience.py](../../../../src/vaultspec_rag/tests/benchmarks/bench_document_index_resilience.py) prepares a deterministic, marker-owned document workload containing raw text and extracted binary inputs. Its measurement path exercises document preflight, extraction/chunking and queue-weight measurement, then profile admission. The acceptance path loads the embedding model and store, interrupts indexing after durable ledger units exist, resumes, and checks generation continuity and storage/result counts. The CLI supports preparation-only, measurement, acceptance, and optional JSON output.
- [src/vaultspec_rag/tests/benchmarks/bench_hash_gate.py](../../../../src/vaultspec_rag/tests/benchmarks/bench_hash_gate.py) is a CPU/disk performance test over 2,000 files. It times raw digest, stat, cancellation checkpoint, durable job-state persistence, and the production hash gate cold and warm; source assertions compare ratios and verify warm hash reuse.
- [src/vaultspec_rag/tests/benchmarks/bench_large_index_resilience.py](../../../../src/vaultspec_rag/tests/benchmarks/bench_large_index_resilience.py) creates or resumes a marker-owned Python corpus, samples files through the production chunker, applies managed-service admission, and can run the production code index while measuring memory and wall time. It checks resulting files/chunks against the requested floor and can log or retain benchmark evidence. Defaults describe 83,624 files and 250,872 expected chunks.
- [src/vaultspec_rag/tests/benchmarks/bench_progress_publish.py](../../../../src/vaultspec_rag/tests/benchmarks/bench_progress_publish.py) compares repeated real manager progress updates against full persisted-state writes and checks the live progress value and an amortization ratio.
- [src/vaultspec_rag/tests/benchmarks/bench_rag.py](../../../../src/vaultspec_rag/tests/benchmarks/bench_rag.py) defines performance tests for embedding throughput, full indexing, no-op incremental indexing, vault search latency, and GPU/Qdrant disk usage.
- [src/vaultspec_rag/tests/benchmarks/bench_search_noise.py](../../../../src/vaultspec_rag/tests/benchmarks/bench_search_noise.py) constructs a synthetic polyglot corpus with production modules and test, docs, locale, vendored, generated, and worktree copies. Its fixture indexes through the code indexer and searches with the noise profile enabled or with domains re-admitted; assertions check that worktree paths stay out, hidden domains disappear under defaults, overall noise falls, and an only-domain query returns only that domain.
- [conftest.py](../../../../conftest.py) supplies session-scoped benchmark components built from a 48-document synthetic vault (seed 300), indexes the corpus, and exposes model, store, indexer, searcher, and root fixtures. It closes the shared store at fixture teardown.
- `baselines/ab_469k_local.json` and [src/vaultspec_rag/tests/benchmarks/baselines/ab_469k_server.json](../../../../src/vaultspec_rag/tests/benchmarks/baselines/ab_469k_server.json) are captured three-scenario same-root reports with six requests at concurrency three. They retain per-phase and latency/throughput metrics for vault, code, and mixed search.
- `baselines/w01_baseline.json` and [src/vaultspec_rag/tests/benchmarks/baselines/w05_results.json](../../../../src/vaultspec_rag/tests/benchmarks/baselines/w05_results.json) are captured four-scenario reports with eight requests at concurrency four, adding cross-root mixed search to the same-root scenarios.
- `baselines/search_readiness_471_cpu_control.json` records a CPU-only readiness registry control, a live-service comparison, environment/command details, and stated acceptance values for issue 471.
- [src/vaultspec_rag/tests/benchmarks/__init__.py](../../../../src/vaultspec_rag/tests/benchmarks/__init__.py) is empty.

## Interfaces and data flow

- Pytest callers use the performance-marked functions in the chunking, hash-gate, progress-publish, RAG, and search-noise modules. The benchmark fixture module provides shared components to tests that request its named fixtures. The concurrency module has a `main(argv)` CLI entry and documents `python -m vaultspec_rag.tests.benchmarks.bench_concurrency`; the two resilience modules also have module CLIs.
- The concurrency CLI accepts repeated project roots, request count, concurrency, top-k, timeout, optional reindex, and optional report path. It reads `service.json` under configured status storage, sends JSON to localhost `/search` and optionally `/reindex`, recognizes bearer-token authentication, and aggregates JSON response status/results plus timing and readiness data. Outputs are console summaries and an optional report containing roots, scenarios, and readiness-control measurements.
- The document harness writes a marker, raw `.txt` and extracted `.blob` inputs, a generated extractor script, and preprocessing configuration under its workload root. Measurement reports source/extracted/chunk/weighted/queue and RSS/CUDA byte counts. Acceptance also interacts with the document indexer, run ledger, embedding model, and store, then returns a report with interruption/resume evidence.
- The large-index harness writes source modules under its dedicated root and a corpus marker; it measures the real index run and validates store counts and support measurements. Its JSON output may be written to a requested path; a separate evidence helper logs the report and can retain an atomic JSON copy in an explicit or environment-configured directory.
- The RAG fixture path uses the parent test helpers `RagComponentsWithManifest` and `_index_corpus`, plus `build_synthetic_vault`. The RAG memory test reads CUDA device/memory metrics and sums files below the configured local Qdrant directory when that path exists. Other isolated performance tests use pytest temporary roots.
- The baselines are static data artifacts, not executable benchmark entry points.

## Boundaries and dependencies

- This slice shows callers and imports, not the implementation of imported services. Production behavior of `CodebaseIndexer`, `DocumentIndexer`, `VaultStore`, `EmbeddingModel`, `VaultSearcher`, the search/reindex HTTP handlers, admission rules, preprocessing, storage, and ledger durability remains unverified.
- The codebase chunking test imports `produce_chunks`; the hash-gate test imports `StatEvidenceGate` and `hash_paths`; document and large-index harnesses call production preflight/chunk/index/store paths. Their local assertions establish only what the harness checks when run.
- Concurrency’s readiness measurement directly constructs `ReadinessRevisionRegistry`, but the registry’s locking, scheduling, or service integration are outside this slice. The recorded CPU/live-service values are historical data and are not independent validation.
- [src/vaultspec_rag/tests/benchmarks/bench_search_noise.py](../../../../src/vaultspec_rag/tests/benchmarks/bench_search_noise.py) states that it uses real GPU/Qdrant components and imports real classes in its fixture. This source alone does not verify the external fixture implementations, installed backend, or a run in this environment. Likewise, module docstrings in other benchmarks describe intent and operating assumptions rather than verified outcomes.
