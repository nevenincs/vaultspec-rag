## Capability summary

- **[tools/check_docs_conventions.py](../../../../tools/check_docs_conventions.py)** checks fixed manual pages for mixed CLI invocation lanes and missing lane declarations, all docs Markdown for environment-only code examples without nearby explanation, the service-version example ordering, and platform-specific PATH spellings in the MCP manual. It prints issues and returns 1, otherwise prints a clean summary and returns 0 (implementation: lines 270-303).
- **[tools/check_docs_version.py](../../../../tools/check_docs_version.py)** scans README and Markdown below docs for vaultspec-rag vX.Y.Z literals and compares them with the package version parsed from pyproject; stale literals return 1 (47-70).
- **[tools/citation_gate.py](../../../../tools/citation_gate.py)** scans repo text for development-record citations and separately scans a broader file set for workstation identity leaks. Python citations are limited to prose positions such as docstrings, comments, documentary arguments and user-facing messages; product text/config is scanned as raw text. Generic absolute-drive paths are reported as non-failing smells. Findings are split into active/deferred citations, hard leaks and smells; default mode fails on active citations or leaks, while --report-only returns 0 (scanner boundaries: 770-840, 945-1025; enumeration/collection/CLI: 1028-1303).
- **[tools/health_report.py](../../../../tools/health_report.py)** ranks six dimensions across src/vaultspec_rag: cyclomatic and cognitive complexity, Ruff function-size findings, physical module length, maintainability, and strict-type diagnostics. Its module documentation says it is a measurement report that always exits 0. --top limits displayed rows and --fast skips basedpyright (103-337).
- **[tools/conftest.py](../../../../tools/conftest.py)** provides session fixtures repo_root and parsed pyproject for release-instrument tests (25-34). Fixture consumers were not inspected.
- **[tools/monitor/\_\_init\_\_.py](../../../../tools/monitor/__init__.py)** adds the checkout src directory to sys.path if absent, for imports from bare release interpreters (6-9).
- **[tools/monitor/frontend.py](../../../../tools/monitor/frontend.py)** inventories regular frontend assets, hashes/types them, rejects symlinks and unsupported files, requires HTML and JavaScript, and checks local asset references. It copies an inventory into a new handoff with a JSON identity/asset manifest, then validates identity and the full asset inventory before compilation (51-68, 98-141).
- **[tools/monitor/build.py](../../../../tools/monitor/build.py)** binds a frontend handoff to checkout revision and package-lock digest, rejects dirty release checkouts unless explicitly development-marked, builds Vite once, and compiles a native monitor with provisioned Bun. It validates the handoff, verifies Bun and output, finalizes platform resources/signing, and writes a checksum. CLI operations are frontend, compile, and test (41-77, 158-268).
- **[tools/monitor/provenance.py](../../../../tools/monitor/provenance.py)** resolves a canonical release tag to its exact commit, verifies GitHub attestations for archives against the expected repository workflow, tag and source digest, checks bundle producer identity, and validates cross-target release-set consistency (39-147). Its CLI validates a supplied release directory (149-156).
- **[tools/monitor/acquire.py](../../../../tools/monitor/acquire.py)** obtains latest-release metadata or uses a supplied tag, authenticates the target archive, cross-checks live checksums, extracts and verifies bundle executables, then probes the monitor in a shell-only directory. It can select the offline probe and writes JSON output (35-162, 165-187).
- **[tools/monitor/offline.py](../../../../tools/monitor/offline.py)** wraps the canonical smoke probe with platform-specific outbound-network denial: macOS Seatbelt, Linux seccomp via [tools/monitor/linux_exec.py](../../../../tools/monitor/linux_exec.py), or Windows host-provided executable firewall policy. It checks an outbound positive control and returns report fields describing mechanism and scope (27-33, 55-110, 113-231).
- **[tools/monitor/linux_exec.py](../../../../tools/monitor/linux_exec.py)** verifies a binary digest, installs a seccomp filter for reviewed x86_64/aarch64 syscall maps, then replaces the Python process with the binary. The filter denies connect, io_uring setup and non-approved socket use while preserving local AF_UNIX and TCP stream use (26-82).
- **[tools/monitor/entitlements.plist](../../../../tools/monitor/entitlements.plist)** grants macOS JIT and unsigned-executable-memory entitlements (1-10).

Docstrings/comments and CLI help are documentation claims, not execution results. No selected source is a test suite.

## Interfaces and data flow

- The docs checks are executable Python CLIs with fixed repo-relative inputs; they print diagnostics and status codes. The convention checker reads MANUAL_PAGES and then all docs Markdown for environment-only examples. The version checker reads the project version and scans README/docs (conventions: 44-62, 270-303; version: 25-70).
- Citation-gate flow: enumerate Git cached and non-ignored untracked files, partition citation surfaces, scan Python AST/comment views and raw text, discover host identity from environment/git configuration unless injected, scan the separate identity file set, sort findings, and choose a status. collect_findings(repo_root, machine_identity=...) and per-file scanners can target another tree; CLI accepts --report-only (546-615, 945-1025, 1035-1225, 1228-1303). Results are in-memory tuples; this code writes no persistent report.
- Health-report flow reads TOML thresholds, walks package Python files, invokes radon/complexipy APIs and Ruff/basedpyright subprocesses, then renders Rich tables. Arguments are --top N and --fast (66-90, 103-159, 162-221, 244-337).
- Monitor release flow: build produces a manifest-backed frontend handoff; compile consumes it with expected manifest digest and producer identity. Acquisition resolves a release and downloads metadata/checksums/archive, admits the archive, extracts verified binaries, then passes a binary and identity metadata to a smoke probe. Provenance separately validates all supported-target archives and release-set consistency (build: 41-77, 80-123, 158-201; acquire: 90-162; provenance: 70-147).
- Offline probing verifies the monitor digest. Linux launches under the Python seccomp wrapper; macOS invokes sandbox-exec; Windows copies monitor/control binaries into host-designated denied paths under an exclusive claim lock, verifies denial, probes, and removes the copies. The browser harness is passed to the smoke probe and is described as outside policy on Windows/Linux (offline: 113-231; Linux wrapper: 71-82). Acquisition requires target and report path; its JSON output combines smoke results with release/provenance identities (acquire: 143-183).

No tool was run and no dependency/config implementation was inspected. Health threshold ownership is described as pyproject gates, but that config was not read.
