## Capability summary

- [src/vaultspec_rag/logging_config.py](../../../../src/vaultspec_rag/logging_config.py) owns RAG’s structured event format, bounded managed-log query/read/validation/rendering contract, daemon stdout/stderr capture and log rotation pipeline, fatal-fault dump setup, successful poll-access filtering, and selected third-party logger levels. Its module documentation says producers should use its event/log pipeline (1-19); public exports are listed at 49-73.
- [src/vaultspec_rag/memory_probe.py](../../../../src/vaultspec_rag/memory_probe.py) provides optional RSS/CUDA checkpoints and a background RSS sampler, backend-neutral CUDA/MPS observations, CUDA ceiling derivation, resident-baseline tracking, lock-bracketed forward-peak capture, and an immutable per-run memory budget that latches typed failures. It also projects snapshots to resource bytes and renders probe reports.
- [src/vaultspec_rag/monitor_inventory.py](../../../../src/vaultspec_rag/monitor_inventory.py) builds offline repository or storage-survey inventory payloads for a monitor when there is no live daemon response. It delegates to service projections and disk-survey operations (9-47).
- [src/vaultspec_rag/monitor_process.py](../../../../src/vaultspec_rag/monitor_process.py) starts and owns the compiled monitor process, verifies its readiness/access link, publishes its process incarnation and port, exposes discovery fields, and reaps stale monitor processes only after PID/start-time checks (37-319).

## Interfaces and data flow

- Logging: log_event(logger, namespace, event, \*\*fields) validates event and field tokens, renders a stable namespace/event/key=value record, and passes structured metadata to Python logging (154-227). configure_logging resolves the level and delegates root setup to core (852-896). The managed-log API resolves the status directory, reads service and/or Qdrant active plus sparse rotated files under record/source byte limits, then applies filters, paging, response bounds, payload validation, and rendering (230-849). The all result orders service then Qdrant, without claiming cross-source chronology (516-546).
- Daemon capture: installation validates retention settings, creates a pipe and stderr handler, replaces root handlers, starts one drain thread that writes through RawRotatingLogSink, and installs logger filters/levels (983-1137, 1220-1234, 1269-1339). DaemonLogCapture.close flushes producers, detaches stdout/stderr, joins the writer, and reports completion. Fatal interpreter dumps go to a .fatal sibling (1236-1266).
- Memory: environment variable VAULTSPEC_RAG_MEMORY_PROBE gates only the diagnostic MemoryProbe; invalid boolean spellings raise (95-101, 172-195, 1249-1276). RSS uses a cached psutil.Process; torch is imported lazily for guarded CUDA/MPS readings (198-219, 261-421). MemoryBudget enforcement is independently active when constructed: it stores optional admitted ceilings/baseline, tracks RSS and captured CUDA peaks, and raises/latches JobError on unavailable enforced readings or a strict ceiling breach. RSS takes precedence over CUDA on a simultaneous breach; reserved CUDA memory is diagnostic (830-1189). Snapshot projection reports peak RSS and allocated CUDA bytes, not reserved bytes (811-827).
- Monitor inventory: accepts an operation and string parameters. It resolves an optional root, dispatches repositories to the repository projection with no live reading, or validates a survey status and shapes a disk survey with a UTC timestamp and source=disk; unsupported operation/status or unavailable storage directory raises (9-47).
- Monitor process: MonitorProcess(backend_port).start() finds the executable, chooses a port above the backend, starts it with managed status/backend/Python settings, and waits for a readiness line containing a loopback HTTP capability URL with a fragment and port above the backend (37-81, 175-260). Identity JSON records owner and child PID/start times and port under a status write lock; discovery fields appear only while the child is alive (84-99, 185-196, 262-267). Output lines other than readiness are logged with a 4,096-character cap (269-281). Stop/reap paths signal and wait, preserve records when identity or lock state cannot safely be verified, and remove a matching record after exit (101-172, 283-319).
