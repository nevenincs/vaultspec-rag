## Capability summary

- [src/vaultspec_rag/indexer/\_vault_indexer.py](../../../../src/vaultspec_rag/indexer/_vault_indexer.py) defines `VaultIndexer`, the vault indexing coordinator. Its public operation methods are `full_index` and `incremental_index`; private locked methods implement their work. The class serializes operations per instance, records observational memory telemetry, resolves donor reuse, controls run lifecycle/checkpoints, calls the store and streaming helpers, then returns `IndexResult`.
- Full indexing scans the vault, prepares and hashes documents, opens a full-run checkpoint, streams replacement content, removes shrunken chunk tails, and then purges stale documents after the stream and ingest barrier complete. `clean=True` also removes superseded-layout points. Collection recreation is attempted on a storage-geometry error only for a clean rebuild. Successful work publishes proof/generation metadata and reports added, removed, duration, device, and reuse information.
- Incremental indexing recovers pending publication first. With `changed_paths=None`, it scans the current vault, reads prior publication evidence, hashes and classifies documents, reconciles changed/new documents, deletes removed documents, and publishes a generation. With `changed_paths` present, it delegates to `_scoped_incremental_locked` from the imported mixin; that implementation was not inspected.
- [src/vaultspec_rag/indexer/\_vault_prep.py](../../../../src/vaultspec_rag/indexer/_vault_prep.py) owns `IndexResult`, metadata/title/status/feature extraction, markdown document preparation, and document-to-chunk conversion. It can split a corpus serially or through CPU-only spawn workers according to worker configuration and a byte threshold; a broken process pool triggers serial splitting.
- No external call-site files were in scope. The two operation methods and the helper calls visible inside them are the only callers/interfaces that can be described from this slice.

## Interfaces and data flow

- `VaultIndexer(root_dir, model, store, *, gpu_lock=None, publish_readiness=None)` retains the workspace, embedding model, vector store, optional GPU lock, and readiness callback. Initialization also creates a per-instance writer lock and a resident stat-evidence cache at the workspace-volume path `vault_index.statgate.sqlite3` ( [src/vaultspec_rag/indexer/\_vault_indexer.py:67-118](../../../../src/vaultspec_rag/indexer/_vault_indexer.py#L67)).
- `memory_budget_snapshot` exposes the held immutable snapshot. Each operation wrapper enters `_memory_telemetry`; it records before/after process readings and forward peaks with no configured ceiling, and samples CUDA only when `model.device == "cuda"` ([src/vaultspec_rag/indexer/\_vault_indexer.py:120-168](../../../../src/vaultspec_rag/indexer/_vault_indexer.py#L120)).
- `full_index(clean=False, *, reporter, authority=REBUILD, run_control=NO_RUN_CONTROL)` checkpoints the run, applies rebuild-specific ledger/publication handling, takes the writer lock, and invokes the lifecycle wrapper. The locked path uses the configured embedding batch size, `scan_vault`, the mixin's document preparation and hashing methods, `VaultRunCheckpoint`, donor reuse, and `_stream_encode_and_upsert_vault`. It computes the expected point count for `apply_ingest_barrier` before stale deletion, then publishes proof and generation metadata ([src/vaultspec_rag/indexer/\_vault_indexer.py:184-445](../../../../src/vaultspec_rag/indexer/_vault_indexer.py#L184)).
- `incremental_index(*, reporter, changed_paths=None, authority=PUBLICATION, run_control=NO_RUN_CONTROL)` takes the same writer lock, recovers pending publication (replay is full-scan), then invokes lifecycle handling. The unscoped path obtains a publication snapshot and stored chunk counts, hashes current documents, reconciles classified changes, records confirmed deletions, publishes the generation, and returns counts including payload-only updates. The scoped branch is delegated to the mixin ([src/vaultspec_rag/indexer/\_vault_indexer.py:446-667](../../../../src/vaultspec_rag/indexer/_vault_indexer.py#L446)).
- `_prepare_collection` calls `store.ensure_table()` and snapshots chunk counts. If geometry is incompatible, a non-clean rebuild raises; a clean rebuild drops and recreates the table and treats the new snapshot as empty. `_purge_shrunk_chunk_tails` deletes ordinals above the replacement chunk count through the streaming mutation helper and can record checkpoint deletion evidence ([src/vaultspec_rag/indexer/\_vault_indexer.py:676-772](../../../../src/vaultspec_rag/indexer/_vault_indexer.py#L676)).
- `prepare_document(path, root_dir, skip_read_errors=True)` reads UTF-8 text; a read exception is logged and returns `None` by default, while `skip_read_errors=False` re-raises. `vault_document_from_text` parses metadata, resolves document type and path, builds an ID from the relative path without its extension, derives title/status/body line, strips the body, and returns a `VaultDocument` with an empty vector. Unknown document types return `None` ([src/vaultspec_rag/indexer/\_vault_prep.py:364-474](../../../../src/vaultspec_rag/indexer/_vault_prep.py#L364)).
- `split_document` makes ordered, non-overlapping markdown chunks and attaches path/type/feature/date/tags/related/title/status plus line spans, section, and passages. The first chunk carries the full body in `doc_content`; an empty or whitespace-only split falls back to a single chunk. `split_documents` preserves batch result order, checks run control between work units, and uses the serial path when worker planning returns one ([src/vaultspec_rag/indexer/\_vault_prep.py:187-363](../../../../src/vaultspec_rag/indexer/_vault_prep.py#L187)).
- `IndexResult` carries total/added/updated/removed counts, elapsed milliseconds, device, payload-only updates, file/preprocessing counts and failures, optional reuse stats, and optional drift telemetry ([src/vaultspec_rag/indexer/\_vault_prep.py:67-120](../../../../src/vaultspec_rag/indexer/_vault_prep.py#L67)).

## Boundaries and dependencies

- The coordinator imports `VaultIncrementalMixin`, `classify_documents`, and `controlled_phase` from `._vault_incremental`. Methods including `_prepare_documents_bounded`, `_hash_documents`, `_scan_vault_for_docs`, `_scoped_incremental_locked`, `_reconcile_classified`, and publication evidence helpers are used or expected through that relationship; their behavior is uninspected.
- Storage mutation and streaming semantics are delegated through `._streaming` (`_stream_encode_and_upsert_vault`, `execute_store_mutation`) and the injected `VaultStore`. Checkpoint, run ledger, lifecycle, publication state, fingerprints, stat evidence, configuration, and reuse behavior are delegated to imported modules. Their implementations and failure semantics are uninspected.
- Vault scanning and metadata parsing are delegated to `vaultspec_core.vaultcore` (`scan_vault`, `parse_vault_metadata`, `get_doc_type`, `DocType`). Chunking and Markdown structure are delegated to `._chunking` (`TextSplitter`, `locate_pieces`) and `.._markdown_passages.parse_markdown`. The source shows how these interfaces are called but not their internal behavior.
- `VaultIndexer`'s class docstring describes Qdrant, but the implementation in this slice interacts through the injected `store`; the concrete backend was not inspected. Likewise, configured worker counts, thresholds, chunk size, and embedding batch size were not read from settings.
- The split worker function documents CPU-only spawn work and does not construct an embedding model or touch CUDA. This is a source-level responsibility statement; worker process behavior and pool guard internals were not inspected.
