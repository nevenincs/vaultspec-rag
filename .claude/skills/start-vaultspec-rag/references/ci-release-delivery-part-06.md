## Capability summary

- [tools/monitor/smoke.py](../../../../tools/monitor/smoke.py) is the native-binary probe and report writer. It creates an isolated temporary home, config directories, PATH, status/storage locations, and ambient-config tripwires; verifies the supplied binary digest; checks JSON version identity; refuses an occupied strict port; starts a managed instance; checks loopback access-link shape, embedded asset bytes/MIME and identity, unavailable-backend semantics, bearer authorization and foreign-origin refusal, request validation/size boundaries, partial-client recovery, parent-EOF shutdown, and optionally the delivered UI in an installed browser. Its report records those checks and platform metadata. The optional browser driver is a separate [dev/monitor-browser.mjs](../../../../dev/monitor-browser.mjs) file and was not inspected.
- [tools/monitor/release.py](../../../../tools/monitor/release.py) admits the release wheel and target bundle set and connects release inputs to smoke evidence. Wheel admission validates the project wheel and requires exact copies of three canonical owner modules. Native smoke requires a host-native target, reads the matching executable's checksum, selects regular or OS-offline probing, and writes `monitor-smoke.json`. Release-set admission requires precisely the product's supported archive names and verifies each archive's producer revision, lock digest, and frontend digest. Its CLI exposes `wheel`, `native-smoke`, and `verify-set` operations.
- [tools/monitor/tests/__init__.py](../../../../tools/monitor/tests/__init__.py) is assigned as empty. [tools/monitor/tests/test_build.py](../../../../tools/monitor/tests/test_build.py) states expectations for release identity against a clean checkout, dirty lock refusal, and explicit development identity. [tools/monitor/tests/test_frontend.py](../../../../tools/monitor/tests/test_frontend.py) expects bare-interpreter release-tool imports and checks frontend handoff asset/MIME preservation plus refusal of changed bytes, added assets, producer mismatch, rehashed changed content, and nonembedded CSS references. [tools/monitor/tests/test_offline.py](../../../../tools/monitor/tests/test_offline.py) expects offline proof to reject an allowed external TCP connection and invalid/missing denied-directory configuration. [tools/monitor/tests/test_provenance.py](../../../../tools/monitor/tests/test_provenance.py) specifies attestation command flags and archive/source binding, rejects archive mutation during attestation, checks extraction refusal before writes for producer/digest mismatch, requires all supported release targets, and covers annotated-tag peeling, invalid tag input, and duplicate checksum handling. [tools/monitor/tests/test_release.py](../../../../tools/monitor/tests/test_release.py) expects exact canonical wheel owners and a complete target set with common producer, lock, and frontend identity.
- [tools/packaging/__init__.py](../../../../tools/packaging/__init__.py) documents a shared, product-parameterized release-channel renderer. [tools/packaging/products.py](../../../../tools/packaging/products.py) owns product identity, executable names, target/channel matrices, archive naming, and product caveats. It defines the RAG product's three commands and supported targets.
- [tools/packaging/bundles.py](../../../../tools/packaging/bundles.py) builds and verifies one deterministic public archive plus checksum sidecar. It stages target-qualified executables under stable names with the license and generated README, validates monitor smoke evidence against release identity and measured platform floor, writes a manifest describing components/runtime/requirements/platform and each member digest, and emits ZIP for Windows or TAR.GZ otherwise. Verification rejects wrong archive names, non-file/duplicate/extra/missing members, malformed or inconsistent metadata, content/size/hash mismatch, and noncanonical permission modes. Its CLI builds or verifies a bundle.
- [tools/packaging/checksums.py](../../../../tools/packaging/checksums.py) parses SHA256SUMS-style aggregates, rejecting carriage returns, malformed rows, empty input, conflicting duplicate names (or any duplicates when `require_unique=True`), and missing required assets; reads preserve actual newline bytes.
- [tools/packaging/generate.py](../../../../tools/packaging/generate.py) generates Scoop and Homebrew pointers from release checksums after checking that neither channel pointer moves backward. It includes only Homebrew targets supported by the product and listed in the checksum map, warns for missing supported targets, and refuses when no target is available. The CLI selects product/tag/checksum/root and writes both generated files.
- [tools/packaging/scoop.py](../../../../tools/packaging/scoop.py) renders the Windows Scoop manifest, pinning the release archive digest and listing executable aliases plus checkver/autoupdate metadata and product notes. [tools/packaging/homebrew.py](../../../../tools/packaging/homebrew.py) renders a binary formula with one archive URL/hash per available OS/CPU branch, installs the product's stable executable names, carries product notes and applicable Linux glibc caveats, and emits a version smoke test.
- [tools/packaging/pointer.py](../../../../tools/packaging/pointer.py) reads current Scoop/Homebrew versions and rejects a clearly older incoming numeric version prefix; missing, equal, or unorderable values pass through by design. [tools/packaging/tests/__init__.py](../../../../tools/packaging/tests/__init__.py) contains only the test-package docstring.
- [tools/packaging/tests/test_bundles.py](../../../../tools/packaging/tests/test_bundles.py) specifies archive contents, manifest/runtime metadata, checksums, deterministic bytes, canonical modes, and refusal of missing executables, unsupported targets, bad metadata, and unproven monitor evidence. [tools/packaging/tests/test_checksums.py](../../../../tools/packaging/tests/test_checksums.py) specifies valid parsing and rejection of CRLF, malformed rows, duplicates, empty input, absent names, and newline translation. [tools/packaging/tests/test_committed_channels.py](../../../../tools/packaging/tests/test_committed_channels.py) specifies release workflow ordering, published checksum inputs, generated pointer staging/push paths, workflow permissions/key use, and absence of duplicate local channel roots; those external files were not inspected.

## Interfaces and data flow

- Native probe CLI: `--binary`, `--expected-sha256`, `--version`, `--source-revision`, optional `--browser`, and required `--report`. It verifies before launching and writes a JSON report. The `probe` function accepts the same identity as a mapping and optional launch prefix. Runtime outputs include the selected host triple, platform evidence, verified asset count, and booleans for the exercised boundaries ([tools/monitor/smoke.py:339-453](../../../../tools/monitor/smoke.py#L339)).
- Release CLI: required `--tag` and `--directory`, with operation-specific `--source-revision`, `--target`, `--os-offline`, or `--frontend-sha256`. Wheel mode reads the wheel and canonical source tree; native-smoke reads a target binary and `.sha256` sidecar and writes `monitor-smoke.json`; verify-set reads archives from a directory and hashes the repository lockfile ([tools/monitor/release.py:28-43,45-68,71-99,101-139](../../../../tools/monitor/release.py#L28)).
- Bundle input is raw target-qualified executable files, a smoke report, repo license, source revision, and package lockfile. Output is a named `.zip`/`.tar.gz` archive, embedded `manifest.json`, and adjacent `.sha256`; `verify_bundle` returns the parsed manifest after contract validation ([tools/packaging/bundles.py:347-401,404-601](../../../../tools/packaging/bundles.py#L347)).
- Channel generation input is product, version/tag, and release checksum aggregate. It writes `bucket/<product>.json` and `Formula/<product>.rb` under the chosen root ([tools/packaging/generate.py:45-111](../../../../tools/packaging/generate.py#L45)). The generated pointers pin the release archive digest from SHA256SUMS and point at the product's release URL ([tools/packaging/scoop.py:34-78](../../../../tools/packaging/scoop.py#L34); [tools/packaging/homebrew.py:48-91,150-207](../../../../tools/packaging/homebrew.py#L48)).
- The test sources construct local archives/checksum fixtures or inspect workflow text and assert behavior. They do not establish that the implementation was executed successfully in this session.
