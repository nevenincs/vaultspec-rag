## Interfaces and data flow

- **Provisioning (test expectations):** Tests call `provision_dependencies`, `provision_models`, `install_run`, and Click CLI commands. Inputs include workspace paths, skip sets, `local_only`, `configure_torch`, `dry_run`, `assume_yes`, environment values, and test-pinned installation role/daemon capability. Expected outputs include `ProvisionOutcome`, per-step results, and an install backend-choice report. Tests inspect a temporary [pyproject.toml](../../../../pyproject.toml), a managed status directory, model-cache paths, and persisted `local-only.json` state ([src/vaultspec_rag/tests/test_provision.py:64-69, 292-405](../../../../src/vaultspec_rag/tests/test_provision.py#L64); [src/vaultspec_rag/tests/test_provisioning_gate.py:83-149, 155-290, 354-523](../../../../src/vaultspec_rag/tests/test_provisioning_gate.py#L83)).
- **Document scan (test expectations):** `scan_documents(root, sample_limit=...)` returns counts, sampled paths, truncation, preprocessing mode/hook state, membership/content fingerprints, and a policy snapshot. The test creates a preprocessing TOML file and documents beneath a temporary root, then calls a test approval helper to compare unapproved and approved policy results ([src/vaultspec_rag/tests/test_public_document_scan.py:21-76](../../../../src/vaultspec_rag/tests/test_public_document_scan.py#L21)).
- **Publication reads and writes (test expectations):** Tests build ledgers/checkpoints, acquire snapshots by root and `PublicSourceType`, reserve receipts against compatibility keys and parent revisions, record mutation states and path deltas, mutate storage, and advance finalization before publication. Observed output includes proof revision/generation/aggregate/evidence, read conflicts, receipt state, terminal state, and integrity verdict. Storage and ledger access are exercised through named APIs; implementation details are uninspected ([src/vaultspec_rag/tests/test_publication_integrity.py:21-56](../../../../src/vaultspec_rag/tests/test_publication_integrity.py#L21); [src/vaultspec_rag/tests/test_publication_read_paths.py:72-168](../../../../src/vaultspec_rag/tests/test_publication_read_paths.py#L72); [src/vaultspec_rag/tests/test_publication_recovery.py:114-200, 231-314, 398-500, 599-670, 721-807](../../../../src/vaultspec_rag/tests/test_publication_recovery.py#L114)).
- **Scaling inputs (test expectations):** SQLite trace/progress callbacks measure VM instructions and emitted `SELECT`s around production ledger calls; fixtures seed parent proofs and receipts of controlled sizes. Tests assert proportionality and query-plan properties rather than an absolute performance target, except for the stated large/small elapsed ratio ([src/vaultspec_rag/tests/test_publication_scaling.py:87-183, 283-427, 430-523, 526-619](../../../../src/vaultspec_rag/tests/test_publication_scaling.py#L87)).
