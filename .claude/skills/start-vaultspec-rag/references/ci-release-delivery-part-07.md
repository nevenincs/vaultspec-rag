## Capability summary

- [tools/packaging/validate.py](../../../../tools/packaging/validate.py) implements an offline validator for generated Scoop and Homebrew channel pointers. It checks pointer presence and JSON shape, required command installation, Scoop hash/URL count and SHA-256 syntax, Homebrew SHA-256 syntax, version agreement, and whether referenced bundle basenames can be formed from targets in the repository's binary workflow matrix. It returns a list of findings. Its CLI accepts a channel root and optional product, reports matrix/build errors and validation findings to stderr, and exits nonzero on those errors. Its module documentation says it is intended to run after generation and before committing pointers; no caller was inspected to establish that it is wired into that sequence.
- [tools/qdrant_pin_digests.py](../../../../tools/qdrant_pin_digests.py) provides `asset_digests(version, asset)` and a version-taking CLI. It obtains release URL/redirect settings through imported config helpers, selects a binary filename based on whether the asset is the Windows x86 asset, stages a download in a temporary directory, computes an archive SHA-256, calls an imported verified-extraction helper, and prints archive and executable digests alongside whether they match committed tables. The CLI returns 2 for the wrong argument count; otherwise the shown implementation returns 0 whether or not the tables match. Its documentation says it writes no source files and does not run downloaded files; the shown code uses a temporary directory and contains no execution call.
- [tools/packaging/tests/test_generators.py](../../../../tools/packaging/tests/test_generators.py) contains expectations for bundle naming, Scoop manifest URL/hash/bin/autoupdate fields, missing digest rejection, JSON output, Homebrew URL/hash/install/caveat behavior, target availability, backward-version protection, writing both channel files with LF endings, and parser default resolution. These are test-source expectations, not evidence that tests passed. Comments in this file describe mutation runs, which were not independently verified.
- [tools/packaging/tests/test_validate.py](../../../../tools/packaging/tests/test_validate.py) builds temporary channel roots through the imported generator and expects validation to flag missing command installs, malformed or missing hashes, URL/hash count mismatch, channel version disagreement, unbuildable asset names, non-object JSON, missing pointers, and an unreadable or empty build matrix. It also expects matrix targets to be deduplicated and sorted. These are test-source expectations, not a test run.
- [tools/test_audit_gates.py](../../../../tools/test_audit_gates.py) specifies exit-code and argument-parsing expectations for the imported advisory runner: configured finding codes map to success, scanner failures propagate, `--` is required, a Windows batch shim is resolved while preserving argv, subprocess launch uses `shell=False`, and a missing scanner returns 127. The module docstring says the dependency gate's own contract is elsewhere; that file was not inspected.
- [tools/test_check_docs_conventions.py](../../../../tools/test_check_docs_conventions.py) specifies expected findings for mixed CLI invocation lanes, missing lane declarations, unexplained environment-variable-only examples, client/service version ordering and page consistency, and PATH checks for POSIX, PowerShell, and Command Prompt. It also expects output fences to be ignored for lane scanning and wrapped declarations to count. These are test-source expectations, not a test run.

## Interfaces and data flow

`validate(root, product, repo_root=None)` treats `root` as the channel checkout and defaults `repo_root` to the repository containing the binary workflow. It locates the product's Scoop manifest and Homebrew formula using imported path helpers, reads both, and returns findings. `buildable_targets(repo_root)` reads [.github/workflows/binaries.yml](../../../../.github/workflows/binaries.yml), extracts `target:` entries with a regex, sorts/deduplicates them, and raises `UnknownTargetsError` if the file cannot be read or yields no targets. The CLI requires `--root`; `--product` defaults to the Vaultspec RAG product. The validator does not fetch releases or compare digests with downloaded artifacts; the module documentation describes its checks as internal consistency checks.

`asset_digests(version, asset)` derives a release URL from imported defaults, calls the imported downloader into a temporary archive, hashes it, then passes that digest and a platform-specific executable name to the imported extraction helper. `main(argv)` loops over the imported committed asset table, prints derived archive/executable digests and match markers, and prints a summary. The download, redirect enforcement, extraction, and hash helper implementations were not inspected, so their internal guarantees cannot be established here.

The packaging test fixtures write synthetic checksum aggregates or temporary channel roots and call imported generator/validator interfaces. The audit and documentation-convention tests call imported functions, with some tests replacing command resolution or subprocess execution via monkeypatch. No production caller or CI/workflow integration was read.

## Boundaries and dependencies

The validator's buildability check is derived from target strings in the workflow rather than a second target list. It constructs candidate asset names by calling `product.bundle_name` for those targets; the product helper's treatment of unsupported targets is uninspected. Asset checks compare URL/formula basenames to those generated names, while hash checks enforce syntax and channel consistency rather than artifact authenticity.

The following dependencies were referenced but intentionally not inspected: `tools.packaging.generate` (`formula_path`, `generate`, `scoop_path`, and in the other test module `_parser`, `available_targets`, `generate`); `tools.packaging.homebrew`, `scoop`, `products`, `pointer`, and `checksums`; `tools.binaries.build_pyapp.GLIBC_FLOOR`; the relative `tools.advisory` and `tools.check_docs_conventions` modules; and `vaultspec_rag.config._schema.comma_separated`, `vaultspec_rag.config._settings.rag_default`, `vaultspec_rag.qdrant_runtime._constants`, `_download.download_https`, `_provision.extract_verified_archive`/`file_sha256`, and `_resolve.binary_filename`. No behavior behind those imports is asserted beyond the calls or contracts visible in the assigned files.
