## Capability summary

- [src/vaultspec_rag/tests/test_conformance_surfacing.py](../../../../src/vaultspec_rag/tests/test_conformance_surfacing.py): specifies the health and CLI degradation contract. It expects a healthy service to be ready; a nonconforming collection to produce a degraded reason naming the affected collection and embedding-model mismatch; and that cause to map to a rebuild command while missing-model causes retain their own remediation. It also expects a held/quiesced service to report paused, suppress the hold-induced missing-model fault, and retain independent conformance findings (18-22, 48-80, 83-156, 159-202).
- [src/vaultspec_rag/tests/test_content_kind_checkpoint_restart.py](../../../../src/vaultspec_rag/tests/test_content_kind_checkpoint_restart.py): exercises code and document checkpoints against their ledgers. With either clean setting, it expects reopening a cancelled generation to retain confirmed units and replay only each kind’s final unconfirmed unit. A vault rebuild case expects a confirmed unit to survive reopen while its file remains incomplete (17-185, 188-231).
- [src/vaultspec_rag/tests/test_content_policy.py](../../../../src/vaultspec_rag/tests/test_content_policy.py): specifies admission and resolved-policy snapshot behavior: ignored paths take precedence; conflicting overlapping routes and route/transform conflicts are rejected; explicit routes are layout-agnostic; pickle round-tripping preserves classification and fingerprints; and a refused legacy-config migration leaves the root unchanged with MIGRATION_REQUIRED (38-168).
- [src/vaultspec_rag/tests/test_content_route_migration.py](../../../../src/vaultspec_rag/tests/test_content_route_migration.py): covers route scans, cross-kind code/document migration, cleanup and recovery using synthetic chunks, a local VaultStore, checkpoints, and a SQLite route-migration journal. Expectations include payload-only origin inspection under stale sparse identity, retaining origins when the selected destination is incompatible or absent, noncreating/restricted administration, fresh bounded route surveys, destination-first replay after interruption, stale-destination protection, ledger-aware unpublished-row cleanup, cancellable same-kind cleanup/resume, bounded journal batches, and bounded generation reconciliation (72-861; especially 286-434, 437-483, 485-590, 593-739, 741-861).
- [src/vaultspec_rag/tests/test_controller_projection.py](../../../../src/vaultspec_rag/tests/test_controller_projection.py): defines expected serialization of a watcher ControllerSnapshot into an actionable envelope, including scope age/counts, measurement availability, backpressure, transition, retry/circuit fields, default refusal remediation, consistent absent/present measurement shapes, and conversion of scheduler monotonic timestamps to wall time (28-127, 130-158, 168-201, 204-241).
- [src/vaultspec_rag/tests/test_controller_surface_conformance.py](../../../../src/vaultspec_rag/tests/test_controller_surface_conformance.py): expects the service-state projection, authenticated /watcher response, /jobs detail, and /jobs listing to publish the same controller envelope. Its AST guard expects client adapters not to recompute controller timing/state authority (37-108, 110-139).
- [src/vaultspec_rag/tests/test_controller_client_adapters.py](../../../../src/vaultspec_rag/tests/test_controller_client_adapters.py): expects the watcher transport to forward only supported root/source/state/limit filters with URL encoding, and the job-detail renderer to display embedded controller facts and remediation (13-29, 31-62).
- [src/vaultspec_rag/tests/test_dense_backend.py](../../../../src/vaultspec_rag/tests/test_dense_backend.py): asserts a torch default and ONNX model path in config, plus an environment override to ONNX. Its module docstring says the ONNX execution path is covered in an integration test; that file was not read (1-38).
- [src/vaultspec_rag/tests/test_dev_aggregators.py](../../../../src/vaultspec_rag/tests/test_dev_aggregators.py): guards development-target aggregation. It expects targets to be reachable from their aggregate unless specifically exempted, test-all to include python/gpu/mps/perf, hardware lanes to be gated, an all-skipped aggregate to return NOTHING_SELECTED, one executed lane plus a skip to pass while naming the skip, a failing lane to stop later lanes, and directly selected gated work to return a nonzero skip marker (23-49, 52-105, 107-129, 132-222).
- [src/vaultspec_rag/tests/test_docs_cli_surface.py](../../../../src/vaultspec_rag/tests/test_docs_cli_surface.py): defines checks that documented CLI invocations/options resolve against the live Typer tree, documented bare flags are known or explicitly allowlisted (including foreign, MCP, and retired flags), the generated reference matches its renderer, and every leaf command is mentioned in docs/README. The docs and live application were not inspected, and the docs-dependent tests are marked to skip when docs are absent (1-21, 42-80, 82-188, 226-399).
- [src/vaultspec_rag/tests/test_doctor_repair_and_holders.py](../../../../src/vaultspec_rag/tests/test_doctor_repair_and_holders.py): specifies human and JSON expectations for `server doctor`: repairs depend on compute capability; daemon interpreter selection scopes both probing and holder scans; holder output includes actionable process/launcher details but not cmdline; receipt verdicts report ordered fixes and durability; capped lists report totals; and an unknown future holder role still renders (49-110, 113-173, 176-215, 218-293, 296-375).

## Interfaces and data flow

- The tests invoke health and degradation surfaces through `_service_health_status` and `degradation_findings`, with quiesce snapshots and Qdrant runtime state as inputs. Expected status/reasons are then converted to JSON-shaped degradation data for CLI finding/remediation assertions ([src/vaultspec_rag/tests/test_conformance_surfacing.py](../../../../src/vaultspec_rag/tests/test_conformance_surfacing.py): 18-22, 43-46, 48-156).
- Content classification tests construct `RootContentPolicy`, `ContentRoute`, preprocessing rules, and resolved policy snapshots, then call `classify_content` or `resolve_index_policy`; the tested outputs are dispositions, errors, fingerprints, and pickle equality ([src/vaultspec_rag/tests/test_content_policy.py](../../../../src/vaultspec_rag/tests/test_content_policy.py): 38-168).
- Checkpoint tests create code/document open requests with policy, run settings, model/backend identities, and temporary data roots; they record confirmed segments/slices, cancel generations, reopen, and query commit state. The vault case records a storage-confirmed ledger unit and checks generation/file status after reopen ([src/vaultspec_rag/tests/test_content_kind_checkpoint_restart.py](../../../../src/vaultspec_rag/tests/test_content_kind_checkpoint_restart.py): 47-185, 188-231).
- Route-migration tests construct code/document payloads and vectors, open per-kind checkpoints, persist chunks through `VaultStore`, then call the imported migration scan/reconcile/purge/replay functions. The tested persistence surfaces include a store sidecar and `route_migrations.sqlite3`; the tests inspect rows, vectors, collection presence, journal pending entries, and ledger-confirmed point IDs ([src/vaultspec_rag/tests/test_content_route_migration.py](../../../../src/vaultspec_rag/tests/test_content_route_migration.py): 85-206, 286-434, 485-590, 634-861). This is the test harness’s flow; internal production ordering was not inspected.
- Controller tests build typed observations, measurements, transitions, and snapshots, call `controller_snapshot_envelope`, then compare it with service and HTTP/job projections. The surface fixture creates an HTTP app and sends authenticated requests to /watcher and /jobs ([src/vaultspec_rag/tests/test_controller_projection.py](../../../../src/vaultspec_rag/tests/test_controller_projection.py): 28-127; [src/vaultspec_rag/tests/test_controller_surface_conformance.py](../../../../src/vaultspec_rag/tests/test_controller_surface_conformance.py): 37-108).
- CLI documentation checks parse code spans from documentation into command words/options and resolve those against a Typer command tree ([src/vaultspec_rag/tests/test_docs_cli_surface.py](../../../../src/vaultspec_rag/tests/test_docs_cli_surface.py): 82-188, 226-305). Doctor tests invoke the Typer app with `server doctor` and `--json`, substituting daemon probe and process-holder scan functions to assert output ([src/vaultspec_rag/tests/test_doctor_repair_and_holders.py](../../../../src/vaultspec_rag/tests/test_doctor_repair_and_holders.py): 49-110, 125-215, 218-375).
- Development aggregate guards inspect `VERBS`/targets and call `_execute`, using synthetic commands/gates to assert aggregate exit/output behavior ([src/vaultspec_rag/tests/test_dev_aggregators.py](../../../../src/vaultspec_rag/tests/test_dev_aggregators.py): 52-105, 107-129, 132-222).

This is a test boundary, not a finding about the store implementation.
- Controller client seams are guarded against recomputing controller timing/state facts; the canonical projected object is expected to flow through service, watcher, and job surfaces ([src/vaultspec_rag/tests/test_controller_surface_conformance.py](../../../../src/vaultspec_rag/tests/test_controller_surface_conformance.py): 78-139; [src/vaultspec_rag/tests/test_controller_client_adapters.py](../../../../src/vaultspec_rag/tests/test_controller_client_adapters.py): 31-62).

- All implementation dependencies are uninspected. The tests import production code from health, policy, checkpoint, route migration, storage, controller, CLI, service, and operator-state modules. They also name docs and a generated CLI reference, but their contents were not read. No behavior beyond the assertions and authored test rationale is claimed.
