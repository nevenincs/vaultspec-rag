## Capability summary

This slice contains pytest guards and shared fixtures; it does not contain production admission implementation. Every behavior below is a test expectation unless explicitly labeled as a source comment or docstring claim.

- [src/vaultspec_rag/tests/gpu_admission/__init__.py](../../../../src/vaultspec_rag/tests/gpu_admission/__init__.py) — package docstring identifies this test package as guards for the model-load admission gate.
- [conftest.py](../../../../conftest.py) — supplies deterministic `CudaDeviceMemory` scenarios around a test floor of 8,448 MiB: roomy and crowded values, unreadable readings with and without total memory, and workload measurement constants. It also defines lock-holder source and bounded release/reap timing values. The autouse fixture clears the process-local admission latch and settles the unreadable streak via production entry points before and after each test. The `floor` fixture sets `GPU_ADMISSION_FLOOR_MIB` through `managed_env`. `windowed` wraps the real `device_load_window` with a supplied reading and counts entries, so guards can detect skipped device/window evaluations.
- [src/vaultspec_rag/tests/gpu_admission/test_floor_and_window.py](../../../../src/vaultspec_rag/tests/gpu_admission/test_floor_and_window.py) — `TestTheFloorPredicate` expects an inclusive free-memory floor, credit for this process's own reserved memory, truncation to whole MiB, distinct torch-missing/no-device reasons, tolerance of one unreadable reading, and refusal at the persistent-unreadable threshold. It checks refusal reasons/messages. `TestTheUnreadableLedger` checks accumulation, reset by a readable value, preservation when no CUDA device is present, and ledger use by supplied readings and diagnostic reads. The same class checks that persistent unreadability blocks loads and does not latch. `TestTheFloorIsDerivedFromTheWorkload` checks a zero shipped default, coverage of declared profile demand, smaller embedded than managed demand, an operator override, and demand declarations against measured model-stack constants. `TestTheLoadWindow` checks contention from same-process and child-process lock holders, reclamation after killing a holder, release after window exit, fallback to the floor when an anchor cannot be opened, and an anchor independent of the configured status directory.
- [src/vaultspec_rag/tests/gpu_admission/test_latch_and_wire.py](../../../../src/vaultspec_rag/tests/gpu_admission/test_latch_and_wire.py) — `TestTheAdmissionLatch` checks MPS admission and one evaluation across later loads, bypass of a new floor check after this process is admitted, refusal not being latched, loader-owned errors passing through for an absent device, latch clearing directly and through resident-baseline rebasing, unreadable/unverifiable verdicts not being latched, and serialization of two threads' first load. `TestTheWireReading` checks the six-field wire projection (`admitted`, `free_mib`, `total_mib`, `own_mib`, `floor_mib`, `reason`), composition of a reading from evaluation, and `None` for probe errors or torch absence; it distinguishes a missing torch package from a broken torch import in warning behavior. `TestTorchFreedom` runs child interpreters with torch or `memory_probe` unavailable and expects admission evaluation to return a refusal without raising.

## Interfaces and data flow

The entry points in this slice are pytest tests, not application callers. Tests construct `CudaDeviceMemory` values and invoke `admission_from_reading`, `evaluate_device_admission`, `device_load_reading`, `device_load_wire`, `device_load_window`, and `admit_accelerator_load`. Some pass a test loader callback through `admit_accelerator_load`; the tests expect it to run after an admitted verdict and not run after a refusal. Diagnostics are expected to expose a dictionary projection or `None` on probe failure. Load refusals are expected to surface as `RuntimeError`; loader exceptions for an absent device are expected to pass through unchanged.

Test state is process-local for the latch and unreadable streak, as described by fixture and test comments. The window tests supply a temporary anchor and exercise the imported real lock/window path. A separate child interpreter takes the lock using the provided `_HOLDER_SOURCE`, while polling retries a claim after child termination until a deadline. Other inputs include managed environment overrides for the floor/profile/status path, monkeypatched memory probes, and fake or unavailable torch imports. The tests exercise profile values through `get_config`, `get_index_support_profile`, and CUDA byte-to-MiB conversion; those implementations and profile contents were not inspected.
