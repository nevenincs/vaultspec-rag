## Interfaces and data flow

The documented runtime callers are the vaultspec-rag CLI and assistant MCP clients. The README describes a host/client split in which one service on a machine serves multiple repositories, while a client forwards requests to a same-release host ([README.md](../../../../README.md): 40-52, 145-176, 252-267). It describes indexing code, Vault records, and documents, then searching code, Vault, documents, or combined content (186-229, 252-263).

As documented, settings flow from flags and the process environment, with only the Typesafe credential eligible for workspace-.env loading under the specified install/interpreter gate; selected state may also come from a service-local marker (.env.example: 15-36, 100-104, 771-785). The described storage choices are a shared managed Qdrant service or per-project local storage; model files use the Hugging Face cache, while service status/logs and the managed Qdrant child live under the service status area ([README.md](../../../../README.md): 297-319; .env.example: 100-104, 229-246, 886-898). Optional hosted Typesafe ranking sends queries and candidate content to its API when a usable key is present ([README.md](../../../../README.md): 321-329; .env.example: 771-785). These are documentation claims; responsible code was not inspected.

Release inputs described by the runbook are a merged release proposal/tag and checked-out producer source. It says the pipeline builds Python distributions and target archives, combines checksums, verifies native monitor evidence/provenance, uploads to PyPI, publishes the GitHub Release, then updates package-manager pointers and runs acquisition checks ([RELEASING.md](../../../../RELEASING.md): 56-129, 332-353, 371-408). Its commands name GitHub Actions, GitHub CLI, uv, npm, native browsers and PyPI trusted publishing as tooling or integrations (179-234, 275-329, 607-617); these flows were not executed or independently verified.
