## Capability summary

- [src/vaultspec_rag/\_process_probe.py](../../../../src/vaultspec_rag/_process_probe.py) centralizes process identity, inspection, cleanup, and environment-holder discovery. It implements platform-specific liveness and image probes, start-time identity checks, bounded reads, process-tree cleanup, lineage and zombie checks, listener ownership, lazy process-table inspection, server-launch recognition, and environment-holder classification. Holder results retain why a process matched and whether the scan was complete or partly uninspectable. Signal, process-group signal, child reap, and bounded exit-wait helpers are also provided.
- [src/vaultspec_rag/\_program_lookup.py](../../../../src/vaultspec_rag/_program_lookup.py) resolves a bare executable name in explicitly selected installation, operating-system, or absolute PATH directories. It skips relative and empty search entries, handles Windows executable suffixes, and returns an absolute executable path.
- [src/vaultspec_rag/\_public_index.py](../../../../src/vaultspec_rag/_public_index.py) exposes scan_documents and DocumentScanResult as a bounded preflight projection of document work. It reports sampled relative paths, fingerprints, policy state, rule count, execution mode, and hook state; the docstring describes the facade as model-free and storage-free.
- [src/vaultspec_rag/\_public_search.py](../../../../src/vaultspec_rag/_public_search.py) defines document-only and combined-search request/filter records and timed/untimed entry points. Document search validates document filters, counts indexed chunks, and searches under a registry lease. Combined search counts the selected vault, code, and optional document domains independently, carries domain-specific failures and availability facts, and searches through one lease with typed partial outcomes and timing data.
- [src/vaultspec_rag/\_publication_state.py](../../../../src/vaultspec_rag/_publication_state.py) reads and validates the canonical publication proof for a source projection, fences related reads with a token, reads proof evidence in keyset pages, clears a source’s publication authority, and resets an open incremental publication under rebuild control. It also defines recognized unreadable-publication errors and a context-local recovery receipt.
- [src/vaultspec_rag/\_python_child.py](../../../../src/vaultspec_rag/_python_child.py) supplies module, inline, and script child command builders. Each inserts Python’s safe-path flag before the requested operation.
- [src/vaultspec_rag/\_qdrant_local_client.py](../../../../src/vaultspec_rag/_qdrant_local_client.py) is the local Qdrant constructor. It configures the local persistence thread check from sqlite3.threadsafety before opening the client.
- [src/vaultspec_rag/\_qdrant_local_lifetime.py](../../../../src/vaultspec_rag/_qdrant_local_lifetime.py) closes an existing collection handle when the owned Qdrant client is local; it does not authorize or perform collection deletion.
- [src/vaultspec_rag/\_qdrant_server_client.py](../../../../src/vaultspec_rag/_qdrant_server_client.py) is the Qdrant server constructor. It resolves and supplies the API key, passes the optional timeout, and suppresses the insecure-key warning only for literal loopback IP hosts.
- [src/vaultspec_rag/\_qdrant_transport.py](../../../../src/vaultspec_rag/_qdrant_transport.py) exports shared transport-failure and server-refusal exception tuples for Qdrant call guards.

Documentation claims and test expectations: the assigned Python files contain extensive module docstrings/comments describing motivation, intended fail-closed behavior, prior regressions, and performance observations. Those statements are source documentation, not independently verified measurements or tests. No test source was assigned or read, so no test expectations or passing-test claims are reported.

## Interfaces and data flow

- Process probing: exported functions in [src/vaultspec_rag/\_process_probe.py](../../../../src/vaultspec_rag/_process_probe.py) are the visible API. pid_alive chooses the Windows handle path or POSIX signal-zero path. pid_image_matches requires liveness and uses an image path, then platform-specific fallback naming; pid_start_time and pid_matches_start_time provide a creation-time witness. bounded_call runs optional time-bounded inspection in a daemon thread and returns the specified fallback if the wait expires. Tree cleanup captures descendant pid/start-time witnesses before killing, then waits for the child and descendants. environment_holders resolves and scans a root, classifies image, launch-path, and working-directory relations, pairs exact-command-line launchers, and returns completeness, blind-process count, and optional self-held state.
- Process launch recognition: [src/vaultspec_rag/\_process_probe.py](../../../../src/vaultspec_rag/_process_probe.py) derives server console-script names from installed entry-point metadata, recognizes Python module or console-script argv forms, and parses a unique option such as --port. On Windows, unreadable image paths can lead \_windows_image_matches to find tasklist with \_program_lookup.find_program before running fixed argv.
- Document preflight: scan_documents resolves the requested root, calls DocumentIndexer.for_preflight(...).preflight_content(), and projects policy fingerprints and a bounded path sample into DocumentScanResult.
- Search: search_documents_timed validates source-owned filters, resolves the root, obtains a supplied registry or get_registry(), short-circuits an empty document collection, and executes search_document_timed inside search_lease. search_combined_timed validates the combined filter surface, independently counts selected domains and creates source facts, then returns preserved count failures/empty outcomes or searches the positive-count domains within a lease and classification scope. The per-domain search callbacks pass only their domain-owned filters to the searcher.
- Publication state: acquire_publication_snapshot resolves the root, locates the run ledger under the workspace volume, identifies the configured backend, and acquires a proof/token for one concrete source. PublicationSnapshot.validate rechecks the token; read_all_publication_evidence pages by path. clear_publication_state clears one source identity. reset_pending_publication_for_rebuild requires an open recoverable receipt, checkpoints RunControl, enters its protected section, then resets that source in the store.
- Qdrant and child-process construction: the local and server Qdrant constructors are intentionally separate. \_python_child command builders return argv lists and do not execute processes. The Qdrant lifetime helper closes only a present local collection object.
- Caller evidence inside the slice: \_process_probe.\_windows_image_matches calls find_program; environment_holders calls the holder scan and optionally process_lineage; public search entry points call their timed counterparts or registry search leases. No repository-wide caller inventory was made.

Imports establish integration points only; this report does not claim the behavior of those dependencies.
