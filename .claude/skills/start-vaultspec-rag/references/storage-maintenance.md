## Limits and reconciliations

Findings describe the inspected snapshot. External dependency internals and operational outcomes were not verified. Test assertions and recorded benchmark results do not establish a current passing run.

- Destruction defers on unknown proof; shorter temporary grace retains safety gates.
- Restore rejects local/Windows-server/occupied destinations in supplied implementation evidence; platform effects remain unexecuted.
- CLI/HTTP survey envelopes differ. Suite prose claiming direct MCP/CLI survey coverage exceeds the visible HTTP/admin assertions; completeness is unresolved.
- Documentation ambiguity: docs/service-mode.md:451-463 describes ungated GET /health returning service_token, while docs/service-discovery.md:155-157 says unauthenticated /health omits service_token; conditional authentication behavior is unresolved. Source-backed server/client evidence resolves the response contract: no-credential health is anonymous, presented invalid credentials are rejected, and service_token is included only for authenticated health. Discovery publication is token-bearing separately; conflicting guide wording remains a documentation limitation.
- Named test coverage gap: TestDocumentIndexerGateWiring at test_stat_gate.py:360-362 is empty; full source is covered. The empty TestDocumentIndexerGateWiring class establishes no test oracle. Document indexing implementation is covered by s1-0158 and related tests; full source coverage does not invent missing assertions.
- Stdio lifetime suite prose calls the surface five-tool, but EXPECTED_TOOLS lists twelve names and the test asserts that exact set (test_stdio_lifetime_e2e.py:3-8,34-47,146-154). The twelve-name expected set and guide six-read/six-mutation wording contradict stale five-tool prose. Compact MCP implementation evidence establishes handlers/filtering but omits exact registration names/count; do not promote the expected set to an observed runtime inventory.
- Storage-survey suite docstring claims MCP survey_storage and service-first CLI coverage, while visible assertions exercise /storage/survey and \_try_http_admin rather than direct calls to those named surfaces (test_storage_survey_service.py:1-8,31-405). Visible HTTP /storage/survey and \_try_http_admin assertions support service/admin contracts. Direct named MCP survey_storage/CLI coverage claimed in suite prose remains unestablished by compact evidence.
