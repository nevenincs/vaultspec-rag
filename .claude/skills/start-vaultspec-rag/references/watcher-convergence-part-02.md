## Capability summary

- [src/vaultspec_rag/server/\_watcher.py](../../../../src/vaultspec_rag/server/_watcher.py) owns watcher lifecycle coordination and a service-owned controller scheduler. It exports `WatcherStartOutcome`, watcher start/stop/cleanup functions, controller registration/snapshot helpers, and scheduler wake-up ([src/vaultspec_rag/server/\_watcher.py:20-32](../../../../src/vaultspec_rag/server/_watcher.py#L20)).
- The scheduler registers one controller per canonical root/source key, reevaluates registered controllers, asks a `WatcherAdmissionArbiter` for a selection, dispatches at most one admission callback per cycle, and wakes on events or deadlines. It exposes stable sorted snapshots and bounded release waits ([src/vaultspec_rag/server/\_watcher.py:151-168](../../../../src/vaultspec_rag/server/_watcher.py#L151), `178-240`, `242-288`). Callback transitions are logged when controller state or reason changes ([src/vaultspec_rag/server/\_watcher.py:290-320](../../../../src/vaultspec_rag/server/_watcher.py#L290)).
- Watcher starts are coalesced by canonicalized root and guarded by per-root stop generations. `WatcherStartOutcome` distinguishes running, pending, queued behind drain, disabled, and unavailable states ([src/vaultspec_rag/server/\_watcher.py:86-127](../../../../src/vaultspec_rag/server/_watcher.py#L86), `671-754`). `_ensure_watcher_soon` schedules cold project-slot warming on a worker thread; `_ensure_watcher` warms synchronously, then publishes only a generation still valid under the watcher lock ([src/vaultspec_rag/server/\_watcher.py:545-597](../../../../src/vaultspec_rag/server/_watcher.py#L545), `599-658`, `671-821`).
- Publishing a watcher creates `WatcherConfiguration` and a background `watch_and_reindex` task, records task and stop-event ownership in `vaultspec_rag.server`, and attaches a completion callback ([src/vaultspec_rag/server/\_watcher.py:824-879](../../../../src/vaultspec_rag/server/_watcher.py#L824)). A natural exit enters drain handling; initialization failure does not schedule a replacement ([src/vaultspec_rag/server/\_watcher.py:504-543](../../../../src/vaultspec_rag/server/_watcher.py#L504)).
- Stop disables public intake immediately and invalidates pending starts. Private drain ownership is retained until intake, watcher-origin job attempts, scheduler callbacks, and retry settlements release within the configured bound. Successful drains can publish one queued restart; failed drains remain retryable ([src/vaultspec_rag/server/\_watcher.py:881-930](../../../../src/vaultspec_rag/server/_watcher.py#L881), `933-1005`, `1033-1104`, `1128-1192`). `_stop_all_watchers` and `_wait_for_watcher_cleanup` provide aggregate and bounded cleanup helpers ([src/vaultspec_rag/server/\_watcher.py:1206-1251](../../../../src/vaultspec_rag/server/_watcher.py#L1206)).
- [src/vaultspec_rag/server/\_watcher_measurements.py](../../../../src/vaultspec_rag/server/_watcher_measurements.py) captures canonical service facts and composes immutable measurements for automatic admission. Captured facts include job snapshots, machine pressure/storage evidence, limiter stats, search activity without query text, quiesce state, and retry state ([src/vaultspec_rag/server/\_watcher_measurements.py:31-76](../../../../src/vaultspec_rag/server/_watcher_measurements.py#L31), `79-119`).
- Measurement composition identifies nonterminal index generations; projects backlog, index/search concurrency, latency, pressure, storage, and quiesce state into `ControllerMeasurement`; and explicitly records unavailable evidence ([src/vaultspec_rag/server/\_watcher_measurements.py:153-175](../../../../src/vaultspec_rag/server/_watcher_measurements.py#L153), `177-224`, `234-255`). Malformed/missing JSON-shaped readings are omitted, and search latency uses the maximum valid recent duration ([src/vaultspec_rag/server/\_watcher_measurements.py:257-316](../../../../src/vaultspec_rag/server/_watcher_measurements.py#L257)).
- In-file caller claims: `_ensure_watcher_soon` documents search and reindex routes as per-request callers ([src/vaultspec_rag/server/\_watcher.py:545-553](../../../../src/vaultspec_rag/server/_watcher.py#L545)). This slice does not include those routes, so their actual callsites are unverified. The other entry points are exported here, but external callers were not inspected.

## Interfaces and data flow

- Lifecycle start: a caller supplies `root` and `ServiceRegistry`; optional debounce/cooldown overrides flow into a restart request and then `WatcherConfiguration`. The direct path gets config and project slot, then creates the watcher task. The deferred path uses `registry.peek_project(root)` through `anyio.to_thread.run_sync`, checks task identity and stop generation, then publishes or hands off to a newer registry ([src/vaultspec_rag/server/\_watcher.py:545-658](../../../../src/vaultspec_rag/server/_watcher.py#L545), `671-879`).
- Lifecycle stop: `_stop_watcher(root)` advances the stop generation when an owner exists, removes queued restart intent, marks a deferred warm suppressed, removes active intake bookkeeping, and schedules cleanup on the intake task's event loop ([src/vaultspec_rag/server/\_watcher.py:881-981](../../../../src/vaultspec_rag/server/_watcher.py#L881)). Cleanup has one deadline based on `job_shutdown_timeout_seconds`; it joins the intake task without propagating cancellation, finds active INDEX/CORPUS jobs initiated by watcher for the exact resolved root, awaits their exact attempts, releases scheduler ownership, and waits for retry settlements ([src/vaultspec_rag/server/\_watcher.py:984-1030](../../../../src/vaultspec_rag/server/_watcher.py#L984), `1033-1104`, `1106-1192`).
- Controller path: a controller plus `reevaluate` and `admit` callbacks is registered against its snapshot's canonical root/source. The module lazily starts the scheduler using configured reevaluation seconds and the current loop's monotonic clock; registration or external fact changes wake it. Unregister and wake safely route work onto the scheduler's owner loop from other threads ([src/vaultspec_rag/server/\_watcher.py:190-222](../../../../src/vaultspec_rag/server/_watcher.py#L190), `401-466`). Snapshot readers get up to 256 sorted controller snapshots by default, with a truncation flag; job lookup searches that bounded view ([src/vaultspec_rag/server/\_watcher.py:382-399](../../../../src/vaultspec_rag/server/_watcher.py#L382)).
- Measurement path: `capture_watcher_measurement(registry, key, retry_state, generation, observed_at)` collects facts, then calls the pure `compose_watcher_measurement(facts)`. Active job count plus index waiters becomes backlog. Search activity count falls back to limiter borrowed count when absent; missing evidence remains `None` and is listed in `unavailable` rather than treated as zero ([src/vaultspec_rag/server/\_watcher_measurements.py:79-119](../../../../src/vaultspec_rag/server/_watcher_measurements.py#L79), `153-224`, `234-255`).

Their implementation and consistency guarantees are outside this slice ([src/vaultspec_rag/server/\_watcher_measurements.py:8-18](../../../../src/vaultspec_rag/server/_watcher_measurements.py#L8), `79-119`).
