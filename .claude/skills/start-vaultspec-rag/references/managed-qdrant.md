## Limits and reconciliations

Findings describe the inspected snapshot. External dependency internals and operational outcomes were not verified. Test assertions and recorded benchmark results do not establish a current passing run.

- Trust/held-launch/auth/port/native identity behavior and upstream store migration remain unverified; manifests alone are not executable trust proof.
- Test pins do not establish live-release provenance; the digest-maintenance CLI visibly returns zero even when mismatches are printed.
- The inspected mirror test requires a provisioned host binary, so its absent-binary fallback prose is not established scenario coverage.
- MCP conformance docstring describes read-only retrieval/search/refresh, but its expected tools include clean_documents and clean_all with destructive/idempotent annotations. Destructive clean handlers/annotations and read-only filtering are separate boundaries. Blanket read-only conformance prose conflicts with expected clean tools; neither docs nor expected sets prove a runtime inventory.
- s1-0111 describes a computed monitor spawn-scan target as src/monitor/server/\*.ts; s1-0104/0105 name src/vaultspec_rag/monitor/server/local-service.ts. This is uncertain report path wording, not proof of a faulty scan. The included source inventory places the monitor bridge at src/monitor/server/local-service.ts; the src/vaultspec_rag/monitor/ locator in test-only report prose is incorrect. The derived src/monitor/server target matches the source layout, while runtime scan effectiveness remains unverified.
- Terminology ambiguity: holder 'dimension' in s1-0115 versus exactly torch/models/qdrant aggregate dimensions plus environment_holders in s1-0114; no behavioral contradiction proven. Supplied readiness contracts distinguish the three aggregate dimensions torch/models/qdrant from supplemental environment holders. Preserve that distinction; do not infer a fourth dimension or contradict the owning readiness reports.
- Documentation-to-test scope mismatch: test_helpers_qdrant_mirror.py mentions absent-binary fallback, but its assigned test requires a present provisioned host Qdrant binary. The test requires a present provisioned host binary; absent-binary fallback prose is not demonstrated by that scenario. Managed supply/runtime and harness evidence are routed without claiming fallback coverage.
