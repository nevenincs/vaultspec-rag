## Interfaces and data flow

- Test entry points are pytest functions/classes. They create temporary SQLite ledgers through `RunLedger`, use signatures, commit units, file states, publication proofs/receipts, and call ledger operations such as `start_generation`, `record_storage_confirmed_unit(s)`, `record_file_state`, iterators, proof/receipt transitions, compaction, and superseded-point lookup. These are the interfaces exercised by this test slice, not a complete inventory of production callers.
- Reuse tests construct `CodeChunk` or `VaultChunk` values, seed donor vectors through `VaultStore`, then invoke `encode_and_upsert_code_slice` or `DonorReuseContext.adopt_verified_vectors`. The tests inspect stored vectors/payloads and `ReuseStats`; test doubles record or reject encoder calls.
- Ledger tests persist state in temporary SQLite paths. They inspect both public ledger results and, in selected corruption/measurement cases, SQLite rows, triggers, and transaction changes. Concurrency cases use threads or subprocesses against the same ledger path. No external service integration is established by this slice.
- Test helpers and fixture modules supply signatures, proof lineages, certification, receipt sealing, generation lookup, and measurement probes. Their implementations were not inspected, so helper internals and any behavior hidden there are unknown.
