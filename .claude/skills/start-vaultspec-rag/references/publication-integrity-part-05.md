## Capability summary

- [src/vaultspec_rag/tests/test_checkpoint_ledger_connection_lifetime.py](../../../../src/vaultspec_rag/tests/test_checkpoint_ledger_connection_lifetime.py): unit expectations for a checkpoint-scoped idle SQLite/WAL handle. Helpers construct a `RunLedger`/`CodeRunCheckpoint` and inspect WAL/SHM files (41-63). Cases assert WAL retention after confirmed commits, cleanup on normal/error/control exits, preservation of published success after a late exception, concurrent code/document writer transactions, and default WAL recycling (65-238). These are expected lifecycle properties; this file does not establish the implementation or test result.
- [src/vaultspec_rag/tests/test_chunk_worker_parity.py](../../../../src/vaultspec_rag/tests/test_chunk_worker_parity.py): tests worker and producer behavior across source disposition, hashing, chunk identity, scheduling, and decoding. It expects vanished files to have a dedicated no-chunk disposition while other read errors propagate; checks byte/hash consistency and sink handling for vanished, blank, skipped, and genuinely unindexable results (78-280). It also sets up a real spawn-pool scheduler probe and fatal-preprocessor case (283-514), compares serial and parallel output, guards unique emitted IDs and commit-unit construction, checks worker planning against byte thresholds and explicit counts, checks fresh worker imports exclude Torch, and asserts `file_digest` and CRLF/LF parity (516-775). The module docstring describes intended no-GPU/no-model/no-mock coverage (1-13), but this report did not execute it.
- [src/vaultspec_rag/tests/test_citation_gate.py](../../../../src/vaultspec_rag/tests/test_citation_gate.py): contract tests for a dynamically loaded [tools/citation_gate.py](../../../../tools/citation_gate.py). A local Protocol describes the expected API (`scan_file`, `scan_file_paths`, `scan_text`, `collect_findings`, identity discovery/pattern functions) and result tuple shapes (50-86); the gate is loaded from the repo root (88-121). Tests expect citation detection across Python prose constructs and token classes, accurate line positions, multiline matching without crossing paragraph boundaries, and avoidance of ordinary-value false positives (144-527). Collector tests cover included/excluded product surfaces, Git-tracked/untracked enumeration, ignored trees, and separate identity/path scanning with injected identities (530-1049). A live-checkout cleanliness assertion is explicitly described as a regression guard, not proof that the detector works (1053-1072).
- [src/vaultspec_rag/tests/test_cli.py](../../../../src/vaultspec_rag/tests/test_cli.py): in-process `CliRunner` expectations for root and nested help, version, user-facing help text, option/command removals, and service-start port handling (28-424). JSON tests assert envelope shapes, error codes, exit codes, and clean stdout for selected failures and service states (426-580). Subprocess cases check `--help` for bare carriage-return output and several `--json` paths for one parseable, ANSI/Rich-free document (582-705). The app, runner, environment helpers, and status writer come from uninspected test support.
- [src/vaultspec_rag/tests/test_cli_argv_expansion.py](../../../../src/vaultspec_rag/tests/test_cli_argv_expansion.py): subprocess guards that CLI arguments reach search parsing verbatim from a seeded working directory, including glob, environment-variable, and home shorthand values (1-165). Direct filter tests specify include/exclude glob behavior and contrast a glob against a locally substituted file list (168-230). This file imports `filter_raw_codebase_results`; neither it nor the CLI implementation was inspected.
