## Capability summary

This package exposes a lazy public facade over API, indexing, search, model, and store modules. It also contains shared low-level facilities for file publication, process coordination, path classification, and GPU ownership/admission.

- [README.md](../../../../README.md): documents the toolkit as a companion semantic retrieval engine for vault documents and codebases, and shows code search options for locale deduplication and production/tests/documentation preference.
- [src/vaultspec_rag/__init__.py](../../../../src/vaultspec_rag/__init__.py): declares the public exports and resolves them on first attribute access through `__getattr__`; imported facade modules are cached. It also exposes the names through `__all__` and `__dir__`.
- [src/vaultspec_rag/__main__.py](../../../../src/vaultspec_rag/__main__.py): provides the `python -m vaultspec_rag` entry point. It imports the root CLI app inside `main()`, reports an interrupt during CLI startup on stderr, flushes streams, and exits with status 130; once the app is imported, it delegates to the app.
- [src/vaultspec_rag/\_anchor_claim.py](../../../../src/vaultspec_rag/_anchor_claim.py): implements non-blocking OS-backed claims on persistent anchor files, with `HELD`, `CONTENDED`, `ABSENT`, `FREE`, and `UNAVAILABLE` outcomes. It supports shared machine-wide anchors, optional readable PID records, in-place fixed-width record publication, owner observation, and best-effort release. The file explicitly identifies resident-service, model-load-window, and GPU-test-session ownership as uses, but their caller implementations are outside this slice.
- [src/vaultspec_rag/\_atomic_write.py](../../../../src/vaultspec_rag/_atomic_write.py): centralizes temporary-sibling JSON publication, atomic replacement with retries for sharing violations, optional crash durability, private file creation, and temp cleanup. Durability uses a write-through move on Windows and parent-directory fsync on POSIX.
- [src/vaultspec_rag/\_backoff.py](../../../../src/vaultspec_rag/_backoff.py): supplies capped exponential and jittered backoff calculations, with exponent and final-wait caps.
- [src/vaultspec_rag/\_content_route_syntax.py](../../../../src/vaultspec_rag/_content_route_syntax.py): validates caller-authored content-route patterns as nonblank and NUL-free.
- [src/vaultspec_rag/\_domain.py](../../../../src/vaultspec_rag/_domain.py): classifies project-relative paths into `prod`, `tests`, `docs`, `locale`, `generated`, `vendored`, or `worktree`, using path segments and basenames in a fixed precedence order.
- [src/vaultspec_rag/\_error_payload.py](../../../../src/vaultspec_rag/_error_payload.py): creates a transport-neutral `{ok: false, error, message}` failure mapping.
- [src/vaultspec_rag/\_fd_lock.py](../../../../src/vaultspec_rag/_fd_lock.py): wraps the platform advisory lock primitive: a one-byte non-blocking lock/unlock through `msvcrt` on Windows or whole-file `flock` on POSIX. It leaves contention policy to callers.
- [src/vaultspec_rag/\_git_repository.py](../../../../src/vaultspec_rag/_git_repository.py): reads `.git` directory or worktree-file metadata to resolve a repository's common Git directory without spawning Git; unreadable/unrecognized layouts return `None`.
- [src/vaultspec_rag/\_gpu.py](../../../../src/vaultspec_rag/_gpu.py): centralizes CUDA-first, then MPS accelerator selection and lazy torch import. CPU inference is refused. `load_accelerator()` checks GPU ownership before importing torch, resolves the backend, applies the configured CUDA allocator fraction, and runs configuration under the load-admission gate.
- [src/vaultspec_rag/\_gpu_admission.py](../../../../src/vaultspec_rag/_gpu_admission.py): evaluates whether device memory meets a workload-derived or configured floor, credits memory already held by the current process, tracks consecutive unreadable CUDA-memory readings, and serializes check-and-load windows across processes. It provides a stable JSON projection and refusal messages. Admission is latched per process after a verdict reaches the floor comparison; explicit latch clearing supports a later reload after resident release.
- [src/vaultspec_rag/\_gpu_owner.py](../../../../src/vaultspec_rag/_gpu_owner.py): coordinates one model-stack owner per machine through a shared hardware anchor. It distinguishes local ownership, a valid loan to this process/ancestor, free hardware, another owner, a service holding the machine, and unverifiable state. It supports PID/start-time-bound loans, reclaim, owner observation, and fork-child cleanup.

## Interfaces and data flow

The package-level API names in `__all__` map to modules in `_LAZY_EXPORTS`; requesting a name imports its module, fetches the attribute, and caches it on the package. The declared API covers indexing, search, scanning, status, related-document lookup, embeddings, indexers, search result types, and store models; those underlying implementations were not inspected. `python -m vaultspec_rag` calls the root Typer app after guarded startup import.

The observed compute sequence is `load_accelerator()` → `require_gpu_ownership()` → lazy torch import/backend resolution → `admit_accelerator_load(configure, backend=...)`. The ownership layer uses a machine-shared GPU-owner anchor held for the process lifetime; the admission layer uses a separate machine-shared load-window anchor only around a memory check and the load callback. An owner may publish a loan to a borrower PID and process start time; the borrower is accepted only when that identity occurs in its own process lineage. The admission reading compares whole-MiB `free + own` against the floor, while an unreadable-memory streak is managed separately. MPS is admitted by the device-memory evaluator without a CUDA memory reading.

Anchor claims call the shared descriptor-lock primitive. PID-bearing anchor records are written in place at fixed width, with the lock byte placed beyond the record so Windows mandatory byte locking does not prevent contenders from reading the PID. Atomic JSON writes follow a separate temp-and-replace path; those do not replace lock-bearing anchor files.

Their behavior is not inferred beyond the names and call sites visible in this slice. Service/indexing call sites for the general helpers were not assigned, so their actual project-wide caller sets remain unknown.
