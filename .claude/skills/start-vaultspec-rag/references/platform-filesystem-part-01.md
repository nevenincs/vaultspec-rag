## Capability summary

- [src/vaultspec_rag/\_loopback_http.py](../../../../src/vaultspec_rag/_loopback_http.py) centralizes a loopback TCP connect verdict and an HTTP opener that clears proxy settings and refuses redirects. `FAST_CONNECT_TIMEOUT_SECONDS` is documented for fast probes where a false “down” is tolerable; each caller supplies the timeout. The module's documentation identifies the service client and Qdrant runtime as prior/corresponding users, and distinguishes public-HTTPS provisioning from this loopback opener. Actual call sites were not read.
- [src/vaultspec_rag/\_machine_lock.py](../../../../src/vaultspec_rag/_machine_lock.py) implements a process-retained machine lock lease and a separate machine-wide discovery pointer alongside managed Qdrant storage. It validates lease object identity, PID, and descriptor before pointer mutation; discovery writes are atomic and require the payload PID to match. Acquisition and probing delegate OS lock operations to uninspected `_anchor_claim`; the lock file remains after release because OS lock ownership, not file existence, is authoritative. Documentation describes CLI pre-flight and daemon-lifespan use; call sites were not read.
- [src/vaultspec_rag/\_managed_log_sink.py](../../../../src/vaultspec_rag/_managed_log_sink.py) provides a single-writer raw-byte log sink with bounded active and numbered backup files, secure file-open flags/permissions, backup retention cleanup, and rollover including a Windows copy/truncate fallback. It normalizes CR and CRLF into newline record boundaries while carrying at most one trailing CR across writes.
- [src/vaultspec_rag/\_markdown_passages.py](../../../../src/vaultspec_rag/_markdown_passages.py) parses markdown bodies into passages no longer than 1,200 characters, with source line spans and heading section paths. It recognizes ATX and setext headings, fenced blocks, lists, thematic breaks, and paragraph-like blocks; long blocks split at list-item, line, sentence, then word boundaries and short adjacent passages may merge below 200 characters. `MarkdownStructure` also maps offsets to lines/sections and clips passages to a text interval. Its documentation describes it as stdlib-only and suitable for split workers; no importer was inspected.
- [src/vaultspec_rag/\_model_cache.py](../../../../src/vaultspec_rag/_model_cache.py) separates a cheap structural cache-presence check from content verification. It locates snapshots through the hub in local-files-only mode; pinned snapshots are checked against committed per-file SHA256 manifests, while unpinned snapshots are checked for config, tokenizer, and safe weight structure. Verification holds file handles during a load, and checks for additions before successful context exit. The load path never downloads and wraps failures with operator remedies. Windows-specific handle behavior delegates to uninspected `_win32`; manifest lookup is in [src/vaultspec_rag/\_model_pins.py](../../../../src/vaultspec_rag/_model_pins.py).
- [src/vaultspec_rag/\_model_pins.py](../../../../src/vaultspec_rag/_model_pins.py) records repository IDs, pinned commits, and immutable per-file digest manifests for the default dense, reranker, and sparse models. `committed_revision` and `committed_manifest` return pin coverage; an unknown repository or uncovered revision has no manifest. The file documents the derivation process and says operator-named models are unpinned. The sparse ID and revision come from uninspected `_sparse_profile`.
- [src/vaultspec_rag/\_named_root.py](../../../../src/vaultspec_rag/_named_root.py) selects the root through `resolve_target`, passing the explicit path and the RAG root registry entry. Its documentation describes precedence across explicit input, `VAULTSPEC_RAG_ROOT`, then `VAULTSPEC_TARGET_DIR`, with working-directory discovery left to the framework when no rung names a root. It says CLI, MCP, and stdio entry points use this policy; call sites were not inspected.
- [src/vaultspec_rag/\_operator_commands.py](../../../../src/vaultspec_rag/_operator_commands.py) centralizes operator-facing CLI command strings, including port formatting, job filters, preprocess commands, server doctor/status/start/stop, restart remedy, shared “not running” text, and index commands. `IndexCommandOptions` controls rebuild/dry-run/full/port/target options; target paths are quoted for the current shell. `index_source_option` maps the combined source to `all`. The source documentation reports prior duplication across modules, but no caller modules were inspected.
- [src/vaultspec_rag/\_operator_lists.py](../../../../src/vaultspec_rag/_operator_lists.py) normalizes offset, finite page limit, and ascending/descending display order. Defaults are offset 0, limit 200, maximum limit 5,000, and descending order; invalid values fall back to defaults (offset is clamped at zero, limit at zero and the maximum).
- [src/vaultspec_rag/\_plain_directory.py](../../../../src/vaultspec_rag/_plain_directory.py) holds and validates a directory path beneath a caller-selected root while refusing symlinks, Windows junctions, and non-directory components. It exposes held-entry `lstat`, `unlink`, and tree removal operations, plus context-managed open/create and convenience parent/directory checks. POSIX descriptor-relative operations and Windows no-delete-sharing handles are selected by platform. Tree removal delegates to uninspected `_rmtree`; Windows opens delegate to uninspected `_win32`.
- [src/vaultspec_rag/\_ports.py](../../../../src/vaultspec_rag/_ports.py) provides loopback bind availability checks and upward scanning for the next available TCP port, stopping at 65535 and raising when the start is invalid or no port remains.

## Interfaces and data flow

- Loopback calls take a port and caller-selected timeout and return `accepted`, `refused`, or `indeterminate`; `LOOPBACK_OPENER` is a module-level opener configured with `NoRedirect` and an empty proxy map ([src/vaultspec_rag/\_loopback_http.py:43-117](../../../../src/vaultspec_rag/_loopback_http.py#L43)).
- Machine lock acquisition returns `(lease, pid)` on success or `(None, holder_pid)` for contention. Discovery is JSON-object read/write/delete state stored next to the lock; publishing requires an active lease and matching PID. Probe returns `MachineLockProbe(held, holder_pid)` ([src/vaultspec_rag/\_machine_lock.py:70-304](../../../../src/vaultspec_rag/_machine_lock.py#L70)). The config-derived storage directory determines the lock and discovery locations; the lock is intended to guard shared managed storage.
- The log sink accepts a path, maximum bytes, and backup count, then receives byte payloads through `write`; `close` releases its active stream. Active and numbered backup files form its storage state ([src/vaultspec_rag/\_managed_log_sink.py:26-248](../../../../src/vaultspec_rag/_managed_log_sink.py#L26)).
- Markdown input is a string plus optional first file line. Parsing returns text, passages, line offsets, heading offsets, and section paths; passage offsets are character indices into the supplied body ([src/vaultspec_rag/\_markdown_passages.py:63-177](../../../../src/vaultspec_rag/_markdown_passages.py#L63)).
- Snapshot APIs take repository, revision, and (for cache checks/verification) optional cache directory. `cached_snapshot_is_complete` returns a structural boolean; `verified_snapshot`/`loadable_snapshot` yield a held reader or raise `ModelSnapshotError`; `verify_snapshot` performs the verification without retaining handles after return. The hub cache is read-only through `local_files_only=True`; pinned file digests come from [src/vaultspec_rag/\_model_pins.py](../../../../src/vaultspec_rag/_model_pins.py) ([src/vaultspec_rag/\_model_cache.py:154-178, 282-403, 408-543](../../../../src/vaultspec_rag/_model_cache.py#L154)).
- `named_root(explicit)` returns the framework `ResolvedTarget` result ([src/vaultspec_rag/\_named_root.py:43-68](../../../../src/vaultspec_rag/_named_root.py#L43)). Operator command functions return strings; list helpers return normalized integers or order literals; port helpers return availability booleans / a port integer ([src/vaultspec_rag/\_operator_commands.py:75-260](../../../../src/vaultspec_rag/_operator_commands.py#L75); [src/vaultspec_rag/\_operator_lists.py:9-40](../../../../src/vaultspec_rag/_operator_lists.py#L9); [src/vaultspec_rag/\_ports.py:12-29](../../../../src/vaultspec_rag/_ports.py#L12)).
- `open_plain_directory(root, relative, create=...)` is a context manager yielding `PlainDirectory` or `None` when a component is absent and creation is disabled. Operations are routed through the held final descriptor where supported ([src/vaultspec_rag/\_plain_directory.py:69-220](../../../../src/vaultspec_rag/_plain_directory.py#L69)).
