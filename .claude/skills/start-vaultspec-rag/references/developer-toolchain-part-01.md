## Capability summary

- [dev/__init__.py](../../../../dev/__init__.py) initializes the development harness package and sets UTF-8 for Python child processes and the current stdout/stderr streams where supported. Its docstring describes the package as the `just` harness and points to `dev.toolchain` and `dev.runner` as registry and process primitives.
- [dev/__main__.py](../../../../dev/__main__.py) is the `python -m dev` CLI for listing verbs, rendering target help, resolving a verb/target, and executing declared steps. It dispatches echo, target-reference, command, tool-or-Docker, and tool-or-skip steps; applies gates; summarizes aggregate outcomes; preserves failures; maps advisory findings through `advisory_result`; and treats skipped-only runs as unproven/nonzero.
- [dev/actionlint.py](../../../../dev/actionlint.py) provides a pinned actionlint installer and workflow-check entry point. It selects archive and digest by normalized OS/architecture, downloads only from a fixed HTTPS GitHub origin, verifies downloaded archive bytes, extracts only the named executable, and runs actionlint with fixed external-linter settings. `--install` provisions when unavailable; the check path uses `find` and reports a missing tool without downloading. `find` prefers PATH and also accepts an existing cache file; those paths are not re-verified here.
- [dev/audit/__init__.py](../../../../dev/audit/__init__.py) marks the audit package and documents dependency audit as its gating audit.
- [dev/audit/dependency_audit.py](../../../../dev/audit/dependency_audit.py) collects pinned coordinates from discovered Python, npm, and Cargo lockfiles plus an optional declared-binaries manifest; queries OSV in batches; loads expiring advisory suppressions; builds a human/machine report and gate verdict; optionally writes JSON; and provides an extra-package probe option. It fails closed when coordinates cannot be collected, the scan cannot complete, or suppressions are invalid/expired.
- [dev/audit/tests/__init__.py](../../../../dev/audit/tests/__init__.py) identifies the package as guards for the dependency audit gate.
- [dev/audit/tests/test_dependency_audit_gate.py](../../../../dev/audit/tests/test_dependency_audit_gate.py) declares unit-level expectations for dependency-audit verdicts, suppression parsing/expiry and alias matching, coordinate collection, and optional report artifact output. This is test source evidence only; no passing result is established.
- [dev/ci_formats.py](../../../../dev/ci_formats.py) conditionally augments command arguments for GitHub Actions annotations: GitHub output for `ruff check` and `ty check`, JSON for `basedpyright`, and no changes when annotations are off or an output format is already selected.
- [dev/complexity.py](../../../../dev/complexity.py) exposes `gate` and `audit` modes. The gate applies complexity checks to production code and uses radon to explain xenon failures while returning xenon's status. The audit scans test-tree complexity through an advisory wrapper so findings do not gate, while scanner/configuration failures remain nonzero.

## Interfaces and data flow

- `python -m dev [verb] [target]` takes argv or `sys.argv`, resolves `VERBS`/defaults through `dev.toolchain`, and passes registered `Step` values to `dev.runner` or recursively resolves `Ref` targets. Exit codes flow through target execution and aggregate summaries; direct skipped targets become `NOTHING_SELECTED` ([dev/__main__.py:151-243,246-291](../../../../dev/__main__.py#L151)).
- `python -m dev.actionlint [--install] [actionlint args...]` takes CLI args. Provisioning selects `ARCHIVES` by `_platform_key`, stores in `RUNNER_TOOL_CACHE` or the project `.venv` cache, downloads and verifies an archive, then extracts the executable. Check mode locates the executable and invokes it with forwarded args ([dev/actionlint.py:56-103,105-248,251-298](../../../../dev/actionlint.py#L56)).
- `python -m dev.audit.dependency_audit [--json] [--extra-package ECOSYSTEM:NAME:VERSION]` collects coordinates, adds probes, parses suppressions, queries OSV, builds a `Report`, then prints human or JSON output and returns the report verdict. `VAULTSPEC_CI_REPORTS`, when set, selects the optional `dependency-audit.json` artifact directory ([dev/audit/dependency_audit.py:236-259,280-316,365-415,493-552,609-634,642-698](../../../../dev/audit/dependency_audit.py#L236)).
- `ci_formats.augment(argv, env)` returns an argv list, using the process environment if `env` is omitted. It recognizes `GITHUB_ACTIONS=true` case-insensitively and appends a compatible output flag based on the command ([dev/ci_formats.py:29-67](../../../../dev/ci_formats.py#L29)).
- `python -m dev.complexity [gate|audit]` defaults to `gate`; the gate invokes `uv run --no-sync` tools on `src/vaultspec_rag`, while audit invokes advisory-wrapped checks over its tests and module from the specified working directories ([dev/complexity.py:28-53,79-112,115-137](../../../../dev/complexity.py#L28)).

## Boundaries and dependencies

No result is known.
