## Capability summary

- [conftest.py](../../../../conftest.py): pytest infrastructure. Session and per-test fixtures isolate status/Qdrant singleton paths and reset config caches; teardown checks committed-pin drift and machine GPU-anchor claims. Helpers pin installation role, daemon capability, and hardware anchors. It defines typed RAG bundles, synthetic-vault/model/reranker fixtures, config helpers, loopback address selection, and a lazily imported job-service fixture.
- [src/vaultspec_rag/tests/constants.py](../../../../src/vaultspec_rag/tests/constants.py): shared test paths, ports, timeout budgets, delays, and ACP timeout constants; documents that these constants do not depend on production config.
- [src/vaultspec_rag/tests/corpus.py](../../../../src/vaultspec_rag/tests/corpus.py): re-exports the synthetic corpus types and single-vault builder, and creates multiple project roots with incremented seeds.
- [src/vaultspec_rag/tests/metrics.py](../../../../src/vaultspec_rag/tests/metrics.py): computes precision@k, reciprocal rank, and binary-relevance NDCG@k. Precision divides by requested k, including when fewer than k results were retrieved.
- [src/vaultspec_rag/tests/test_adr_regression.py](../../../../src/vaultspec_rag/tests/test_adr_regression.py): broad source-shape, import-boundary, and behavior regression expectations covering MCP async tools; registry/cache behavior; embedding/model-loading choices; reranker construction; search filters and RRF; graph invalidation; storage-maintenance boundaries and geometry; ledger concurrency and error taxonomy; GPU test selection; bounded OOM recovery; stdio watchdog placement; reindex timeout; and adaptive watcher scheduling, recovery, fairness, and adapter boundaries.
- [src/vaultspec_rag/tests/test_anchor_claim_refusals.py](../../../../src/vaultspec_rag/tests/test_anchor_claim_refusals.py): exercises outcomes for held-anchor contention and classifies constructed lock errors as either holder contention or unavailable/fault; checks that unavailable refusal closes its descriptor.
- [src/vaultspec_rag/tests/test_api_clean_admission.py](../../../../src/vaultspec_rag/tests/test_api_clean_admission.py): expects cleanup to respect warm and cold store leases, checks selected-source reset preserves sibling collections, and structurally guards that `api.clean` delegates maintenance-store ownership through the registry.
- [src/vaultspec_rag/tests/test_attempt_memory_telemetry.py](../../../../src/vaultspec_rag/tests/test_attempt_memory_telemetry.py): parameterizes code/document index attempts and checks memory-peak ownership across new, refused, unchanged, and unobserved attempts, including publication/checkpoint state.
- [src/vaultspec_rag/tests/test_backend_capabilities.py](../../../../src/vaultspec_rag/tests/test_backend_capabilities.py): expects service capability projection and response-schema validation to identify local versus server Qdrant from configured URL.
- [src/vaultspec_rag/tests/test_builtin_rule_directives.py](../../../../src/vaultspec_rag/tests/test_builtin_rule_directives.py): expects the built-in rule source file to exist and contain four required directive tokens; the referenced rule itself was not read.
- [src/vaultspec_rag/tests/test_checkpoint_common.py](../../../../src/vaultspec_rag/tests/test_checkpoint_common.py): expects shared checkpoint classification for interrupted runs, empty incremental receipt closure, resumed mutation confirmation, and configuration fingerprints for code/document configuration values.

## Interfaces and data flow

- Pytest fixtures accept `tmp_path`, `tmp_path_factory`, `monkeypatch`, and pytest request state. `managed_env` applies environment changes and resets both config caches at entry/exit. The session singleton fixture yields the canonical containment environment; autouse fixtures re-arm it around each test.
- `embedding_model` and `shared_reranker` yield session-shared model objects after snapshot setup. `synthetic_vault` builds 24 docs; `rag_components` indexes that vault and yields model, store, vault/code indexers, result, root, manifest, and reranker. `rag_components_full` builds 48 docs for quality-marked tests and yields the same bundle. These are fixture implementations described in [conftest.py](../../../../conftest.py), not proof that fixture setup succeeds in this environment.
- `build_multi_project_fixture(base, n_projects, docs_per_project, seed)` returns one manifest per child project, using seed+i. Metric helpers consume sets/lists of IDs and return floats.
- The tests feed temporary roots, monkeypatched config/backend values, synthetic content, or constructed exceptions into imported APIs. Some assert persisted Qdrant/SQLite state; others inspect imported source or AST, exercise import checks in a fresh interpreter, or capture resilience publications. The production modules and helper modules they import are outside this slice.
