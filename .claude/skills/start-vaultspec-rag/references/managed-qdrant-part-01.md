## Capability summary

- [src/vaultspec_rag/qdrant_runtime/__init__.py](../../../../src/vaultspec_rag/qdrant_runtime/__init__.py): documents the package boundary and exports no names. It describes this package as covering the server pin, asset mapping/resolution, provisioning, and supervised child startup, while saying the package import should remain lightweight for CLI startup. These are module documentation claims, not independently checked against other package files.
- [src/vaultspec_rag/qdrant_runtime/\_child_tree.py](../../../../src/vaultspec_rag/qdrant_runtime/_child_tree.py): ends a supervised Qdrant process together with its descendants. It chooses a Windows Job Object path or a POSIX process-group path; it avoids signaling a reused group identifier where it can keep the leader unreaped, reports when safe cleanup is no longer possible, and confirms process disappearance. Public functions are `exited` and `end_tree`.
- [src/vaultspec_rag/qdrant_runtime/\_constants.py](../../../../src/vaultspec_rag/qdrant_runtime/_constants.py): centralizes the pinned server version, named release assets, archive and executable SHA256 pin tables, manifest/staging names and manifest-source values. Defines structured `ProvisionReport`, `BinarySource`, `ResolvedBinary`, and `QdrantRuntimeState` data types, including JSON views for the report and runtime state. The module documents the digest derivation and client-version relationship; those procedural claims were not independently verified.
- [src/vaultspec_rag/qdrant_runtime/\_credential.py](../../../../src/vaultspec_rag/qdrant_runtime/_credential.py): generates a random API key, writes and reads its managed credential record, recognizes the managed loopback endpoint, chooses the configured or managed key for a URL, and probes the Qdrant collections data plane to confirm anonymous requests are refused and keyed requests succeed. Its documented intent is to protect the managed local store from other OS accounts and avoid sending the managed key to arbitrary endpoints.
- [src/vaultspec_rag/native_binary/\_download.py](../../../../src/vaultspec_rag/native_binary/_download.py): provides a bounded HTTPS-to-open-file transfer with HTTPS-only, host-constrained redirects; total and per-read time bounds; declared and streamed size limits; categorized failures; progress callbacks; and bounded retries for transient transport/HTTP failures. The module says callers verify content against their own committed digest. It names managed installation and build tools as consumers in its documentation, but their call sites were not inspected.
- [src/vaultspec_rag/native_binary/\_hold.py](../../../../src/vaultspec_rag/native_binary/_hold.py): opens and retains a regular executable file while hashing and preparing execution. `HeldExecutable` exposes the held path, handle, launch path, inherited descriptors, exclusivity, `sha256`, `names_held_file`, and post-launch `unchanged` checks. `held_executable` supplies platform-specific behavior: Windows denies write/delete sharing; Linux with `/proc` can launch through an inherited descriptor; other supported paths use path identity and a post-launch content check. The module explicitly leaves binary origin and expected digest decisions to callers.
- [src/vaultspec_rag/qdrant_runtime/\_managed_install.py](../../../../src/vaultspec_rag/qdrant_runtime/_managed_install.py): classifies the managed executable as absent, healthy, refused, unreadable, obstructed, or accompanied. It hashes the file against committed executable pins, then checks directory entries for unexpected companions; it does not read the manifest to decide whether the executable is trusted. It constructs operator-facing refusal guidance and exposes `classify_managed_binary`, `companions_verdict`, and `unreadable_refusal`, along with `InstallState` and `ManagedInstall`. Its documentation names resolver, spawn check, provisioner, and status surfaces as consumers; no such caller source was inspected.

## Interfaces and data flow

- The pin and type boundary is [src/vaultspec_rag/qdrant_runtime/\_constants.py](../../../../src/vaultspec_rag/qdrant_runtime/_constants.py): asset names map to archive digests and executable digests; `ProvisionReport` carries action, target version, asset, URL, binary, digest, and message; `ResolvedBinary` carries path, source, known version, and expected digest; `QdrantRuntimeState` carries mode, endpoint, child liveness/PID/port, version, restart count, and extra fields. `BinarySource` distinguishes operator-configured, managed, and attached processes. Digest contents are not repeated in this report.
- `download_https(url, out, *, redirect_hosts, on_progress, limits)` writes into a caller-opened, seekable binary file. A retry resets/truncates that file before starting again. The response's declared size is checked and passed to the caller's `admit` callback before body reads; an undelimited response may be checked by the caller's `whole` callback. Errors are `DownloadError` values with a `DownloadFailure` kind, optional HTTP status, and attempt count. The downloader does not itself authenticate the downloaded artifact.
- `classify_managed_binary(binary)` returns a `ManagedInstall` verdict. It first checks the named filesystem object, then holds and hashes a regular file against the committed executable digests, and for a matching digest checks directory companions. The manifest is not consulted. Unexpected companions make a matching executable unusable until removed; unreadable paths and non-file obstructions receive separate states and guidance.
- `held_executable(path)` yields a `HeldExecutable`; callers can hash the open handle, use its launch path/inherited descriptors, and check whether the path/content remained acceptable after process creation. In this slice, `_managed_install._judge_content` uses it for classification. The spawn integration that would use `unchanged` is outside the assigned ranges.
- The managed credential path is `storage_dir.parent / "credential.json"`. `write_managed_api_key` atomically writes the key as private JSON; `read_managed_api_key` returns the key or `None` for a missing/unusable record. `server_api_key` gives a configured key precedence, otherwise reads the managed key only when the URL is the configured HTTP loopback endpoint. `data_plane_auth_fault` issues GET `/collections` without a key and then with the candidate key; it accepts anonymous 401/403 followed by keyed 200, returning a reason otherwise.
- `end_tree(proc, job, timeout=...)` returns whether the supervised process tree is gone. Windows termination uses a job handle and confirms the child/job count; POSIX sends SIGTERM to the child-led group, waits, escalates to SIGKILL, and reports survivors. `exited(proc)` is the non-stopping liveness query, using wait-without-reap where available on POSIX.
