## Capability summary

- The slice is integration-test coverage for managed service jobs and their operator-facing surfaces. It does not contain implementation or standalone documentation source.
- [src/vaultspec_rag/tests/integration/test_service_job_control.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control.py) covers typed HTTP transport operations and conflicts; human CLI prefix lookup and pause/resume/stop/retry/delete; JSON CLI exact-ID lookup, force-stop refusal, cancellation replay, and deletion replay; an import probe for job-admission resource snapshots; and MCP reindex compatibility, including the expected absence of job-control MCP tools (1–381).
- [src/vaultspec_rag/tests/integration/test_service_job_control_pause_restart.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control_pause_restart.py) exercises real manager/indexer/store behavior: a large vault job pauses after publishing, releases resources, resumes as a second attempt, and can be cancelled without changing captured store IDs or run-ledger SQLite state (136–288). It also models restart with queued, paused, and interrupted jobs, then asserts dispatch/restoration, resumed interrupted work, durable deletion, and retained pause intent (291–543). Its final scenario changes source files while a code job is paused and expects resume to discover the current corpus (545–624). It re-exports the shared E2E fixture (38–55).
- [src/vaultspec_rag/tests/integration/test_service_job_control_transport_matrix.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control_transport_matrix.py) puts one job through a real loopback HTTP server, typed transport, and JSON CLI. Expected cross-surface behavior includes exact IDs, stale-revision conflict and already-satisfied replay, active-delete refusal, force-stop refusal, cancellation, and deletion (54–231).
- [src/vaultspec_rag/tests/integration/test_service_job_control_watcher.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control_watcher.py) covers automatic watcher jobs: pause coalesces later edits into resumed work; cancellation is followed by replacement convergence; stopping the watcher releases job/runtime resources and permits project-store closure (42–292).
- [src/vaultspec_rag/tests/integration/test_service_jobs_cli_basics.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_cli_basics.py) specifies the `server jobs` CLI's not-running response, help flags and wording, filter aliases and validation, removed flags, and actionable empty output (24–417). It also extracts a troubleshooting command from [docs/automatic-convergence.md](../../../../docs/automatic-convergence.md) and expects it to submit a watcher-trigger filter; the document itself was not read (108–134).
- [src/vaultspec_rag/tests/integration/test_service_jobs_cli_detail.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_cli_detail.py) specifies human detail rendering for state, attribution, paths/process resources, normalized cleanup progress/errors, and progress freshness; it expects JSON to preserve the service payload and `--watch` to reject JSON mode. It also checks CLI/MCP `get_jobs` parity at a shallow registration/callability level (28–262).
- [src/vaultspec_rag/tests/integration/test_service_jobs_cli_feed.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_cli_feed.py) specifies line-oriented list rendering: count and ordering summary, active/waiting/finished/failed rows, missing-field language, disk-space and subsecond-duration normalization, single-line failure details, and the distinction between filtered display counts and service totals (23–396).
- [src/vaultspec_rag/tests/integration/test_service_jobs_cli_filters.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_cli_filters.py) expects active and waiting selections to separate running work by progress shape, maps user-facing progress into plain language, covers absent context and cancelled automatic updates (24–259).
- [src/vaultspec_rag/tests/integration/test_service_jobs_mcp.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_mcp.py) expects MCP-triggered reindex jobs to appear in the admin job list with snapshot/CLI attribution, terminal polling to honor a short deadline, newest-first ordering, limits, source filtering, and empty results for non-positive limits (23–126).
- [src/vaultspec_rag/tests/integration/test_service_jobs_progress.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_progress.py) uses a stub `/jobs` response to expect a no-progress warning for an old running job and no warning for a fresh one (26–117).
- [src/vaultspec_rag/tests/integration/test_service_jobs_resilience.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_resilience.py) seeds terminal resilience snapshots and expects parity across job collection/detail routes, health, and CLI JSON/human output for cancellation, interruption, RSS/CUDA ceilings, timeout, and watcher-circuit outcomes (39–402).
- [src/vaultspec_rag/tests/integration/test_service_jobs_routes_auth.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_routes_auth.py) specifies `/jobs` authorization outcomes and an exact authenticated collection-envelope shape, including pagination, ordering, summary, filters, GPU/pressure/device-load, and quiesce fields; it also expects bearer and query-token access (21–105).

## Interfaces and data flow

- **Manager path (test expectations):** tests construct `JobSpec`/`JobInitiator`, call `JobManager.create`, then use `set_desired_state`, `wait_for_attempt`, `get`, `delete`, and in resilience setup `start_attempt`/`finish_attempt`/`update_terminal_resilience`. Expected job fields include ID, state, desired state, revision, attempt number, and resilience data ([src/vaultspec_rag/tests/integration/test_service_job_control.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control.py) 43–66; [src/vaultspec_rag/tests/integration/test_service_job_control_pause_restart.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control_pause_restart.py) 71–101, 158–193, 382–476; [src/vaultspec_rag/tests/integration/test_service_jobs_resilience.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_resilience.py) 39–117).
- **HTTP and typed transport:** tests exercise `/jobs`, `/jobs/{job_id}`, and `/health`, with authenticated collection/detail requests in the resilience suite. `/jobs` route tests expect 401 without or with a wrong token, and 200 with bearer/query token. Transport helpers cover lookup, desired-state changes, retry, and delete. Exact server implementation and all HTTP verbs are uninspected ([src/vaultspec_rag/tests/integration/test_service_jobs_routes_auth.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_routes_auth.py) 21–105; [src/vaultspec_rag/tests/integration/test_service_jobs_resilience.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_resilience.py) 125–144; [src/vaultspec_rag/tests/integration/test_service_job_control.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control.py) 78–136).
- **CLI:** entry points invoked in tests are `server jobs` with state/index/query/failed/job-id/started-by/since/watch/interval-style filters and `--json`, plus `server job show|pause|resume|stop|retry|delete`. Tests expect human output to translate service fields and JSON output to retain structured payloads. Command implementations are uninspected ([src/vaultspec_rag/tests/integration/test_service_jobs_cli_basics.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_cli_basics.py) 46–105, 173–243, 269–360; [src/vaultspec_rag/tests/integration/test_service_jobs_cli_detail.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_cli_detail.py) 97–134, 226–255; [src/vaultspec_rag/tests/integration/test_service_job_control.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control.py) 176–311).
- **MCP:** reindex tools submit index requests and return queued job IDs/outcomes. Tests explicitly expect no MCP job-control tools such as show/pause/resume/stop/retry/delete/list, and use a separate admin client for listing ([src/vaultspec_rag/tests/integration/test_service_job_control.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control.py) 314–381; [src/vaultspec_rag/tests/integration/test_service_jobs_mcp.py](../../../../src/vaultspec_rag/tests/integration/test_service_jobs_mcp.py) 23–45, 64–126).
- **State and integrations:** the E2E tests create `.vault` documents or code files, take project compute leases, hold indexer writer locks, inspect store IDs, and compare run-ledger SQLite contents. Restart coverage copies the manager's state path, invokes manager restore/startup, then checks job state. These establish what tests inspect, not the storage format or production persistence guarantees ([src/vaultspec_rag/tests/integration/test_service_job_control_pause_restart.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control_pause_restart.py) 214–288, 319–379, 479–543, 545–624; [src/vaultspec_rag/tests/integration/test_service_job_control_watcher.py](../../../../src/vaultspec_rag/tests/integration/test_service_job_control_watcher.py) 130–192, 195–253, 256–292).

## Boundaries and dependencies

- All evidence in this slice comes from tests. No production implementation or user documentation was inspected; observed contracts must be treated as test expectations.
- The tests directly name production surfaces including `cli.app`, `cli._service_jobs_presentation`, `jobs`, `job_manager.manager.JobManager`, `job_models`, `server.create_http_app`, `server._lifespan`, `serviceclient._transport`, `mcp._mcp`, `mcp._tools`, `service_quiesce`, indexer run-ledger models, and storage helpers. Their internal behavior is not inspected.
- Test harness/support dependencies were not followed: `. _service_jobs_support` (HTTP fixtures, payloads, formatting helpers), `. _service_job_control_e2e_support` (runtime fixture and release assertions), `.._service_jobs_route_helpers`, `.._config_fixtures`, `.._ports`, `.._sqlite_state`, `.._store_fixtures`, `.._import_probe`, `.._http_stubs`, `tests._admin_client`, and `tools.check_docs_conventions`. The unusual space after the leading dot in the first two names above is typographic only; import names in source are `._service_jobs_support` and `._service_job_control_e2e_support`.
- The convergence-doc test reads [docs/automatic-convergence.md](../../../../docs/automatic-convergence.md) at runtime, but the document was outside the assigned read set; only the test's expectation is known. No imports were followed, and no HTTP server, watcher, GPU job, or service was started by this analysis.
