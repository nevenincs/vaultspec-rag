## Capability summary

- [src/vaultspec_rag/tests/test_job_manager_transitions.py](../../../../src/vaultspec_rag/tests/test_job_manager_transitions.py) exercises lifecycle and ownership cases through `JobManager`: resource-boundary reset on a resumed attempt versus preservation on same-attempt pause withdrawal; shutdown closing the attempt-claim boundary; pause/resume races; progress validation and exact attempt/task ownership; queued and running cancellation; first-terminal-writer behavior; retry/delete rules; and shutdown, persistence restore, and checkpoint continuation. These are test expectations, not observed results. (1-40, 48-536, 539-603)
- [src/vaultspec_rag/tests/test_job_progress_durability.py](../../../../src/vaultspec_rag/tests/test_job_progress_durability.py) specifies coalesced progress persistence: progress may update in memory while its write is deferred; terminal transitions synchronously persist the complete current generation, including deferred progress; a publish after the budget expires flushes; and explicit flush clears dirty state. Tests inspect the state file through the persistence loader. (1-6, 48-85, 88-222)
- [src/vaultspec_rag/tests/test_job_quiesce_operator_intent.py](../../../../src/vaultspec_rag/tests/test_job_quiesce_operator_intent.py) specifies editable operator pause intent while global quiesce is draining or holding jobs, persisted pause capability, revision conflict handling, prevention of restart after operator pause, replay of the same intent, and absorbing cancellation. (1-177)
- [src/vaultspec_rag/tests/test_job_rebuild_resume_dispatch.py](../../../../src/vaultspec_rag/tests/test_job_rebuild_resume_dispatch.py) checks real source-entry binding for code, document, and vault dispatch: rebuild resumes preserve clean rebuild authority across fresh, quiesce, operator, and restored paths; incremental resumes bind each source's incremental method; and unsupported authority or absent admitted preflight is rejected. Its pre-entry pause checks also expect unstarted recovery not to touch source storage. (50-105, 123-169, 171-274)
- [src/vaultspec_rag/tests/test_job_resilience.py](../../../../src/vaultspec_rag/tests/test_job_resilience.py) specifies snapshot validation, manager ownership by the current attempt/task, persistence and restore, shared status projection, explicit bounded REST shaping, operator-readable CLI formatting, per-job CUDA forward-peak accounting, support-profile admission dimensions, and vault observe-only telemetry with no borrowed ceilings. (41-198, 201-275, 279-422, 425-619)
- [src/vaultspec_rag/tests/test_job_retry_resolution.py](../../../../src/vaultspec_rag/tests/test_job_retry_resolution.py) specifies retry-lineage resolution: a successful linked retry supersedes ancestors while preserving history; failed retries leave parents retryable; successful chained retries settle all ancestors; rejection and superseding events include target/requester context; and superseded state round-trips persistence. (35-91, 94-354)
- [src/vaultspec_rag/tests/test_job_runtime_owner_tickets.py](../../../../src/vaultspec_rag/tests/test_job_runtime_owner_tickets.py) specifies compute-ticket release on terminal completion and control acknowledgement, and ownership replacement behavior including idempotent release. A source-inspection guard expects `state.py` to be the sole runtime-owner assignment site. (38-55, 58-151)
- [src/vaultspec_rag/tests/test_jobs_admission_display.py](../../../../src/vaultspec_rag/tests/test_jobs_admission_display.py) specifies CLI feed interpretation of `admission_acquired_at`: a null stamp means waiting for the GPU slot, a present stamp means active even before progress, and an omitted field preserves the older/unknown reading. It asserts rendered console text. (1-17, 29-155)

## Interfaces and data flow

- Test callers construct `JobSpec` and `JobInitiator`, create jobs, then drive transitions with `start_attempt`, `set_desired_state`, `update_progress`, resource updates/releases, `acknowledge_control`, `finish_attempt`, `retry`, and `delete`. Dispatch-focused cases additionally call `bind_dispatch`, dispatch/wait methods, quiesce preparation, restore, flush, and status methods. These call sites evidence test-facing interfaces only. (transitions 61-140, 168-208, 215-270, 286-354, 356-536, 539-603; durability 48-85, 105-218; rebuild 50-105)
- Attempt input is represented in these tests by an asyncio task, `RunControlToken`, `JobAttemptContext`, and typed progress/resource/terminal records. Assertions inspect returned outcome codes and snapshots, revisions, attempt lineage, runtime/resource ownership, capabilities, and desired/terminal state. (transitions 73-139, 286-348, 392-457, 482-532)
- Durable state is selected by a `state_path`; tests compare bytes, load `JobSnapshot` records, inspect `persistence_dirty`, and restore managers. Progress can be deferred, while transition and explicit flush assertions expect persisted state to catch up. This describes the tested contract, not writer implementation. (durability 48-85, 88-222; transitions 97-109, 539-603; retry 326-354)
- Resilience assertions follow a test-visible path from `IndexResilienceSnapshot` through manager snapshots and `to_dict()`, then into `index_job_status` or CLI formatting; a separate route-shaper test passes a resilience record to `_job_resilience`. Memory tests call budget/recorder seams directly. (resilience 64-141, 143-187, 201-275, 279-422, 425-569)
- Dispatch tests bind an `_AttemptDispatch` to a source-specific indexer and inspect the actual `full_index` frame or bound incremental method. The test expects admitted code/document preflights and `run_control`/authority to reach that boundary. (rebuild 123-154, 157-228)
- The admission-display test passes dictionary payloads to `_render_jobs_feed`; its input includes phase, runtime, optional progress, and either null, present, or absent admission timestamp. The test captures console output. (admission 29-60, 63-155)
- Quiesce tests connect a `ServiceRegistry` and `JobManager` through the registry's quiesce controller and inspect ticket counts and pause/resume outcomes. The precise controller implementation is uninspected. (quiesce 36-55, 58-149; owner tickets 59-135)
