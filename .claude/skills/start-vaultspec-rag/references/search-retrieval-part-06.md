## Capability summary

- [src/vaultspec_rag/search/\_validation.py](../../../../src/vaultspec_rag/search/_validation.py) defines search filter options, accepted document/domain/preference values, typed validation errors, and checks compatibility between supplied filters and code, vault, document, and combined search types. It derives code/vault/document filter vocabularies from `store_schema`.
- [src/vaultspec_rag/search/\_typesafe_questions.py](../../../../src/vaultspec_rag/search/_typesafe_questions.py) constructs query interpretation questions and per-candidate usefulness questions. It preserves the original query, optionally splits simple natural-language queries into literal clauses, and avoids splitting code-like or highly compound queries.
- [src/vaultspec_rag/search/\_typesafe_policy.py](../../../../src/vaultspec_rag/search/_typesafe_policy.py) coordinates hosted query interpretation and candidate scoring. It builds bounded candidate windows and batches, uses full `rerank_text` content as evidence, records timing/cost/confidence metrics, and only drops a result when every clause receives a high-confidence, high-probability `not_useful` judgment. Surviving result scores are replaced with the highest useful probability and sorted descending.
- [src/vaultspec_rag/search/\_typesafe_transport.py](../../../../src/vaultspec_rag/search/_typesafe_transport.py) implements the optional TypeSafe HTTP integration: environment enrollment, status reporting, deadlines and size limits, request coalescing and caching, a circuit cooldown, response validation, and redacted failure reasons. In this slice it exposes `available`, `enrollment_status`, and `evaluate`.
- [src/vaultspec_rag/search/\_typesafe_pool.py](../../../../src/vaultspec_rag/search/_typesafe_pool.py) maintains a small locked pool of exclusive HTTP connection leases, reusing recent idle connections for the same identity and closing stale or mismatched leases.

## Interfaces and data flow

- Filter validation enters at `validate_search_filters(search_type, options, include_documents=...)`; options are represented by `SearchFilterOptions`. It canonicalizes source type, validates individual values, groups supplied options using schema key tuples, then rejects filters that do not match the selected search type. ([src/vaultspec_rag/search/\_validation.py:25-49,154-210,229-284](../../../../src/vaultspec_rag/search/_validation.py#L25))
- Query classification enters at `prepare_query(query, surface, filters=None)`. If the query is nonblank and transport is available, it builds state containing query, surface, and constraints, checks a 24,000-byte request estimate, sets a shared 10-second deadline, and calls `transport.evaluate` with `query_questions()`. It returns `None` on unavailability or an unusable response; otherwise it returns a `ClassificationSession` with advisory preferences and timing data. ([src/vaultspec_rag/search/\_typesafe_policy.py:99-132](../../../../src/vaultspec_rag/search/_typesafe_policy.py#L99))
- Candidate ranking is performed by `ClassificationSession.rank(results)`. It derives clauses from the query, packages candidate content and metadata into bounded batches, and asks `candidate_questions` for each candidate/clause pair. At most two requests are submitted concurrently by this layer. An unavailable transport marks the session failed and propagates the reason; successful judgments annotate metrics, remove only strongly rejected candidates, update survivor scores, and sort them. ([src/vaultspec_rag/search/\_typesafe_policy.py:135-164,184-213,215-293](../../../../src/vaultspec_rag/search/_typesafe_policy.py#L135))
- Query questions classify intent, wording, evidence form, domain, and clarity. Candidate questions assess each exact clause independently against `state.candidates.cN.content`, while treating that content as evidence rather than instructions and query assessment as advisory context. ([src/vaultspec_rag/search/\_typesafe_questions.py:49-103,106-139](../../../../src/vaultspec_rag/search/_typesafe_questions.py#L49))
- Transport reads the process-enrolled credential through `env_value(entry(EnvVar.TYPESAFE_API_KEY))`; it stores only process-local circuit, response-cache, connection-pool, and in-flight request state in this module. It sends JSON to the fixed TypeSafe HTTPS endpoint and validates returned evaluations. Cache hits and coalesced followers report zero new request/token counts. ([src/vaultspec_rag/search/\_typesafe_transport.py:27-38,75-113,116-157,205-267,406-490](../../../../src/vaultspec_rag/search/_typesafe_transport.py#L27))
- The pool accepts HTTPS or HTTP to `127.0.0.1`, with HTTP/1.1 configured for HTTPS; other endpoint forms raise `unsupported_endpoint`. The transport's configured endpoint is HTTPS. ([src/vaultspec_rag/search/\_typesafe_pool.py:40-70](../../../../src/vaultspec_rag/search/_typesafe_pool.py#L40); [src/vaultspec_rag/search/\_typesafe_transport.py:27](../../../../src/vaultspec_rag/search/_typesafe_transport.py#L27))
