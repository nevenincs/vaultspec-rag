## Capability summary

This integration-test area defines expected cross-component behavior around preprocessing, public document retrieval, background-process containment, managed Qdrant lifecycle/security, server-backed storage, retrieval quality, ranking judgments, and reindex consent.

- [src/vaultspec_rag/tests/integration/test_preprocess_integration.py](../../../../src/vaultspec_rag/tests/integration/test_preprocess_integration.py) covers command preprocessors from direct invocation through indexing and search, plus cache identity and failure policy. Its fixtures create per-test status/approval state and temporary project files. The suite expects schema-v1 JSON extraction outputs with one or more units, metadata and page anchors to survive, and source redirection to be rejected. It exercises the CLI `preprocess list/check/status --json` policy-error shape; a binary PDF indexed/searchable through full and incremental index paths; and the `off`, unapproved, and edited-policy gates, where hooks do not execute and previously owned indexed data/cache/ledger snapshots remain intact. It also covers retryable or converged skip outcomes, `passthrough` raw-text search, command-version cache invalidation, and requiring an explicit full rebuild for global ignore membership changes. These are test expectations, not verified runtime guarantees.
- [src/vaultspec_rag/tests/integration/test_public_document_search.py](../../../../src/vaultspec_rag/tests/integration/test_public_document_search.py) specifies the public document and combined-search facade behavior for empty projects without a model and source-path filtering when two documents share the same phrase.
- [src/vaultspec_rag/tests/integration/test_pytest_daemon_anchor.py](../../../../src/vaultspec_rag/tests/integration/test_pytest_daemon_anchor.py) specifies Windows session-job anchoring: a hard-killed owner must not strand its child; anchoring a live process must report success; and an AST guard requires test service launches to go through the session anchor, with one named exception module.
- [src/vaultspec_rag/tests/integration/test_qdrant_attach.py](../../../../src/vaultspec_rag/tests/integration/test_qdrant_attach.py) checks managed-server REST/gRPC authentication using a real provisioned server, the internal server client’s credential discovery, reuse of a healthy owned server, and refusal to adopt servers with wrong/missing credentials, no identity, or a version mismatch. A local stdlib HTTP server is used for refusal/decision cases that do not need a process witness.
- [src/vaultspec_rag/tests/integration/test_qdrant_descriptor_child_witnesses.py](../../../../src/vaultspec_rag/tests/integration/test_qdrant_descriptor_child_witnesses.py) is Linux-only evidence for the descriptor-launched server case: the process short name is numeric, while image path/image and listener checks identify the child; an already-running owned child is attached to, and a child left by a killed owner is classified/reaped before replacement.
- [src/vaultspec_rag/tests/integration/test_qdrant_long_paths.py](../../../../src/vaultspec_rag/tests/integration/test_qdrant_long_paths.py) specifies that the supervised server can create its production-schema collection when its storage path is at least 140 characters on Windows.
- [src/vaultspec_rag/tests/integration/test_qdrant_orphan_reap.py](../../../../src/vaultspec_rag/tests/integration/test_qdrant_orphan_reap.py) exercises process reaping against real Python child processes and action classification: dead/invalid PIDs, start-time witness mismatches, bounded wait budgets, live incompletely witnessed holders, managed orphans, and target-image checks.
- [src/vaultspec_rag/tests/integration/test_qdrant_server_mode.py](../../../../src/vaultspec_rag/tests/integration/test_qdrant_server_mode.py) covers server-backed vault/code indexing and hybrid search; unlocked point operations in server mode; root-specific collection names on one server; scoped deletion of code and vault content; watcher-driven deletion eviction for both; child stop/reap and restart; and startup selection between default server mode and local-only mode, including an actionable missing-binary failure.
- [src/vaultspec_rag/tests/integration/test_quality.py](../../../../src/vaultspec_rag/tests/integration/test_quality.py) specifies known-answer retrieval for audit/ADR/plan/needle queries, type/feature/date and combined filters, ranking/authority expectations, positive scores, larger-limit behavior, and low scores for irrelevant or nonsense queries.
- [src/vaultspec_rag/tests/integration/test_ranking_testimonial.py](../../../../src/vaultspec_rag/tests/integration/test_ranking_testimonial.py) converts predeclared persona/intent/authority observations into `satisfied`, `wrong-role`, or `off-topic` verdicts; the expected authority must occur before rank index 3 for the machine assertion to pass.
- [src/vaultspec_rag/tests/integration/test_reindex_consent_boundary.py](../../../../src/vaultspec_rag/tests/integration/test_reindex_consent_boundary.py) specifies that changing a run signature’s backend identity changes its content-compatibility fingerprint, and that a committed reconciliation batch counts as durable progress under `RunPolicy`.

## Interfaces and data flow

- Preprocessing tests construct `.vaultragpreprocess.toml` command rules, create binary or text source files, optionally approve the policy, then invoke either `run_preprocessor`, `CodebaseIndexer.full_index/incremental_index`, or the `vaultspec_rag preprocess` CLI subprocess. Example child output includes `schema_version`, preprocessor id/version, source path, metadata, and unit text/title/section/anchor/locator. Assertions inspect search hits, store IDs/counts, preprocess result fields, cache contents, and run-ledger file state. Approval state is isolated through the status-dir environment setting.
- The document facade tests pass `DocumentIndexOptions`, `DocumentSearchRequest`, and `CombinedSearchRequest` to `index_documents`, `search_documents`, and `search_combined`, then assert result paths and branch status.
- Qdrant tests route configuration through environment variables (including URL, HTTP port, storage path, status directory, API key, binary path/digest, and local-only selection). `QdrantSupervisor` or `start_supervised_from_config` starts or adopts the service; tests inspect readiness/version, process identity, endpoint authentication, collections, index/search effects, and child liveness. Some endpoint probes use REST on the configured HTTP port and raw gRPC on the adjacent port.
- Retrieval-quality tests consume the shared `rag_components` fixture (model, store, root, reranker, and sometimes manifest) and query `VaultSearcher`; the ranking testimonial test consumes `frozen_corpus_evidence["testimonials"]` and records the observed top list against an authority chosen before the search.
- The consent-boundary test constructs a `RunSignature` for a code/full run and compares fingerprints after replacing backend identity; a `RunPolicy` records a reconciliation-batch durable-progress event.
