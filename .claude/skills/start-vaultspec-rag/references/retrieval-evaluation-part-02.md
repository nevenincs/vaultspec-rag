## Capability summary

This package contains two evaluation datasets, a graded-relevance rubric, pure ranking/evidence metrics, a frozen-vault materializer, and recorded quality baselines. Its package docstring calls these evaluation support modules and names `tests/integration/test_intent_ranking.py` as the gating test (documentation claim only).

- [src/vaultspec_rag/tests/quality/__init__.py](../../../../src/vaultspec_rag/tests/quality/__init__.py): describes the package scope as rubric, role-aware metrics, and labeled intent queries, and points to the integration gate; it defines no behavior in the assigned lines.
- [src/vaultspec_rag/tests/quality/\_frozen_corpus.py](../../../../src/vaultspec_rag/tests/quality/_frozen_corpus.py): pins the evaluation corpus to commit `c02c12cff9505f5283dc9c37b08696416a791fe8`. `materialize_frozen_vault(dest_root, repo_root)` obtains a `.vault` archive with Git and extracts it under the destination using tarfile's `data` filter; it returns the materialized `.vault` path. `frozen_vault_document_count(repo_root)` lists that ref's tracked `.vault` paths and counts Markdown files outside `data/`. Git reads have a 120-second timeout. The stated purpose is to avoid quality-gate drift as the live vault changes.
- [src/vaultspec_rag/tests/quality/rubric.py](../../../../src/vaultspec_rag/tests/quality/rubric.py): defines the `Intent` enum (orientation, debugging, implementation), ADR active/inactive status sets, and `grade_for`. Its matrix grades relevant records by intent and document role; active/unknown ADRs and inactive ADRs are separate roles, and `codebase` aliases to `code`. Off-topic or unrecognized roles score zero.
- [src/vaultspec_rag/tests/quality/metrics.py](../../../../src/vaultspec_rag/tests/quality/metrics.py): exports role-aware `ndcg_at_k`, `rank_of_first_grade`, `authoritative_at_k`, `mrr_at_first_grade`, `role_precision_at_k`, and evidence normalization/matching functions. Inputs are ranked document IDs plus gold-grade mappings (and cutoffs/thresholds where applicable); outputs are metric values, a rank/None, or booleans. NDCG uses gain (2^grade-1); evidence matching lowercases, removes backticks/bold markers, collapses whitespace, then tests whether the entire normalized evidence string occurs in the excerpt. The module states that functions are pure and do not call a retriever.
- [src/vaultspec_rag/tests/quality/intent_queries.toml](../../../../src/vaultspec_rag/tests/quality/intent_queries.toml): supplies 11 labeled queries across the three intents, with gold document IDs and grades 0-3. Its comments say labels are mechanically assigned from the rubric and absent documents are grade 0. It includes an orientation case where an accepted ADR is grade 3 and its implementation exec record grade 1, plus a superseded-ADR trap.
- [src/vaultspec_rag/tests/quality/evidence_queries.toml](../../../../src/vaultspec_rag/tests/quality/evidence_queries.toml): supplies 36 evidence cases. Each has an ID, natural-language query, direct/paraphrase kind, note, and gold record(s) with section, verbatim evidence span, and body offset. Its header describes blind authoring and the intended snippet check after normalization. This is labeled input data; the consuming gate was not inspected.
- [src/vaultspec_rag/tests/quality/baseline.json](../../../../src/vaultspec_rag/tests/quality/baseline.json): stores before/after-intent-prior aggregates by intent and per-query results for the with-prior run, including NDCG, role precision, and authoritative@3 or grade-3 MRR fields as applicable.
- [src/vaultspec_rag/tests/quality/evidence_baseline.json](../../../../src/vaultspec_rag/tests/quality/evidence_baseline.json): records floors for hit@1, MRR, evidence-in-snippet, and section match, plus measurements for chunk-head snippets and query-selected passages. Its notes describe 36 cases and the respective snippet/span setup.
- [src/vaultspec_rag/tests/quality/ab_report.md](../../../../src/vaultspec_rag/tests/quality/ab_report.md): explains the intent-ranking A/B results and their interpretation, including the stated orientation target, debugging/implementation outcomes, no-regress floor, and provenance. These are report claims, not independently reproduced measurements.

## Interfaces and data flow

The visible support-function interfaces are `grade_for(intent, doc_type, status=None, on_topic=True)` in [src/vaultspec_rag/tests/quality/rubric.py](../../../../src/vaultspec_rag/tests/quality/rubric.py) and the exported metric functions in [src/vaultspec_rag/tests/quality/metrics.py](../../../../src/vaultspec_rag/tests/quality/metrics.py). The intent data stores already graded gold judgments; comments say grades derive mechanically from the rubric. The metric functions score a caller-provided ranked list against those judgments. For evidence evaluation, the data supplies a query, gold section/span, and body offset; `contains_evidence(excerpt, evidence)` checks normalized text containment.

The frozen-corpus helpers accept repository/destination paths and return a corpus path or document count. They invoke local Git commands and, for materialization, write extracted tracked vault files under the destination. The report says the harness uses a hermetic vault copy and real GPU/Qdrant/models, but this setup and the actual call sequence are documentation claims in [src/vaultspec_rag/tests/quality/ab_report.md](../../../../src/vaultspec_rag/tests/quality/ab_report.md), not inspected implementation.

## Boundaries and dependencies

The rubric and metrics are implemented with Python standard-library types, regex, and math and make no I/O in the visible code. Frozen-corpus support depends on an available Git executable, a repository containing the pinned ref, and filesystem access to the extraction destination; it imports subprocess and tarfile. The datasets and JSON files are static inputs. No retriever, ranker, GPU, Qdrant, query parser, baseline loader, or integration-test implementation is present in the assigned ranges, so their interactions remain unverified.
