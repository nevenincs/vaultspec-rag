## Capability summary

- [src/vaultspec_rag/\_readiness.py](../../../../src/vaultspec_rag/_readiness.py) defines a bounded readiness report for torch/compute, configured model snapshots, and Qdrant, plus an independent optional environment-holder snapshot. `compute_readiness` accepts an optional assessed compute report, a holder-scan root, and a deep model-verification flag. It emits JSON-friendly dataclasses; model checks may list cache completeness or verify pinned file digests, and the Qdrant check resolves and verifies the selected binary within a bound while reading supervised runtime state without spawning a server. Holder scans are opt-in and bounded (lines 54-72, 108-263, 266-343, 408-537, 540-717). The module documentation says CLI and MCP adapters share this service-domain behavior (lines 22-30).
- [src/vaultspec_rag/\_rich_console.py](../../../../src/vaultspec_rag/_rich_console.py) exports `supports_live(console)`, a small capability predicate based on interactivity and dumb-terminal state (lines 10-15).
- [src/vaultspec_rag/\_rmtree.py](../../../../src/vaultspec_rag/_rmtree.py) exports `remove_tree`, using `shutil.rmtree` with an error handler that unlinks encountered symlinks and re-raises other failures; it forwards an optional directory descriptor for relative removal (lines 37-78). Its documentation describes this as protection for links appearing below an already-validated real directory, including Windows junctions (lines 8-17).
- [src/vaultspec_rag/\_root_identity.py](../../../../src/vaultspec_rag/_root_identity.py) provides `canonical_root_path` (reject NUL, resolve a path) and `canonical_root_key` (normalize the resolved spelling for platform equivalence) (lines 9-18).
- [src/vaultspec_rag/\_runtime_identity.py](../../../../src/vaultspec_rag/_runtime_identity.py) centralizes interpreter fields (`executable`, `prefix`, `base_prefix`, `virtual_env`) and process identity fields (adds PID, parent PID, OS user) in typed dictionaries (lines 34-78). Its documentation distinguishes stable interpreter identity used by discovery/health from process identity used for job records (lines 3-14, 51-71).
- [src/vaultspec_rag/\_search_state.py](../../../../src/vaultspec_rag/_search_state.py) owns the shared search-readiness vocabulary and payload builders: source availability/freshness/authority, wait evidence and generation identity, bounded source facts, a derived multi-source aggregate, failure responses, result-collapse signal, and canonical `index_state` block (lines 38-69, 72-235, 254-457, 460-614, 617-721). Its documentation describes it as a neutral leaf shared by in-process and daemon search surfaces (lines 10-15).
- [src/vaultspec_rag/\_service_borrower.py](../../../../src/vaultspec_rag/_service_borrower.py) supplies `BorrowerLeaseMixin`: validates borrower lease status, binds capability only after safe quiescence, stamps ownership onto published quiesce snapshots, lends the GPU to a verified borrower, clears matching ownership after resume, and attempts recovery when the borrower's OS lease is lost (lines 30-189).
- [src/vaultspec_rag/\_service_eviction.py](../../../../src/vaultspec_rag/_service_eviction.py) supplies `ProjectEvictionMixin`: acquires/releases slot pins, selects idle and LRU victims, serializes teardown under root store guards, supports forced eviction with busy/not-found outcomes, and exposes busy-root/project snapshots and a shared projects envelope (lines 26-240). Leased slots are not candidates (lines 88-107, 127-146).
- [src/vaultspec_rag/\_service_residency.py](../../../../src/vaultspec_rag/_service_residency.py) supplies `GPUResidencyMixin` for pause/resume transitions. One caller owns side effects while same-direction callers wait boundedly and opposite-direction requests conflict; transitions drain compute, detach or rebuild shared GPU dependencies, coordinate job recovery, validate closed/drained admission epochs, and fail closed after partial rebuild (lines 48-97, 99-223, 225-332, 334-500). This assigned range ends at a section marker for per-project slots, so it does not cover that later section (line 502).
- [src/vaultspec_rag/\_service_types.py](../../../../src/vaultspec_rag/_service_types.py) defines registry vocabulary: health shape, errors, GPU release/rebuild evidence and recipe, transition operation, project compute runtime and slot, and ticketed compute/search leases. It also validates resource-transition timeouts and rejects absent lifecycle references explicitly (lines 32-67, 84-128, 131-205, 207-295).
- [src/vaultspec_rag/\_source_types.py](../../../../src/vaultspec_rag/_source_types.py) defines canonical public source names, concrete index-source typing, opt-in legacy aliases, strict parsing with a structured transport error, and a shared refusal envelope for unsupported point-ID feedback (lines 21-78, 81-150, 153-193).
- [src/vaultspec_rag/\_sparse_encoder.py](../../../../src/vaultspec_rag/_sparse_encoder.py) restricts sparse inference to the reviewed model ID, imports the model class from verified snapshot bytes against a committed digest, loads model/tokenizer locally, prepares tokenized inputs separately, and runs forward under accelerator inference mode (lines 48-100, 103-169). The module documentation describes avoiding the model library's repository-code loading path (lines 1-8).
- [src/vaultspec_rag/\_sparse_profile.py](../../../../src/vaultspec_rag/_sparse_profile.py) holds the sparse model ID, pinned revision, vocabulary width, and document maximum length shared by inference/acquisition (lines 1-6).

## Interfaces and data flow

- Readiness: `compute_readiness(holders_root=None, compute=None, verify_models=False)` gets config/effective backend, uses the supplied compute verdict or `local_compute()`, constructs dependency nodes in torch/models/Qdrant order, and skips holder scanning unless a root is supplied ([src/vaultspec_rag/\_readiness.py:266-316](../../../../src/vaultspec_rag/_readiness.py#L266)). Model results carry per-repository presence, pinned state, revision, and whether verification was requested; import failure for the hub client yields `UNKNOWN` ([src/vaultspec_rag/\_readiness.py:408-494](../../../../src/vaultspec_rag/_readiness.py#L408)). Qdrant readiness returns resolution source/path and runtime snapshot, or a refusal/missing-binary diagnosis; local-only, client, and already-remote cases report the binary as not needed ([src/vaultspec_rag/\_readiness.py:585-717](../../../../src/vaultspec_rag/_readiness.py#L585)). `ReadinessReport.to_dict` also includes support-profile status, storage-schema description, and local package version ([src/vaultspec_rag/\_readiness.py:230-263](../../../../src/vaultspec_rag/_readiness.py#L230)).
- Search state: immutable `GenerationEvidence`, `WaitObservation`, and `SearchSourceFact` objects validate bounded identifiers, finite non-negative timing, enum types, evidence counts, and consistency between authority/freshness/generation. `SearchReadinessAggregate.from_sources` derives availability, freshness, authority, usable count, and degraded sources; serializers place the facts and aggregate together ([src/vaultspec_rag/\_search_state.py:237-457,460-614](../../../../src/vaultspec_rag/_search_state.py#L237)). `SearchReasonCode` maps setup/transition causes to stable failure codes and optional operator remediation ([src/vaultspec_rag/\_search_state.py:115-208](../../../../src/vaultspec_rag/_search_state.py#L115)). `search_index_state` produces source/count/root/status and optional shortfall, collapse, and integrity blocks ([src/vaultspec_rag/\_search_state.py:678-721](../../../../src/vaultspec_rag/_search_state.py#L678)).
- Source selection: `parse_source_type(value, allow_aliases=False)` accepts canonical enum/string values and accepts legacy spellings only when opted in; otherwise it raises `SourceTypeParseError`, which serializes an error payload/envelope ([src/vaultspec_rag/\_source_types.py:81-150](../../../../src/vaultspec_rag/_source_types.py#L81)). Feedback refusal is returned only when point IDs are supplied for document or combined search ([src/vaultspec_rag/\_source_types.py:153-193](../../../../src/vaultspec_rag/_source_types.py#L153)).
- Service registry lifecycle: `ComputeLease` obtains a controller ticket before the project-slot context, creates a runtime, then releases slot ownership before releasing the ticket; `SearchLease` wraps it and exposes the searcher only while entered ([src/vaultspec_rag/\_service_types.py:207-295](../../../../src/vaultspec_rag/_service_types.py#L207)). Eviction uses a project map/refcounts plus per-root store guards and invokes watcher-close callback, graph-cache invalidation, and store close ([src/vaultspec_rag/\_service_eviction.py:109-200](../../../../src/vaultspec_rag/_service_eviction.py#L109)). Residency operations coordinate a quiesce controller, job manager, GPU owner, model/reranker fields, and project compute runtimes ([src/vaultspec_rag/\_service_residency.py:69-139,225-278,334-500](../../../../src/vaultspec_rag/_service_residency.py#L69)). Borrower lifecycle adds an external capability/lease check around this quiescence state ([src/vaultspec_rag/\_service_borrower.py:71-117,144-189](../../../../src/vaultspec_rag/_service_borrower.py#L71)).
- Sparse inference: a verified snapshot supplies the reviewed source class and local model/tokenizer files. `prepare` tokenizes before accelerator forward; `forward` moves the prepared tensors to the selected device and invokes the model under inference mode ([src/vaultspec_rag/\_sparse_encoder.py:62-100,103-169](../../../../src/vaultspec_rag/_sparse_encoder.py#L62)). Identity helpers provide normalized root keys and interpreter/process fact dictionaries to consumers that need them ([src/vaultspec_rag/\_root_identity.py:9-18](../../../../src/vaultspec_rag/_root_identity.py#L9); [src/vaultspec_rag/\_runtime_identity.py:51-78](../../../../src/vaultspec_rag/_runtime_identity.py#L51)).
