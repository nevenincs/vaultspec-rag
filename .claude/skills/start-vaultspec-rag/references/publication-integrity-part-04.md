## Capability summary

- [src/vaultspec_rag/indexer/\_run_ledger_publication_storage.py](../../../../src/vaultspec_rag/indexer/_run_ledger_publication_storage.py) implements SQLite row decoding, bounded publication-evidence queries, receipt hydration, snapshot queries, and readiness checks. It converts malformed persisted proofs/evidence/receipts into ledger corruption or proof-rebuild errors, checks compatibility keys, reconstructs mutation units and path deltas, batches path lookups by `FETCH_BATCH`, recognizes a narrowly defined no-op publication, and verifies commit readiness. The module does not declare an external entry point; its function callers are in uninspected publication mixins. Visible internal calls include `require_proof_row` → `proof_row` / `require_exact_key`, `hydrate_receipt` → mutation and delta readers, and `proof_snapshot_row` → stable-key snapshot lookup.
- [src/vaultspec_rag/indexer/\_run_ledger_runtime.py](../../../../src/vaultspec_rag/indexer/_run_ledger_runtime.py) owns `RunLedger` construction, generation lifecycle, schema creation and exact schema verification, an explicit integrity scan, signature hydration, and set-aside handling for unsupported ledgers. It composes publication proof/read/receipt, commit, file, and finalization mixins. Construction creates the parent directory, opens or initializes the SQLite ledger through supplied preflight/initialization callbacks, and verifies its schema. `start_generation` resumes a compatible active generation, retires one at the configured consecutive-failure threshold, invalidates a generation with a changed signature, or inserts a new generation; non-clean generations may record a compatible publication-proof parent. `verify_integrity` runs SQLite `quick_check` on demand. Unsupported schemas fail with a rebuild-required error; the explicit set-aside function renames the database and journal companions under a lock before a rebuild. Public exports are `RunLedger` and `set_aside_unsupported_ledger`. External calls into the class and methods supplied by its mixins are outside this slice.
- [src/vaultspec_rag/indexer/\_run_policy.py](../../../../src/vaultspec_rag/indexer/_run_policy.py) provides per-attempt, thread-safe no-progress liveness and cooperative interruption through `RunPolicy`, `RunPolicySnapshot`, and `DurableProgressKind`. It uses a monotonic timeout clock, latches expiry as a typed `JobError`, checks `RunControl` at safe boundaries, provides protected intervals and interruptible waits, and exposes the same remaining-time and wait behavior through a `StoreWritePolicy`. Only explicitly typed durable progress updates the clock; an optional observer receives snapshots. `from_config` reads the configured timeout lazily. Exported names are listed in `__all__`. Callers that decide when storage work is durable are not present in the assigned range.
- [src/vaultspec_rag/indexer/\_scan_cache.py](../../../../src/vaultspec_rag/indexer/_scan_cache.py) implements `MembershipScanCache`, a thread-safe one-slot cache keyed by a fingerprint and monotonic TTL (default 30 seconds), with `get`, `put`, and `invalidate`. The module docstring says scoped runs bypass discovery and callers invalidate after membership changes; those caller policies are claims in the source documentation, not behavior established by this cache class alone. No callers are present in the assigned range.
- [src/vaultspec_rag/indexer/\_slicing.py](../../../../src/vaultspec_rag/indexer/_slicing.py) estimates retained memory for code and document chunks, creates bounded document slices, segments a single code file by chunk and byte limits, packs ordered segments into bounded weighted code slices, and constructs embedding input strings for code, documents, and vault chunks. Limits come from explicit request values or lazily loaded configuration; dense/sparse vector dimensions and encoded text/payload sizes contribute to estimates. Run-control checkpoints are interleaved through iterators. Code segments preserve file-local ordinals and a final-file marker; weighted packing validates segment transitions and can skip segments while preserving boundaries. No caller that feeds an encoder or store is included here.
- [src/vaultspec_rag/indexer/\_source_file.py](../../../../src/vaultspec_rag/indexer/_source_file.py) binds reads to admitted regular files. `source_file_stat` rejects links/non-canonical paths and non-regular files. `open_source_file` validates before yielding a binary stream, then checks the opened descriptor against the observed file identity. POSIX opens each path component with no-follow flags; Windows checks the path obtained from the opened handle. It raises `SourceIdentityError` when the source name redirects or changes. No caller is present in the assigned range.

## Interfaces and data flow

- Publication persistence: `sqlite3.Connection` and `sqlite3.Row` values flow into typed proof, evidence, receipt, mutation, and delta models. Stable compatibility identity scopes proof/evidence queries. Receipt hydration combines header rows with child mutation, point, delta, and receipt-point rows; malformed structure is treated as durable-state corruption. Snapshot helpers expose the current proof plus whether an open receipt exists. These helpers use model/identity modules whose implementations were not inspected.
- Run lifecycle: `RunLedger(path)` establishes a SQLite ledger. `start_generation(RunSignature)` returns a `RunGeneration`; `generation(generation_id)` loads one or raises `KeyError`. Schema DDL contains generation, commit-unit, file-state, publication-proof/evidence, receipt/mutation/delta, and tombstone records. The runtime checks version, required object/column/index definitions, predicates, and unexpected objects. `set_aside_unsupported_ledger(path)` returns the moved-aside path or `None`; lock contention is surfaced as `RunLedgerContentionError`.
- Liveness: `RunPolicy(no_progress_timeout_seconds, run_control)` exposes `checkpoint`, `protected`, `remaining_seconds`, `record_durable_progress`, `complete`, `wait`, `snapshot`, and `store_write_policy`. Progress snapshots include elapsed and remaining seconds, count, last kind/label, and expiry state.
- Discovery cache: `MembershipScanCache[T]` stores a generic value with its fingerprint and deadline. `get(fingerprint)` yields the value or `None`; `put` replaces the single slot; `invalidate` empties it.
- Slicing: the two estimator functions accept a chunk and dense/sparse dimensions. `iter_weighted_document_slices(request)` consumes document chunks from the request. `iter_code_file_segments(request)` consumes one file's chunks and emits ordered `CodeFileSegment`s. `iter_weighted_code_slices(segments, ...)` emits `WeightedCodeSlice`s. Embedding helpers accept chunks or plain field values and return strings; vault input is title plus text, code input includes path and available class/function context, and document input includes source path and available title/section.
- Source access: `source_file_stat(path, root_dir)` returns `os.stat_result`; `open_source_file(path, root_dir)` is a context manager yielding a binary reader only after path and descriptor checks.
