**Test expectations:**

- [src/vaultspec_rag/tests/test_vault_chunking_unit.py](../../../../src/vaultspec_rag/tests/test_vault_chunking_unit.py) covers document splitting, exact chunk and passage file-line spans, ordinal/count and point-key consistency, placing full body on the first chunk, and flattening document metadata onto chunks. It also checks per-document search-result grouping (best-score representative and selected runner-up passages) and bounded additive graph reranking (lines 45-136, 138-173, 175-222).
- [src/vaultspec_rag/tests/test_vault_fingerprint.py](../../../../src/vaultspec_rag/tests/test_vault_fingerprint.py) covers split fingerprint encoding/parsing and delta classification for unchanged, metadata-only, body, and unseen documents; line-ending normalization for classification; raw on-disk byte identity; malformed/legacy/unrecognized-path handling; and undecodable-byte fallback (lines 86-142, 144-204, 206-260). Comments describe the intended consequence of classifying body changes for rebuilds, but this suite portion chiefly pins classifier outputs.
- [src/vaultspec_rag/tests/test_vault_metadata_subset.py](../../../../src/vaultspec_rag/tests/test_vault_metadata_subset.py) enforces a partition of chunk payload keys into body, structural, and indexed metadata fields. It checks that every indexed field affects the digest, whitespace canonicalization, body exclusion, order-sensitive tags, and a frontmatter insertion that moves stored body line metadata (lines 62-117, 119-160).
- [src/vaultspec_rag/tests/test_vault_payload_batching.py](../../../../src/vaultspec_rag/tests/test_vault_payload_batching.py) exercises local store payload overwrite and the indexer's payload-refresh path. Its oracles cover bounded batches, a batch-size snapshot for one write, exact payload replacement with obsolete-key removal, vector preservation, waiting for writes, and stable point addressing (lines 165-228). It checks document-level receipt confirmation only after all operations complete, rejects incomplete result sets/statuses without confirming the current document, retries a partially applied transport batch exactly, and preserves unconfirmed state on write failures (lines 230-427). It also checks caller deadline propagation and retry exhaustion (lines 429-466).
- [src/vaultspec_rag/tests/test_vault_progress_phases.py](../../../../src/vaultspec_rag/tests/test_vault_progress_phases.py) checks progress ownership for hashing and scoped incremental preparation, including metadata-only, unchanged, and mixed metadata/body cases. It asserts phase totals, no rejected/stray advances, and result/store/ledger calls consistent with changed-document classes (lines 65-95, 153-229).
- [src/vaultspec_rag/tests/test_vault_readiness_publication.py](../../../../src/vaultspec_rag/tests/test_vault_readiness_publication.py) checks full, incremental, and scoped vault publication against a pending readiness target, notification after a successful durable publication, no notification when proof or generation publication fails, and actual runtime construction wiring a vault callback (lines 68-119, 121-149, 152-193).
- [src/vaultspec_rag/tests/test_vault_run_liveness.py](../../../../src/vaultspec_rag/tests/test_vault_run_liveness.py) exercises real local `VaultStore` and checkpoint/ledger paths with a lightweight unloaded embedding model. Expectations cover deadline renewal only on new durable units, duplicate/empty confirmation not renewing, timeout blocking terminal success, successful completion retiring the run deadline while preserving cancellation and closed storage admission, and storage/ledger/terminal-write failures not completing the run (lines 118-334). Further tests inspect actual write-policy/control delivery through streaming and payload refresh, checkpoint policy adoption in full/incremental/scoped entries, bounded point-lock waits, and writer cleanup after deadline expiry (lines 336-559).
- [src/vaultspec_rag/tests/test_vault_split_parallel.py](../../../../src/vaultspec_rag/tests/test_vault_split_parallel.py) compares parallel splitting with serial output, checks auto mode and worker-count limits, and probes a fresh import to ensure vault preparation does not import torch (lines 75-111).
- [src/vaultspec_rag/tests/test_verified_import.py](../../../../src/vaultspec_rag/tests/test_verified_import.py) covers execution from digest-matched source bytes, refusal before executing mismatched bytes, ignoring adjacent bytecode and a model library's planted module-cache copy, and an AST policy over shipped package modules for model-library remote-code/dynamic-loader usage (lines 59-127, 129-215, 218-258).
- [src/vaultspec_rag/tests/test_watcher_admission.py](../../../../src/vaultspec_rag/tests/test_watcher_admission.py) checks oldest-deadline fairness independent of input order, resistance to newer noisy work, rotating deterministic ties by canonical root/source, exclusion of ineligible/future decisions, and rotation when tie membership changes (lines 39-111).
- [src/vaultspec_rag/tests/test_watcher_controller.py](../../../../src/vaultspec_rag/tests/test_watcher_controller.py) checks the public state/reason vocabulary and immutable source-qualified scope/snapshot/measurement/transition facts, path/count validation, adaptive coalescing, batch and quiet-tree readiness, pressure/freshness timing, retry/circuit transitions, admission while collecting, refused admission, job lifecycle/convergence/cooling, active-job identity under new observations, retry reset/release/refusal behavior, generated pressure sequences, independent fair-selection claims, and durable exact-scope persistence through interruption, success, and restart (lines 132-171, 174-266, 269-394, 395-504, 505-670, 671-827).

## Interfaces and data flow

- Test-visible vault indexing entry points include `VaultIndexer.full_index` and `incremental_index`; incremental tests pass `changed_paths` for scoped indexing. Tests also call private preparation/refresh/streaming seams (`split_document(s)`, `_apply_payload_refresh`, `_stream_encode_and_upsert_vault`) directly. These are test call paths, not a complete public API inventory (progress: [src/vaultspec_rag/tests/test_vault_progress_phases.py:65-95,153-229](../../../../src/vaultspec_rag/tests/test_vault_progress_phases.py#L65); readiness: [src/vaultspec_rag/tests/test_vault_readiness_publication.py:68-119](../../../../src/vaultspec_rag/tests/test_vault_readiness_publication.py#L68); liveness: [src/vaultspec_rag/tests/test_vault_run_liveness.py:336-489](../../../../src/vaultspec_rag/tests/test_vault_run_liveness.py#L336)).
- Test fixtures create `VaultDocument`/`VaultChunk` values and synthetic vault files. Fingerprint tests pass bytes or paths plus a root and receive encoded strings parsed into split values; payload tests read stored Qdrant-local point payloads/vectors and observe batch update requests; publication tests inspect checkpoint/ledger receipts and publication snapshots ([src/vaultspec_rag/tests/test_vault_fingerprint.py:66-83,147-204](../../../../src/vaultspec_rag/tests/test_vault_fingerprint.py#L66); [src/vaultspec_rag/tests/test_vault_payload_batching.py:76-162,283-359](../../../../src/vaultspec_rag/tests/test_vault_payload_batching.py#L76); [src/vaultspec_rag/tests/test_vault_readiness_publication.py:82-116](../../../../src/vaultspec_rag/tests/test_vault_readiness_publication.py#L82)).
- Progress tests use a reporter interface (`phase_start`, `advance`, `phase_end`) or a job reporter publication seam. Readiness tests use `ServiceRegistry` and its readiness registry; liveness tests use `RunControlToken`, checkpoint `RunPolicy`, store-write policy, local store, and SQLite-backed run ledger ([src/vaultspec_rag/tests/test_vault_progress_phases.py:44-63,97-113](../../../../src/vaultspec_rag/tests/test_vault_progress_phases.py#L44); [src/vaultspec_rag/tests/test_vault_readiness_publication.py:78-94](../../../../src/vaultspec_rag/tests/test_vault_readiness_publication.py#L78); [src/vaultspec_rag/tests/test_vault_run_liveness.py:71-115,197-250](../../../../src/vaultspec_rag/tests/test_vault_run_liveness.py#L71)).
- Watcher tests construct source-qualified scope observations and controller measurements, then call controller observation/evaluation/admission/lifecycle methods. Admission arbitration consumes snapshots and exposes a selected root/source/deadline; retry-policy tests persist pending/captured scope and attempt identity across success, interruption, and reconstruction ([src/vaultspec_rag/tests/test_watcher_controller.py:48-129,269-317,462-670,754-827](../../../../src/vaultspec_rag/tests/test_watcher_controller.py#L48); [src/vaultspec_rag/tests/test_watcher_admission.py:19-47](../../../../src/vaultspec_rag/tests/test_watcher_admission.py#L19)).
