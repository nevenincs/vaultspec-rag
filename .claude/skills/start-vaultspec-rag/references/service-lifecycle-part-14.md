## Capability summary

- [src/vaultspec_rag/tests/test_server_routes.py](../../../../src/vaultspec_rag/tests/test_server_routes.py): test coverage for HTTP routes and root validation, search-activity admission and review records, audit authority checks, reindex preprocess status, service-state and document/file routes, error payload shapes, and watcher registry access. Test clients build `ServerRouteRuntime` and call `create_http_app`. Assertions cover HTTP 400s for absent/empty roots; validation-rejected activity records for malformed search requests; authentication before query exposure; waiting for activity capacity; and audit authority validation before the domain call (41–219, 220–351, 352–596, 599–697, 699–872, 874–979). Comments/docstrings say root checks fire before model/store access and explain why a preprocess status is returned for queued reindexing; those are claims in test source, not independently verified (41–52, 699–710).
- [src/vaultspec_rag/tests/test_service_cleanup_callers.py](../../../../src/vaultspec_rag/tests/test_service_cleanup_callers.py): a shared regression test exercises status, attach, and start-failed cleanup callers with a dead recorded process and a successor status pointer; it expects cleanup to retain the successor (27–62).
- [src/vaultspec_rag/tests/test_service_discovery_schema.py](../../../../src/vaultspec_rag/tests/test_service_discovery_schema.py): tests atomic JSON output/temporary-file cleanup, agreement between the CLI parent writer and daemon heartbeat writer on schema/version and timestamp format, retention of same-port daemon identity during merge, bounded lock acquisition, cross-process delete/merge races, and heartbeat upgrade of legacy unversioned status (57–304). Its module docstring describes a past consumer-format divergence; that history was not checked against other sources (1–8).
- [src/vaultspec_rag/tests/test_service_env_preflight.py](../../../../src/vaultspec_rag/tests/test_service_env_preflight.py): covers daemon-log tailing and executable labels; path-based classification of uv tool, uvx ephemeral, project venv, and other environments; CUDA remediation command/platform choices; tool receipt durability and repair/upgrade commands; and warnings for ephemeral daemon/caller environments (46–647). The test comments explain intended uv/package-manager hazards; those explanations are not corroborated by inspected implementation or external documentation.
- [src/vaultspec_rag/tests/test_service_environment.py](../../../../src/vaultspec_rag/tests/test_service_environment.py): covers the `judge_service_environment` result from installation role and interpreter capability, including client short-circuiting, reuse of a supplied probe result, missing interpreters, blocking and nonblocking capabilities, and carrying a diagnostic reason (32–192). Two tests compare the current machine’s metadata/child-interpreter probe, but were not run here.
- [src/vaultspec_rag/tests/test_service_launcher_lifetime.py](../../../../src/vaultspec_rag/tests/test_service_launcher_lifetime.py): uses a CPU-only bootstrap child to exercise detached `_spawn_service`, a reaper thread, and cleanup after reaper-thread startup failure; it expects launcher ownership to last until child exit and failed ownership setup to reap the child (21–163). The child is a test harness, not a live service.
- [src/vaultspec_rag/tests/test_service_lifecycle_helpers.py](../../../../src/vaultspec_rag/tests/test_service_lifecycle_helpers.py): tests token merge/write behavior in service status, startup phase labels, the serving predicate across job-history degradation and backend modes, and warning rendering including unknown reasons (19–293).
- [src/vaultspec_rag/tests/test_service_preflight_cli.py](../../../../src/vaultspec_rag/tests/test_service_preflight_cli.py): exercises `server preflight --json` over real local HTTP route hosts and discovery records. It expects preflight to observe a safely quiesced service while remaining non-authorizing, and to refuse unsafe, stale/future/malformed, incompatible, unreachable, mismatched-identity, or unavailable service state. It also checks that a listening but silent endpoint is reported as a health timeout, that authenticated state is tied to the machine pointer token, and that importing the CLI verb does not load torch (49–68, 71–245, 247–600).

## Interfaces and data flow

- Route tests construct a runtime and ASGI app, send authenticated or unauthenticated HTTP requests, then inspect JSON responses and, for search validation, the activity ledger. Audit tests constrain accepted authority and capture the arguments expected at the canonical audit owner. Reindex tests send a root and inspect a preprocess block while the job remains queued (56–68, 69–219, 407–513, 699–872).
- Discovery tests isolate status/storage paths, seed or read `service.json`, call the parent writer or heartbeat tick, and check schema, version, timestamp, heartbeat thresholds, and merge/delete results. A machine-lock lease is used by the publisher fixture; atomic write and discovery helpers are imported but their implementations were not inspected (65–130, 135–304).
- Environment tests pass an interpreter path and optional probe depth/result to the environment judgment; related tests call classifier and remediation/upgrade command builders and compare returned enums, labels, and command strings. This records the tested interface shape, not the underlying algorithms (77–215, 242–647; [src/vaultspec_rag/tests/test_service_environment.py](../../../../src/vaultspec_rag/tests/test_service_environment.py) 42–192).
- Lifecycle tests mutate an isolated status file and compare its JSON/mtime, or provide health/status payloads and compare rendered labels, serving decisions, and warning lines. The launcher harness starts a child through `_spawn_service`, communicates through temporary PID/stop witnesses, and checks child/reaper lifetime (83–293; [src/vaultspec_rag/tests/test_service_launcher_lifetime.py](../../../../src/vaultspec_rag/tests/test_service_launcher_lifetime.py) 21–163).
- CLI preflight tests publish discovery data, host the production route table in-process or in a child process, invoke the Typer command, and inspect its exit code/JSON text. Assertions expose `ok`, `error`, `source`, `port`, `authorized`, `lease_required`, `state`, `safe_to_borrow_gpu`, and `capacity` as observed response fields; no full schema is established by this slice (49–68, 150–245, 247–600).

## Boundaries and dependencies

- All eight assigned files are tests under `src/vaultspec_rag/tests`; none is an implementation module. Accordingly, no implementation responsibility can be established directly from this slice.
- Route tests import server, server utilities/state/activity, service registry, CLI-independent source/authority types, MCP resource handling, and preprocess approval helpers. They monkeypatch the audit owner in some cases and inspect watcher source in one case. Those are test relationships, not inspected implementation internals ([src/vaultspec_rag/tests/test_server_routes.py](../../../../src/vaultspec_rag/tests/test_server_routes.py) 16–32, 74–75, 181–185, 460–482, 932–979).
- Discovery-schema tests connect the CLI status writer, server lifecycle/state heartbeat, serviceclient discovery helpers, atomic JSON writing, and machine-lock lease helpers ([src/vaultspec_rag/tests/test_service_discovery_schema.py](../../../../src/vaultspec_rag/tests/test_service_discovery_schema.py) 25–45).
- Environment/preflight tests connect CLI start/status helpers, operator-state provisioning/topology/environment modules, torch index configuration, and status discovery/transport helpers ([src/vaultspec_rag/tests/test_service_env_preflight.py](../../../../src/vaultspec_rag/tests/test_service_env_preflight.py) 15–41; [src/vaultspec_rag/tests/test_service_environment.py](../../../../src/vaultspec_rag/tests/test_service_environment.py) 20–27; [src/vaultspec_rag/tests/test_service_preflight_cli.py](../../../../src/vaultspec_rag/tests/test_service_preflight_cli.py) 20–37).
- Cleanup-callers tests reuse helpers from `test_service_stop_port.py`; their behavior is not covered by this assignment and that file was not read ([src/vaultspec_rag/tests/test_service_cleanup_callers.py](../../../../src/vaultspec_rag/tests/test_service_cleanup_callers.py) 10–19). Launcher tests import process probing and CLI spawn helpers. Lifecycle-helper tests import status update and start-rendering helpers. Implementations for all these imports remain uninspected.
- Inference: the slice concentrates on service routes, daemon discovery/lifecycle, operator environment guidance, and a non-authorizing service preflight path. This grouping follows the assigned test names/imports and should not be treated as a complete package architecture map.
